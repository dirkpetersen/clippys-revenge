# M16.5 Revisit in `DraftWorker` (`DraftWorker.Revisit.cs`)

Base: `dev` with M16.2 and M16.3 merged (both are). Runs **beside M16.4**;
the two briefs share no file (see "Parallel work"). Everything here is Core
and is tested with fakes only.

## Goal

Make the automatic pass re-evaluate Clippy's own tracked AI drafts when
their thread moves on (§23.2, §23.6): a revisit step per mailbox before the
candidates, the "user replied" check, the guard read, the reply-target
choice, cap/backoff/hold shared with drafting, the model call with
`RevisitSchema`, keep / replace (new draft **before** the move) / remove,
`ai_revisits` and `ai_drafts` bookkeeping, the 3-attempt give-up,
`revisited` rows for the newer messages, the `Draft`/`Ai` events of §23.9
and the pass summary, balloon and log additions. Automatic drafts start
being tracked in `ai_drafts` (§23.3). The rescan (M16.6) will reuse the
per-draft method built here.

SPEC refs: §23.1, §23.2, §23.3 (row insert rule), §23.6, §23.7 (request
shape), §23.9, §19.7 (steps 3–4, 6a, 8, backoff, hold, pass summary/log),
§19.11 (logs), §21.6 (meeting times), §23.11 (Core bullet "`DraftWorker`
revisit with fakes"). The M16.3 brief's open point is closed here: the
revisit `<thread>` excludes the old draft and Drafts rows (Behavior E.3).

## Hard rules that apply here

- **Never send, never delete.** The worker only calls `IReplyDraftWriter`
  (save-only reply path, marker `ai`, `Re:: ` via `ReplySubject.Normalize`
  in the writer) and `IAiMailbox.MoveObsoleteAiDraftAsync` (the COM side
  re-checks the guard itself). No other Outlook write.
- **AI files** (§19.12): `DraftWorker.Revisit.cs`, `DraftRevisit.cs`,
  `DraftRules.cs`, `DraftWorker.cs` must contain no `.Send(`, `.Display(`,
  `.Move(`, `Delete(` and no COM types (`Outlook.`, `Marshal`, `MailItem`,
  `CreateReplyDraft`). `MoveObsoleteAiDraftAsync(` doesn't match the scan.
- **Model output is untrusted**: only `DraftRevisit.Parse`'s fields are
  used; `body_html` goes through `DraftHtml.Sanitize`; `reason` is never
  read, stored, logged or shown. The model gets no tools (unchanged
  `IDraftModel`).
- **Logs** (§19.11, §23.9): no subjects, entry ids, addresses, draft text,
  prompts, model output, fingerprints or `reason`. Revisit Debug lines are
  exactly `AI drafts: revisit <outcome>`.
- Only rows of Clippy's own index are written/removed.

## Behavior

### A. Pass integration (`DraftWorker.cs`)

1. `RunMailboxesAsync`: for each `key`, right after `index`/`mailboxSmtp`
   are set and before the candidate loop:
   ```csharp
   var cur0 = _s.Settings().Clone();
   if (cur0.AiDrafting.ReviseDrafts)
   {
       var stop = await RevisitMailboxAsync(p, new RevisitScope(index, key, mailboxSmtp, cur0, identity, userSmtp,
           WorkPriority.Background), ct).ConfigureAwait(false);
       if (stop is { } e) return e;
   }
   ```
   The candidate loop is unchanged. A pass with `ReviseDrafts = false`
   makes no `DueRevisits` call, no draft read, no revisit call.
2. Step 8 of `ProcessCandidateAsync`, after `Write(... Drafted ...)` and
   before the `Draft` event: when `made.Fingerprint` is not null and
   `DraftFingerprint.IsValid(made.Fingerprint)` →
   `index.RecordAiDraft(made.EntryId, c.EntryId, created, made.Fingerprint, c.EventTime, created)`
   inside `try { } catch (Exception ex) when (ex is not OperationCanceledException)`
   with a Warning `AI drafts: couldn't record an AI draft ({Type}).` (a
   bookkeeping failure never fails the draft). Independent of
   `ReviseDrafts` (§23.3). The manual path records **nothing** in
   `ai_drafts` (§23.1).
3. `PassCoreAsync` `finally`:
   - summary when `p.Rows > 0 || p.Revisits > 0`:
     `DraftTexts.Summary(p.Drafted, p.NoReply, p.LowConfidence, p.Skipped, p.Failed, elapsed, p.Updated, p.Moved, p.Kept)`;
   - balloon when `p.Drafted + p.Updated > 0`: `BalloonTexts.AiDrafted(p.Drafted + p.Updated)`, `ShowDrafts`;
   - log line: `"AI drafts pass: {End}, {Drafted} drafted, {Updated} updated, {Moved} moved, {Kept} kept, {NoReply} no reply, {LowConfidence} low confidence{LowConfidenceDetail}, {Skipped} skipped, {Failed} failed, {Calls} calls in {Ms} ms"`.
   - result `new DraftPassResult(end, p.Drafted, p.NoReply, p.LowConfidence, p.Skipped, p.Failed, p.Calls, p.Updated, p.Moved, p.Kept)`.
4. `DraftTexts.Summary`: after `"<d> drafted"`, append
   `", <u> updated"`, `", <m> moved to Deleted Items"`, `", <k> kept"`
   (each only when > 0), then the existing parts. Invariant culture.
5. Split `BuildRequest`: a private
   `DraftPromptInput PromptInput(Settings settings, string key, PromptEmail email, IReadOnlyList<ThreadMessage> thread)`
   builds now/zone/label/signature exactly as today; `BuildRequest` calls
   it with `index.Thread(...)`. `BuildRequest`'s output stays byte-identical
   (existing tests pass unchanged).

### B. `RevisitMailboxAsync(p, s, ct)` (§23.2)

```
now = _time.GetUtcNow()
due = s.Index.DueRevisits(now - TimeSpan.FromDays(DraftRevisit.MaxDraftAgeDays), DraftRevisit.MaxRevisitsPerMailbox)
foreach d in due (newest UpTo first, as returned):
    if ct cancelled → Cancelled; if _yield > 0 → Yielded
    cur = _s.Settings().Clone()
    if !cur.AiDrafting.Enabled || !HasConsent → Disabled
    if !cur.AiDrafting.ReviseDrafts → return null (go on to candidates)
    if s.Key.Length > 0 && !SharedAiEnabled(cur, s.Key) → return null
    stop = await RevisitAsync(p, s with { Settings = cur }, d.Thread, d.UpTo, ct)
    if stop → return stop
return null
```

A `DueRevisits` exception (index failure) → Warning
`AI drafts: listing drafts to revisit failed ({Type}).` and `null` (the
candidates still run).

### C. `RevisitAsync(p, s, t, upTo, ct)` — steps (§23.6)

`id = t.Draft.DraftEntryId`, `fp = t.Draft.Fingerprint`,
`oldChecked = t.Draft.Checked`, `topic = t.ConversationTopic`,
`ai = s.Settings.AiDrafting`, `tag = s.Key.Length == 0 ? null : s.Key`.
Every path logs exactly one Debug `AI drafts: revisit {Outcome}` line with
the outcome id named below, except the paths marked *(no line)*.

**Step 1 — user replied.**
`newer = s.Index.ThreadInbox(topic, oldChecked, upTo, EmailIndex.MaxThreadInboxRows)`.
Replied when `s.Index.RepliedTo(null, topic, t.Draft.Created)`, or
(`s.Key.Length > 0` and the own index's `RepliedTo(null, topic, t.Draft.Created)`),
or any `newer` row with `DraftRevisit.IsOwnAddress(row.SenderEmail, s.UserSmtp, s.MailboxSmtp)`.
→ `SetAiDraftState(id, Replied, null, t.Draft.Attempts, now)`, outcome
`replied`, return null. No COM, no model call.

**Step 2 — read and guard.** `info = await _s.Mailbox.ReadAiDraftAsync(s.Key, id, s.Priority, ct)`.
- `OutlookUnavailableException` → return `OutlookUnavailable` *(no line)*.
- `OperationCanceledException` when `ct` cancelled → return `Cancelled` *(no line)*.
- any other exception → Warning `AI drafts: reading an AI draft failed ({Type}, HResult {HResult}).`,
  no state change, return null *(no line)*; next pass tries again.
- `status = AiDraftGuard.Evaluate(info, fp)`:
  `Gone`/`NotInDrafts`/`Sent` → state `Gone`, outcome `gone`;
  `NotMarked`/`Changed` → state `Edited`, outcome `edited`;
  `Open` → no change, outcome `open`; each returns null.
  Only `Movable` goes on. (`SetAiDraftState(id, state, null, t.Draft.Attempts, now)`.)

**Step 3 — reply target.**
`rows = s.Index.ThreadInbox(topic, t.SourceTime, upTo, EmailIndex.MaxThreadInboxRows)`;
`target = DraftRevisit.PickReplyTarget(rows, s.MailboxSmtp, s.UserSmtp, ai)`;
`targetId = target?.EntryId ?? t.Draft.SourceEntryId`;
`detail = s.Index.Get(targetId)`; null (and `target` was not null) →
retry once with the source (`t.Draft.SourceEntryId`); still null → no
change, return null *(no line)*.

**Step 4 — limit and backoff** (as §19.7 steps 3–4, same fields):
`CapReached(ai.DailyCap)` → the once-a-day `DraftTexts.DailyLimit` event,
return `DailyLimit`. `_retryAt > now` → return `Backoff`. *(no line)*

**Step 5 — model call.**
- `thread = DraftRevisit.PromptThread(s.Index.Thread(topic, upTo, DraftRevisit.ThreadFetch, targetId), id)`.
- `email = new PromptEmail(detail.SenderName, detail.SenderEmail, detail.To, detail.Cc, detail.EventTime, detail.Subject, NonInlineNames(detail.Attachments), detail.Body)`.
- `input = PromptInput(s.Settings, s.Key, email, thread)`.
- request: `new ModelRequest(DraftPrompt.RevisitSystemPrompt(s.Identity.DisplayName, s.UserSmtp, _s.Style.ReadForPrompt(), ai.MeetingTimes), DraftPrompt.RevisitUserPrompt(new RevisitPromptInput(input, info.PlainBody, t.Draft.Created)), DraftModel.RevisitSchema, ai.Model, ai.Effort, TimeSpan.FromSeconds(ai.TimeoutSeconds), DraftModel.DraftMaxOutputTokens)`.
- progress as a candidate: `p.Scope ??= Begin(Drafting, DraftingLabel)`,
  `p.Total++`, `Report` before; `p.Done++`, `Report` after.
- result:
  - `Ok` → `p.Calls++`, `p.Revisits++`; `reply = DraftRevisit.Parse(ok.Output)`;
    null → failure `BadOutput`.
  - `RateLimited` → `_retryAt` and `DraftTexts.RateLimited` event exactly as
    §19.7; return `RateLimited` (no row) *(no line)*.
  - `NotSignedIn` → `EnterHold()`; return `NotSignedIn` (no row) *(no line)*.
  - `Failed { Kind: Cancelled }` when `ct` cancelled → return `Cancelled` (no row) *(no line)*.
  - `Failed f` → `p.Calls++`, `p.Revisits++`, failure `f.Kind`; anything
    else → same with `BadOutput`.
- **Failure** (`Fail(kind)`): `AddRevisit(id, now, Failed, 1)`; `a = t.Draft.Attempts + 1`;
  `a >= DraftRevisit.MaxAttempts` → `SetAiDraftState(id, Open, upTo, 0, now)` (trigger given up)
  else `SetAiDraftState(id, Open, null, a, now)`; `p.Failed++`;
  `_consecutiveFailures++`, `_retryAt` and `DraftTexts.CallFailed(kind, minutes)`
  as §19.7; outcome `failed`; return `Failed`.

**Step 6 — result.** `_consecutiveFailures = 0` on a parsed reply.
- *Low confidence*: `reply.Action != Keep && reply.Confidence < ai.MinConfidence`
  → `AddRevisit(id, now, LowConfidence, 1)`, `SetAiDraftState(id, Open, upTo, 0, now)`,
  `p.Kept++`, outcome `low_confidence`, then step 7. No Outlook call, no
  `Ai` low-confidence event (its text is about undrafted email).
- *Keep* (any confidence) → `AddRevisit(id, now, Keep, 1)`,
  `SetAiDraftState(id, Open, upTo, 0, now)`, `p.Kept++`, outcome `keep`,
  step 7.
- *Replace* → Behavior D.
- *Remove* → Behavior F.

**Step 7 — rows for the newer messages** (after every step-6 outcome,
including `edited`/`gone`/`open`/`left` reached inside D or F, never after
step 1, 2, 4 or a failure): for each row of
`s.Index.ThreadInbox(topic, oldChecked, upTo, EmailIndex.MaxThreadInboxRows)`
except the replace's target when its `drafted` row was written:
`prior = GetDecision(row.EntryId)`; when `prior is null` or
`prior.Outcome == Failed` → `UpsertDecision(new AiDecision(row.EntryId, row.InternetMessageId, null, now, Skipped, DraftRuleIds.Revisited, prior?.ModelCalls ?? 0, prior?.Attempts ?? 0))`.
These rows don't count in `p.Skipped` or `p.Rows`. Return null.

### D. Replace (§23.6 step 6 "replace")

1. `html = DraftHtml.Sanitize(reply.BodyHtml)`; empty → `Fail(BadOutput)` (C step 5).
2. Meeting times when `DraftMeetingTimes.IsWanted(ai, new DraftReply(true, reply.Confidence, reply.ReplyAll, reply.BodyHtml, reply.Meeting), html)`:
   - headers: `facts = await GetFactsAsync(s.Key, targetId, s.Priority, ct)`;
     `europe = SenderRegion.IsEurope(detail.SenderEmail, facts?.TransportHeaders)`;
     a non-gone, non-cancel exception → `IsEurope(detail.SenderEmail, null)` and a Debug
     `AI drafts: reading the email's headers for meeting times failed ({Type}).`
   - `mt = await _meetings.ApplyAsync(new MeetingTimesRequest(html, reply.Meeting, s.UserSmtp, s.Key, detail.SenderEmail, detail.To, detail.Cc, reply.ReplyAll ?? false, europe, now, s.Settings), s.Priority, ct)`;
     `html = mt.Html`; `LogMeetingTimes(mt)`.
   - `OutlookUnavailableException` in either → `AddRevisit(id, now, Failed, 1)`,
     attempts as `Fail` (no backoff, no event), return `OutlookUnavailable`;
     cancellation → same, return `Cancelled` *(no line for either)*.
3. Re-read the old draft: `ReadAiDraftAsync(s.Key, id, s.Priority, ct)` +
   `Evaluate(…, fp)`:
   - `Gone`/`NotInDrafts`/`Sent` → `AddRevisit(id, now, Replace, 1)`, state `Gone`, outcome `gone`, step 7;
   - `NotMarked`/`Changed` → `AddRevisit(Replace)`, state `Edited`, outcome `edited`, step 7;
   - `Open`, or a non-gone read exception → `AddRevisit(Replace)`, no state
     change (`checked` stays, so a later pass revisits again), outcome `open`, step 7;
   - `OutlookUnavailableException` / cancellation → `AddRevisit(Replace)`, return `OutlookUnavailable` / `Cancelled`;
   - `Movable` → go on. Nothing is created in the other cases.
4. **Create the new draft first**:
   `made = await _s.Writer.ReplyAsync(MakePlan(targetId, reply.ReplyAll ?? false, html, s.Priority), ct)`
   (marker `ai`, `DraftBody.Fragment`, signature as every AI draft).
   - `ItemNotFoundException` (target gone) → `Fail`-like bookkeeping without
     backoff or event: `AddRevisit(id, now, Failed, 1)`, attempts +1 /
     give-up, `p.Failed++`, outcome `failed`, return null. Old draft untouched.
   - `OutlookUnavailableException` → same bookkeeping, return `OutlookUnavailable`.
   - cancellation → same bookkeeping, return `Cancelled`.
   - any other exception → same bookkeeping, `Ai` event `DraftTexts.SaveFailed`,
     Warning `AI drafts: saving a reply draft failed ({Type}, HResult {HResult}).`,
     return null (as §19.7 step 8: the pass goes on).
5. After a saved draft (`created = _time.GetUtcNow()`):
   - target decision: `priorT = GetDecision(targetId)`;
     `UpsertDecision(new AiDecision(targetId, detail.InternetMessageId, null, created, Drafted, null, priorT?.ModelCalls ?? 0, priorT?.Attempts ?? 0, reply.Confidence, made.EntryId, created))`
     (calls are counted in `ai_revisits`, so `model_calls` is **not** +1);
   - `ai_drafts` for the new draft when `DraftFingerprint.IsValid(made.Fingerprint)`:
     `RecordAiDraft(made.EntryId, targetId, created, made.Fingerprint!, upTo, created)`;
   - `AddRevisit(id, created, Replace, 1)`; `p.Updated++`.
   - Each of these three index writes is in its own try/catch (non-cancel)
     with a Warning `AI drafts: couldn't record a revisit ({Type}).`: the new
     draft exists and the old one is still moved.
6. **Then move the old one**: `move = await _s.Mailbox.MoveObsoleteAiDraftAsync(s.Key, id, fp, s.Priority, ct)`.
   - `Moved` → state `Replaced`, outcome `replaced`;
   - any other status → state `Left`, outcome `replaced_left`;
     `NoDeletedItems` also records the `Ai` event `RevisitTexts.MoveFailed`;
   - an exception other than cancellation/`OutlookUnavailable` → state `Left`,
     outcome `replaced_left`, `Ai` event `MoveFailed`, Warning
     `AI drafts: moving an outdated draft failed ({Type}, HResult {HResult}).`;
   - `OutlookUnavailableException` / cancellation → state `Left`, outcome
     `replaced_left`, then step 7, then return `OutlookUnavailable` / `Cancelled`.
   - `Draft` event (`tag`): `RevisitTexts.ForReplace(oldStatus, made.Subject)`
     with `oldStatus = move.Status`, or `null` when the move threw.
   - `SetAiDraftState(id, Replaced|Left, upTo, 0, now)`; step 7.

### E. Pure helpers (`DraftRevisit.cs`)

1. `IsOwnAddress`: trim all three; false for a blank address; equal to a
   non-blank `userSmtp` or `mailboxSmtp`, `OrdinalIgnoreCase`.
2. `PickReplyTarget`: iterate in the given order; skip `IsOwnAddress(row.SenderEmail, userSmtp, mailboxSmtp)`;
   `rule = DraftRules.EvaluateIndex(row, mailboxSmtp, settings, () => false)`;
   accept when `rule is null || rule == DraftRuleIds.NotDirect`. First
   accepted wins; none → null.
3. `PromptThread`: keep a row unless `string.Equals(row.EntryId, draftEntryId, OrdinalIgnoreCase)`
   (when `draftEntryId` isn't blank) or the first `\`-segment of
   `row.Folder` (trimmed) equals `Drafts` or `Deleted Items`
   (OrdinalIgnoreCase). `DraftPrompt.RevisitUserPrompt` then keeps the
   newest 8 of what's left (unchanged builder). Spec change 1.

### F. Remove (§23.6 step 6 "remove")

`move = await MoveObsoleteAiDraftAsync(s.Key, id, fp, s.Priority, ct)`; then
`AddRevisit(id, now, Remove, 1)` (always, the call happened) and:

| Move result | State (`SetAiDraftState(id, …, null, t.Draft.Attempts, now)` unless noted) | Outcome | Events / counts |
|---|---|---|---|
| `Moved` | `Removed` (`checked = upTo`, attempts 0) | `removed` | `Draft` (`tag`): `RevisitTexts.Removed(move.Subject)`; `p.Moved++` |
| `Open` | no change | `open` | — |
| `Changed`, `NotMarked` | `Edited` | `edited` | — |
| `Gone`, `NotInDrafts`, `Sent` | `Gone` | `gone` | — |
| `NoDeletedItems`, `Movable` (defensive) | `Left` | `left` | `Ai`: `RevisitTexts.MoveFailed` |
| exception (non-cancel, non-unavailable) | `Left` | `left` | `Ai`: `MoveFailed`; Warning as D.6 |
| `OutlookUnavailableException` / cancellation | `Left` | `left` | then step 7, return `OutlookUnavailable` / `Cancelled` |

Then step 7, return null.

### G. Order, limits and sharing

- Revisits share `_gate` (they run inside the pass), `CapReached`,
  `_retryAt`, `_consecutiveFailures`, the hold and the yield check with
  drafting. A revisit failure ends the pass like a drafting failure.
- `DueRevisits` already returns only the newest `open` draft per thread,
  at most 10, newest `upTo` first, created within 14 days.
- All revisit COM calls in a pass use `WorkPriority.Background`.
- States other than `open` are final (`SetAiDraftState` enforces it).

## Spec changes

Not applied by this brief (the caller asked for the brief only); to be
recorded in `SPEC.md` by the architect:

1. **§23.7 user prompt**: the revisit `<thread>` is built from
   `EmailIndex.Thread(topic, upTo, 50, reply target excluded)` minus the
   old draft's own row and rows whose folder's first segment is `Drafts`
   or `Deleted Items`; then the newest 8 (`DraftRevisit.PromptThread`).
2. **§23.2 user replied** uses only the topic half of `RepliedTo` with
   `after = created`; the "newer Inbox row from the user or mailbox" looks
   at rows in `(checked, upTo]` (`DraftRevisit.IsOwnAddress`).
3. **§23.6 step 3**: the reply target rows are `ThreadInbox(topic,
   source time, upTo]`; "the index rules don't skip" = `EvaluateIndex`
   returns null or `not_direct` (`DraftRevisit.PickReplyTarget`). A target
   whose index row vanished falls back to the source; no row at all → no
   change.
4. **§23.6 step 2 / replace re-read**: a read that throws (not
   `OutlookUnavailable`) is "no change, try again next pass". In the
   replace re-read, `Open` (or a failed read) stops with row `replace`,
   nothing created and `checked` unchanged.
5. **§23.6 replace**: meeting-time headers come from `GetFactsAsync` on
   the target (failure → no headers, as the manual path). Outlook gone or
   cancellation after the call and before the new draft is saved → row
   `failed` with an attempt, no backoff. Creating the new draft:
   `ItemNotFound` → row `failed` with an attempt, no event; other errors →
   also the `SaveFailed` event, the pass goes on. After the move:
   `Outlook unavailable`/cancel → `left`, then the pass ends.
6. **§23.6 low confidence** applies to `replace`/`remove` only (a `keep`
   is a keep at any confidence) and emits no `Ai` low-confidence event.
   `revisited` rows don't count as `skipped` in the pass summary; a
   failed revisit counts as `failed`; the summary is recorded when any
   row was written or any revisit call was made.
7. **§19.7 / §23.9 API**: `DraftPassResult` gains `Updated`, `Moved`,
   `Kept` (optional, 0); `DraftTexts.Summary(..., updated = 0, moved = 0,
   kept = 0)`; `DraftRuleIds.Revisited`; `DraftRevisit.ThreadFetch = 50`,
   `IsOwnAddress`, `PickReplyTarget`, `PromptThread`.
8. **§3 layout**: add `DraftWorker.Revisit.cs` (revisit step, §23.6).
