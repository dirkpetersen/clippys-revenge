# M17.4 Live test: one-time attachment download link against real Outlook

Base: `dev` at or after `1879878` (M17.3 merged: `AttachmentTools.attachment_link`,
`AttachmentLinkTool`, `OutlookAttachmentLinkSaver`/`SaveAttachmentForLink`,
`PrivateFolder.Ensure`, `McpHostOptions.Links`, `FilesEndpoint`).
Tests and the live-test script only: **no `src/` change**. Parallel work:
an M18.3 coder (`DraftPrompt`, `DraftWorker*`, `ReplySchema`/`RevisitSchema`,
`DraftReasonLine`, their tests, `SafetySourceScanTests.cs`) and an M17.5
docs writer (`manual/`, `README.md`). This brief touches none of their
files. Don't bump `<Version>` (release plan 2026-11-16: one release v0.1.1
after M17–M20).

## Goal

Prove §24 end to end against the user's real classic Outlook (§24.7
"Live"): on a synthetic email with a known attachment, `attachment_link`
saves it through the production COM path into a user-only private
folder; an HTTP GET of the returned URL with the bearer token returns
bytes identical to `SaveAsFile` of the same attachment (and to the file
that was attached); a second GET is 404; the link folder is empty
afterwards and its ACL names only the current user; nothing is sent and
only the items the test created are deleted. The test runs its **own
in-process `McpHttpHost` on an ephemeral loopback port** (port 0) with its
own bearer token and its own link folder under the run's temp root, so it
never talks to, or races with, the user's running Clippy and never
touches `%LOCALAPPDATA%\ClippysRevenge\links\`.

SPEC refs: §24.7 (Live bullet), §24.1 (result fields), §24.2 (private
folder, temp name, save at creation, delete after download), §24.3
(single use), §24.4 (bearer + link token, 404 empty, headers), §11.3
(selection errors), §15 (live tests: opt-in, never send, delete only own
items), §1 hard rules, CLAUDE.md "Live Outlook tests".

## Hard rules that apply here

- **Never send anything.** No `.Send(`, `.Display(`, `.Activate(`,
  `.Move(`, no `SendAndReceive` (the existing `LiveSafetyScanTests` facts
  scan every `Live/*.cs` for these). The synthetic email is an **unsent,
  self-addressed draft** made by `create_draft` (`CreateDraftTool`), as in
  `LiveDraftTests`/`LiveObsoleteDrafts`. `WithCleanupAsync` asserts Sent
  Items and Outbox are unchanged.
- **Delete only what the test created**, only through the fixture's
  existing token-checked `DeleteAsync` (recorded EntryID + subject starting
  `[<RunToken>] `), via `scope.Track(...)` inside `fx.WithCleanupAsync`.
  The test never calls `Delete`/`PermanentDelete` on Outlook items. Files:
  the reference copy, the attached source file and the link folder all
  live under `fx.TempRoot`, which the fixture removes at the end (it only
  ever deletes the exact per-run directory).
- **Never launch Outlook** (attach-only fixture, unchanged).
- **Localhost + token**: the host is the production `McpHttpHost`
  (loopback only, `UseBearerAuth`, `Origin` rejected). The bearer token is
  a fresh `AuthToken.Generate()` held only in memory; it and the link
  token/URL are **never** written to `fx.Result`, assertion messages or
  test output (assert on booleans/lengths, not on strings that contain
  them; use `Assert.True(cond, "fixed text")` where xUnit would print the
  URL).
- **`SaveAsFile` in tests**: the §24.6 scan covers `src/` only; the
  test's own reference `SaveAsFile` is allowed and writes only under
  `fx.TempRoot`.
- Opt-in: `[Trait("live","outlook")]`, `[Trait("os","windows")]`,
  `[Collection(LiveOutlookCollection.Name)]`, skips via
  `fx.RequireReadyAsync` unless `CLIPPY_LIVE=1` and Outlook is usable. CI's
  filter `live!=outlook&live!=claude` excludes it.

## Public API (test-internal)

```csharp
namespace ClippysRevenge.Core.Tests.Live;

[Collection(LiveOutlookCollection.Name)]
[Trait("live", "outlook")]
[Trait("os", "windows")]
public sealed class LiveAttachmentLinkTests(LiveOutlook fx)
{
    /// <summary>"clippy-live Prüfbericht.pdf": a space and a non-ASCII letter exercise filename/filename* and
    /// LinkFileName.ForShell. Content is random bytes, not a real PDF (Outlook doesn't check).</summary>
    private const string AttachmentName = "clippy-live Prüfbericht.pdf";

    /// <summary>300_007 bytes: several FilesEndpoint.CopyBufferSize (81_920) chunks plus an odd tail.</summary>
    private const int AttachmentBytes = 300_007;

    [Fact(Timeout = 180_000)]
    public Task Attachment_link_downloads_once_with_the_saved_bytes_and_leaves_nothing();

    /// <summary>Worker thread. Opens the item by (entryId, storeId), finds the one attachment whose FileName equals
    /// name (ordinal), SaveAsFile(path). Releases item, attachments, attachment, session. Throws
    /// InvalidOperationException("The test attachment is not on the synthetic email.") when none matches.</summary>
    private static void SaveReference(Outlook.Application app, string entryId, string storeId, string name, string path);

    /// <summary>Polls every 100 ms for up to 5 s until cond() is true; returns the last cond() value.</summary>
    private static Task<bool> EventuallyAsync(Func<bool> cond, CancellationToken ct);
}
```

## Behavior

### A. Objects under test (all production code)

```csharp
var linksDir = Path.Combine(fx.TempRoot, "links");          // must not exist before the test
using var hub = new ActivityHub();                           // the host's hub, for the download event
using var links = new AttachmentLinks(new AttachmentLinksOptions
{
    Folder = linksDir,
    EnsurePrivateFolder = PrivateFolder.Ensure,              // the App's real ACL code
});
var bearer = AuthToken.Generate();
await using var host = new McpHttpHost(new McpHostOptions
{
    Tokens = new TokenHolder(bearer),
    Hub = hub,
    Links = links,
    // ConfigureMcp/ConfigureServices/ConfigureLogging: null (no MCP tools, no logging needed)
});
Assert.True(await host.StartAsync(0, ct), "The in-process MCP host did not start on a loopback port.");
var port = host.Port!.Value;
var tool = new AttachmentLinkTool(links, new OutlookAttachmentLinkSaver(fx.Worker, fx.Mail, fx.Stores),
    () => host.Port ?? throw new InvalidOperationException("The test host stopped."), TimeZoneInfo.Local);
using var http = new HttpClient(new SocketsHttpHandler { UseProxy = false, AllowAutoRedirect = false });
```

- Disposal order (`using`/`await using` gives it): HTTP client, host, link
  store, hub. The folder checks in B.9 run **before** any disposal, so
  they prove the endpoint deleted the file (not `Clear()` on dispose).
- GET helper: `new HttpRequestMessage(HttpMethod.Get, url)`, header
  `Authorization: Bearer <bearer>` via `TryAddWithoutValidation` unless
  the step says otherwise; `HttpCompletionOption.ResponseContentRead`.

### B. `Attachment_link_downloads_once_with_the_saved_bytes_and_leaves_nothing`

Shape: `ct = TestContext.Current.CancellationToken`;
`await fx.RequireReadyAsync(ct)`; `me = await fx.MeAsync()`;
`storeId = await fx.RunAsync("reading the store id", app => fx.StoreIdOf(app, ""))`;
then everything below inside
`await fx.WithCleanupAsync([""], [Outlook.OlDefaultFolders.olFolderDrafts, Outlook.OlDefaultFolders.olFolderDeletedItems], async scope => { … })`.

1. **Source file.** `original = RandomNumberGenerator.GetBytes(AttachmentBytes)`;
   `source = Path.Combine(fx.AllowedDir, AttachmentName)`;
   `File.WriteAllBytesAsync(source, original, ct)`.
2. **Synthetic email.** `subject = $"[{fx.RunToken}] attachment link"`;
   `created = await new CreateDraftTool(fx.Settings, new Signatures(_ => null, Path.Combine(fx.TempRoot, "no-signatures")), new OutlookDraftWriter(fx.Worker, fx.Stores), fx.Hub).RunAsync(new CreateDraftArgs(Recipients.Format([me]), subject, "Synthetic message for the attachment link live test.\n" + fx.RunToken, Attachments: [source]), ct)`
   (no signature, so the attachment is the only one). **Immediately**
   `scope.Track(new TrackedItem(TrackedKind.Draft, "", created.Id, storeId, subject))`.
3. **Reference copy (independent `SaveAsFile`).**
   `refPath = Path.Combine(fx.TempRoot, "link-reference", "reference.bin")`
   (create the directory first); `await fx.RunAsync("saving the reference copy", app => { SaveReference(app, created.Id, storeId, AttachmentName, refPath); return true; })`;
   `reference = File.ReadAllBytes(refPath)`.
   Assert `reference.AsSpan().SequenceEqual(original)` — "Outlook's SaveAsFile copy differs from the attached file." (by-value attachments keep their bytes).
4. **Bad selection leaves nothing.** `Assert.ThrowsAnyAsync<McpException>(() => tool.CreateAsync(created.Id, "clippy-live-missing.pdf", null, ct))`;
   message starts with `This email has no attachment named "clippy-live-missing.pdf". Its attachments: `
   (§11.3, `AttachmentSelection`) and is not an `AttachmentLinkException`.
   Then `links.OpenCount == 0` and `linksDir` has **no files**
   (`Directory.Exists(linksDir) ? Directory.EnumerateFileSystemEntries(linksDir).Count() : 0` is 0)
   — the failed save's temp file was discarded.
5. **Make the link.** `indexedBefore = fx.Indexes.For("").Status().TotalEmails`;
   `before = DateTimeOffset.Now`;
   `r = await tool.CreateAsync(created.Id, AttachmentName, null, ct)`;
   `after = DateTimeOffset.Now`. Assert (fixed messages, never printing `r.Url`/`r.Curl`):
   - `r.FileName == AttachmentName`; `r.Size == AttachmentBytes`.
   - `Regex.IsMatch(r.Url, $"^http://127\\.0\\.0\\.1:{port}/files/[A-Za-z0-9_-]{{43}}$")`.
   - `r.Curl == LinkTexts.Curl(LinkFileName.ForShell(AttachmentName), r.Url)`;
     `r.Curl` contains `$CLIPPY_TOKEN` and does **not** contain `bearer`.
   - `r.Note == LinkTexts.Note`.
   - `expires = DateTimeOffset.ParseExact(r.ExpiresAt, "yyyy-MM-dd'T'HH:mm:sszzz", CultureInfo.InvariantCulture)`;
     `before + AttachmentLinks.LinkLifetime - 1 s <= expires <= after + AttachmentLinks.LinkLifetime + 1 s`
     (seconds are truncated in the format).
   - `links.OpenCount == 1`.
6. **Private folder while the link is open.**
   - `Assert.StartsWith(fx.TempRoot, linksDir, OrdinalIgnoreCase)` (never the user's real folder).
   - `PrivateFolderTests.AssertUserOnly(linksDir)` (protected DACL, only
     Allow rules, all for the current user's SID, not inherited,
     FullControl, ContainerInherit|ObjectInherit).
   - `new DirectoryInfo(linksDir).LinkTarget` is null.
   - Exactly one entry in `linksDir`; it is a file, `LinkPaths.IsTempFileName(Path.GetFileName(f))`
     is true, its length is `AttachmentBytes`, and
     `PrivateFolderTests.AssertOnlyMe(new FileInfo(f).GetAccessControl(AccessControlSections.Access), directory: false)`
     passes (the file inherits the user-only rule).
   - The file name does not contain the attachment name (it is
     `<32 hex>.bin`; implied by `IsTempFileName`, no extra assert needed).
7. **Bearer required, link not used up by a 401.**
   - GET `r.Url` **without** `Authorization` → 401, empty body.
   - GET `r.Url` with `Authorization: Bearer <AuthToken.Generate()>` (a wrong
     token) → 401, empty body.
   - `links.OpenCount == 1` still.
8. **First GET with the bearer token** → 200. Assert:
   - `body = await resp.Content.ReadAsByteArrayAsync(ct)`;
     `body.Length == reference.Length` and `body.AsSpan().SequenceEqual(reference)`
     — "The downloaded bytes differ from Outlook's SaveAsFile copy."
   - Headers equal `FileDownloadHeaders.Build(AttachmentName, AttachmentBytes)`
     for `Content-Type`, `Content-Disposition`, `Content-Length`,
     `X-Content-Type-Options`, `Cache-Control` (read each from
     `resp.Headers.NonValidated` or `resp.Content.Headers.NonValidated`, joined with `,`,
     as `McpHttpHostTests.Header` does; that helper is private to another
     class, so a 6-line private copy in this file is fine).
9. **Gone afterwards** (before disposing anything):
   - `await EventuallyAsync(() => !Directory.EnumerateFileSystemEntries(linksDir).Any(), ct)` is true —
     "The link's temp file was not deleted after the download." (The
     endpoint deletes in `finally` after the response completes, so allow
     up to 5 s.)
   - `await EventuallyAsync(() => hub.GetEvents().Count(e => e.Kind == ActivityKind.Tool && e.Summary == FilesEndpoint.DownloadEvent) == 1, ct)`
     is true, and no event has `Summary == FilesEndpoint.DownloadFailedEvent`.
   - `links.OpenCount == 0`.
10. **Second GET** of the same URL with the bearer token → 404 with an
    empty body. The folder is still empty.
11. **Nothing indexed:** `fx.Indexes.For("").Status().TotalEmails == indexedBefore`
    (the link path never writes the index; the run doesn't sync during
    this test because the collection is not parallel).
12. **ACL still user-only after the download:** `PrivateFolderTests.AssertUserOnly(linksDir)`.
13. `fx.Result("m17-link", $"{AttachmentBytes} bytes downloaded once and equal to SaveAsFile; second GET 404; 401 without bearer kept the link; folder empty and user-only")`.
    Never put the URL, token, port-plus-token or bearer in a result line.

After the `WithCleanupAsync` body returns, the fixture deletes the draft by
its EntryID (token-checked), purges it from Deleted Items, asserts no
`[RunToken]` item is left in Drafts or Deleted Items, and asserts Sent
Items/Outbox are unchanged. After the `using` scope (inside the body,
step order above), also assert `!Directory.EnumerateFileSystemEntries(linksDir).Any()`
once more after `links.Dispose()` (structure the code so the store and host
are disposed at the end of the body, e.g. an inner block, then this final
check).

## Spec changes

Not applied by this brief (the caller asked for the brief file only); to
be recorded in `SPEC.md` §24.7 "Live" by the architect:

1. **Own host, own folder.** The live test runs the production
   `McpHttpHost` in-process on an ephemeral loopback port (port 0) with
   its own random bearer token, and a link store whose folder is
   `<live run temp root>\links` made private by the App's
   `PrivateFolder.Ensure`. It never uses the user's running Clippy or
   `%LOCALAPPDATA%\ClippysRevenge\links\` (the running app's own links
   would make "empty afterwards" racy, and the test must not create or
   delete files there). A live scan pins this.
2. **Tool entry point.** The test calls `AttachmentLinkTool.CreateAsync`
   (what the `attachment_link` MCP method forwards to) with the
   production `OutlookAttachmentLinkSaver`, not a `tools/call` over MCP;
   the tool's description and annotations stay covered by the M17.3
   tests.
3. **Synthetic email and reference bytes.** "A synthetic email with a
   known attachment" is an unsent, self-addressed draft created by
   `create_draft` with a random-bytes attachment from the run's allowed
   folder (no signature). The reference is the test's own `SaveAsFile`
   of that attachment; it must also equal the attached file's bytes.
4. **Additions to the checked list:** a 401 (no or wrong bearer) doesn't
   use the link up; a bad selection leaves no file in the folder; the
   temp file is user-only by inheritance while the link is open; one
   `attachment download` event; the index row count is unchanged.
