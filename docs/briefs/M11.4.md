# M11.4 `IDraftModel`, `DraftModel` and the Claude Code CLI backend

Base: `dev` after M11.1 is merged (track C: M11.1 → M11.4). This task
reads `AiDraftingSettings` (SPEC §19.2) from M11.1 by name. It uses only
`ClaudeCliPath`. If M11.1 isn't merged yet, stop and report it as blocked.

## Goal

Add the model abstraction that every AI feature calls (SPEC §19.3), and
its default backend: the user's installed Claude Code CLI, run headless
(`claude -p`). This covers:

- `IDraftModel` and the request/result types, with their exact shapes
  pinned here (§19.3 says "pinned in the M11.4 brief").
- The reply and style JSON schemas and `DraftReply.Parse` (§19.7, §19.6).
- `ClaudeCliLocator`, which finds the CLI.
- The status probe (`CheckAsync`), which runs `--version`, `--help` and
  `auth status --json`. It makes no model call.
- `ClaudeCliArgs`, the only place that builds CLI arguments.
- `ClaudeCliRunner`, which runs processes: the system-prompt file, stdin,
  output caps, timeouts and killing the process tree.
- `ClaudeCliOutput.Parse`, which reads the result envelope tolerantly and
  classifies errors and rate limits.
- `ClaudeCliModel`, which ties these together.
- Tests with a fake `claude` script.

SPEC refs: §1.10, §3 (layout: `DraftModel.cs`, `ClaudeCli.cs`), §5.1
(CLI working folder), §19.2, §19.3, §19.5, §19.7 ("Reply JSON"), §19.11,
§19.12, §15.

Nothing is wired into `Program` here. `DraftWorker` and the App wiring
belong to M11.7, and the tray/Settings UI to M11.8.

## Hard rules that apply here

- **No credentials.** Clippy never reads Claude Code's stored credentials
  (`.credentials.json`, the keychain, OAuth tokens) and never sets a
  credential environment variable. The child process inherits the
  environment unchanged. In `src/`, no string literal may contain
  `.credentials`, `claudeAiOauth`, `oauthAccount` or `sk-ant-oat`.
- **No sign-in.** The only `auth` subcommand used is `status`. No literal
  in `src/` may *equal* `login` or `--bare`. The texts `/login` and
  `not logged in` are fine as classification substrings.
- **The model gets no tools.** Pass `--tools ""` and
  `--strict-mcp-config`. Never pass `--mcp-config`, `--allowedTools`,
  `--add-dir`, `--resume`/`--continue`, `--dangerously-skip-permissions`
  or a prompt argument. The user prompt goes over **stdin only**.
- **Privacy (§19.11).** Never log, store or put into an exception
  message any of: prompts, stdout, stderr, model output, `reason`, or the
  `auth status` fields other than `loggedIn`, `authMethod` and
  `subscriptionType`. Never log `authMethod` or `subscriptionType`
  either; they are shown in the UI only. Logs may contain outcome kinds,
  exit codes, durations, token counts, the CLI version and whether
  `--safe-mode` was found.
- **`UseShellExecute = false`** always. `.cmd`, `.bat` and `.ps1` files
  are never run.
- In files named `Draft*` or `Claude*`, no `.Send(`, `.Display(`, or
  Outlook `.Move(`/`Delete(`. `File.Delete` on Clippy's own `sp-*.md`
  files is allowed (see "Spec changes" #1).

namespace ClippysRevenge.Core;

public interface IDraftModel
{
    /// <summary>Never throws except OperationCanceledException when ct is cancelled. Makes no model call.</summary>
    Task<ModelStatus> CheckAsync(CancellationToken ct);

    /// <summary>
    /// Never throws (ArgumentNullException for a null request aside). Cancellation gives Failed(Cancelled).
    /// </summary>
    Task<ModelResult> RunAsync(ModelRequest request, CancellationToken ct);
}

public sealed record ModelRequest(string SystemPrompt, string UserPrompt, string JsonSchema,
    string Model, string Effort, TimeSpan Timeout, int MaxOutputTokens);

public enum ModelFailure { NotInstalled, Timeout, Cancelled, BadInput, BadOutput, NoStructuredOutput, ProcessExit, Http }

public abstract record ModelResult
{
    private ModelResult() { }

    /// <summary>Output is a JSON object, already Clone()d (it outlives its JsonDocument).</summary>
    public sealed record Ok(JsonElement Output, TimeSpan Duration, int? InputTokens, int? OutputTokens) : ModelResult;
    /// <summary>RetryAt null = unknown (the caller waits 60 min, §19.7).</summary>
    public sealed record RateLimited(DateTimeOffset? RetryAt) : ModelResult;
    public sealed record NotSignedIn : ModelResult;
    /// <summary>Code: the process exit code (ProcessExit) or the HTTP status (Http); else null.</summary>
    public sealed record Failed(ModelFailure Kind, int? Code) : ModelResult;
}

public sealed record ModelStatus(bool Ready, string Text);

public static class DraftModel
{
    /// <summary>§19.7 reply schema, compact, property order as in SPEC.</summary>
    public const string ReplySchema =
        """{"type":"object","additionalProperties":false,"required":["needs_reply","confidence","reason"],"properties":{"needs_reply":{"type":"boolean"},"confidence":{"type":"number","minimum":0,"maximum":1},"reply_all":{"type":"boolean"},"body_html":{"type":"string"},"reason":{"type":"string","maxLength":200}}}""";

    /// <summary>§19.6 style schema (used by M11.6).</summary>
    public const string StyleSchema =
        """{"type":"object","additionalProperties":false,"required":["body_markdown"],"properties":{"body_markdown":{"type":"string"}}}""";

    public const int DraftMaxOutputTokens = 8_000;     // §19.3
    public const int StyleMaxOutputTokens = 16_000;    // §19.3
    public static readonly TimeSpan StyleTimeout = TimeSpan.FromSeconds(600); // §19.3

}

public sealed record DraftReply(bool NeedsReply, double Confidence, bool? ReplyAll, string? BodyHtml)
{
    /// <summary>Null when invalid (→ the caller treats it as BadOutput). Never throws.</summary>

## Behavior

### A. `DraftReply.Parse(JsonElement output)`

Return null (invalid) when any of these holds:
- `output.ValueKind != Object`.
- `needs_reply` is missing or isn't `true`/`false`.
- `confidence` is missing, isn't a number, isn't finite, or is outside
  `[0, 1]` (0 and 1 are valid).
- `reply_all` is present and not a boolean. JSON `null` counts as absent.
- `body_html` is present and not a string (`null` counts as absent).
- `body_html` is over `MaxBodyHtmlChars` (50,000 UTF-16 chars), whatever
  `needs_reply` says.
- `needs_reply` is `true` and `body_html` is absent or
  `string.IsNullOrWhiteSpace`.
- `reason` is present and not a string (`null` counts as absent).

These are tolerated (decided, see "Spec changes" #7): a missing `reason`
(the CLI's validation isn't trusted, but Clippy doesn't use `reason`, so
there's no point failing on it), a `reason` over 200 chars, and unknown
properties. `reason` is never copied anywhere. `BodyHtml` is returned
unchanged (not trimmed). Sanitizing is M11.3/M11.7's job.

### B. `ClaudeCliLocator.Find(configuredPath)`

The separator is `\` and the PATH separator `;` when `isWindows`;
otherwise `/` and `:`. Join paths with your own helper using that
separator, **not** `Path.Combine`, so Windows-mode tests run on Linux.
The executable names are `claude.exe` / `node.exe` on Windows and
`claude` / `node` otherwise.

"Fully qualified local", per `isWindows`:
- Windows: matches `^[A-Za-z]:\\` and contains no `/`. This rejects UNC
  (`\\server`), device (`\\?\`, `\\.\`) and drive-relative paths.
- Otherwise: starts with `/`.

**1. `configuredPath` not blank (trimmed).** It is the **only**
candidate, with no fallback to the search (decided, "Spec changes" #6).
Return null when:
- it isn't fully qualified local;
- its extension (case-insensitive) is `.cmd`, `.bat` or `.ps1`;
- on Windows, the extension is neither `.exe` nor `.js`;
- `fileExists` is false.

Otherwise:
- `.js` → `node` from PATH (same PATH rules as step 2), giving
  `(nodePath, [configuredPath])`. Null when there's no node.
- Anything else → `(configuredPath, [])`.

**2. PATH.** Split `getEnv("PATH")`. Trim each entry and strip one pair
of surrounding `"`. Skip entries that are empty or not fully qualified
(relative PATH entries would resolve against the working folder). Return
the first `dir + sep + exeName` for which `fileExists` is true, as
`(that path, [])`.

**3. Native installer.** `getEnv("USERPROFILE")` (Windows) or
`getEnv("HOME")` (otherwise) `+ \.local\bin\claude.exe` (or
`/.local/bin/claude`). It must be fully qualified and exist.

**4. npm (Windows only).**
`getEnv("APPDATA") + \npm\node_modules\@anthropic-ai\claude-code\cli.js`
must exist, and `node.exe` must be found on PATH →
`(nodePath, [cliJsPath])`. On non-Windows this step is skipped.

**5.** Otherwise null.

Only exact `claude.exe`/`claude`/`node.exe`/`node` names are ever probed,
so the npm shim `claude.cmd` in `%APPDATA%\npm` is never picked up.
`Find` never throws: a null env var is treated as empty, and an exception
from `fileExists` counts as false.

### C. `ClaudeCliArgs`

`Build(model, effort, jsonSchema, systemPromptFile, safeMode)` checks:
- `model`: 1–64 chars and `^[A-Za-z][A-Za-z0-9._\[\]-]*$` (§19.2). If
  M11.1 exposes this rule as a public member of `AiDraftingSettings`
  (check `src/ClippysRevenge.Core/AiSettings.cs`), call it. Otherwise use
  a private `static readonly Regex` here, with the same pattern and
  `RegexOptions.CultureInvariant`.
- `effort`: exactly one of `low`, `medium`, `high`, `xhigh`, `max`
  (ordinal, lower-case). The same reuse rule applies.
- `jsonSchema`: parses as a JSON object. Re-serialize it compactly with
  `Utf8JsonWriter` (`Indented = false`) and `RootElement.WriteTo`.
  Property order is kept.
- `systemPromptFile`: `Path.IsPathFullyQualified` (the real OS check;
  this is a real file).

The returned list, in exactly this order:

```
-p
--model            <model>
--effort           <effort>
--output-format    json
--json-schema      <compact schema>
--tools            ""            ← an empty string element (string.Empty)
--strict-mcp-config
--no-session-persistence
--system-prompt-file <systemPromptFile>
--disable-slash-commands
--safe-mode                       ← only when safeMode
```

Never `--bare`, a prompt argument, `--mcp-config`, `--allowedTools`,
`--add-dir`, `--resume`, `--continue`,
`--dangerously-skip-permissions`, `--verbose` or `--max-turns`.
`--tools` is variadic in the CLI. That's fine because the next element
is a flag. .NET's `ArgumentList` quotes the empty element as `""` on
Windows.

`HelpMentions` uses
`(?<![A-Za-z0-9_-])` + `Regex.Escape(flag)` + `(?![A-Za-z0-9_-])`.
So `--system-prompt` matches `--system-prompt <prompt>` and
`--system-prompt[-file]`, but not `--system-prompt-snapshot` on its own,
and `--tools` doesn't match `--toolsx`. The installed 2.1.323 `--help`
lists all six required flags and `--safe-mode`. `--system-prompt-file`
isn't listed but is accepted, which is why the check is for
`--system-prompt`.

### D. `ClaudeCliRunner`

**`RunAsync(command, args, stdin, timeout, ct)`:**

1. `Directory.CreateDirectory(workDir)`. If that throws (I/O or access),
   return `SetupFailed`.
2. Build the `ProcessStartInfo`:
   - `FileName = command.FileName`; `ArgumentList` = `PrefixArgs` then
     `args`;
   - `UseShellExecute = false`, `CreateNoWindow = true`;
   - redirect stdin, stdout and stderr;
   - `StandardInputEncoding`, `StandardOutputEncoding` and
     `StandardErrorEncoding` = `new UTF8Encoding(false)`;
   - `WorkingDirectory = workDir`.

   Don't touch `Environment`; it's inherited (§19.3).
3. Start the clock (`time.GetTimestamp()`) and call
   `Process.Start(psi)`. Use the static `Process.Start`: the safety scan
   allow-lists exactly this file. A `Win32Exception`, a
   `FileNotFoundException` or a null return gives `NotStarted`.
4. Run three tasks at the same time:
   - **stdin:** when `stdin` is not null, write it and flush. In all
     cases, close stdin (immediately when it's null, so nothing waits
     for input). `IOException` and `ObjectDisposedException` are
     swallowed, because a process may exit without reading.
   - **stdout and stderr:** each is read with a bounded reader (a
     `char[]` buffer of 8 KiB, `ReadAsync` until EOF). Past
     `MaxStdoutChars` / `MaxStderrChars` it stops appending, sets an
     overflow flag and triggers the kill (step 5). The caps count UTF-16
     chars (decided, "Spec changes" #9).
   - **exit:** `WaitForExitAsync` with a linked token of `ct` and
     `new CancellationTokenSource(timeout, time)`.
5. **Kill:** on timeout, cancellation or overflow, call
   `process.Kill(entireProcessTree: true)` and swallow
   `InvalidOperationException` and `Win32Exception`. Then await the exit
   and the readers, bounded by 5 s (async, no `.Wait()`). The outcome:
   - `OutputTooLarge` when overflow happened (this wins);
   - else `Cancelled` when `ct.IsCancellationRequested`;
   - else `TimedOut`.
6. Normal exit: await both readers (EOF), then return
   `Exited(ExitCode, stdout, stderr, duration)`.
7. Always dispose the process. It doesn't throw for process failures.

**`RunPromptAsync(command, request, safeMode, ct)`:**

1. If `Encoding.UTF8.GetByteCount(request.UserPrompt) > MaxPromptBytes`,
   return `PromptTooLarge`. No file is written and no process starts.
2. The first call on this instance runs `CleanupStaleFiles()` once (an
   `Interlocked` flag).
3. `Directory.CreateDirectory(workDir)`. Set
   `path = Path.Combine(workDir, $"sp-{Guid.NewGuid():N}.md")` and call
   `File.WriteAllText(path, request.SystemPrompt, new UTF8Encoding(false))`.
   An I/O error here gives `SetupFailed`.
4. `args = ClaudeCliArgs.Build(request.Model, request.Effort, request.JsonSchema, path, safeMode)`.
5. `try { return await RunAsync(command, args, request.UserPrompt, request.Timeout, ct); }`
   `finally { delete path, swallowing I/O errors }`. A file left behind
   because a killed grandchild still held it is removed by the next
   start-up cleanup.

**`CleanupStaleFiles()`:** delete each `sp-*.md` in `workDir` whose
`File.GetLastWriteTimeUtc` is older than `time.GetUtcNow() - StaleAge`.
Never touch other files. If the folder is missing, do nothing. Swallow
every I/O error.

The runner is thread-safe. Concurrent runs each have their own file and
process.

Logging, at Debug: `"Claude CLI process: {Outcome} exit {ExitCode} in {Ms} ms"`.
Never log arguments (they contain the schema and the path), stdin,
stdout or stderr.

### E. `ClaudeCliOutput.Parse(exitCode, stdout, stderr, duration, now, localZone)`

**Find the envelope** (each step catches `JsonException`):
1. If `stdout.Trim()` parses as a JSON **object**, that's the envelope.
2. Else, if it parses as a JSON **array**, use the last element that is
   an object with `"type": "result"`. (This tolerates a user config that
   turns on verbose output.)
3. Else, split `stdout` into lines and walk from the last line to the
   first. The first line that parses as an object with
   `"type": "result"` is the envelope.
4. Else there's no envelope (`notJson = true`).

**Read the envelope** (tolerant: a missing or wrong-typed field counts
as absent):
- `is_error`: a bool, or absent.
- `subtype`: a string, or absent.
- `result`: a string, or absent.
- `errors`: an array of strings. This is the SDK error variant, which
  has `errors: string[]` instead of `result`.
- `api_error_status`: an int, or absent.
- `structured_output`: any kind.
- `usage.input_tokens` and `usage.output_tokens`: `TryGetInt32`, else
  null.

**Error or success:** it's an error when `notJson`, or
`exitCode != 0`, or `is_error == true`, or `subtype` starts with
`error` (ordinal, ignore case). Otherwise it's success.

**Success:**
1. If `structured_output` is an object → `Ok(structured_output.Clone(), duration, in, out)`.
2. Else, if `result` (trimmed) parses as a JSON object → `Ok(thatObject.Clone(), …)`.
   As a tolerance, first strip one surrounding Markdown fence
   (` ```json ` or ` ``` ` on the first line, ` ``` ` on the last)
   ("Spec changes" #8).
3. Else → `Failed(NoStructuredOutput, null)`.

**Error.** Build one classification text: `result`, each `errors[i]`,
`subtype`, `stderr`, and the raw `stdout` when `notJson`, joined with
`\n`. Then the first match wins:

| # | Condition | Result |
|---|---|---|
| 1 | `api_error_status` is 429 or 529 | `RateLimited(RetryAt(text))` |
| 2 | `api_error_status` is 401 or 403 | `NotSignedIn` |
| 3 | text matches (ignore case) `usage limit`, `rate[ _]limit`, `limit reached`, `hit your (\w+ )?limit`, `overloaded`, `\b429\b`, `\b529\b` | `RateLimited(RetryAt(text))` |
| 4 | text matches (ignore case) `not logged in`, `/login`, `invalid api key`, `authentication`, `\b401\b`, `oauth` | `NotSignedIn` |
| 5 | `subtype == "error_max_structured_output_retries"` | `Failed(NoStructuredOutput, null)` |
| 6 | `notJson && exitCode == 0` | `Failed(BadOutput, null)` |
| 7 | otherwise | `Failed(ProcessExit, exitCode)` |

Rows 1, 2, 5 and 6, `rate_limit`, `hit your weekly limit` and the word
boundaries on the numbers are tolerances added to §19.3
("Spec changes" #3). All regexes are `static readonly`, with
`IgnoreCase | CultureInvariant` and a 100 ms match timeout. A
`RegexMatchTimeoutException` counts as "no match".

**`RetryAt(text)`**, the first rule that applies:
1. `\|\s*(\d{9,11})\b` → `DateTimeOffset.FromUnixTimeSeconds(n)`, kept
   only when it's within `now ± 8 days`.
2. `resets\s+(?:at\s+)?(\d{1,2})(?::(\d{2}))?\s*(am|pm)\b(?:\s*\(([A-Za-z0-9_+\-/]+)\))?`
   with hour 1–12 and minute 0–59:
   - Convert to 24 h: `12am` is 0 and `12pm` is 12.
   - Zone: when group 4 is present and
     `TimeZoneInfo.TryFindSystemTimeZoneById` finds it (IANA ids work on
     both OSes in .NET 10), use that zone. Otherwise use `localZone`.
   - Take today's date in that zone at `hh:mm`. If that's `<= now`, use
     the next day.
   - If the time is invalid in that zone (DST gap), add 1 hour.
   - Convert with `zone.GetUtcOffset`.
3. Otherwise null. Forms with a date, such as `resets Nov 15 at 9am`,
   aren't parsed, so they give null and the caller waits 60 min.

`Parse` never logs and never throws. Catch everything and return
`Failed(BadOutput, null)` as the last resort.

### F. `ClaudeCliModel`

**Status probe (`CheckAsync`)**, serialized by a `SemaphoreSlim(1)`:

1. Run `locator.Find(settings().ClaudeCliPath)`. If it returns null →
   `(false, NotFound)`.
2. Cache: the key is `FileName + "\0" + join("\0", PrefixArgs)`. If a
   cached probe has the same key and is younger than `StatusCacheTime`
   (by `time`), return it. **Only ready probes are cached** (decided,
   "Spec changes" #5). Not-ready results are probed again each time,
   because they're what the user is busy fixing.
3. **`--version`** (`VersionTimeout`, no stdin):
   - `NotStarted` → `NotFound`.
   - `TimedOut`, `SetupFailed`, `OutputTooLarge`, a non-zero exit, or no
     `\d+\.\d+\.\d+` in stdout → `NoAnswer("version")`.
   - `Cancelled` → throw `OperationCanceledException(ct)`.
   - Otherwise, the version is the first match.
4. **`--help`** (`HelpTimeout`): failures as above, with step
   `"help"`. Check the text `stdout + "\n" + stderr`:
   - If any of `RequiredHelpFlags` is missing → `TooOld(version)`.
   - Otherwise, `safeMode = HelpMentions(text, SafeModeFlag)`.
5. **`auth status --json`** (`AuthTimeout`):
   - `TimedOut`, `SetupFailed` or `OutputTooLarge` →
     `NoAnswer("auth status")`. `NotStarted` → `NotFound`.
     `Cancelled` → throw.
   - When `Exited` (**whatever the exit code**, since a signed-out CLI
     may exit 1 and still print the JSON): parse stdout as a JSON object.
     If it doesn't parse as an object → `NoAnswer("auth status")`.
   - Read **only** `loggedIn`, `authMethod` and `subscriptionType`. Use
     `TryGetProperty` on these three names only. Never enumerate the
     object, and never keep the document or the stdout string after this
     step.
   - If `loggedIn` isn't `true` → `NotSignedIn`.
   - Clean `authMethod` and `subscriptionType`: remove every
     `char.IsControl` char, trim, cut to 40 chars. A non-string or empty
     value becomes null.
6. Ready → `Ready(version, authMethod, subscriptionType, safeMode)`.
   Cache it.

`ClaudeCliStatusTexts.Ready` formats:
- `✓ Claude Code 2.1.323 · signed in (claude.ai, max)`.
- With only `authMethod`: `… · signed in (claude.ai)`.
- With no `authMethod`: `… · signed in`. This holds even when
  `subscriptionType` is set, because §19.3 puts it only after
  `authMethod`.
- Append `UpdateHint` when `!safeModeListed`.

The `·` is U+00B7, `✓` is U+2713 and `✗` is U+2717. Copy them from §19.3.

Log at Information, once per probe:
`"Claude Code status: {Kind}, version {Version}, safe-mode {SafeMode}"`.
`Kind` is one of NotFound, TooOld, NotSignedIn, NoAnswer or Ready.

**`RunAsync(request, ct)`:**

1. `ArgumentNullException.ThrowIfNull(request)`.
2. Input checks, which run before anything else → `Failed(BadInput, null)`:
   - `Timeout <= 0`;
   - `SystemPrompt` or `UserPrompt` is null;
   - `Model` or `Effort` fails the §C rules;
   - `JsonSchema` isn't a JSON object.

   An over-long prompt is left to the runner (`PromptTooLarge`).
3. Get the probe through the same cached path as `CheckAsync`. A
   cancelled probe gives `Failed(Cancelled, null)`. Then:

   | Probe | Result |
   |---|---|
   | NotFound or TooOld | `Failed(NotInstalled, null)` |
   | NotSignedIn | `NotSignedIn` |
   | NoAnswer | `Failed(ProcessExit, null)` |

4. Call `runner.RunPromptAsync(command, request, probe.SafeMode, ct)`
   and map the outcome:

   | `CliRunOutcome` | `ModelResult` |
   |---|---|
   | `Exited` | `ClaudeCliOutput.Parse(exit, stdout, stderr, duration, time.GetUtcNow(), time.LocalTimeZone)` |
   | `NotStarted` | `Failed(NotInstalled, null)`, and invalidate the status |
   | `PromptTooLarge` | `Failed(BadInput, null)` |
   | `TimedOut` | `Failed(Timeout, null)` |
   | `Cancelled` | `Failed(Cancelled, null)` |
   | `OutputTooLarge` | `Failed(BadOutput, null)` |
   | `SetupFailed` | `Failed(ProcessExit, null)` |

5. A `NotSignedIn` result invalidates the cached status (§19.3).
6. `request.MaxOutputTokens` is **ignored** by this backend. The CLI has
   no such flag, and Clippy adds no environment variables
   ("Spec changes" #4).
7. Log at Information:
   `"Claude call: {ResultKind} in {Ms} ms, tokens {In}/{Out}, exit {Exit}"`.
   `ResultKind` is `Ok`, `RateLimited`, `NotSignedIn` or
   `Failed:<ModelFailure>`. Nothing else is logged.

`settings()` is read on each call, so a `ClaudeCliPath` change takes
effect at once: the cache key changes with it.

### F. `ClaudeCliRunnerTests` with a fake `claude`

**Mechanism.** Core can't reference the App, and real `claude` must not

What each script does (both OSes):
- **Echo:**
  - Writes `$PWD` to `pwd.txt`.
  - Writes each argument on its own line to `args.txt` (sh only;
    Windows PowerShell 5.1 may drop empty arguments under `-File`).
  - Finds the value after `--system-prompt-file`. If that file exists,
    copies its bytes to `sp-copy.md` and writes `yes` to `sp-exists.txt`.
  - Reads all of stdin as UTF-8 and writes it, UTF-8 without BOM, to

  `$(dirname "$0")`.

## Spec changes (proposed, not applied)

The task said not to edit SPEC, so these go in with the review. All of
them are low-risk and reversible. None touches a hard rule.

1. **§19.12 / §15 safety scan wording (needed for M11.9).** "Files named
   `Draft*`, `Claude*`, `Style*`, `Anthropic*` … contain no `.Move(` or
   `Delete(`" taken literally also matches `File.Delete(` (this task's
   `sp-*.md` cleanup) and M11.6's atomic `File.Move(` of `SKILL.md`. The
   proposed wording: "… no `.Send(`, `.Display(`, or `.Move(`/`Delete(`
   calls on anything other than `File` or `Directory` (the same
   exception the existing Delete/Move scans make)". Also add to §15:
   "`Process.Start` is allowed only in `OutlookLauncher.cs`, `TrayApp.cs`
   (Open data folder) and `ClaudeCli.cs`".
2. **§19.3 exact shapes:** the `ModelResult` nested records, `ModelStatus`
   and `ModelRequest` exactly as in "Public API" above. Add
   `ClaudeCliModel.InvalidateStatus()` for Settings → Check.
3. **§19.3 Output, tolerances:**
   - The envelope may be a JSON array (take the last `type: result`
     element).
   - The SDK error variant has `errors: string[]` and no `result`, so
     `errors` is part of the classification text.
   - `api_error_status` 429/529 → `RateLimited` and 401/403 →
     `NotSignedIn`, checked first.
   - `subtype: error_max_structured_output_retries` →
     `Failed(NoStructuredOutput)`.
   - `rate_limit` and `hit your <word> limit` count as rate limits.
   - Numeric codes match as whole words.
   - When stdout isn't JSON and the exit code is 0 → `BadOutput`.
   - A `|<unix>` reset is kept only within now ± 8 days.
   - `resets …` honors a following `(<IANA zone>)` when .NET knows it,
     else uses local time.
   - Reset forms with a date give `null`.
4. **§19.3 Arguments:** the CLI backend ignores `MaxOutputTokens`. There
   is no flag for it, and Clippy adds no environment variables.
5. **§19.3 Status cache:** the key is the resolved command (file name +
   prefix arguments), not the version. Only ready results are cached.
   `auth status` JSON is read whatever its exit code. With no
   `authMethod`, the ready text is `✓ Claude Code <v> · signed in`.
   Step names in the "didn't answer" text are `version`, `help` and
   `auth status`.
6. **§19.3 Finding it:** when `ClaudeCliPath` is set, it is the only
   candidate (no fallback to the search). It must be `.exe` or `.js` on
   Windows. Relative PATH entries are skipped. The npm `cli.js` step is
   Windows-only. On other OSes the native path is `$HOME/.local/bin/claude`.
7. **§19.7 `DraftReply.Parse`:** a missing or over-long `reason` is
   tolerated, and JSON `null` in optional fields counts as absent.
8. **§19.3 Output:** a `result` string wrapped in one Markdown code fence
   is accepted.
9. **§19.3 Running:** "2 MB" is 2,097,152 UTF-8 bytes. The stdout/stderr
   caps (4 MiB / 64 KiB) count UTF-16 chars. A failure to create the
   working folder or the system-prompt file gives
   `Failed(ProcessExit, null)`.

## Risk to confirm in M11.10 (not blocking)

Claude Code implements `--json-schema` with an internal structured-output
tool. It isn't verified, without a paid call, that this tool stays
available under `--tools ""`. If the M11.10 live call returns no
`structured_output`, the parser's `result` fallback (and the fence
tolerance) still gets a JSON reply when the model writes one. If that
isn't enough, the fix is a SPEC decision (for example
`--tools StructuredOutput`, if the CLI names it), not a change in this
brief.
