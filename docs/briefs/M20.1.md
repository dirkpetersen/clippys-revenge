# M20.1 Learning from edits: recording and matching (schema 5)

Base: `dev` with M18, M19.1 (schema 4, `ai_calls`) and M19.6
(`AttachmentCounts.UsedText` at every save) merged. M20.3 is merged too
(`DontDraft.cs`, `AiDraftingToggler.ApplyAiEdit`). M19.7 (App attachment
reading, Settings checkbox) and M20.8 (localized Drafts/Deleted Items in
`MailFolders.cs` and the App's folder resolution) run in parallel: see
"Out of scope". **No release for this task** (v0.1.1 ships after M17–M20):
don't bump `<Version>`.

## Goal

When any AI path saves a reply draft, Clippy keeps the draft's own text
(redacted, at most 1,500 characters) in the **own** index. After own-mailbox
sync cycles (at most every 5 minutes), it finds sent replies in Sent Items
that began as Clippy AI drafts (`clippy_marker = 'ai'` and `in_reply_to`),
matches each to the newest recorded draft text of the email it answers,
computes a token-LCS similarity, and stores a capped, purged set of redacted
draft/sent pairs (`ai_edits`). Everything comes from the index: no COM
call, no model call, no write to any mail item. M20.2 later feeds these
pairs to the style generation; this task only records, matches, diffs and
purges, plus the two settings and the `Ai` count event.

SPEC refs: §27.1–§27.5 (all of it), §27.6 (settings, event text only),
§27.8 (tests), §9.1 (schema 5), §19.2 (`LearnFromEdits`,
`EditsNoticeShown`), §19.11 (logs: counts only), §1.6 (attachment content
never enters the index), §11.12 (`query_index` can't read the new tables).

## Hard rules that apply here

- **Attachment content never enters the index.** When the draft's prompt
  held any `read` or `truncated` attachment item
  (`AttachmentCounts.UsedText`), **no** `ai_draft_texts` row is written
  (user decision 2026-11-16). The flag itself is never stored.
- **Never send, never delete or move mail.** `EditLearning` and the new
  `EmailIndex` members take only the index. The only DELETEs are SQL rows
  of Clippy's own catalogue.
- **Logs and Activity never hold texts** (§19.11, §27.5): no draft text,
  sent text, imid, entry id, subject or address in any log line or event.
  Warnings carry the exception type name only. Recorded text is the user's
  own mail; tests prove it never reaches a log or event.
- No new model call and no change to prompts (M20.2 owns the prompt side).

## Behavior

### Schema 5

`Step5Ddl` is the §27.2 DDL with `IF NOT EXISTS` on every statement:

```sql
CREATE TABLE IF NOT EXISTS ai_draft_texts (
  draft_entry_id TEXT PRIMARY KEY,
  mailbox TEXT NOT NULL,
  source_imid TEXT NOT NULL,
  created INTEGER NOT NULL,
  text TEXT NOT NULL,
  state TEXT NOT NULL,
  updated INTEGER NOT NULL);
CREATE INDEX IF NOT EXISTS ix_ai_draft_texts_imid ON ai_draft_texts(source_imid, state);
CREATE TABLE IF NOT EXISTS ai_edits (
  id INTEGER PRIMARY KEY,
  sent_entry_id TEXT NOT NULL UNIQUE,
  sent INTEGER NOT NULL,
  similarity REAL NOT NULL,
  draft_chars INTEGER NOT NULL, sent_chars INTEGER NOT NULL,
  draft_text TEXT, sent_text TEXT);
CREATE INDEX IF NOT EXISTS ix_ai_edits_sent ON ai_edits(sent);
```

Comment above it: `// Learning from edits (SPEC 9.1, 27.2): redacted own text, capped and purged.`
`Migrations = [Step1, Step2, Step3, Step4, Step5]`. A new file goes 0 → 5 in
one transaction; a schema-4 file gets only `Step5`; rows of every other
table are untouched. Shared indexes get the tables by migration but never a
row. `query_index` needs no code change (its authorizer denies every real
table that isn't a view; the security test proves it).

### Recording (DraftWorker, §27.2)

`RecordDraftText(sourceImid, html, counts, made)`:
1. Return when `_s.Settings().AiDrafting.LearnFromEdits` is false (the live
   value at save time), when `counts.UsedText`, when `sourceImid?.Trim()`
   is null/empty, or when `made.EntryId` is null/blank.
2. `text = EditTexts.Prepare(DraftHtml.ToPlainText(html), null)`; return
   when `text` is `""`.
3. `_s.Indexes.For(MailboxIndexes.OwnMailbox).RecordAiDraftText(made.EntryId, made.Mailbox, imid, _time.GetUtcNow(), text)`
   (`made.Mailbox` is the normalized key: `""` own, else the shared SMTP).
4. Steps 2–3 in `try`/`catch (Exception ex) when (ex is not OperationCanceledException)`:
   Warning `AI drafts: couldn't record a draft's text ({Type}).` with
   `ex.GetType().Name`. The draft, its decision row, its `ai_drafts` row and
   its `Draft` event are never affected.

`html` is the worker's sanitized model body **after meeting times**, i.e.
exactly the `html` argument passed to `MakePlan` (M18.3): never
`ReplyPlan.HtmlFragment`, never `top` (reason line, §26.7 notes), never the
signature. The three call sites, each one line:

| Path | Where | Call |
|---|---|---|
| Automatic and rescan (`ProcessCandidateAsync`, step 8) | right after the `RecordAiDraft` `try`/`catch`, before the `Draft` event | `RecordDraftText(detail.InternetMessageId ?? factsImid, html, built.Attachments.Counts, made);` |
| Manual (`ManualCoreAsync`) | inside the save `try`, right after `made = await _s.Writer.ReplyAsync(...)` and before `text = DraftTexts.ManualDone;` | `RecordDraftText(e.InternetMessageId, html, built.Attachments.Counts, made);` |
| Revisit replace (`ReplaceAsync`) | right after the `RecordAiDraft` `try`/`catch`, before the `AddRevisit` `try` | `RecordDraftText(detail.InternetMessageId, html, attachments.Counts, made);` |

The rescan reuses `ProcessCandidateAsync`, so it needs no own call. The
revisit's `remove`/`keep` save nothing and record nothing. `reply_draft`
(`tool` marker) never records.

### Matching (`EditLearning`, §27.3)

`OnSyncCycleCompleted(cycle)`: inside `try`/`catch (Exception)` (Warning
`AI drafts: starting to learn from edits failed ({Type}).`, return null),
under a lock: return null when `cycle` is null, when no
`cycle.Mailboxes` entry has `Mailbox == MailboxIndexes.OwnMailbox` and
`!NotMounted`, when `settings()` has `LearnFromEdits` false or
`!HasConsent`, when a run is in flight, or when `_lastStart` is set and
`now - _lastStart < MinInterval`. Else set `_lastStart = now` and return
`Task.Run(() => MatchAsync(CancellationToken.None))`. (Aborted cycles never
raise `CycleCompleted`, so they never trigger. `OwnSentBackfillCompleted` is
not hooked: the cycle that finishes the backfill raises `CycleCompleted`
too.)

`MatchAsync(ct)`:
1. `SemaphoreSlim(1, 1).Wait(0)`; busy → `NotRun`. Released in `finally`.
2. Read `settings()`: `LearnFromEdits` false or `!HasConsent` → `NotRun`
   (the index is not touched).
3. `index = indexes.For(MailboxIndexes.OwnMailbox)`; `now = time.GetUtcNow()`;
   `sigs = signatureTexts()` (exception → `[]`);
   `rows = index.SentAiRepliesToMatch(now - MatchWindow, EmailIndex.MaxSentRepliesToMatch)`.
   An exception in this step (not `OperationCanceledException` for `ct`) →
   Warning `AI drafts: learning from edits failed ({Type}).`, return
   `new(true, 0, 0, 0)`.
4. For each row (`ct.ThrowIfCancellationRequested()` first), inside a
   per-row `try`/`catch (Exception ex) when (ex is not OperationCanceledException)`
   (`failed++`, keep the first exception's type name):
   - `cands = index.PendingDraftTexts(row.InReplyTo, row.EventTime)`;
     empty → next row (raced).
   - `newest = cands[0]`; `draftText = newest.Text`;
     `sentText = EditTexts.Prepare(row.Body, sigs)`
     (`StyleCorpus.OwnText` does `DraftReasonLine.StripPlain` first, so a
     kept reason line or attachment note isn't an edit).
   - `sim = EditDiff.Similarity(draftText, sentText)`;
     `same = EditDiff.IsUnchanged(sim)`.
   - `edit = new AiEdit(row.EntryId, row.EventTime, sim, draftText.Length, sentText.Length, same ? null : draftText, same ? null : sentText)`.
   - `index.StoreEdit(newest.DraftEntryId, row.InReplyTo, edit, now)` true →
     `stored++` (and `unchanged++` when `same`).
5. After the loop: `failed > 0` → Warning
   `AI drafts: couldn't note {Failed} edited drafts ({Type}).`.
   `stored > 0` → `hub.Event(ActivityKind.Ai, EditTexts.Noted(stored))`
   (no mailbox) and Debug
   `AI drafts: noted {Stored} sent drafts ({Unchanged} unchanged, {Failed} failed)`.
   Return `new(true, stored, unchanged, failed)`.

Rules that follow from the queries:
- A sent row without the `ai` marker (incl. `tool` drafts and replies
  written from scratch), with a blank `in_reply_to`, older than 30 days, or
  with an `ai_edits` row is never listed.
- A sent row whose only draft texts are newer than its `event_time`, or not
  `pending`, is never listed. Because the "has a candidate" test is part of
  `SentAiRepliesToMatch` (`EXISTS`), there is **no in-memory skip set**
  (see Spec changes); rows without a candidate cost one indexed query per
  run and can't starve newer rows.
- Only the own index is read and written. Shared-mailbox drafts were
  recorded in the own index (with `mailbox` = the shared SMTP) and match
  their sent copies in the own Sent Items like own drafts.

### `SentAiRepliesToMatch` SQL

```sql
SELECT e.entry_id AS EntryId, e.event_time AS EventTime, e.in_reply_to AS InReplyTo,
       substr(e.body, 1, 20000) AS Body
FROM emails e
WHERE <SentItemsFilter> AND e.clippy_marker = 'ai'
  AND e.in_reply_to IS NOT NULL AND trim(e.in_reply_to) <> ''
  AND e.event_time >= @since
  AND NOT EXISTS (SELECT 1 FROM ai_edits x WHERE x.sent_entry_id = e.entry_id)
  AND EXISTS (SELECT 1 FROM ai_draft_texts t WHERE t.state = 'pending'
              AND t.source_imid = e.in_reply_to AND t.created <= e.event_time)
ORDER BY e.event_time DESC, e.id DESC LIMIT @max
```

Use the existing `SentItemsFilter` constant (`EmailIndex.Ai.cs`) and
`MaxThreadBodyChars` (build the string like `SentForStyle` does).

### `StoreEdit` (one transaction, `@now` = now unix seconds)

1. `UPDATE ai_draft_texts SET state = 'matched', text = '', updated = @now WHERE draft_entry_id = @m AND state = 'pending'`
   → 0 rows: roll back, return false.
2. `UPDATE ai_draft_texts SET state = 'superseded', text = '', updated = @now WHERE state = 'pending' AND source_imid = @imid AND created <= @sent`
   (the older candidates; `@imid` trimmed, `@sent` = `edit.Sent`).
3. `INSERT INTO ai_edits (sent_entry_id, sent, similarity, draft_chars, sent_chars, draft_text, sent_text) VALUES (...) ON CONFLICT(sent_entry_id) DO NOTHING`
   → 0 rows: roll back, return false.
4. When `edit.DraftText` is not null:
   `UPDATE ai_edits SET draft_text = NULL, sent_text = NULL WHERE draft_text IS NOT NULL AND id NOT IN (SELECT id FROM ai_edits WHERE draft_text IS NOT NULL ORDER BY sent DESC, id DESC LIMIT 20)`
   (`MaxEditPairs`; numbers stay).
5. Commit, return true.

Matched and superseded rows keep no text (it now lives in `ai_edits`, or
is useless). Pending rows created after `@sent` stay pending.

### Purge (`PurgeDecisions(now)`, same transaction as today)

With `@t30 = now − DraftTextRetention`, `@t90 = now − EditRetention`,
`@now = now`, in this order:
1. `DELETE FROM ai_draft_texts WHERE state <> 'pending' AND updated < @t30` (counted)
2. `UPDATE ai_draft_texts SET state = 'expired', text = '', updated = @now WHERE state = 'pending' AND created < @t30` (not counted)
3. `DELETE FROM ai_edits WHERE sent < @t90` (counted)

So a pending row expires after 30 days and is deleted 30 days later;
matched/superseded rows are deleted 30 days after their match. Update the
doc comment ("…, ai_draft_texts and ai_edits per SPEC 27.2/27.5"). The
return value counts deleted rows only. `PurgeOlderThan` is not changed.
Rebuild deletes both tables with the file.

### `EditDiff`

- `Tokens`: enumerate `text.EnumerateRunes()`. `Rune.IsLetterOrDigit(r)` or
  `r` is `'` (U+0027) or `’` (U+2019) → append to the current word.
  `Rune.IsWhiteSpace(r)` → end the current word. Anything else → end the
  current word, then add `r.ToString()` as its own token.
- `Similarity`: `n = draftTokens.Count`, `m = sentTokens.Count`;
  `n + m == 0` → `1.0`; `n == 0 || m == 0` → `0.0`; else LCS with two
  `int[]` rows of length `m + 1` (string.Equals ordinal), result
  `2.0 * lcs / (n + m)` (this exact expression, so 98/100 equals the
  literal `0.98`). Inputs are at most 1,500 chars each, so at most ~1,500
  tokens a side.

### Settings

- Defaults `LearnFromEdits = true`, `EditsNoticeShown = false`;
  System.Text.Json picks them up (no `FillDefaults` change, no validation).
  A `settings.json` without the fields loads with the defaults.
- `SettingsEditor.Rebase`: `if (l.EditsNoticeShown) d.EditsNoticeShown = true;`
  right after the `AttachmentsNoticeShown` line.
- Turning `LearnFromEdits` off stops recording (checked at each save) and
  matching (checked in the hook and in `MatchAsync`); stored rows stay and
  age out.
- **Not in this task**: the Settings checkbox, `AiTabTexts` text, consent
  text, `AiDraftingToggler.RecordConsent` setting `EditsNoticeShown`, the
  `AiNotice` value and the one-time notice. They belong with M20.2 (see
  Out of scope).

## Spec changes

Low-risk decisions made in this brief; the SPEC owner should add them to
§27.2–§27.5 (and fix §9.1, which still says "pending the user's decision"
for the attachment rule that the user decided on 2026-11-16):
1. **No in-memory skip set** (§27.3 step 2): `SentAiRepliesToMatch` lists
   only sent rows that have a pending candidate (`EXISTS`), so rows without
   one are never rechecked in Core code and can't starve newer rows. Same
   result as the set, without state.
2. **One text rule on both sides**: draft and sent texts both go through
   `EditTexts.Prepare` = `StyleCorpus.OwnText` (reason-line strip, then
   `MailText.OwnText` once per signature text) → `MailText.Redact` →
   `AttachmentBudget.Cut(…, 1500)` (at most 1,500 chars incl. a final
   `…`). The sent side uses both default signatures (New and Reply,
   `StyleCorpus.SignatureTexts`, as style sampling does) instead of the
   reply signature only; the draft side passes none (the model's `html`
   has no signature).
3. **Draft text recorded only when non-empty** after `Prepare`, and only
   for a non-blank draft entry id. `LearnFromEdits` is read live at save
   time.
4. **Matched and superseded rows drop their text** (`text = ''`) in the
   match transaction, and every non-pending `ai_draft_texts` row is deleted
   30 days after its `updated` (expired, matched and superseded alike).
5. `draft_chars`/`sent_chars` are the lengths of the prepared (redacted,
   cut) texts.
6. Matching uses `in_reply_to` exactly as indexed (trimmed) against the
   trimmed recorded imid, ordinal; at most 500 sent rows per run, newest
   first.
7. Event wording: `AI drafts: noted how you edited 1 sent draft.` for one,
   `… <n> sent drafts.` otherwise (N0, invariant); `n` counts every
   `ai_edits` row stored in the run, including those sent unchanged.
8. Throttle: 5 minutes between run **starts**; a cycle without an own
   result (or with the own store not mounted) doesn't start a run and
   doesn't reset the timer. `OwnSentBackfillCompleted` isn't hooked.
9. `PurgeOlderThan` doesn't touch the new tables (only `PurgeDecisions`,
   which runs every sync cycle).
10. Known limit (accept): if a revisit's `replace` couldn't move the old
    draft and the user sends the **old** one, the newer recorded text is
    matched (one noisy pair, aged out with the rest).
