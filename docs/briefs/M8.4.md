# M8.4 `CreateMeeting` + `send_meeting_invite`

## Goal

Implement the only sending tool, `send_meeting_invite` (SPEC §11.9), in
all three `MeetingInviteMode`s. Also implement the COM side,
`OutlookCalendar.CreateMeeting` (§8): resolve every recipient, use the
shared calendar for `mailbox`, and add the Teams note. It sits behind
`InviteGate` (§12) and the confirmation dialog flow (§6.6: resolve on
COM, then await the dialog on the UI, then create on COM). The flow
produces activity events and balloons (§6.5, §7). All the orchestration
goes in Core behind two small interfaces, so it is unit-tested with
fakes: argument validation, time parsing, gate decisions, result and
message texts, events and balloons. The App only gets the COM
implementation and the thin MCP tool method. This brief puts in the one
`.Send()` the codebase allows (§1.4, CLAUDE.md hard rule).

`ToolDescription` (exact):
`Creates a meeting and sends the invite to the attendees. This is the only tool that can send anything. In Send mode the user is asked to confirm in a dialog, and the invite goes out immediately once they click Send; they may instead save it as a draft or cancel. ## Behavior

### `MeetingRequest.Create` (Core, pure)

The checks run in this order, and the first failure throws `McpException`.
`<text>` is the caller's text, trimmed and cut to 100 characters.

1. `recipients`: null, or blank after `Recipients.Parse`, gives
   `recipients is empty. Pass at least one attendee as "Name <email>" or a bare email, separated by ";".`
   A `FormatException` from `Recipients.Parse` is rethrown as
   `McpException(ex.Message)`, with the message unchanged.
2. `subject`: CR and LF are replaced with a space and runs of spaces
   collapse to one, then the text is trimmed. If that leaves it empty:
   `subject is empty. Give the meeting a subject.`
3. `start` and then `end`, each:
   - Blank gives `start is empty. Pass a local date-time like 2026-03-01T14:30, or the start of a find_free_times suggestion.`
     (`end is empty. Pass a local date-time like 2026-03-01T15:30, or the end of a find_free_times suggestion.`)
   - A date-only value (`^\d{4}-\d{2}-\d{2}$`), or anything
     `SearchDates.ParseFrom(text, tz)` rejects (`FormatException` or
     `ArgumentOutOfRangeException`), gives
     `start "<text>" is not a valid date-time. Use an ISO date-time like 2026-03-01T14:30 (local time), or the start and end of a find_free_times suggestion.`
     (`end` likewise). Reuse `SearchDates.ParseFrom` rather than a new
     parser, so the accepted forms are the §11.1 date-time forms: `T` or a
     space, optional seconds and fraction, optional `Z` or `±hh:mm`.
   - The value is converted to local wall clock with
     `TimeZoneInfo.ConvertTime(dto, tz).DateTime`, then
     `DateTime.SpecifyKind(…, Unspecified)`. If the conversion overflows,
     it gets the same invalid message.
4. `end <= start` gives `end (<end yyyy-MM-dd HH:mm>) must be after start (<start yyyy-MM-dd HH:mm>).`
   (invariant culture).
5. A local `end` at or before `now` converted to `tz` gives
   `This meeting ends in the past (<end yyyy-MM-dd HH:mm>). Pick a future time.`
   A start in the past with an end in the future is allowed.
6. `body`: null becomes `""`. `\r\n`, `\r` and `\n` are all normalized to
   `\r\n`. It is not trimmed.
7. `location`: trimmed. Blank becomes `null`.
8. `mailbox`: `MailboxIndexes.Normalize(mailbox)` (reuse it). Nothing is
   validated here. `ResolveAsync` validates it (M5.2).

### `MeetingInvites.SendAsync` (Core)

1. `mode0 = settings().MeetingInviteMode`. If it is `Disabled`, the
   result is `d = InviteGate.Decide(Disabled, null, false)`: record the
   event `Invite refused: invites are disabled` and throw
   `McpException(d.RefuseReason)`, which is `InviteGate.DisabledMessage`
   verbatim. This happens **before** argument validation and before any
   COM call.
2. `req = MeetingRequest.Create(…, timeZone, time.GetUtcNow())`.
3. `r = await calendar.ResolveAsync(req, ct)`. If `r.Unresolved` is not
   empty, throw `McpException(InviteTexts.Unresolved(r.Unresolved))`.
   Nothing is created and the dialog isn't shown. Resolving happens in
   **every** non-disabled mode (§8: `CreateMeeting` fails on unresolved
   recipients).
4. If `InviteGate.RequiresConfirmation(mode0)` is true (Send):
   - Build the `InvitePreview` from `req` and `r`, then call
     `c = await confirmer.ConfirmAsync(preview, TimeSpan.FromSeconds(settings().InviteConfirmTimeoutSeconds), ct)`.
   - Read `mode1 = settings().MeetingInviteMode` again. Use
     `mode = MostRestrictive(mode0, mode1)`, where Disabled is more
     restrictive than DraftOnly, which is more restrictive than Send. A
     user who downgrades the mode while a dialog is open is honored.
     Never upgrade.
   - `d = InviteGate.Decide(mode, c.Choice, c.TimedOut)`.

   Otherwise (DraftOnly): `d = InviteGate.Decide(mode0, null, false)`.
   Don't call the confirmer.
5. Act on `d.Action`:
   - `Refuse`: event `Invite refused: invites are disabled`, then throw
     `McpException(d.RefuseReason)`.
   - `Cancel`: `CreateAsync` is **not** called. Event
     `Invite cancelled by the user: "<subj>"`. Return
     `{status:"cancelled", message: InviteTexts.Cancelled}`, with all
     other fields null.
   - `Send` or `SaveDraft`:
     `m = await calendar.CreateAsync(req, d, CancellationToken.None)`.
     After the decision, the request's `ct` is no longer passed on, so a
     choice the user made is always carried out.
6. The result for `Send` or `SaveDraft`:
   - `status`: `"sent"` or `"saved_as_draft"`. `reason` is `d.ReasonCode`.
   - `subject` is `req.Subject`. `start` and `end` use
     `"yyyy-MM-ddTHH:mm:sszzz"` with the `tz` offset at that local time,
     the same shape as find_free_times. `mailbox` is `req.Mailbox`.
   - `organizer` is `Recipients.Format([new(r.OrganizerName, r.OrganizerEmail)])`.
     `recipients` is `Recipients.Format(r.Attendees.Select(a => new Recipient(a.Name, a.Email)))`.
   - `teams` is `m.TeamsAdded`. `note` is `InviteTexts.TeamsUnavailable`
     when `req.Teams && !m.TeamsAdded`, and null otherwise.
   - `message` is one of the following, with `C = InviteTexts.Calendar(req.Mailbox)`,
     `n` the attendee count, and `s` = `""` when n == 1, else `"s"`. When
     there is a note, append `" " + note`.
     - sent: `The invite was sent to <n> recipient<s> from <C>.`
     - user_choice: `The user chose Save as draft. The meeting is saved unsent in <C>; the user needs to review it in Outlook and send it from there.`
     - timeout: `Nobody answered the confirmation dialog within <InviteConfirmTimeoutSeconds> seconds, so the meeting is saved unsent in <C>. The user needs to review it in Outlook and send it from there.`
     - draft_only_mode: `Meeting invites are set to Draft only, so the meeting is saved unsent in <C>. The user needs to review it in Outlook and send it from there.`
7. Activity: **exactly one** `ActivityKind.Invite` event per call, for
   every outcome. Its `mailbox` argument is `req.Mailbox` when non-empty,
   else null (null in the refused-before-parse case too). `<subj>` is
   `TrayText.Truncate(req.Subject, 80)`. The summaries:
   - `Invite sent: "<subj>" to <n> recipient<s>`
   - `Invite saved as draft (<reasonCode>): "<subj>"`
   - `Invite cancelled by the user: "<subj>"`
   - `Invite refused: invites are disabled`
   - `Invite failed: <McpException message, TrayText.Truncate(…, 200)>`
     for any `McpException` from steps 2–5. Rethrow it unchanged.
   - `Invite abandoned: the request was cancelled` for
     `OperationCanceledException`. Rethrow it.

   Other exceptions also record `Invite failed: <ex.Message truncated>`
   and are rethrown. Never include the body in an event.
8. Balloons (§6.5), through `balloons.Post(text)`, rate-limited, with the
   return value ignored:
   - sent: `InviteTexts.SentBalloon(n)` =
     `It looks like you're trying to schedule a meeting. I sent <n> invite<s>.`
   - timeout: `InviteTexts.TimeoutBalloon(subject)` =
     `It looks like you stepped away. I saved "<subj>" as a draft — review it in Outlook.`

   No balloon for any other outcome.
9. `InviteTexts`:
   - `Unresolved(entries)` =
     `These recipients could not be resolved in Outlook: <entries joined with "; ">. Nothing was created. Check the addresses and try again.`
   - `NoCalendarRights(smtp)` =
     `The user doesn't have delegate or editor rights on the calendar of <smtp>, so the meeting can't be organized from it. Ask the user to get editor or delegate access from the mailbox owner, or leave mailbox empty to organize it from their own calendar.`
   - `Calendar("")` = `your calendar`. `Calendar(smtp)` = `the <smtp> calendar`.
   - `TeamsUnavailable` =
     `A Teams meeting was requested, but Clippy's Revenge can't add one through the Teams add-in on this PC, so the invite has no Teams link. If one is needed, the user can open the meeting in Outlook and click Teams Meeting.`

### `OutlookCalendar` (App, COM, runs only inside `worker.RunAsync(…, Priority.Interactive, …)`)

`ResolveInvite(app, req)`:
- Call `OutlookStores.Get(app, req.Mailbox)` to validate the mailbox. It
  throws for an unknown, disabled or `all` mailbox.
- Organizer:
  - Own mailbox: `Session.CurrentUser.AddressEntry`, with the name from
    `.Name` and the email from `GetExchangeUser()?.PrimarySmtpAddress`,
    else `.Address`.
  - Shared mailbox: the name is the `SharedMailbox.DisplayName` from
    settings (fall back to the store display name, then the smtp). The
    email is `req.Mailbox`.
- Resolve each recipient with `Session.CreateRecipient(r.Email)`, then
  `.Resolve()`.
  - When it resolves: the name is `AddressEntry.Name` (fall back to
    `r.Name`), the email is `GetExchangeUser()?.PrimarySmtpAddress`
    (fall back to `r.Email`), and
    `IsExternal = !AttendeeKinds.IsInternal((int)AddressEntry.AddressEntryUserType)`.
  - When it doesn't: add `Recipients.Format([r])` to `Unresolved`.
  - Release every `Recipient`, `AddressEntry` and `ExchangeUser` with
    `Marshal.ReleaseComObject` inside the loop.
- `TeamsAvailable`: **always `false` in v1**. See the blocking question
  in the reply. Keep it in one private method, `TeamsAddinUsable(app)`,
  that returns false, with a comment pointing to this brief.

`CreateMeeting(app, req, decision)`. This is the only `.Send(` in `src/`.
- First, if `decision.Action` is neither `Send` nor `SaveDraft`, throw
  `InvalidOperationException` before touching COM.
- Own mailbox: `app.CreateItem(OlItemType.olAppointmentItem)`.
- Shared mailbox: `Session.CreateRecipient(req.Mailbox)`, `Resolve()`,
  `Session.GetSharedDefaultFolder(recip, OlDefaultFolders.olFolderCalendar)`,
  `folder.Items.Add(OlItemType.olAppointmentItem)`. A `COMException` (or
  `UnauthorizedAccessException`) while getting the folder or adding,
  saving or sending the item throws
  `McpException(InviteTexts.NoCalendarRights(req.Mailbox))`.
- Set `MeetingStatus = olMeeting`, `Subject`, `Start`, `End` (local
  `DateTime`s), `Location` (when non-null) and `Body` (plain text, only
  when non-empty).
- Add each `req.Recipients[i].Email` with `item.Recipients.Add(email)`,
  setting `Type = (int)OlMeetingRecipientType.olRequired`, and release
  each `Recipient`. Then `item.Recipients.ResolveAll()`. When that returns
  false, collect the unresolved entries, call
  `item.Close(OlInspectorClose.olDiscard)` and throw
  `McpException(InviteTexts.Unresolved(…))`. Nothing is saved.
- Teams: when `req.Teams && TeamsAddinUsable(app)`, nothing happens in v1
  (unreachable). `TeamsAdded = false`.
- `decision.Action == InviteAction.Send` calls `item.Send()`.
  `InviteAction.SaveDraft` calls `item.Save()`. Write it as a `switch`
  with a throwing default.
- Release the item, the folder and the recipients in `finally`. Never
  call `Display()`, never open an Inspector, and never use `SendKeys`.
- Don't write the text `.Send(` anywhere else. That includes comments,
  XML docs, strings and test names in `src/`. The §15 source scan
  requires exactly one.

## Spec changes (proposed)

Append to §11.9, after the `teams=true` paragraph:

> Details (M8.4): `start`/`end` take the §11.1 date-time forms (not
> date-only), and an offset is converted to local time. `end` must be
> after `start` and in the future. Blank `recipients`, `subject`, `start`
> or `end` are errors. The mode is checked first, so `Disabled` refuses
> before anything else. Recipients are resolved in `Send` and `DraftOnly`
> mode before anything is created or shown. If the user lowers
> `MeetingInviteMode` while a dialog is open, the lower mode is used.
> Once a decision is made, the request's cancellation no longer aborts
> it. Results other than `cancelled` are
> `{status, reason?, message, subject, start, end, mailbox, organizer, recipients, teams, note?}`,
> where `start`/`end` use the find_free_times format and `teams` is true
> only when a Teams link was added. Each call records exactly one
> `Invite` event, and the body never appears in events. The orchestration
> is Core's `MeetingInvites`. COM sits behind `IMeetingCalendar`
> (`OutlookCalendar`).

Append to the §8 `CreateMeeting` bullet:

> It takes the `InviteDecision` and calls `.Send()` only for
> `InviteAction.Send` and `.Save()` only for `SaveDraft`. Any other
> action throws before COM is touched. The own mailbox uses
> `CreateItem(olAppointmentItem)`. On unresolved recipients the item is
> discarded unsaved. It never displays an Inspector. Recipients count as
> internal (not highlighted) when their `AddressEntryUserType` is an
> Exchange user, distribution list, public folder, agent or organization
> entry.

Pending the Teams question, append to §18 "Open":

> 4. **Teams link**: the Outlook object model has no supported call to
>    add a Teams meeting, so v1 never adds one: `teams=true` returns the
>    note.
