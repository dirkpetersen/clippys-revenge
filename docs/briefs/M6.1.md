# M6.1 `SyncService`: changes pass, newest-first backfill, watermarks, progress, purge, all mailboxes, pause/resume, Sync now, rebuild

## Goal

Build background indexing as SPEC §10 describes (steps 1–4, purge, the
`Sync` event, Rebuild, how a larger `RetentionMonths` behaves). It uses the
index from §9.1–§9.3, reports activity as §6.1 and §7 describe, fires the
balloon from §6.5 when an initial backfill finishes, and backs the tray
items **Sync now**, **Pause/Resume indexing** and **Rebuild index…** (§6.2).
It also supplies the tray's `TrayStats` (§6.1 idle tooltip, §6.2 second
status line). All logic runs in **Core** against a small `IMailSource`
interface, so the tests use an in-memory fake. Outlook isn't on this machine
or in CI. The App gets one thin COM adapter (`OutlookMailSource`) on top of
`OutlookWorker` (M5.1), `OutlookStores` (M5.2) and `OutlookMail` (M5.3), plus
wiring in `Program` and `TrayApp`. The task also writes the `meta` keys from
§9.1 and applies the `MailboxIndexes` carry-forward fixes from `docs/PLAN.md`.

These belong to **M6.2** and are not built here: step 5 (daily reconcile:
delete missing, add missing, refresh unread via `ListEntryIds`) and the
*immediate* purge when `RetentionMonths` gets smaller. M6.1 picks up a
smaller retention at the next cycle's purge, through the normal cycle.

## Behavior

### A. Engine: one mailbox (`SyncMailboxAsync`)

1. `now = time.GetUtcNow()` at the start. `cutoff = now.AddMonths(-plan.RetentionMonths)`
   (UTC) (§10 step 1). `prefix = SyncLabels.MailboxPrefix(plan.Mailbox)`.
   Start a stopwatch with `time.GetTimestamp()`.
2. `mb = await source.OpenMailboxAsync(plan.Mailbox, ct)`. If it is null, return
   `NotMounted = true`, with empty `Folders` and no index writes. Otherwise
   `SetMeta("mailbox_smtp", mb.Smtp)` and `SetMeta("store_id", mb.StoreId)`.
3. For each folder path in `plan.Folders`, in order:
   - `f = GetFolderAsync(mb, path)`. If it is null, add `FolderSyncResult(path, Missing: true, 0, 0, false)` and continue.
   - `state = index.GetSyncState(f.FolderKey)`. If it is null (first run, step 2), write
     `new SyncState(f.FolderKey, path, ModifiedWatermark: now, OldestSynced: now, null, false)`
     **before** any listing. If it exists but `FolderPath != path`, rewrite it with the new path.
   - `ChangesPassAsync`, then `BackfillPassAsync`.
4. **Skip rule (both passes).** Call `index.GetSyncInfo(ids)` for the listed rows.
   A row needs a **read** when its id is unknown, when the stored
   `LastModified` is null, or when the stored value differs from
   `row.LastModified` in whole unix seconds. A row whose `LastModified`
   matches but whose `Unread` differs needs no read: it goes into one
   `index.SetUnread` call for the pass, counted in `UnreadUpdated`. Other
   rows are skipped. Rows with `EventTime < cutoff` are always dropped,
   whatever the source returned.
5. **Changes pass** (step 3):
   - `rows = ListChangedAsync(f, state.ModifiedWatermark, cutoff)`. Apply rule 4,
     then sort the rows to read by `LastModified` ascending (null first), then
     `EntryId` ordinal.
   - When `n = rows to read > 0`, hold
     `hub.Begin(Syncing, label)` around the pass, where
     `label = (prefix == "" ? "" : prefix + " ") + FolderLabel(path) + " +" + n`,
     giving `Inbox +12` or `helpdesk@… Inbox +12`.
   - Per batch of ≤ 50: `emails = ReadAsync(f, ids)`, set `Folder = path` on every
     email (`with { Folder = path }`), `UpsertBatch`, then
     `ModifiedWatermark = max(old, max LastModified of the batch's rows)`
     (the listed rows, not only the ones read back), `SetSyncState`, and
     finally `ct.ThrowIfCancellationRequested()`.
   - Apply the unread-only updates before the first batch.
   - `Upserted += emails.Count`.
   - If no row needs a read, the watermark still advances to the max
     `LastModified` of the rows that were listed and kept.
6. **Backfill pass** (step 4). Runs only while `state.OldestSynced > cutoff`:
   - If `BackfillComplete` is true here (retention got bigger), set it to false and persist.
   - `rows = ListRangeAsync(f, cutoff, state.OldestSynced)` sorted `EventTime` desc, then `EntryId` ordinal.
     `total = rows.Count`.
   - When `total > 0`, emit
     `Event(Backfill, $"{FolderLabel}: backfill started, {total:N0} emails to index ({cutoffLocal:yyyy-MM} → now)", mailbox: plan.Mailbox)`.
     `cutoffLocal` is the cutoff in `time.LocalTimeZone`, formatted with the
     invariant culture.
   - Hold `hub.Begin(Backfilling, $"{prefix-and-space}{FolderLabel} ({cutoffLocal:yyyy-MM} → now)")`
     for the pass, and call `hub.Report(done, total)` once before the first batch
     (done = 0) and after each batch.
   - Per batch of ≤ 50 rows in that order: apply rule 4 to the batch, read
     what needs reading, set `Folder`, upsert, and apply that batch's
     unread-only updates. Then set
     `OldestSynced = EventTime of the batch's last (oldest) row`, persist,
     `done += batch row count`, `Report`, and finally
     `ct.ThrowIfCancellationRequested()`.
   - After the last batch, or right away when `total == 0`, set
     `OldestSynced = cutoff` and `BackfillComplete = true`, persist, and emit
     `Event(Backfill, $"{FolderLabel}: backfill complete", mailbox: plan.Mailbox)`.
     Emit that event only when `total > 0`.
   - When `state.OldestSynced <= cutoff` and `BackfillComplete` is false, set it to true and persist.
7. **Purge.** After all folders: if `index.Status().Oldest < cutoff`, hold
   `hub.Begin(Purging, $"{plan.RetentionMonths} months")` and
   `purged = index.PurgeOlderThan(cutoff)`. When `purged > 0`, emit
   `Event(Purge, $"removed {purged:N0} emails older than {cutoffLocal:yyyy-MM-dd}", mailbox: plan.Mailbox)`.
8. `SetMeta("retention_months", RetentionMonths invariant)` and
   `SetMeta("last_sync", now unix seconds invariant)`. Take `now` again from
   the clock at this point.
9. **Sync event.** When any folder has `Upserted + UnreadUpdated > 0` or
   `purged > 0`, emit
   `Event(Sync, string.Join(", ", nonMissing.Select(r => $"{FolderLabel(r.Folder)} +{r.Upserted}")) + $" ({secs:0.0} s)", duration, plan.Mailbox)`.
   `secs` is the elapsed time from the stopwatch, in the invariant culture.
   Example: `Inbox +12, Sent +3 (1.8 s)`. Missing folders are left out.
10. `BackfillFinished` is true when at least one folder is not missing,
    every non-missing folder is `BackfillComplete` at the end, and at least
    one of them was missing its state or was incomplete when the cycle
    started.
11. Every scope is a `using` scope. On any exception, all scopes are
    disposed and the exception propagates. Never log subjects, bodies,
    addresses beyond the mailbox key, or attachment names.

### B. Service loop (`ExecuteAsync`)

1. When it starts, fill the cached per-mailbox email counts from
   `indexes.For(k).Status().TotalEmails` for every key in
   `indexes.Mailboxes`. Catch and log failures. Then run the first cycle
   right away.
2. **Cycle.**
   - Take the gate (`SemaphoreSlim(1,1)`).
   - Create `_cycleCts` linked to `stoppingToken`.
   - Run `plans = SyncPlanner.Build(settings().Clone())`.
   - For each plan, in order:
     - `index = indexes.Add(plan.Mailbox)`. It is idempotent, and `""` returns the own index.
     - `await engine.SyncMailboxAsync(...)`.
     - Update the cached count from `Status().TotalEmails`.
   - Per-mailbox handling:
     - **Success:** dispose that mailbox's Error scope, if any. Clear its "reported" flags for not-mounted and missing folders where the item is present again. Post the balloon when `BackfillFinished`: `balloons.Post(BalloonTexts.BackfillDone(SyncLabels.MailboxName(key), count))`.
     - **`NotMounted`:** emit `Event(Error, $"{key} is not in Outlook; skipped", mailbox: key)` only on the first cycle of each not-mounted episode. Don't start an Error scope.
     - **Missing folder:** emit `Event(Error, $"folder \"{path}\" not found; skipped", mailbox: key)` once per episode for each (mailbox, path) pair.
     - **`MailSourceUnavailableException`:** stop the cycle (`Aborted = true`), log at Information level, and emit no event and no Error state.
     - **`OperationCanceledException` from a pause, rebuild or stop:** stop the cycle (`Aborted = true`).
     - **Any other exception:** log it, emit `Event(Error, "sync failed: " + Truncate(ex.Message, 200), mailbox: key)`, and keep one Error scope per mailbox open: `hub.Begin(Error, "sync failed for " + (key == "" ? "your mailbox" : prefix))`. Only one scope per mailbox: don't open a second while one is already open. Then continue with the next mailbox.
   - At the end, set `LastSync = now` (only when the cycle isn't aborted) and `CycleEnd = now`.
   - Raise `CycleFinished` and release the gate.
3. **Wait.**
   - While paused, wait only for the wake signal (Resume) or for stop.
   - Otherwise wait for whichever comes first:
     - the wake signal (`SyncNow`, `NotifySettingsChanged`, `Resume`, the end of a rebuild);
     - `Task.Delay(CycleEnd + interval - now, time, ct)`, where `interval = settings().SyncIntervalSeconds`, read fresh each time.
   - The wake signal is a bounded channel of capacity 1 with `DropWrite`.
     Several signals during one cycle collapse into one follow-up cycle.
4. **Pause.**
   - Set `IsPaused`.
   - Open `hub.Begin(Paused, "")`, held until Resume or stop.
   - Cancel `_cycleCts`. The running cycle stops at the next batch
     boundary, and every batch already finished stays persisted.
   - `SyncNow` and `NotifySettingsChanged` are ignored while paused.
   - The paused state isn't saved, so it doesn't survive a restart.
5. **Resume.** Dispose the Paused scope, clear `IsPaused`, and signal a wake.
6. **Rebuild** (`RebuildAsync`), the §10 "stop sync, `Close()`, delete the DB, start again from step 2":
   1. Resolve the targets: `""`, every key in `indexes.Mailboxes`, or the one shared key.
      It throws `ArgumentException` when that shared key isn't open.
   2. Cancel `_cycleCts`, then `await gate.WaitAsync(ct)`.
   3. For each target:
      - Dispose its Error scope.
      - `indexes.Reset(key)`.
      - Set its cached count to 0.
      - Emit `Event(Backfill, "index deleted for rebuild", mailbox: key)`.
   4. Release the gate and signal a wake. The next cycle does a first run (step 2) because no `sync_state` rows exist.
   - While paused, the files are still reset, and indexing starts on Resume.
7. **Stop.**
   - `StopAsync` cancels `stoppingToken`.
   - `ExecuteAsync` returns once the current awaited call honors `ct`.
   - It then disposes the Paused scope and every Error scope.
   - It never throws, except `OperationCanceledException` from the base class.
8. **`GetStats()`** returns `new TrayStats(EmailCount, LastSync, NextSync, IsPaused)`:
   - `EmailCount` is the sum of cached counts over the current plan's keys, or null before any count is known.
   - `LastSync` is the end of the last cycle that wasn't aborted, or null.
   - `NextSync` is null while paused or while a cycle runs. Otherwise it is `CycleEnd + interval`, or null before the first cycle.
   - It is thread-safe and never touches SQLite. It is called from the UI thread once a second.
9. All public members are thread-safe. Use `System.Threading.Lock` for the
   fields. There is no `.Result` or `.Wait()`.

### C. `EmailIndex` additions

- `GetMeta` / `SetMeta` read and write the `meta` table. `SetMeta(k, null)` deletes the row.
  Writing `schema_version` is refused.
- `GetSyncInfo` runs `SELECT entry_id, last_modified, unread FROM emails WHERE entry_id IN (…)` in chunks of 500, all parameterized.
- `Status().LastSync` is `meta.last_sync` (unix seconds) when present and
  parseable. Otherwise it is `MAX(sync_state.last_reconcile)`, the current
  behavior, so the existing M2.3 tests stay green.

### D. `OutlookMailSource` (App)

- Every member does exactly one `worker.RunAsync(..., Background, ct)`.
  `ReadAsync` handles ≤ 50 items per call (§4 chunk rule).
  - If M5.3's enumeration is a lazy Table reader, pull at most 500 rows per
    `RunAsync` call and keep the Table between calls on the worker.
  - If it returns a materialized list, one call is fine.
  - Release the Table at the end.
- Map M5.1's "Outlook unavailable" exception to `MailSourceUnavailableException`.
  Let `OperationCanceledException` pass through.
- `OpenMailboxAsync` uses M5.2:
  - For `""`, use the own store. If M5.2 exposes no own SMTP, take it from
    `Session.CurrentUser.AddressEntry.GetExchangeUser()?.PrimarySmtpAddress`,
    else `""`.
  - For a shared key, return null when the mailbox isn't mounted. If M5.2
    throws `McpException` for a mailbox that is configured but not mounted,
    catch it and return null.
- `GetFolderAsync`:
  - The first segment `Inbox` maps to `store.GetDefaultFolder(olFolderInbox)` and `Sent Items` to `olFolderSentMail`. Any other first segment is a child of `store.GetRootFolder()`.
  - Later segments are matched case-insensitively among `.Folders`.
  - When a segment is missing, return null.
  - `FolderKey = folder.EntryID`, `IsSent = FolderPaths.IsUnderSentItems(path)`.
  - Release every intermediate `Folder`/`Folders` object.
- `ReadAsync`:
  - Call `Session.GetItemFromID(id, folder.StoreId)` for each id.
  - Only a `MailItem` goes to `ReadForIndex`. Skip other item types (meeting requests, reports).
  - When a single item's lookup fails with a "not found" COM error, skip that item.
  - Release each item in the loop with `Marshal.ReleaseComObject`.
- Read only. No `.Save()`, no `.Send()`, and no property writes (that includes `UnRead`).
- Never `new Outlook.Application()`, `Activator.CreateInstance` or `CoCreateInstance`.

### E. `Program` wiring

- `localDir = %LOCALAPPDATA%\ClippysRevenge` (§5.1).
- Create `new MailboxIndexes(localDir, settings.SharedMailboxes.Where(m => m?.Enabled == true).Select(m => m.Smtp))`.
  - If that throws (a newer schema, I/O), log it and hold
    `hub.Begin(Error, "index can't be opened")` for the life of the process.
  - Then don't create the sync service. The tray controls are passed as null.

### H. `MailboxIndexes` carry-forward fixes (PLAN "Carry-forward notes")

1. In single-mailbox `Search`, call `For(mailbox)` with the caller's raw
   argument, so the error echoes the caller's text (trimmed, original case).
   Tag the hits with the normalized key.
2. `Add` opens the `EmailIndex` **outside** `_lock`, then takes the lock
   again. If another thread added the key in the meantime, it returns the
   existing instance and drops the new one without calling `Close()` (the
   two share a connection pool). Otherwise it registers the new one. The
   same no-SQLite-under-lock rule applies to `Reset`.
3. If opening any index in the constructor throws, `Close()` every index
   already opened and rethrow.
4. Not here: `SearchDates` turning `ArgumentOutOfRangeException` into a
   `FormatException`. That stays with M7.1 (search tools).
