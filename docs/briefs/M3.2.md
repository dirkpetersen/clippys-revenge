# M3.2 `ActivityHub`: ref-counted states, ring buffer, 10 Hz throttle

## Goal

Implement `ActivityHub` in Core (SPEC §7, state table and precedence from
§6.1, event kinds from §6.4, threading role from §4 item 1). The hub keeps
the current `ActivityState`, which is the highest state among all active
`Begin` scopes, or `Idle` when there are none. It also keeps the
`Progress` of the winning scope and a 500-entry ring buffer of
`ActivityEvent`s, and raises `Changed` at most 10 times per second. It is
UI-agnostic: no WinForms, no `SynchronizationContext`. The tray (M4.3)
subscribes and posts to the UI thread itself. The MCP tool-call filter is
M4.1, not this task.

## Cross-task dependencies

None. This task owns `ActivityState`, `ActivityKind`, `ActivityProgress`
and `ActivityEvent`. No sibling task (M1.x, M3.1) should define them. If a
sibling brief needs one, it must reference this task instead.

## Public API

Namespace `ClippysRevenge.Core`, file-scoped.

```csharp
/// Higher numeric value wins (SPEC §6.1 table, bottom to top).
public enum ActivityState
{
    Idle = 0,
    Serving = 1,
    Paused = 2,
    Purging = 3,
    Syncing = 4,
    Backfilling = 5,
    OutlookUnavailable = 6,
    AwaitingConfirmation = 7,
    Error = 8,
}

public enum ActivityKind { Sync, Backfill, Purge, Tool, Draft, Invite, Blocked, Error }

public readonly record struct ActivityProgress(int Done, int Total, string Label)
{
    public static ActivityProgress None { get; } = new(0, 0, "");
}

public sealed record ActivityEvent(
    long Id,                 // 1, 2, 3, ... per hub, never reused
    DateTimeOffset Time,     // TimeProvider.GetUtcNow() at the Event call
    ActivityKind Kind,
    string Summary,
    TimeSpan? Duration,
    string? Mailbox);        // null = not mailbox-specific / own mailbox; stored as given

public sealed class ActivityHub : IDisposable
{
    public const int EventCapacity = 500;
    public static readonly TimeSpan ChangedInterval = TimeSpan.FromMilliseconds(100);

    public ActivityHub(TimeProvider? timeProvider = null);   // null => TimeProvider.System

    public ActivityState State { get; }
    public ActivityProgress Progress { get; }

    /// Throws ArgumentNullException (label null),
    /// ArgumentOutOfRangeException (state undefined or Idle).
    public IDisposable Begin(ActivityState state, string label);

    /// Throws ArgumentOutOfRangeException when done < 0 or total < 0.
    public void Report(int done, int total);

    /// Throws ArgumentNullException (summary null),
    /// ArgumentOutOfRangeException (kind undefined).
    public void Event(ActivityKind kind, string summary, TimeSpan? duration = null, string? mailbox = null);

    /// Snapshot copy, oldest first. At most EventCapacity entries.
    public IReadOnlyList<ActivityEvent> GetEvents();

    public event Action? Changed;

    public void Dispose();
}
```

`Begin` returns a private nested `sealed class Scope : IDisposable`. Do not
make it public.

## Behavior

### State and scopes

- All mutable state is guarded by one private `lock` (`System.Threading.Lock`).
  Every public member is thread-safe. `Changed` is **never** invoked while
  that lock is held.
- Each `Begin` adds an active scope record with
  `(long seq, ActivityState state, string label, int done = 0, int total = 0)`.
  `seq` increases monotonically.
- `State` is the maximum `state` over the active scopes, or `Idle` when no
  scope is active. That is the precedence of SPEC §6.1 ("the highest one in
  this table wins"). Ref-counting falls out of this: two `Syncing` scopes
  keep the state `Syncing` until both are disposed.
- `Scope.Dispose()` removes its record. It is **idempotent**: a second
  dispose does nothing and does not raise `Changed`. Disposing a scope after
  the hub was disposed is allowed and does not throw.
- `Begin(ActivityState.Idle, …)` throws
  `ArgumentOutOfRangeException(nameof(state), "Idle is the absence of activity and cannot be begun.")`.
  Undefined enum values (`!Enum.IsDefined`) throw `ArgumentOutOfRangeException(nameof(state))`.
  A `null` label throws `ArgumentNullException(nameof(label))`. An empty
  label is allowed.

### Progress

- `Progress` belongs to the **winning scope**: among the active scopes whose
  state equals `State`, the one with the highest `seq`. It returns
  `new ActivityProgress(scope.done, scope.total, scope.label)`. With no
  active scope it returns `ActivityProgress.None`.
- `Report(done, total)` writes `done`/`total` into the active scope with the
  highest `seq` whose state is `Backfilling`, `Syncing` or `Purging` (the
  states that `SyncService` drives, §10). If there is no such scope it is a
  no-op and does not raise `Changed`. This makes a tool call (`Serving`) or
  an `AwaitingConfirmation` dialog that starts during a backfill unable to
  capture the backfill's progress.
- `done > total` is accepted and stored as given (totals can be estimates).
  Negative values throw `ArgumentOutOfRangeException` with the offending
  parameter name.
- Formatting tooltips (`Clippy — indexing Inbox 1,240 / 8,000 …`) is the
  tray's job (M4.3), not the hub's.

### Event ring buffer

- `Event(...)` appends `new ActivityEvent(++lastId, timeProvider.GetUtcNow(), kind, summary, duration, mailbox)`.
  Once there are `EventCapacity` (500) events, the oldest one is dropped
  (SPEC §7: "a ring buffer of 500 events").
- Use a fixed array with head/count indices, not a `List.RemoveAt(0)`.
- `GetEvents()` returns a new array copy, oldest first. Later `Event` calls
  must not change a list that was already returned.
- The hub does not inspect or truncate `summary`. Keeping bodies, search
  text and attachment content out of it (§6.4) is the caller's job.

### `Changed` throttle (at most 10 Hz)

Every mutation is a change: `Begin`, the first `Scope.Dispose`, a `Report`
that updated a scope, and `Event`. Raising is leading-edge plus
trailing-edge with a 100 ms window (`ChangedInterval`):

- Throttle time comes from `timeProvider.GetTimestamp()` /
  `GetElapsedTime(...)`, not from `GetUtcNow()`, so wall-clock jumps don't
  matter.
- The constructor creates one timer:
  `timeProvider.CreateTimer(OnTimer, null, Timeout.InfiniteTimeSpan, Timeout.InfiniteTimeSpan)`.
- On a change, under the lock:
  - If the timer is not armed and either nothing has fired yet or at least
    100 ms have passed since the last fire: record the fire time, release
    the lock, then raise `Changed` **synchronously on the calling thread**.
  - Otherwise: set `pending = true`. If the timer is not armed, arm it with
    `Change(lastFire + 100 ms - now, Timeout.InfiniteTimeSpan)` (clamped to
    `>= TimeSpan.Zero`).
- `OnTimer`: under the lock, disarm. If `pending`, clear it, record the fire
  time, release the lock and raise `Changed`.
- Result: a burst of changes produces one immediate `Changed` and exactly
  one trailing `Changed` at most 100 ms later, and the last change is
  always delivered. This meets the §17 "tray icon updates within 250 ms"
  target.
- Raising: take a snapshot of the delegate, then call each entry of
  `GetInvocationList()` in its own `try/catch`. Exceptions from a subscriber
  are swallowed so that they can never crash a timer thread, the COM worker
  or a Kestrel request, and later subscribers still run. Subscribers may
  call back into the hub (no lock is held). A change made from inside a
  handler falls into the throttle window and is delivered on the trailing
  edge.
- `Changed` carries no arguments. Handlers read `State`, `Progress` and
  `GetEvents()`.

### Dispose

- `ActivityHub.Dispose()` disposes the timer and sets a flag. Afterwards
  `Changed` is never raised again, including a pending trailing edge. Every
  other member keeps working and does not throw. `Dispose` is idempotent.

`tests/ClippysRevenge.Core.Tests/ActivityHubTests.cs`, namespace

**Test fake (private nested class).** `ManualTimeProvider : TimeProvider`
starts at `2026-01-01T00:00:00Z`. It overrides `GetUtcNow()`,

offset in ticks) and `CreateTimer(...)`, which returns a fake `ITimer` that
records `due`/`period`. `Advance(TimeSpan by)` moves time forward and
synchronously invokes, on the test thread, every armed timer whose due time
is `<= now`, in due order. A timer with an infinite period disarms after it
fires. Most tests use `var tp = new ManualTimeProvider(); using var hub = new ActivityHub(tp); int fired = 0; hub.Changed += () => fired++;`.

## Spec changes (proposed)

These are low-risk and reversible, and they don't change user-visible
behavior. Append them to SPEC §7 after the `event Action Changed` bullet:

> - `State` is the highest state (§6.1 order) among active `Begin` scopes,
>   or `Idle` when none. `Begin(Idle, …)` is rejected. Disposing a scope
>   twice has no effect.
> - `Progress` is that of the newest active scope in the winning state;
>   `(0, 0, "")` when idle. `Report(done, total)` updates the newest active
>   `Backfilling`, `Syncing` or `Purging` scope and is a no-op when there is
>   none, so a tool call or invite dialog never captures sync progress.
> - Events carry an increasing `Id` and a UTC `Time`; `GetEvents()` returns
>   a snapshot, oldest first.
> - `Changed` is throttled leading + trailing edge over a 100 ms window: the
>   first change fires at once on the caller's thread, later ones within the
>   window coalesce into one call at the window's end (timer thread), so the
>   final state is always delivered. Subscriber exceptions are swallowed.
> - The hub takes a `TimeProvider` (default `TimeProvider.System`) for
>   testability.
