# M15.2 Category and tracking: `Clippy draft invite`, `DraftInvitesStore`, `DraftInvites.CheckAsync`

Base: `dev` after M15.1 (`docs/briefs/M15.1.md`). This brief is written
against M15.1's seam: `IMeetingCalendar.CreateAsync(request, ct)` →
`CreatedMeeting(EntryId, StoreId)`, `MeetingDraftResult.Category`
(always written, null until now), `MeetingInvites(calendar, settings, hub,
timeZone, time?)`, `OutlookCalendar.CreateMeeting(app, req)` that calls
`.Save()` once and reads the ids afterwards. If M15.1 landed with
different names, adapt the names, not the behavior. M15.3 (`reply_to_id`,
note) runs in parallel and also edits `MeetingInvites.cs`; keep the

## Goal

Every meeting `create_meeting_draft` saves gets the `Clippy draft invite`
category (added once, orange, to the own master category list when
missing) and is tracked in `%APPDATA%\ClippysRevenge\draft-invites.json`.
A check (`DraftInvites.CheckAsync`) reads the tracked meetings in one COM
work item (at most 50), keeps the unsent ones, and for the ones the user
has sent (or turned into a plain appointment, or cancelled) removes
**only** Clippy's category with a Categories-only `.Save()` (skipped while
the meeting is open in an Inspector), then stops tracking them. Deleted or
vanished meetings are dropped without any COM write; unsent meetings that
ended more than 30 days ago are dropped and keep their category. The check
runs after sync cycles (at most every 5 minutes, `Background`) and on
demand; `create_meeting_draft` adds an entry without a COM read. The class
exposes the pending list and a `Changed` event for the tray list (M15.4)
and the badge (M15.5).

SPEC refs: §22.2 (all), §22.3 (Store, Check, When; not the tray item),
§22.1 (`category` in the result, "added to the tracking list"), §22.6
(count source: "every tracked entry not yet found sent, deleted or
expired"; last count kept while Outlook is unavailable), §22.7 (`DraftInvites`
check, `Categories` helpers, `DraftInvitesStore` bullets), §8 `CreateMeeting`
"From M15" paragraph, §5 data-file table (`draft-invites.json`), §3
(`DraftInvites.cs`), §18 decision of 2026-11-14.

## Hard rules that apply here

- **Never send anything.** No `.Send(` (M15.1's scan stays). The only
  writes to Outlook in this task are `item.Categories = …` followed by
  `item.Save()` on a meeting Clippy created (at creation, and once more to
  remove its own category), and `Categories.Add(…)` on the master list
  when the name is missing.
- **Never delete or move.** No `Delete`, `PermanentDelete`, `Move`,
  `Close(olSave)`, no removal from the master category list, no colour
  change of an existing category. Dropping an entry from
  `draft-invites.json` is Clippy's own file, not mail.
- **Never launch Outlook.** No new COM entry point; everything runs on
  `OutlookWorker`. Background checks only start while the worker state is
  `Available`.
- **No `.Display(`** (M15.4 adds the one allowed call). `NoDisplayCalls`
  stays as it is.
- Logs carry no subjects, entry ids, store ids or category strings of the
  user: exception **type** and the decision reason only.

## Behavior

### §A `DraftInviteCategories`

- `Split`: separators = `listSeparator.Trim()` (when not null/blank), `","`
  and `";"`. Split on any of them, trim each part, drop empty parts. Order
  kept.
- `TryRemove(categories, name, sep, out result)`:
  - `Split`; if no part equals `name` (`OrdinalIgnoreCase`, after trimming
    `name`) → `result = categories ?? ""`, return false.
  - Else keep the non-matching parts in order. Joiner = the separator (of
    the set above) whose first occurrence in `categories` has the lowest
    index, followed by one space; if `categories` contains none (single
    entry), the joiner is `", "` (irrelevant: at most one part is kept).
    `result = string.Join(joiner, kept)`; `""` when nothing is kept. Return
    true.
  - Why the detected separator and not always `", "`: Outlook parses
    `Categories` with the Windows list separator. On a locale whose
    separator is `;`, writing `A, B` could turn the user's two categories
    into one called `A, B`. Re-using the separator Outlook itself produced
    always round-trips. On English systems this is `", "` exactly as §22.2
    says. (Spec change 1.)
- Matching is whole-entry only: `Clippy draft invites` or
  `My Clippy draft invite` are not removed.

### §B `DraftInvitesStore`

- JSON: an array of objects with exactly `entryId`, `storeId`, `mailbox`,
  `createdUtc` (ISO 8601 with offset, as `System.Text.Json` writes
  `DateTimeOffset`). No subject, times or recipients (§22.3). Indented.
  Unknown properties are ignored when reading.
- Load validation per entry (skip the entry, no log per entry): `entryId`
  null/blank or longer than `MaxEntryIdLength`; `storeId` longer than
  `MaxStoreIdLength` (null → `""`); `createdUtc` missing (`default`).
  `entryId` and `storeId` are trimmed; `mailbox` →
  `MailboxIndexes.Normalize` (null → `""`). A JSON `null` element is
  skipped.
- File failures (exists but unreadable, larger than `MaxFileBytes`, invalid
  JSON, top-level not an array): return empty and log one Warning
  `draft-invites.json could not be read ({Type}); starting with an empty list.`
  with `{Type}` = the exception type name or `TooLarge`/`NotAnArray`. The
  file is not renamed; the next `Save` replaces it (§22.3).
- `Save`: dedupe and cap like `Load` (newest 200 by `CreatedUtc`), sort
  ascending, write atomically. Exceptions propagate (DraftInvites catches).

### §C `DraftInvites.Decide(s, nowLocal, sep)` (pure; the order matters)

1. `Lookup == NotFound` → `Drop`, `NotFound`.
2. `Lookup == Unreadable` → `Keep`, `Unreadable`.
3. `InDeletedItems` → `Drop`, `Deleted` (no write, even if sent).
4. "No longer an unsent draft" when `Invited == true` **or**
   `MeetingStatus != 1` (olMeeting). Reason: `Sent` if `Invited == true`;
   else `Cancelled` if `MeetingStatus` is 5 or 7; else `NotAMeeting`.
   Then:
   - `!TryRemove(s.Categories, CategoryName, sep, out var next)` →
     `Drop`, `CategoryGone` (the user removed it; nothing is written).
   - `OpenInInspector` → `Keep`, `OpenInInspector` (retry next check).
   - else `RemoveCategory` with that reason and `NewCategories = next`.
5. Unsent (`Invited` false or null and `MeetingStatus == 1`): if
   `s.Details` is not null and `s.Details.End < nowLocal - ExpireAfterEnd`
   (strictly more than 30 days) → `Drop`, `Expired` (category stays).
6. Otherwise → `Keep`, `Unsent`.

### §D `DraftInvites` (tracking, check, triggers)

State (all under one `Lock`): the tracked list (from `store.Load()` in the
constructor), `Details` per entry id (memory only), last-checked time per
entry id (memory only), the in-flight check task, the last check start
time, `LastCheckUtc`. Entry ids compare `OrdinalIgnoreCase` everywhere.

**Track(entry, details)**: blank `EntryId` → Warning
`A created meeting draft has no entry id; it is not tracked.` and return.
Normalize (trim ids, `MailboxIndexes.Normalize(mailbox)`). If already
tracked: keep the stored entry (its `CreatedUtc`), replace `Details` when
the new one is not null. Else add; when the count exceeds 200 drop the
oldest by `CreatedUtc` (and their memory state). Persist (§ Persist),
raise `Changed`. Never throws.

**Forget(entryId)**: remove if present, persist, raise `Changed`, return
true; else false.

**Persist**: `store.Save(list)` inside the lock; `IOException` /
`UnauthorizedAccessException` → Warning
`draft-invites.json could not be saved ({Type}).`; the in-memory list stays
authoritative and the next change tries again.

**CheckAsync(priority, ct)**:

1. If nothing is tracked or `!outlookAvailable()` → return `Pending` (no
   COM, `LastCheckUtc` unchanged).
2. Single flight: if a check is running, await it
   (`.WaitAsync(ct)`) and return `Pending`. Otherwise start one (below)
   with `CancellationToken.None`, record its start time
   (`time.GetUtcNow()`), and await it the same way. The priority of a
   joining caller is ignored.
3. The check: pick the batch under the lock: at most `MaxPerCheck`
   entries ordered by last-checked time (never checked first), then
   `CreatedUtc` ascending. So with 60 entries the first check takes the 50
   oldest and the next one starts with the 10 that weren't checked (§22.3
   "oldest first … the rest next time").
4. `nowLocal = TimeZoneInfo.ConvertTime(time.GetUtcNow(), timeZone).DateTime`;
   call `calendar.CheckAsync(batch, s => Decide(s, nowLocal, sep), priority, CancellationToken.None)`.
5. Exceptions: `OutlookUnavailableException` (incl. not responding) →
   Information log `Draft invite check stopped: Outlook is not available.`;
   any other exception → Warning `Draft invite check failed ({Type}).`. In
   both cases the tracked list, the file, `Details` and `LastCheckUtc` stay
   unchanged and no `Changed` is raised (§22.3 step 5).
6. Apply outcomes under the lock, matching by entry id; outcomes for
   entries no longer tracked (forgotten meanwhile) are ignored, entries
   tracked meanwhile are untouched:
   - `Drop` → remove.
   - `RemoveCategory` with `Applied` → remove. Without `Applied` (the write
     failed) → keep.
   - `Keep` → keep.
   - Every outcome: set last-checked = now; when `Details` is not null,
     store it.
   - Log per removed entry at Information:
     `Draft invite no longer tracked ({Reason}).` and for an applied
     removal `Draft invite sent; Clippy's category was removed ({Reason}).`
     (reason enum name only).
7. Persist if anything was removed; set `LastCheckUtc = now`; raise
   `Changed` if anything was removed or any `Details` value changed
   (record equality).
8. Clear the in-flight slot in a `finally`.

**OnSyncCycleCompleted()**: returns null unless all hold: something is
tracked, `outlookAvailable()`, no check in flight, and the last check
start (any priority) is null or at least `MinBackgroundInterval` before
now. Then starts `CheckAsync(WorkPriority.Background)` and returns that
task (its result is ignored by the hook; exceptions cannot escape, see
step 5). It never waits.

### §F `CreateMeeting(app, req, log)` (App)

Right before M15.1's single `item.Save()`, inside the same inner `try`:

```csharp
EnsureDraftCategory(app, log);                 // master list; never throws unless Outlook is gone
var categorized = TrySetDraftCategory(item, log);
item.Save();
```

and return `new CreatedMeeting(entryId, storeId, categorized)`.

- `EnsureDraftCategory`: a `private static volatile bool s_draftCategoryKnown`;
  return at once when true. Else `session = app.Session`,
  `cats = session.Categories`; for `i = 1..cats.Count`: `c = cats[i]`,
  compare `c.Name` with `DraftInvites.CategoryName` `OrdinalIgnoreCase`,
  release `c` in the loop. When none matched:
  `cats.Add(DraftInvites.CategoryName, Outlook.OlCategoryColor.olCategoryColorOrange)`
  and release the returned `Category`. Set the flag after "found" or
  "added". A found category is never touched (no `Color` set, no rename).
  `COMException` that is not `IsOutlookGone`, or
  `UnauthorizedAccessException` → Warning
  `Adding the draft-invite category to the master category list failed ({Type}).`;
  the flag stays false (next create tries again). Release `cats` and
  `session` in `finally`. The own mailbox's list is used for shared-mailbox
  calendars too (§22.2).
- `TrySetDraftCategory(item, log)`: `item.Categories = DraftInvites.CategoryName;`
  (a new item has no categories) → true. Non-gone `COMException` → Warning
  `Setting the draft-invite category failed ({Type}).`, return false; the
  meeting is still saved (§22.2: `category: null`).
- Both helpers let an Outlook-gone `COMException` propagate (the worker
  turns it into `OutlookUnavailableException`); since `IsAccessFailure`
  excludes gone errors, a category failure is never reported as "no
  calendar rights".
- Order matters: the master entry first, so Outlook shows the item's
  category in orange from the start.

### §G `CheckDraftInvites(app, entries, decide, log)` (App)

One worker call; all COM objects released in `finally` blocks, the loop's
per-entry objects inside the loop.

1. `ns = app.Session`. Build the set of open-Inspector entry ids once:
   `insps = app.Inspectors`; for `i = 1..insps.Count`: `insp = insps[i]`,
   `cur = insp.CurrentItem`; if `cur is Outlook.AppointmentItem a`, add
   `a.EntryID` when not blank (read via `ComSafe.Try`; a new unsaved item
   has none); release `cur` and `insp` in the loop; release `insps`.
2. Shared calendars: for an entry with `Mailbox.Length > 0`, open that
   mailbox's calendar once per call before the first lookup
   (`CreateRecipient(mailbox)`, `Resolve()`,
   `GetSharedDefaultFolder(owner, olFolderCalendar)`), cache the folder per
   mailbox for this call, release owner and folders at the end. This makes
   sure the shared store is open in the session after an Outlook restart.
   A non-gone `COMException` / `UnauthorizedAccessException` opening it →
   every entry of that mailbox is `Unreadable` this time (kept). If the
   entry's `StoreId` is `""`, use that folder's `StoreID`.
3. Per entry: `obj = ns.GetItemFromID(entryId, storeId.Length > 0 ? storeId : Type.Missing)`.
   - `ComErrors.IsItemNotFound(ex)` → snapshot `NotFound`.
   - Other non-gone `COMException` → `Unreadable`.
   - `obj` not an `Outlook.AppointmentItem` → `NotFound` (release `obj`).
4. Found: read, each read guarded:
   - In Deleted Items: `parent = item.Parent as Outlook.MAPIFolder`,
     `store = parent.Store`, `del = store.GetDefaultFolder(olFolderDeletedItems)`;
     true when `parent.EntryID` equals `del.EntryID` (OrdinalIgnoreCase) or
     `parent.FolderPath` starts with `del.FolderPath + "\\"`
     (OrdinalIgnoreCase). Any non-gone `COMException` here → false (a
     shared mailbox may not expose its Deleted Items). Release `del`,
     `store`, `parent`.
   - `MeetingStatus` (`(int)item.MeetingStatus`) and `Categories`
     (`item.Categories ?? ""`): a non-gone `COMException` on either →
     snapshot `Unreadable` (never decide "category gone" from a failed
     read).
   - `Invited`: `pa = item.PropertyAccessor`,
     `ComSafe.Try(() => pa.GetProperty(DraftInvites.FInvitedProperty))`; `bool b`
     → `b`, anything else (missing property, null) → `null`. Release `pa`.
   - `Details`: `Subject ?? ""`, `Start`, `End` (local), each `DateTime`
     with `DateTimeKind.Unspecified`; a failed read → `Details = null`.
   - `OpenInInspector`: the item's `EntryID` is in the set from step 1.
5. `d = decide(snapshot)`. For `RemoveCategory`:
   `item.Categories = d.NewCategories!; item.Save();` → `Applied = true`.
   A non-gone `COMException` → Warning
   `Removing the draft-invite category failed ({Type}); retrying next check.`,
   `Applied = false`. Nothing else is assigned on the item, and `Save()` is
   the only method called on it. Never `Close`, `Display`, `Send`, `Move`,
   `Delete`.
6. Outcome `(entry, d, snapshot.Details, applied)`. Release `item`.
7. Outlook-gone exceptions propagate at any point (the worker turns them
   into `OutlookUnavailableException`; DraftInvites keeps the store
   unchanged). A category written before that is harmless: the next check
   sees "sent, category gone" and drops the entry without a write.

## Spec changes

None made by this brief (the caller owns `SPEC.md` for this run).
Proposed low-risk choices, to be recorded in §22.2/§22.3 by the caller:

1. **Re-join separator** (§22.2): the kept categories are joined with the
   first separator found in the original value plus a space, which is
   `, ` on English systems. Always writing `, ` could merge two of the
   user's categories into one on locales whose list separator is `;`.
2. **"Not found"** (§22.3 step 1) = `GetItemFromID` fails with
   `MAPI_E_NOT_FOUND`/`MAPI_E_INVALID_ENTRYID` or returns something that
   isn't an `AppointmentItem`. Any other COM error, or a failed read of
   `MeetingStatus`/`Categories`, keeps the entry unchanged until the next
   check (no write, still counted). That way a network hiccup doesn't drop
   an entry, and a failed read never counts as "category gone".
3. **Shared calendars**: before the lookup, the check opens that mailbox's
   calendar with `GetSharedDefaultFolder`, so the store is open after an
   Outlook restart. If that fails, the mailbox's entries are kept for the
   next check.
4. **Status rule**: any `MeetingStatus` other than `olMeeting` counts as
   "no longer a draft". 0 is `NotAMeeting`, 5 and 7 are `Cancelled`, other
   values are `NotAMeeting`. `FInvited` true always means `Sent`. The
   30-day expiry applies only to unsent meetings.
5. **Master list check**: once per process, after the category is found or
   added. If the user deletes it from the master list while Clippy runs,
   it's added again only after a restart.
6. **Scheduling**:
   - The 5-minute limit counts from the start of the last check of any
     priority.
   - Background checks start only while the worker state is `Available`.
   - A check requested while one is running joins it.
   - Rotation for more than 50 entries is least-recently-checked first,
     then oldest `createdUtc`.
7. **Ids**: a created meeting whose `EntryID` couldn't be read isn't
   tracked (Warning). An empty `StoreID` looks the item up in the default
   store.
8. **Store limits**: 1 MiB file, entry id ≤ 1024 and store id ≤ 4096
   characters. Invalid entries are skipped and duplicates by entry id are
   merged.
9. **Details** (subject, start, end) are kept in memory only, never on
   disk. After a restart, tray lines have no details until the first
   check.
