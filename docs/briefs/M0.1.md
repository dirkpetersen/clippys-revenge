# M0.1 Scaffold: solution, three projects, packages, placeholder test

## Goal

Create `ClippysRevenge.slnx` with the three projects from SPEC §3
(`src/ClippysRevenge.Core`, `src/ClippysRevenge.App`,
`tests/ClippysRevenge.Core.Tests`) and the package references from SPEC §2,
plus one placeholder test. `dotnet build -c Release` and
`dotnet test -c Release --filter "live!=outlook"` must pass with zero
warnings on Windows. Core and its tests must build and run on Linux (§15,
§16). The single-file publish must produce `publish/ClippysRevenge.exe`,
because `.github/workflows/ci.yml` and `release.yml` expect that name (§2, §16).
No features yet.

The architect built this exact layout in a scratch directory with SDK
10.0.404: build had 0 warnings, the filtered test run passed (a
`live=outlook` test was correctly excluded), the publish produced
`ClippysRevenge.exe` with no interop DLL next to it, and the exe ran and
exited 0.

## Spec changes (already applied to SPEC.md by the architect)

- §2 Outlook row: `Microsoft.Office.Interop.Outlook` **15.0.4797.1004**
  from NuGet (its `lib/netstandard2.0` asset, so there is no NU1701). It is a
  NuGet package, not a `COMReference`, because CI runners have no Office.
  Interop types are embedded (`EmbedInteropTypes`) and the DLL is not shipped.
- §2 Database row: `Microsoft.Data.Sqlite` stays on the 10.0.x line to
  match .NET 10 LTS (11.0.0 exists but goes with .NET 11).
- §2 Secrets row: `ProtectedData` comes from the Windows Desktop shared
  framework, so it needs no package.
- §2 Tests row: xUnit v3 through `xunit.v3.mtp-off` + `xunit.runner.visualstudio`
  under VSTest. The plain `xunit.v3` 4.x package pulls in Microsoft Testing
  Platform v2. On the .NET 10 SDK that fails in VSTest `dotnet test` with
  "Testing with VSTest target is no longer supported…", and it would
  force CI and CLAUDE.md to switch from `--filter "live!=outlook"` /
  `--logger trx` to MTP syntax. I chose v3 over v2 because v2 is
  maintenance-only.
- §18 Decided: no central package management (each package is used by
  exactly one project, so `Directory.Packages.props` would add a file and
  save nothing). Core has `FrameworkReference Microsoft.AspNetCore.App`
  because `BearerAuth` (§3, §13) is ASP.NET Core middleware. That shared
  framework is cross-platform and ships with the SDK that
  `actions/setup-dotnet` installs, so Core still builds and tests on Linux.

## Files

Create exactly these files. Do not change `Directory.Build.props`,
`.gitignore` or the workflows. `.gitignore` already covers `bin/`, `obj/`,
`publish/`, `*.exe` and `TestResults`.

### `ClippysRevenge.slnx` (repo root)

Create it with `dotnet new sln -n ClippysRevenge` (the .NET 10 SDK writes
`.slnx`), then
`dotnet sln ClippysRevenge.slnx add src/ClippysRevenge.Core src/ClippysRevenge.App tests/ClippysRevenge.Core.Tests`.
The expected content (folder entries generated by the CLI are fine):

```xml
<Solution>
  <Folder Name="/src/">
    <Project Path="src/ClippysRevenge.App/ClippysRevenge.App.csproj" />
    <Project Path="src/ClippysRevenge.Core/ClippysRevenge.Core.csproj" />
  </Folder>
  <Folder Name="/tests/">
    <Project Path="tests/ClippysRevenge.Core.Tests/ClippysRevenge.Core.Tests.csproj" />
  </Folder>
</Solution>
```

There must be no other `*.sln`/`*.slnx` in the root. The workflows' `detect`
step keys off this file, and a bare `dotnet build`/`dotnet test` needs
exactly one solution.

### `src/ClippysRevenge.Core/ClippysRevenge.Core.csproj`

There are no source files in M0.1. Do not add a placeholder class, because
the test loads the assembly by name. Never add `-windows` TFMs,
`UseWindowsForms`, COM references or the Outlook interop package to Core.

### `src/ClippysRevenge.App/ClippysRevenge.App.csproj`

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>WinExe</OutputType>
    <TargetFramework>net10.0-windows</TargetFramework>
    <UseWindowsForms>true</UseWindowsForms>
    <AssemblyName>ClippysRevenge</AssemblyName>
    <RootNamespace>ClippysRevenge.App</RootNamespace>
  </PropertyGroup>
  <ItemGroup>
    <FrameworkReference Include="Microsoft.AspNetCore.App" />
  </ItemGroup>
  <ItemGroup>
    <PackageReference Include="ModelContextProtocol.AspNetCore" Version="2.4.0" />
    <!-- Compile-time only: types are embedded (target below), DLL not shipped. -->
    <PackageReference Include="Microsoft.Office.Interop.Outlook" Version="15.0.4797.1004" ExcludeAssets="runtime" />
  </ItemGroup>
  <ItemGroup>
    <ProjectReference Include="..\ClippysRevenge.Core\ClippysRevenge.Core.csproj" />
  </ItemGroup>
  <!-- PackageReference can't set EmbedInteropTypes directly. -->
  <Target Name="EmbedOutlookInteropTypes" AfterTargets="ResolveAssemblyReferences">
    <ItemGroup>
      <ReferencePath Condition="'%(FileName)' == 'Microsoft.Office.Interop.Outlook'">
        <EmbedInteropTypes>true</EmbedInteropTypes>
      </ReferencePath>
    </ItemGroup>
  </Target>
</Project>
```

`AssemblyName` must be `ClippysRevenge` so that the publish output is
`ClippysRevenge.exe`. Do not add `RuntimeIdentifier`, `PublishSingleFile`,
`SelfContained`, trimming or an `ApplicationIcon` to the csproj. The
publish flags come from the command line (§2), and icons belong to M4.3.

## Behavior

- Every project inherits `Nullable`, `ImplicitUsings`,
  `TreatWarningsAsErrors` and `Version` from the root
  `Directory.Build.props`. Don't repeat or override them in a csproj.
- Pin exact versions only, with no floating `*` or ranges: Dapper 2.1.89,
  Microsoft.Data.Sqlite 10.0.15, ModelContextProtocol.AspNetCore 2.4.0,
  Microsoft.Office.Interop.Outlook 15.0.4797.1004, Microsoft.NET.Test.Sdk
  18.12.0, xunit.v3.mtp-off 4.0.3, xunit.runner.visualstudio 4.0.1.
- Restore and build must produce zero warnings. Don't suppress warnings
  with `NoWarn` to get there. If a warning shows up, stop and report it.
- Outlook interop is compile-time only and embedded. After
  `dotnet build -c Release`, `Microsoft.Office.Interop.Outlook.dll` must
  **not** be in `src/ClippysRevenge.App/bin/Release/net10.0-windows/`, and
  the publish folder must not contain it either.
- Logging (§2 "rolling file") needs no package in M0.1. The file provider
  is chosen when M4 needs it.

## Tests

`tests/ClippysRevenge.Core.Tests/ScaffoldTests.cs`, namespace
`ClippysRevenge.Core.Tests`. These are cross-platform, so they get no `os`
trait.

1. `CoreAssembly_LoadsAndSharesProductVersion`
   - `var core = Assembly.Load(new AssemblyName("ClippysRevenge.Core"));`
   - Expect `core.GetName().Version` to equal
     `typeof(ScaffoldTests).Assembly.GetName().Version`. Both come from
     `Directory.Build.props`. Do **not** hardcode `0.0.1`, because the test
     must survive version bumps.
2. `CoreAssembly_HasNoWindowsOrComReferences`
   - Load the same assembly and get `core.GetReferencedAssemblies()`.
   - Expect none of the reference names to equal or start with
     `System.Windows.Forms`, `Microsoft.Office.Interop`,
     `Microsoft.Win32.Registry`, `System.Security.Cryptography.ProtectedData`
     or `Microsoft.WindowsDesktop`. Use `Assert.DoesNotContain` with a
     predicate. This guards SPEC §3 ("Core: no Windows, no COM") as Core
     grows.

Don't add a `[Trait("live","outlook")]` test in M0.1. (The architect checked
that the filter excludes such tests.)

## Done when

Run from the repo root on Windows:

```bash
dotnet build -c Release                                   # 0 Warning(s), 0 Error(s)
dotnet test -c Release --no-build --filter "live!=outlook" # 2 passed, 0 failed
dotnet test tests/ClippysRevenge.Core.Tests -c Release --filter "live!=outlook" --logger trx --results-directory TestResults
dotnet publish src/ClippysRevenge.App -c Release -r win-x64 --self-contained \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
test -f publish/ClippysRevenge.exe
test ! -e publish/Microsoft.Office.Interop.Outlook.dll
test ! -e src/ClippysRevenge.App/bin/Release/net10.0-windows/Microsoft.Office.Interop.Outlook.dll
./publish/ClippysRevenge.exe; echo $?                     # prints 0
```

If WSL with the .NET 10 SDK is available, also run
`dotnet test tests/ClippysRevenge.Core.Tests -c Release --filter "live!=outlook"`
there. Otherwise the `core-tests-linux` CI job is the Linux check. Delete
`publish/` and `TestResults/` afterwards. Both are gitignored.
