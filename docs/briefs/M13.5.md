## Goal

Every `SKILL.md` Clippy writes ends with a fixed, Clippy-owned "Offering
meeting times" section between version markers (§21.7), so interactive
Claude Code knows to call `find_free_times` and paste `offer_text`. The
frontmatter description mentions meeting times (§19.6). The style call
gets an optional `meeting_phrasing` field that fills the section's "How
<name> offers times" part, with a fixed default. Existing unedited skills
(pre-M13, or an older section version) get the current section without a
model call (`RefreshMeetingSection`), at app start and at the start of
every `RunIfDueAsync`. Edited skills are never touched. The drafting
prompt reader drops the marker block, because the drafting model has its
own meeting rules (§21.6) and no tools.

SPEC refs: §19.6 (file layout, description, schema note, "Use in
drafting"), §21.7 (all of it), §21.9 (style-skill tests), §19.10 (View
and Regenerate show/keep the section; no UI change), §19.11 (logs/events
carry no skill text), §18 decision of 2026-11-14 (meeting times), §22.5
(the v2 section M15.3 adds later; design for it, don't implement it).

Everything except one line in `Program.cs` is Core and runs on Linux.

## Hard rules that apply here

- **No credentials (§1.10).** The only file under `~/.claude` read or
  written is still `skills/my-email-style/SKILL.md`.
- **The model gets no tools; its output only becomes skill text.**
  `meeting_phrasing` is validated (below) and only ever lands inside the
  marker block of `SKILL.md`. The section itself is fixed text, never
  model-written. The refresh makes **no model call**.
- **Never overwrite the user's edits.** The refresh writes only when the
  user file is *not edited* (`IsEdited()` false), re-checks right before
  writing, and never adds the section to an edited file.
- **Privacy (§19.11).** Logs and events never contain the display name,
  the phrasing, the body or any file text. Only the fixed texts below and
  exception type names.
- **No COM, no `.Send(`/`.Display(`/Outlook `.Move(`/`Delete(`.** File
  replacement stays the existing `WriteAtomic` (`File.Move` / `File.Delete`
  written literally). Don't add a second writer: the refresh calls the
  existing `StyleSkillFiles.Write`.
- **PathPolicy** doesn't apply (fixed app paths, §19.6); no path comes
  from a tool, the model or mail.

## Behavior

### A. Rendering (`Render`, `MeetingSection`)

`Render(displayName, date, n, body, meetingPhrasing)` returns exactly
(`\n` endings, `<N>` = `displayName` as-is, `<b>` = `body.TrimEnd()`):

```
---
name: my-email-style
description: "<N>'s email writing style: greetings, sign-offs, tone, length and phrasing by audience, and how to offer meeting times. Use when drafting or replying to email as <N>."
---
<!-- Generated by Clippy's Revenge on <yyyy-MM-dd> from <n> sent emails. You can edit this file; Clippy won't replace your edits without asking. -->

<b>

<MeetingSection(N, meetingPhrasing)>
```

As a string: `header + (b.Length > 0 ? b + "\n\n" : "") + MeetingSection(N, meetingPhrasing)`,
where `header` is the existing frontmatter + comment + `"\n\n"` with the
new description. So the file is `…<b>\n\n<!-- clippy:meeting-times v1 -->\n…\n<!-- /clippy:meeting-times -->\n`
and always ends with `MeetingEndMarker + "\n"`. An empty body (possible
only from the refresh) gives the header directly followed by the section.

`MeetingSection(name, phrasing)` returns exactly this text (copied from
§21.7; `\n` endings; **ends with `\n`** after the end marker; the code
block is indented by two spaces; the times use U+2013 `–`; `<name>` is
`name`, `<phrasing>` is `CleanMeetingPhrasing(phrasing)`):

~~~~
<!-- clippy:meeting-times v1 -->
## Offering meeting times

This section is written by Clippy's Revenge and replaced when the skill is regenerated.

When an email asks for or suggests a meeting or a call and <name> wants to meet, offer concrete times in the reply:

- Never make up times or guess <name>'s availability. Get them from the Clippy's Revenge MCP server: call `find_free_times` with the people who should attend (the sender, plus the others on the email when they are invited too), `duration_minutes` from the email (60 when it doesn't say), and `offer_cet: true` when the person you are writing to is in Europe.
- Paste the tool's `offer_text` unchanged, one option per line, so <name> can delete the lines that don't suit:

  ```
  1. Tue 11/18  10:00–11:00 PT  (19:00–20:00 CET)
  2. Wed 11/19  14:00–15:00 PT  (23:00–00:00 CET)
  ```

- The options are already ranked: times right before or after <name>'s meetings come first, then times next to tentative meetings, then the rest, each group in date order. Don't reorder them.
- For someone in Europe, each option also shows the time in CET (always labelled CET, also in summer). Options between 08:00 and 18:00 CET come first. If there aren't enough, the others follow in a second list headed "Outside European office hours:"; translate that heading into the language of the reply.
- If `find_free_times` finds no time or isn't available, write that <name> will suggest times, and list none.
- Don't book a meeting or create an invite unless <name> asks.

### How <name> offers times

<phrasing>
<!-- /clippy:meeting-times -->
~~~~

Implementation rules:
- Build the text by concatenating fixed pieces with `name` and the
  phrasing. **Don't** fill a template with sequential `string.Replace`
  calls: a name containing `<phrasing>` (or a phrasing containing
  `<name>`) must stay literal.
- The first line is `MeetingStartMarker`, the last is `MeetingEndMarker`
  (use the constants, so M15.3 changes the version in one place).
- **Design for v2 (M15.3, §22.5).** M15.3 will change
  `MeetingStartMarker` to `v2` and replace the last bullet with the
  `create_meeting_draft` bullet. Keep each bullet a separate piece (e.g.
  a private `string[]` of bullet lines joined with `"\n"`), so that's a
  two-line change. Nothing else in this brief may depend on the number
  `1`: refresh, removal and phrasing extraction work for any version.

`GenerateCoreAsync` (§19.6 generation): after `ParseBody` succeeds, take
`phrasing = StyleSkillText.ReadMeetingPhrasing(ok.Output)` and pass it as
`Render(..., body, phrasing)`. An invalid or missing phrasing never fails
the run (it becomes the default inside `MeetingSection`). Regenerate
therefore always writes the current section (§21.7).

### B. `meeting_phrasing` validation (`CleanMeetingPhrasing`)

`raw` null → default. Otherwise, in this order:
1. Every `char.IsControl` char (CR, LF, tab included) → a space.
2. Collapse whitespace runs (`char.IsWhiteSpace`) to one space; `Trim()`.
3. `MailText.Redact`.
4. Remove `<!--` and `-->`, **repeating until neither occurs** (one
   `Replace` pass can create a new one: `<<!--!--` → `<!--`).
5. Collapse whitespace and `Trim()` again (step 4 can leave double or
   edge spaces; see "Spec clarifications" #2).
6. Length `1..MaxMeetingPhrasingChars` (600) → the result; else (empty or
   longer) → `DefaultMeetingPhrasing`. Never truncate.

Catch everything; an exception → default. The function is idempotent on
its own output (tests check this).

`ReadMeetingPhrasing(output)`: object with a `meeting_phrasing` string →
that string (uncleaned); anything else → null. Never throws (`default`
`JsonElement` → null).

### C. Removing blocks (`RemoveMeetingSections`) and the prompt reader

Line-based on `text` with CRLF/CR normalized to `\n`:
- A **start line** is one whose `Trim()` starts with `MeetingMarkerPrefix`
  (ordinal). (`<!-- /clippy…` doesn't match: the char after `<!-- ` is `/`.)
- An **end line** is one whose `Trim()` equals `MeetingEndMarker`.
- Walk the lines. At a start line, find the next end line after it. If
  there is one, drop every line from the start line through the end line
  and continue after it. If there isn't, stop removing (keep the start
  line and everything after it). A second start line inside a block is
  just part of the block.
- Join with `\n` and `Trim()`.

`StyleSkillFiles.ReadBodyForPrompt()`: for the chosen file (same source
rules as now), `body = RemoveMeetingSections(StripHeader(text))`; empty →
`NoStyleGuideLine`. A user file whose body is only the section therefore
gives the "No style guide yet" line (no fall-through, as before).
`ReadSkillText()` (Settings → View) is **unchanged**: it shows the whole
file, section included.

### D. Reading an existing file (`NameFromDescription`, `PhrasingFromSection`)

`NameFromDescription(fileText)`: normalize line endings. Look only inside
a leading frontmatter block (first line `---` trimmed at the end, up to
the next line that trims to `---`; BOM stripped as in `StripHeader`).
Take the first line there that starts with `description: "` (ordinal).
`name` = the text after `description: "` up to the **first**
`'s email writing style` (ordinal). Not found (no frontmatter, no line,
no suffix) → `"the user"`. Return `CleanDisplayName(name)` (which also
turns a blank result into `the user`). This works for both the pre-M13
and the new description.

`PhrasingFromSection(fileText)`: find the first **complete** block (§C
rules). Inside it, the first line whose `Trim()` starts with `### How `
and ends with ` offers times`. The phrasing is the lines after that
heading up to (not including) the end line, joined with `" "`. No
complete block or no heading → null. Blank → null. The caller passes it
through `CleanMeetingPhrasing` (via `Render`), so a pre-M13 file or an
odd old block gives the default.

### E. Refresh (`StyleSkillFiles.RefreshMeetingSection(zone)`)

1. `user = ReadUsable(UserSkillFile)`, `app = ReadUsable(AppCopyFile)`.
   Either null (missing, a directory, > 64 KiB, unreadable) →
   `NotApplicable`.
2. `IsEdited()` → `NotApplicable`. (No state, a bad state or a hash
   mismatch all count as edited, §19.6.)
3. `state = ReadState()`; null → `NotApplicable` (defensive).
4. `user.Contains(MeetingStartMarker, StringComparison.Ordinal)` →
   `AlreadyCurrent`. (Spec says "contain `<!-- clippy:meeting-times v1`";
   checking the whole marker line is equivalent for every file Clippy
   writes and can't mistake a future `v10` for `v1`; see "Spec
   clarifications" #1.)
5. From the **app copy** text: `name = NameFromDescription(app)`,
   `phrasing = PhrasingFromSection(app)`,
   `body = RemoveMeetingSections(StripHeader(app))`,
   `date = DateOnly.FromDateTime(TimeZoneInfo.ConvertTime(state.GeneratedUtc, zone).DateTime)`.
6. `text = Render(name, date, state.SampleCount, body, phrasing)`. If its
   UTF-8 byte count is over `MaxReadBytes` → `NotApplicable` (writing it
   would make both files unusable for the prompt).
7. Re-check `IsEdited()` right before writing (the user may have saved
   meanwhile) → `NotApplicable`.
8. `Write(text, state.GeneratedUtc, state.SampleCount, state.NewestSentUtc)`
   → `Updated`. `Write` writes the app copy, the user file, then
   `state.json` (§19.6 order), so `state.json` keeps `generatedUtc`,
   `sampleCount` and `newestSentUtc` and gets the new `hash`. Exceptions
   from `Write` propagate.

After a partial failure (app copy written, user file not), the user file
is still unedited and still lacks the marker, so the next call re-renders
from the app copy (whose old block is removed first) and succeeds. A
downgrade (a newer marker in the file, older app) re-renders to the
app's version; accepted (updates only go forward).

### F. `StyleSkill.RefreshMeetingSection()` and where it runs

1. `if (!_gate.Wait(0)) return false;` A style run in progress writes the
   current section itself, and a concurrent refresh would race its write.
   Release in `finally`.
2. `r = Files.RefreshMeetingSection(_time.LocalTimeZone)`.
3. `Updated` → `_logger?.LogInformation("Writing style skill: meeting-times section updated.")`,
   `_activity.Event(ActivityKind.Ai, StyleTexts.MeetingSectionEvent, null, null)`,
   return true. Other results → false, no log, no event.
4. Any exception → `_logger?.LogWarning("Writing style skill: meeting-times section not updated ({Type})", ex.GetType().Name)`,
   return false. Nothing retries in-process except the next
   `RunIfDueAsync` (the spec's "retried at the next start" is a minimum).

Callers:
- **`RunIfDueCoreAsync`**: right after `ct.ThrowIfCancellationRequested()`
  and **before** the settings check, call `RefreshMeetingSection()` and
  ignore the result. So it runs on every automatic pass (cheap: two
  ≤ 64 KiB reads and a hash) regardless of `Enabled`/`AutoRegenerateStyle`;
  the existing gate logic follows unchanged (the refresh has released the
  gate). `RegenerateAsync` doesn't call it (it writes the current section
  anyway).
- **App start (`Program.cs`)**: directly after the AI-drafting
  `try/catch` that builds `styleSkill` (settings are already loaded):

  ```csharp
  if (styleSkill is not null)
  {
      var skillAtStart = styleSkill;
      _ = Task.Run(skillAtStart.RefreshMeetingSection);   // SPEC 21.7: off the UI thread, no consent needed, never throws
  }
  ```

  When AI drafting couldn't be set up (no index), there is no
  `StyleSkill` and no refresh; it happens at a later start. Accepted.
