# M18.3 Reason line at the top of every AI draft

Base: `dev` at or after `748ed34` (M18.1, M18.2, M19.1 merged). M18.3
builds on the M18.2 signatures (`SystemPrompt(…, facts, related)`,
`RevisitSystemPrompt(…, facts, related)`, `BuildRequest(…, imid, …)`).
Parallel: a coder does M19.4 (`DraftAttachments*.cs`,
`EmailIndex.ThreadAttachments.cs`, OneDrive files) and an architect
writes M17.3 (App tool). None of their files are touched here, and none
of the files below are touched by them.

## Goal

Every AI draft starts with one yellow line, written by the model for the
user, saying what the email asks and what the draft answers, e.g.
`Clippy: Ricky asked about the Saturday bus; this answers that.` The
reply and revisit schemas gain an optional `note_for_user` (≤ 160
chars); `DraftReply`/`RevisitReply` parse it leniently (bad or blank =
no note, never an invalid reply); the system prompt gains `ReasonNote`
while the new setting `ReasonLine` (default on) is on;
`DraftReasonLine.Html` turns the untrusted note into one escaped,
link-free, length-capped line of Clippy's own markup, which the worker
prepends to the sanitized body (after meeting times, before
`DraftBody.Fragment`) in the automatic, manual, revisit (`replace`) and
rescan paths. The line is part of the saved `HTMLBody`, so the §23.4
fingerprint covers it: a user who deletes it has edited the draft and
§23 leaves it alone. A revisit's `<current_draft>` drops the line
(`DraftReasonLine.StripPlain`) so the model doesn't read its own note.
SPEC refs: §25.4 (whole section), §25.1 (prompt order), §25.5
(`ReasonLine`), §25.6 (tests), §23.4 (fingerprint), §23.5 (guard
`Changed`), §23.7 (revisit schema and prompt), §19.2 (settings table
already lists `ReasonLine`), §19.5 (model output is untrusted), §19.7
(reply schema, prompt), §19.8 (highlight style), §19.11 (logs), §21.6
(meeting times run first), §26.7 (notes after the reason line, M19),
§27.2 (M20.1 records the draft text without the line).

## Hard rules that apply here

- **Never send / never delete**: no COM change. The line goes through
  the existing reply path (`ReplyPlan.HtmlFragment` →
  `HtmlBody.InsertAtTop` → `.Save()`). No App file changes.
- **Model output is untrusted** (§19.5): the note is plain text from the
  model. It is never inserted as HTML: control/format characters
  removed, whitespace collapsed, URLs replaced, cut to 160 characters,
  then HTML-escaped, and only then wrapped in Clippy's own constant
  markup. The model can't add tags, attributes, styles, links or
  entities. The `Clippy: ` prefix is Clippy's; the model's own
  `Clippy:` prefix is removed so it can't fake a second line.
- **The model gets no tools**: unchanged. `note_for_user` is one more
  output field, used only to build the line.
- **Logs and storage** (§19.11, §25.4 "Logs"): the note is never logged,
  never in an Activity event, exception text or `ai_*` row, never
  stored anywhere except inside the saved draft itself. Only
  `AI drafts: note: yes|no` at Debug.
- `reason` stays as it is: validated for type, dropped, never shown,
  logged or stored.
- Everything is Core. No `Program.cs`, tray or Settings form change (the
  checkbox is M18.4).

## Behavior

### A. `DraftReasonLine.Html(note)`

In this order:

1. Null or empty → `""`. Look only at the first `MaxInputChars` (640)
   characters (one fewer when that would split a surrogate pair).
2. Per character: `char.IsControl` → a space; Unicode category
   `Format` (`CharUnicodeInfo.GetUnicodeCategory(c) == UnicodeCategory.Format`:
   bidi overrides U+202A–U+202E, U+2066–U+2069, zero-width U+200B–U+200F,
   U+FEFF, soft hyphen U+00AD, …) → removed; a lone surrogate (high not
   followed by low, or low not preceded by high) → removed.
3. Every run of `char.IsWhiteSpace` characters (incl. U+00A0, U+2028,
   U+2029) → one space; trim.
4. URLs → `LinkText`: regex
   `(?:(?:https?|ftp|file)://|mailto:|www\.)\S*`, `IgnoreCase |
   CultureInvariant`, 1 s timeout. A `RegexMatchTimeoutException` → return
   `""` (fail-safe: no line).
5. Leading `Clippy:` (OrdinalIgnoreCase) removed, then trimmed again, as
   long as the text still starts with it (so `Clippy: clippy: x` → `x`).
6. Empty → `""`.
7. `DraftPrompt.Cut(text, MaxChars)` (≤ 160 chars + `…`, surrogate-safe).
8. `DraftPrompt.Escape` (`&` → `&amp;` first, then `<`, `>`, `"`; no
   entity passes through, so the model's `&lt;` shows as `&lt;`
   literally).
9. Return `"<p>" + DraftHtml.HighlightOpen + Prefix + escaped + DraftHtml.HighlightClose + "</p>"`,
   i.e. `<p><span style="background-color:#ffff00">Clippy: …</span></p>`.

Cutting (7) happens before escaping (8), so an entity is never split.
The result contains exactly one element pair of each of `p` and `span`,
one `style` attribute (the constant) and nothing else from markup.

### B. `DraftReasonLine.StripPlain(plain)`

1. Null → `""`.
2. Split on `\r\n`, `\r`, `\n`. From the first line on, skip every line
   that is blank (`string.IsNullOrWhiteSpace`) or whose `Trim()` starts
   with `Clippy:` (Ordinal, case-sensitive) followed by a whitespace
   character (`char.IsWhiteSpace`, so U+00A0 counts). Stop at the first
   other line.
3. When no `Clippy:` line was skipped → return `plain` unchanged.
4. Else → the remaining lines (from the stop line to the end) joined with
   `\n`; `""` when nothing remains.

This drops **every** leading Clippy line (the §25.4 "From M19" form;
M19.5 then has nothing to change here). A `Clippy:` line after the first
body line is kept.

### C. Schema and parsing

1. Exact constants (only change: `"note_for_user":{"type":"string","maxLength":160}`


   The schemas are constant: the field is there whether `ReasonLine` is
   on or off (with it off, the prompt doesn't ask for it and any value is
   ignored). `AnthropicWireSchema.TryReduce` drops `maxLength` as for the
   other fields (no code change).
2. `DraftModel.ParseNote(output)`: `output.TryGetProperty("note_for_user", out v)`
   and `v.ValueKind == String` and `!string.IsNullOrWhiteSpace(s)` →
   `DraftPrompt.Cut(s.Trim(), MaxNoteChars)`; anything else (absent,
   `null`, number, bool, object, array, blank) → `null`. Never makes the
   reply invalid, never throws (wrap in the parser's existing `try`).
3. `DraftReply.Parse`: `NoteForUser = ParseNote(output)` for every
   otherwise valid reply (also `needs_reply: false`; the worker only uses
   it when it saves a draft). All other rules unchanged.
4. `DraftRevisit.Parse`: `NoteForUser = ParseNote(output)` for
   `replace`; `null` for `keep` and `remove` (like `ReplyAll`/`BodyHtml`).
5. The note is never logged. Don't add `DraftReply`/`RevisitReply` to
   any log call (their record `ToString()` would include it).

### D. Prompt (`DraftPrompt`)

1. `ReasonNote`, exact (one line; `{name}` replaced like the other
   notes; as a C# string the two `"` around `Clippy:` are escaped):

   ```
   note_for_user: when you write a reply, also set note_for_user to one short sentence for {name}, in the language of your reply, that says what the email asks of {name} and what your draft answers, for example: Ricky asked about the Saturday bus; this answers that. Clippy shows it highlighted at the top of the draft, and {name} deletes it before sending. Unlike reason, it is written for {name}. Use plain text, at most 160 characters, with no HTML, links, email addresses or placeholders, and don't start it with "Clippy:". Never put this sentence in body_html. When you don't write a reply, leave note_for_user out.
   ```

   The same text serves the revisit prompt ("when you write a reply" =
   `replace`).
2. `BuildSystem(template, …, meetingTimes, facts, related, reason)` order
   (§25.1): template → `MeetingNote` (while `meetingTimes`) →
   `"\n\n" + ReasonNote.Replace("{name}", name)` (while `reason`) →
   `RelatedNote` (while `related`) → `ManualNote` (manual) → facts block
   → `<writing_style>`. With `reason = false` both system prompts are
   byte-identical to today's.
3. `BuildUser`, revisit block: the `<current_draft>` text becomes
   `Text(Cut(MailText.OwnText(DraftReasonLine.StripPlain(revisit.CurrentDraftBody), input.SignatureText), MaxCurrentDraftChars))`.
   This runs whether `ReasonLine` is on or off (a draft saved while it
   was on still has the line). Without a leading Clippy line the user
   prompt is byte-identical to today's. Nothing else in `BuildUser`
   changes (thread, related mail and `<email_to_answer>` text are not
   stripped; see "Spec changes" 7).

### E. Worker

1. **Prompt**: `BuildRequest` passes `reason: ai.ReasonLine` after
   `DraftPrompt.HasRelated(input)`. `RevisitAsync` step 5 passes
   `reason: ai.ReasonLine` after `DraftPrompt.HasRelated(input)`. Same
   `ai` snapshot as the rest of that request.
2. **Line**: `ReasonTop(ai, note)` (E.4) at the three save sites, with the
   same `ai` snapshot that built the prompt:
   - candidate path (automatic and rescan), step 8:
     `MakePlan(c.EntryId, reply!.ReplyAll ?? false, html, p.Priority, ReasonTop(ai, reply.NoteForUser))`;
   - manual path: `MakePlan(e.EntryId, reply.ReplyAll ?? false, html, WorkPriority.Interactive, ReasonTop(ai, reply.NoteForUser))`;
   - revisit `ReplaceAsync`: `MakePlan(targetId, reply.ReplyAll ?? false, html, s.Priority, ReasonTop(ai, reply.NoteForUser))`.
   Each call sits inside the existing `try` of the save, directly in the
   `MakePlan(...)` argument list, so it runs only when a draft is about
   to be saved (after meeting times, after the §19.7 re-check and the
   revisit re-read).
3. `html` (sanitized body after meeting times) stays a separate local;
   the line is only concatenated inside `MakePlan`
   (`DraftBody.Fragment(top + html, html: true, sig)`). So the saved
   fragment is `line + body [+ "<br>" + signature]`, the meeting-times
   insertion and `DraftMeetingTimes.IsWanted` see only the body, and
   M20.1 can record `html` (without the line) directly.
4. `ReasonTop`: `!ai.ReasonLine` → `""`, no log. Else
   `var top = DraftReasonLine.Html(note);` log Debug
   `AI drafts: note: {Note}` with `top.Length > 0 ? "yes" : "no"`;
   return `top`. `ReasonLine` on and no/blank/unusable note → no line,
   the draft is saved as before.
5. Nothing about the note is written to `ai_decisions`, `ai_drafts`,
   `ai_revisits`, `ai_calls`, Activity or balloons. The `Draft` event
   text, the pass/rescan summary lines and every existing log template
   are unchanged (no pass-log change in M18.3).
6. A `keep`/`remove`/low-confidence revisit, `needs_reply: false`, a low
   confidence reply and every failure path create no draft and never
   call `ReasonTop`.

### F. Fingerprint (§23.4) — no code change, pinned by tests

The line is inside `ReplyPlan.HtmlFragment`, so `HtmlBody.InsertAtTop`
puts it into `HTMLBody` before `reply.Save()`, and
`OutlookMail.ReadDraftFingerprint` (read right after `Save()`) hashes
it. Deleting the line changes `HTMLBody`, so the fingerprint differs,
`AiDraftGuard.Evaluate` returns `Changed`, and the revisit marks the
draft `edited` and never touches it again (§23.6 step 2). This is the
intended behavior (§25.4 "Fingerprint").

### G. How M20.1 leaves the line out (for the M20.1 architect; no code here)

- Draft side (§27.2 `text`): record from the worker's `html` local
  (sanitized body after meeting times) at the save sites, i.e. the value
  passed to `MakePlan` as `html`, never `plan.HtmlFragment` and never
  `top`. Then `DraftHtml.ToPlainText` → `MailText.OwnText` →
  `MailText.Redact` → cut 1,500. That text contains neither the reason
  line, the M19 notes (also in `top`) nor the signature (added by
  `DraftBody.Fragment`).
- Sent side (§27.3): when the user sent the reply without deleting the
  line, the Sent Items body starts with `Clippy: …`; M20.1 should pass
  the sent plain text through `DraftReasonLine.StripPlain` before
  `OwnText`, so a kept line doesn't count as an edit.

### `DraftReasonLineTests`

1. `Html("Ricky asked about the Saturday bus; this answers that.")` ==
   `<p><span style="background-color:#ffff00">Clippy: Ricky asked about the Saturday bus; this answers that.</span></p>`.
2. `Html(null)`, `Html("")`, `Html("  \t\r\n ")` → `""`.
3. Escaping: `Html("a <b>x</b> & \"q\" &lt;")` → text
   `a &lt;b&gt;x&lt;/b&gt; &amp; &quot;q&quot; &amp;lt;`.
4. HTML injection: `Html("</span></p><a href=\"javascript:x\">click</a><img src=x onerror=y>")`
   → the result contains exactly one `<span`, one `</span>`, one `<p>`,
   one `</p>`, no `<a`, no `<img`, and `style=` occurs once.
5. Controls and whitespace: `Html("line1\r\nline2\t\u0007end    x")` →
   text `line1 line2 end x`.
6. Format characters: `Html("ab‮cd​ef﻿")` → text `abcdef`;
   a lone `\uD800` in the middle is removed; a valid pair (`😀`) is kept.
7. Links: `Html("See https://evil.example/login?x=1 now")` → text
   `See [link] now`; `HTTP://A.B`, `www.evil.example`, `mailto:a@b.c`,
   `file://c/x`, `ftp://h/f` each → `[link]`; `Html("https://x.y")` →
   `…Clippy: [link]…` (not empty). The result never contains `://` or
   `www.`.
8. Own prefix: `Html("Clippy: Ann asked")` and `Html("clippy:Ann asked")`
   → text `Ann asked` (one `Clippy: ` in the result); `Html("Clippy:")`
   and `Html("Clippy: clippy:")` → `""`.
9. Cut: `Html(new string('a', 160))` → 160 `a`, no `…`;
   `Html(new string('a', 161))` → 160 `a` + `…`; `Html(new string('a', 159) + "&bbbbbbbb")`
   → text `aaa…a&amp;…` (159 `a`, `&amp;`, `…`): never a split entity.
10. Surrogate cut: `Html(new string('a', 159) + "😀zz")` → 159 `a` + `…`.
11. Input cap: `Html(new string(' ', 10_000) + "late")` → `""` (only the
    first 640 characters are read); `Html("x" + new string('y', 100_000))`
    returns quickly with 160 chars + `…`.
12. Cut, then whitespace: `Html(new string('a', 100) + new string(' ', 300) + "b")`
    → text `a…a b` (100 `a`, space, `b`).
13. `StripPlain(null)` → `""`; `StripPlain("Hi\nBye")` returns the same
    instance (`Assert.Same`).
14. `StripPlain("Clippy: x\r\n\r\nHi Ricky,\r\nyes.")` → `"Hi Ricky,\nyes."`.
15. `StripPlain("\r\n  Clippy: x\nClippy: y\n\nHi")` → `"Hi"` (every
    leading Clippy line and blank line).
16. `StripPlain("Clippy: x\nHi")` → `"Hi"`.
17. Kept: `"Hi\nClippy: x"`, `"Clippy:x\nHi"`, `"clippy: x\nHi"`,
    `"Clippy:\nHi"` → unchanged.
18. `StripPlain("Clippy: only")` → `""`.
19. Round trip: `DraftHtml.ToPlainText(L("Ann asked") + "<p>Hi</p>")` →
    `StripPlain` of it == `"Hi"`.

## Spec changes

Low-risk, reversible decisions made here; not applied by this brief
(record them in SPEC.md when the M18 spec sync runs). §25.4 unless noted:

1. **Schema position**: `note_for_user` sits after `reason` and before
   `meeting` in both schemas (exact strings in Behavior C.1; §19.7 and
   §23.7 schema listings gain the field). The schemas are constant; with
   `ReasonLine` off the field is still allowed but not asked for, and
   ignored.
2. **Parsing**: the note is trimmed, then cut with the `DraftPrompt.Cut`
   rule (160 characters + `…`); `DraftModel.MaxNoteChars = 160`. It is
   kept for `needs_reply: false` (unused) and dropped (null) for revisit
   `keep`/`remove`. API: `DraftReply(…, MeetingAsk? Meeting = null, string? NoteForUser = null)`,
   `RevisitReply(…, MeetingAsk? Meeting, string? NoteForUser = null)`.
3. **Rendering** (`DraftReasonLine.Html`), in addition to §25.4: only the
   first 640 characters are read; Unicode format characters (bidi
   overrides, zero-width characters, BOM, soft hyphen) and lone
   surrogates are removed; URLs (`http(s)://`, `ftp://`, `file://`,
   `mailto:`, `www.`) become `[link]`, because a yellow `Clippy:` line
   carries Clippy's authority and must not carry a link a prompt-injected
   email chose; a leading `Clippy:` from the model is removed; the cut
   happens before escaping; a regex timeout gives no line. "Cut to 160
   characters with `…`" means 160 characters followed by `…`.
   `DraftReasonLine.Prefix = "Clippy: "`, `MaxChars = 160`,
   `LinkText = "[link]"`.
4. **`StripPlain`** already drops every leading blank or `Clippy: `
   line in M18 (the §25.4 "From M19" form); `Clippy:` must be followed by
   whitespace (U+00A0 counts) and matches case-sensitively; input without
   such a line is returned unchanged. It is applied to `<current_draft>`
   inside `DraftPrompt` whether `ReasonLine` is on or off.
5. **Prompt**: `ReasonNote` text pinned in Behavior D.1; signatures
   `SystemPrompt(…, facts = null, related = false, reason = false)` and
   `RevisitSystemPrompt(…, facts = null, related = false, reason = false)`
   (§19.7, §23.7).
6. **Worker**: the line is built at save time from the same settings
   snapshot as the prompt; `MakePlan(…, top)` with
   `HtmlFragment = DraftBody.Fragment(top + html, true, sig)` (§26.7's
   notes join `top` after the line). Debug log text is
   `AI drafts: note: yes|no`, only while `ReasonLine` is on. No pass or
   rescan log line changes.
7. **Not stripped elsewhere**: `<thread>`, `<related_mail>` and
   `<email_to_answer>` text are not passed through `StripPlain` (they
   are other people's mail or the user's sent mail; see the open point
   in the report).
8. **§27.2 note for M20.1**: the draft text is taken from the worker's
   sanitized body after meeting times (never from the saved fragment),
   and the sent side should go through `StripPlain` (Behavior G).
9. **§3 layout**: `DraftReasonLine.cs` (`DraftReasonLine`, §25.4),
   `DraftWorker.Reason.cs`.
