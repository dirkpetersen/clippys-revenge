# M14.1 `email_stats` Core: shared filter builder and `EmailStats`

Base: `dev` at a5f98ea (M13 spec and plan) or later. Core and Core tests
only. No App changes, no csproj changes, no schema change. M14.2
(`query_index`, `IndexQuery.cs`) is written in parallel and also lives
next to the index: **don't touch `IndexQuery.cs` or `MailboxIndexes.cs`**,
and keep the `EmailIndex.cs` change to the builder extraction below.
M14.3 wires the tool on top of `EmailStats.Run`, so **the names and
signatures below are fixed**.

## Goal

Add the Core half of `email_stats` (SPEC §11.11): one call that counts
the emails matching the `search_emails` filters (§11.1), grouped by
sender, sender domain, recipient, recipient domain, folder, month, ISO
week, weekday or hour, with `order`, `top`, `include_cc` and the
`mailbox="all"` merge, returning counts and names only. The filters are
applied by **the same WHERE-clause builder** that `EmailIndex.Search`
uses (§9.2, §11.11 "one shared builder; no second copy"), extracted from
`SearchPage` without any behaviour change, and mapped by the same
`SearchArgs.ToFilter` (§11.11), which `MailQueries.Search` now also uses
instead of its own copy. Time buckets use an injected `TimeZoneInfo`.
A `[PerfFact]` benchmark over a synthetic 100k-row index checks the §17
targets (1 s; 3 s for the recipient groupings). Test coverage per §15
("Index statistics and SQL").

## Hard rules that apply here

- Read-only: stats only run `SELECT`s on connections from
  `EmailIndex.OpenConnection()`. No writes, no schema change.
- Counts and names only. `EmailStats` never returns or reads `subject`,
  `body` or attachment names (the FTS `MATCH` filter may search them,
  as `search_emails` does).
- No logging in `EmailStats.cs`: no `ILogger` parameter, no `Console`
  (§11.11 "No text is logged"; M14.3 adds the scan).
- Every filter value is a bound parameter (the existing builder already
  does this). No filter text is ever concatenated into SQL.

## Behavior

### A. Shared builder (`EmailIndex.BuildFilter`) — no behaviour change

1. Move lines 563–627 of today's `SearchPage` (the `DynamicParameters`,
   the `where` list, `FtsQuery.Build`, every filter clause including
   `AddRecipient`, the attachment `EXISTS` subqueries and the `unread`
   clause) into `BuildFilter`, unchanged: same clause order, same
   parameter names, same `ESCAPE '\\'`, same `COALESCE`s, same
   `NormalizeFolder`, the 50-recipient cap. `Where` is
   `" WHERE " + string.Join(" AND ", where)` or `""`.
2. `SearchPage` keeps everything after: it takes `From`, `Where`,
   `Parameters` and uses `FtsMatch is not null` where it used
   `fts is not null` (snippet column, outer join with `MATCH @q`), adds
   `take`/`skip` to the same `DynamicParameters`, and produces a
   byte-identical SQL string.
3. The private helpers `Trimmed`, `Escape`, `Like`, `AddRecipient`,
   `NormalizeFolder` stay where they are; nothing else may build filter
   SQL. `EmailStats` gets its WHERE clause only from `BuildFilter`.
4. Tests that guard "no behaviour change" (all must pass unmodified):
   every test in `EmailIndexSearchTests` (each filter alone and
   combined, `Like_WildcardsAreLiteral`, `Folder_Aliases`,
   `Recipient_RawList_MatchesAny`, `Recipient_UnparsableList_FallsBackToSubstring`,
   `AttachmentExt_*`, snippets, paging, `Injection_IsInert`,
   `SearchPage_Unclamped`), the `Search_*` tests in
   `MailboxIndexesTests`, `MailQueriesTests`, `SearchArgsTests`, and
   (with `CLIPPY_PERF=1`) `PerfBenchmarkTests.Search_P95_MeetsTargets`.

### B. `Count` per grouping (one mailbox)

`f = EmailIndex.BuildFilter(filter)`; every query is
`… FROM {f.From}{f.Where} …` with `f.Parameters`, on
`index.OpenConnection()` (dispose it). Streams use Dapper
`Query<T>(sql, p, buffered: false)`. Times in SQL are unix seconds;
convert with `DateTimeOffset.FromUnixTimeSeconds`.

1. **Sender** — one `GROUP BY` query:
   ```sql
   SELECT lower(trim(e.sender_email)) AS K, count(*) AS N,
          min(e.event_time) AS First, max(e.event_time) AS Last,
          max(printf('%020d|%020d|', e.event_time, e.id) || coalesce(e.sender_name, '')) AS Newest
   FROM {From}{Where} GROUP BY K
   ```
   (SQLite's bare-column rule only works with a single `min`/`max`, so
   the newest row's name rides in a sortable string: event time, then
   row id as tie-break.) In C#, each row's key is `SenderKey(K)` (this
   re-normalizes non-ASCII case and whitespace that SQLite's `lower`/
   `trim` miss, and maps NULL/blank to `(unknown)`); rows that end up
   on the same key are combined: counts added, `min` First, `max` Last,
   and Name from the larger `(event_time, id)` parsed from `Newest`
   (chars 0–19 and 21–40; the name starts at index 42).
   `Total` = sum of N.
2. **SenderDomain** — the same query without the `Newest` column; key
   `DomainOf(SenderKey(K))`; combine as above; Name null.
3. **Folder** —
   `SELECT e.folder AS K, count(*) AS N, min(e.event_time) AS First, max(e.event_time) AS Last FROM {From}{Where} GROUP BY e.folder`.
   Key = the stored folder path as is (ordinal). Name null.
4. **Month, Week, Weekday, Hour** — stream
   `SELECT e.event_time AS T FROM {From}{Where}`; key `TimeKey(g, T, zone)`;
   per key count, min, max. `Total` = rows read. Name null.
5. **Recipient, RecipientDomain** — stream
   `SELECT e.id AS Id, e.event_time AS T, e.to_addrs AS ToAddrs, {cc} AS CcAddrs FROM {From}{Where}`
   with `{cc}` = `e.cc_addrs` when `includeCc`, else `NULL`.
   `Total` = rows read (an email with no valid recipient still counts
   in `Total` but in no group).
   - Recipient: for each `r` in `SplitRecipients(ToAddrs, CcAddrs, includeCc)`,
     key `r.Email` (already lower-cased), one count per email; Name =
     `r.Name` of the email with the larger `(T, Id)` (`""` when that
     email had no display name, even if an older one did).
   - RecipientDomain: the distinct `DomainOf(r.Email)` of the email,
     one count per domain per email. Name null.
6. `First`/`Last` per group = earliest / latest `event_time` of the
   counted emails. Returned groups are sorted by key (ordinal) so
   `StatsCounts` is deterministic.
7. FTS: with a `query`, `From` is the FTS join, which yields one row per
   email, so counts stay per email.

### C. Order, top, shape

- `Sort` with `StatsOrder.Count`: count descending, then key ascending
  (`StringComparer.Ordinal`). With `StatsOrder.Key`: key ascending
  (ordinal) — chronological for Month, Week and Hour because the keys
  are zero-padded — except Weekday, which sorts `Mon, Tue, Wed, Thu,
  Fri, Sat, Sun`.
- `Shape`: `rows` = first `Math.Clamp(top, 1, MaxTop)` of `Sort(...)`;
  `total` = `counts.Total`; `distinct` = `counts.Groups.Count`;
  `truncated` = `distinct > clampedTop`; `group_by` = `WireName`;
  `first`/`last` = `MailQueries.Iso(t, zone)`
  (`yyyy-MM-dd'T'HH:mm:sszzz`, invariant, same as `find_free_times`);
  `name` copied from `StatsGroup.Name` (so it is omitted from JSON for
  every grouping except sender and recipient).
- No rows: `{"total":0,"distinct":0,"truncated":false,"rows":[]}`.

### D. `Run`

1. `g = ParseGroupBy(groupBy)`, then `o = ParseOrder(order)`, then
   `filter = filters.ToFilter(zone)` (its `McpException` for bad dates
   passes through:
   `date_from "<text>" is not a valid date. Use an ISO date like 2026-03-01 or a date-time like 2026-03-01T14:30 (local time).`).
   Validation happens before any index is touched.
2. `key = MailboxIndexes.Normalize(filters.Mailbox)`.
   - `key != "all"`: `Count(indexes.For(filters.Mailbox), …)` (an
     unknown mailbox throws the §9.3 `MailboxIndexes.Unknown` text via
     `For`). `mailbox` in the result = `key`.
   - `key == "all"`: for each `k` in `indexes.Mailboxes` (own first,
     then settings order) call `indexes.For(k)`; an `McpException` there
     (mailbox disabled meanwhile) skips it. `Merge` the per-mailbox
     results in that order. `mailbox` = `"all"`. An email indexed in two
     mailboxes counts twice (§11.11).
3. `Shape(counts, g, o, top, key, zone)`.
4. Nothing is cached. No logging.

### E. `Recipients.TryParseEntry` and `Parse`

- `TryParseEntry`: null → false. `entry = entry.Trim()`; empty → false.
  Then exactly today's per-entry logic in `Parse` (the `AngleForm`
  match, name trim, surrounding quotes removed, email trimmed), and
  `EmailAddress.IsValid(email)` → true with `new Recipient(name, email)`
  (original case), else false.
- `Parse` loops the `;`-split parts as today: blank parts skipped; for
  a non-blank part, `TryParseEntry` false → the same `FormatException`
  with the same text (the trimmed entry); then the same
  case-insensitive de-duplication.

### F. `MailQueries.Search`

Build `new SearchArgs { Query = query, …, Limit = limit, Offset = offset }`
and call `ToFilter(tz)` instead of constructing `SearchFilter` itself.
Same clamping, same `McpException` for bad dates. `Iso` keeps its body;
only its accessibility changes.

### T3 Filters apply (shared builder)
On the T2 seed, each case for Sender and for Recipient:
- `Folder = "inbox"` → total 3 (subfolder excluded).
- `DateFrom = 2026-05-01Z, DateTo = 2026-05-31Z` → total 2.
- `Query = "alice"` (FTS over sender/recipients) → only emails that

- `Recipient = "carol@other.net; dave@other.net"` (list form) → total 2.
- `Unread = true` (seed m5 with `unread: true`, the rest read) → total 1.
- `Limit = 1, Offset = 3` on the filter → ignored, total 5.
- `Sender = "100%"` (LIKE metacharacters literal) → total 0.

### T4 `Merge`, `Sort`, `Shape`
- `Merge` of own `{alice: 2, first 03-02, last 05-04, name "A1"}`,
  shared `{alice: 1, first 01-10, last 05-04, name "A2"}` and
  `{bob: 1}` → alice 3, first 01-10, last 05-04, name `A1` (tie keeps
  the earlier mailbox); total = sum of totals. If shared's last were
  06-01, name `A2`.
- `Sort` Count: `[b:2, a:2, c:5]` → `c, a, b`. Key: `a, b, c`.
  Weekday Key: `{Sun, Mon, Wed}` → `Mon, Wed, Sun`. Hour Key:
  `{"23","05","10"}` → `05, 10, 23`.
- `Shape` with 3 groups and top 2 → 2 rows, `distinct` 3, `truncated`
  true; top 3 → false; top 0 → 1 row; top 500 → clamped to 200 (use
  250 groups → 200 rows, truncated true).
- `first`/`last` with `UtcMinus8`: `2026-11-13T16:40:00-08:00` for
  `2026-11-14T00:40:00Z`.
- JSON (`JsonSerializer.Serialize(dto)`): sender rows contain `"name"`;
  folder and month rows have no `"name"` property; property names are
  exactly `group_by, mailbox, total, distinct, truncated, rows` and
  `key, name, count, first, last`.

## Spec changes

None made in `SPEC.md` (the caller owns spec edits in this round).
Decisions taken here that the architect should record in §11.11:

1. `order` error text: `order must be count or key.` (§11.11 says only
   "Anything else is an error"). `order` null/blank means `count`.
2. `group_by` and `order` are matched trimmed and case-insensitively.
3. "Newest" ties (same `event_time`) are broken by the higher index row
   id within a mailbox; across mailboxes (`all`) the earlier mailbox
   (own first) keeps its name.
4. `recipient` `name` is the display name in the newest email that
   contains the address, `""` if that email had none (even when an
   older one did) — the literal reading of §11.11.
5. Sender keys are grouped in SQLite and re-normalized in C#
   (`Trim` + `ToLowerInvariant`), so non-ASCII case variants merge;
   `sender_domain` is derived in C# from the per-address groups (the
   §11.11 "done in C#" option).
6. `MailQueries.Search` now maps its arguments through
   `SearchArgs.ToFilter`, so there is one filter mapping for
   `search_emails` and `email_stats`.
