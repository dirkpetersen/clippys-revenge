# M16.1 Latest-Opus default and visible style source

Base: `dev` after M15 (version 0.0.8). M16.1 ships alone, before the rest
of M16, so it touches no M16.2+ code (no schema 3, no `ReviseDrafts`).

## Goal

Make the default model the alias `opus` ("latest Opus") so drafting and
style generation move to a new Opus without a Clippy update, and make the
writing-style fallback visible. Settings: `DefaultModel = "opus"`, a
one-time-per-load migration of the old default `claude-opus-5-5`, a new
`Model` validation message, a `latest Opus/Sonnet/Haiku` hint next to the
Model box. CLI backend: the alias goes to `--model` unchanged. API
backend: a new `AnthropicModelResolver` turns `opus`/`sonnet`/`haiku`
into a concrete id through `GET /v1/models` with the user's saved key
(newest model of that line, 24 h cache, 10-minute retry after a failure,
401/403 → not signed in, anything else → a pinned fallback id and one
Warning). Style: `StyleSkillFiles.ReadForPrompt()` returns the body
**and** its source (`UserFile`, `AppCopy`, `None`); `StyleGuideSource`
reports a source change once (`Ai` event + log), never per draft.

SPEC refs: §19.2 (`Model` row, "Model default (M16.1)" paragraph), §19.3
("API backend details", "Model aliases (M16.1)"), §19.6 ("Use in
drafting", "Visible style source (M16.1)", "Seam"), §19.10 (Model hint),
§19.11 (logs may hold the resolved id, never the key), §18 (2026-11-13
decision, M16.1 note), §23.11 (M16.1 test bullet), §1.10 / CLAUDE.md
(never touch Claude credentials).

## Hard rules that apply here

- **Never touch Claude credentials.** The model lookup uses only the
  Anthropic API key the user typed in (DPAPI, `SettingsStore.LoadApiKey`
  through the existing `AnthropicApiModel.SafeLoadKey`). Nothing reads
  `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`,
  Claude Code's `.credentials.json` or the credential store. The CLI
  backend never lists models; it only passes the alias.
- **Never log the key** or any response body. Logs may contain the alias,
  the resolved id, the failure kind and the HTTP status.
- No new outbound host: `https://api.anthropic.com` only (the existing
  `AnthropicApiModel.ApiBaseUrl`), only when `Backend = ApiKey` and a key
  is saved.
- The model still gets no tools; nothing here changes prompts.
- AI-file scan (§19.12): the new file `AnthropicModelResolver.cs` is an
  AI file (name starts with `Anthropic`). No `Send`/`Display`/`Move`/
  `Delete` calls in it.

### `AnthropicModelResolver.cs` (new, Core)

```csharp
/// <summary>One /v1/models entry, read from the SDK item's RawData (never from typed getters).</summary>
public sealed record ModelListEntry(string Id, DateTimeOffset CreatedAt, string? Line, string? Lifecycle)
{
    /// <summary>False when "id" isn't a non-empty string or "created_at" isn't a string that parses as an
    /// RFC 3339 date (DateTimeOffset.TryParse, InvariantCulture, DateTimeStyles.RoundtripKind | AssumeUniversal).
    /// "line"/"lifecycle": the string value, or null when missing, JSON null or not a string. Never throws.</summary>
    public static bool TryParse(IReadOnlyDictionary<string, JsonElement>? raw, [NotNullWhen(true)] out ModelListEntry? entry);
}

/// <summary>What one listing attempt gave (closed hierarchy, private constructor).</summary>
public abstract record ModelListOutcome
{
    public sealed record Listed(IReadOnlyList<ModelListEntry> Models) : ModelListOutcome;
    public sealed record Rejected(int HttpStatus) : ModelListOutcome;        // 401 or 403
    public sealed record Failed(string Kind) : ModelListOutcome;             // a ModelLookupKinds text
}

public static class ModelLookupKinds
{
    public const string NoAnswer = "no answer";                 // network/IO error, any other exception
    public const string TimedOut = "timed out";                 // the 15 s bound, not the caller's ct
    public const string Unreadable = "unreadable answer";       // JsonException / AnthropicInvalidDataException
    public const string NoMatch = "no model of that family";    // listed fine, SelectNewest gave null
    public static string Http(int status) => "HTTP " + status.ToString(CultureInfo.InvariantCulture);
}

public enum ModelResolutionKind { Resolved, Fallback, Rejected }

/// <summary>Resolved: Model is the typed non-alias or the looked-up/cached id.
/// Fallback: Model is ModelAliases.Fallback(alias). Rejected: Model is "", HttpStatus is 401/403.</summary>
public sealed record ModelResolution(string Model, ModelResolutionKind Kind, int? HttpStatus = null);

/// <summary>SPEC 19.3 "Model aliases", API backend. Thread-safe.</summary>
public sealed class AnthropicModelResolver
{
    public static readonly TimeSpan CacheFor = TimeSpan.FromHours(24);
    public static readonly TimeSpan RetryAfterFailure = TimeSpan.FromMinutes(10);
    public const int MaxPages = 10;
    public const int PageSize = 100;

    /// <param name="lister">(apiKey, ct) -> one listing attempt. Must throw only OperationCanceledException for ct.</param>
    /// <exception cref="ArgumentNullException">lister is null.</exception>
    public AnthropicModelResolver(Func<string, CancellationToken, Task<ModelListOutcome>> lister,
        TimeProvider? time = null, ILogger? logger = null);

    /// <summary>Non-alias: Resolved(model) at once, no call, no log.
    /// Alias: see Behavior C. fresh = true (CheckAsync) skips the cache and the 10-minute hold.</summary>
    /// <exception cref="ArgumentNullException">model or apiKey is null.</exception>
    /// <exception cref="OperationCanceledException">ct was cancelled (cache/hold unchanged).</exception>
    public Task<ModelResolution> ResolveAsync(string model, string apiKey, bool fresh, CancellationToken ct);

    /// <summary>Drops every cached id, every hold and every open warning episode. A lookup already running
    /// when this is called doesn't store its result (generation counter). Never throws.</summary>
    public void Invalidate();

    /// <summary>Pure selection (Behavior C.3). Null when no entry qualifies.</summary>
    /// <exception cref="ArgumentNullException">models or alias is null.</exception>
    public static string? SelectNewest(IEnumerable<ModelListEntry> models, string alias);
}
```

## Behavior

### A. Default and migration (§19.2)

1. `new AiDraftingSettings().Model == "opus"`. `FillDefaults` still maps a
   null `Model` to `DefaultModel` (so a JSON with `"Model": null` gives
   `opus`).
2. The migration runs **only when settings are loaded from disk**:
   `SettingsStore.ReadSettings` calls `s.AiDrafting.MigrateLegacyModel()`
   after `Settings.FromJson` and before `Validate()`. It is not in
   `FillDefaults`, because `Settings.Clone()` is `FromJson(ToJson())` and
   `SettingsEditor`/`CopyFrom` clone on every Apply: a migration there
   would silently rewrite a value the user just typed. (Spec change 1.)
3. Exactly `claude-opus-5-5` (ordinal) becomes `opus`. Everything else is
   kept: `claude-opus-5`, `claude-sonnet-5-5`, `Claude-Opus-5-5`, `sonnet`,
   a custom id.
4. The migrated value isn't written back at load time; the next normal
   `Save` writes `opus`. No log, no warning, no event.
5. The `Model` validation message is `ModelMessage` (exact text above,
   copied from §19.2). Rule unchanged: 1–64 chars,
   `^[A-Za-z][A-Za-z0-9._\[\]-]*\z`; `opus`, `sonnet`, `haiku` pass.

### B. CLI backend (§19.3)

No code change. `ClaudeCliArgs.Build("opus", …)` emits `--model`, `opus`
as two elements; Claude Code resolves the alias. The CLI never lists
models. Tests pin this (T-CLI).

### C. `AnthropicModelResolver.ResolveAsync`

1. `model` not an alias (`ModelAliases.IsAlias` false) → return
   `Resolved(model)` immediately. No call, no log, no state change.
2. Alias, `fresh == false`:
   - a cache entry for this alias younger than `CacheFor` (`now - storedAt
     < 24 h`, `TimeProvider.GetUtcNow()`) → `Resolved(cachedId)`, no call;
   - else, a hold for this alias (`now < holdUntil`) → `Fallback(
     ModelAliases.Fallback(alias))`, no call, no log;
   - else look up (step 4).
   Alias, `fresh == true` (only `CheckAsync`): always look up (step 4),
   ignoring cache and hold.
3. Selection (`SelectNewest`): candidates are entries with
   `Line == alias` (ordinal), `Lifecycle != "retired"` (ordinal; null
   counts as not retired), and `AiDraftingSettings.IsValidModelName(Id)`.
   Pick the latest `CreatedAt`; on a tie the ordinal-greatest `Id`. Null
   when there is no candidate. The `id` prefix is **not** used (Anthropic's
   models overview: "Read `line` instead of inferring it from the model's
   `id`"). (Spec change 2.)
4. Lookup: single flight per resolver (`SemaphoreSlim(1,1)`, waited with
   `ct`). After acquiring it, a non-fresh call re-checks step 2 (another
   caller may have just filled the cache). Then `await lister(apiKey, ct)`:
   - `Listed(models)` and `SelectNewest` gives `id` → store `(id, now)` in
     the cache, clear the hold and the open warning episode for the alias,
     log Information `AI drafts: "{Alias}" is {Model}.` → `Resolved(id)`.
   - `Listed` with no match → treat as `Failed(ModelLookupKinds.NoMatch)`.
   - `Failed(kind)` → `holdUntil = now + RetryAfterFailure`; leave any
     cache entry as it is (it is already stale or the call was `fresh`; a
     `fresh` failure removes the alias's cache entry so `RunAsync` doesn't
     keep using an id the Check couldn't confirm); if no warning episode
     is open for this alias, open one and log Warning
     `AI drafts: couldn't look up the newest "{Alias}" model ({Kind}); using {Model}.`
     with `Model = ModelAliases.Fallback(alias)` → `Fallback(fallbackId)`.
     The rendered text must equal §19.3's
     `AI drafts: couldn't look up the newest "<alias>" model (<kind>); using <id>.`
   - `Rejected(code)` → `Rejected("", code)`. No hold, no warning, cache
     untouched (the caller maps it to `NotSignedIn` / "rejected").
   - The lister throws `OperationCanceledException` for `ct` → rethrow;
     nothing stored, no hold, no log. Any other exception from the lister
     → treat as `Failed(ModelLookupKinds.NoAnswer)` (defensive; the real
     lister doesn't throw).
   - If `Invalidate()` ran while the lookup was in flight (generation
     changed), return the result but store nothing (no cache, no hold, no
     episode change; the log lines are still written).
5. Episode: opened by the first failure Warning, closed by a successful
   lookup or `Invalidate()`. Repeated failures in one episode (including
   retries after each 10-minute hold) log nothing more.
6. Cache, holds and episodes are per alias, in memory only. Nothing
   persisted.
7. No key, body or prompt in any log line.

### D. `AnthropicApiModel.ListModelsAsync(apiKey, ct)` (private)

- Client: the existing `NewClient(key, new RetryAfterCapture(),
  CheckTimeout)` (same `HttpClient` over `_handler`, `BaseUrl =
  ApiBaseUrl`, `MaxRetries = 0`, `OpenTelemetry = false`, key passed
  explicitly; the SDK sends `Authorization: Bearer <key>` and the
  `anthropic-version` header itself; no `x-api-key`). Dispose it.
- One deadline for all pages: `new CancellationTokenSource(CheckTimeout,
  _time)` linked with `ct` (as `CheckCoreAsync` does).
- `var page = await client.Models.List(new ModelListParams { Limit =
  AnthropicModelResolver.PageSize }, linked.Token)`. For each
  `item in page.Items`, `ModelListEntry.TryParse(item.RawData, out var e)`
  and keep the parsed ones (skip the rest). Then while `page.HasNext()`
  and fewer than `MaxPages` pages were read: `page = await
  page.Next(linked.Token)`. Stop after `MaxPages` pages even when more
  exist and select among what was read. No `lifecycle` filter is sent
  (the default list is active + deprecated).
- Mapping: done → `Listed(entries)`; `AnthropicApiException` 401/403 →
  `Rejected(code)`; other status → `Failed(ModelLookupKinds.Http(code))`;
  `OperationCanceledException` when `ct.IsCancellationRequested` → rethrow
  `new OperationCanceledException(ct)`; other `OperationCanceledException`
  → `Failed(TimedOut)`; `JsonException` or `AnthropicInvalidDataException`
  → `Failed(Unreadable)`; anything else → `Failed(NoAnswer)`. Never read
  exception messages or response bodies.

### E. `AnthropicApiModel` using the resolver

**`RunAsync`** (order inside `RunCoreAsync`): input validation as today
(`IsValidModel(request.Model)` etc.) → `ct` cancelled → `Cancelled` →
key (`SafeLoadKey`; null → `NotSignedIn`, no HTTP) → **resolve**:
`await _resolver.ResolveAsync(request.Model, key, fresh: false, ct)`:
- `Resolved(id)` / `Fallback(id)` → build the Messages request with
  `Model = id` (everything else as today). The `request.Timeout` deadline
  starts after the lookup, as today (it is created after this step).
- `Rejected(code)` → `(NotSignedIn, code)`; no Messages call.
- `OperationCanceledException` → `(Failed(Cancelled), null)`.
A 400/404 on the Messages call with a fallback id is the normal
`Failed(Http, code)`. The existing `Anthropic API call: …` log line is
unchanged (it never contains the model).

**`CheckAsync`**:
- Non-alias model: unchanged (one `GET /v1/models/<model>`, same texts,
  `Ready(model)`).
- Alias: invalid-model and no-key steps as today, then
  `ResolveAsync(model, key, fresh: true, ct)` (no `Models.Retrieve` call):
  - `Resolved(id)` → `ModelStatus(true, ReadyAlias(alias, id))`, log kind
    `Ready`, HTTP 200;
  - `Fallback` → `ModelStatus(false, NoAnswer)`, kind `NoAnswer`;
  - `Rejected(code)` → `ModelStatus(false, Rejected(code))`, kind
    `Rejected`;
  - cancellation of `ct` → throws `OperationCanceledException` (as today).
  So each Check of an alias is one fresh listing (≤ 10 pages within 15 s),
  which also verifies the key, and it refreshes the cache that `RunAsync`
  uses. (Spec change 3.)

**`InvalidateModelCache()`** → `_resolver.Invalidate()`.

### F. Style source (§19.6)

1. `StyleSkillFiles.ReadForPrompt()`:
   - user file text via the existing `ReadUsable(Paths.UserSkillFile)`
     non-null → `Source = UserFile`; body = `RemoveMeetingSections(
     StripHeader(text))`, or `StyleSkillText.NoStyleGuideLine` when empty;
   - else app copy text non-null → `AppCopy`, same body rule;
   - else `None`, body `NoStyleGuideLine`.
   "Usable" is exactly today's `ReadUsable` (exists, ≤ 64 KiB, readable).
   `ReadBodyForPrompt()` returns `ReadForPrompt().Body` (behavior
   identical to today; its existing tests must pass unchanged).
2. `StyleGuideSource.ReadForPrompt()`: `var p = _skill.ReadForPrompt()`;
   under a lock compare `p.Source` with `_lastReported` (`StyleSource?`,
   null at construction) and set it:
   - same as `_lastReported` → nothing;
   - `None` → `Ai` event `StyleTexts.SourceNone` + log Warning (same text);
   - `AppCopy` → `Ai` event `StyleTexts.SourceAppCopy` + log Warning;
   - `UserFile` and `_lastReported` is `None` or `AppCopy` → `Ai` event
     `StyleTexts.SourceBack` + log Information;
   - `UserFile` and `_lastReported` is null (first read after start-up)
     → nothing.
   Event: `_activity.Event(ActivityKind.Ai, text)` (no duration, no
   mailbox). Emit outside the lock. Exceptions from the hub or logger are
   swallowed; `ReadForPrompt` never throws and returns `p.Body`.
   Log calls use the constant text as the message template (no
   placeholders). The texts carry no path, name or content.
3. Only `ReadForPrompt` reports; `BeforePassAsync` doesn't. Every drafting
   path already reads through `IStyleGuideSource.ReadForPrompt`
   (`DraftWorker` line ~856), so automatic and manual drafts are covered;
   M16.5/M16.6 reuse the same seam.

## Spec changes

Not applied by this brief (the caller asked for the brief only); the
architect/caller must apply them to `SPEC.md`:

1. **§19.2 "Model default"**: the migration runs when `settings.json` is
   loaded (`SettingsStore` calls `AiDraftingSettings.MigrateLegacyModel()`
   after `Settings.FromJson`), not in `FillDefaults`, because
   `Settings.Clone()` round-trips through `FromJson` and would rewrite a
   deliberately typed `claude-opus-5-5` on every Apply. The migrated value
   is saved with the next normal Save.
2. **§19.3 "Model aliases"**: the family match is the model's `line` field
   (`line == alias`, ordinal), not the `claude-<alias>-` id prefix
   (Anthropic's models overview: "Read `line` instead of inferring it from
   the model's `id`"). Entries with `lifecycle: retired` or an id failing
   `IsValidModelName` are skipped; entries are read from the raw JSON
   (`id`, `created_at`, `line`, `lifecycle`); page size 100, at most 10
   pages, all within the 15 s bound; no `lifecycle` filter is sent.
3. **§19.3 "Check text"**: `CheckAsync` for an alias always does a fresh
   listing (ignores the cache and the 10-minute hold, refreshes the cache;
   a failed fresh lookup drops the cached id) and makes no
   `GET /v1/models/<id>` call. `RunAsync` uses the cache.
4. **§19.3 "Failure"**: `<kind>` texts are `no answer`, `timed out`,
   `HTTP <code>`, `unreadable answer`, `no model of that family`. A
   successful lookup logs Information `AI drafts: "<alias>" is <id>.` and
   closes the warning episode. 401/403 sets no hold. Fallback ids pinned:
   `sonnet` → `claude-sonnet-5-5`, `haiku` → `claude-haiku-5-5` (Anthropic
   models overview, checked 2026-11-15).
5. **§19.3**: the drop on Save key / Remove key / Settings → Check is
   `AnthropicApiModel.InvalidateModelCache()`, wired in `Program`; it also
   clears holds and warning episodes.
6. **§19.6**: the three source texts live in the existing `StyleTexts`
   class (`StyleTexts.SourceNone`, `SourceAppCopy`, `SourceBack`), not a
   new `StyleSkillTexts` class (avoids a third near-identical class name
   next to `StyleTexts`/`StyleSkillText`).
7. **§3 layout**: new `AnthropicModelResolver.cs` (alias lookup, §19.3);
   `ModelAliases` lives in `AiSettings.cs`.
8. **§19.3 SDK note** (no change, for the record): the SDK authenticates
   with `Authorization: Bearer <key>`, not `x-api-key`; the existing tests
   assert `x-api-key` is absent, and the list call keeps that.
