# M12.4 App wiring: restarter, Program, tray About, Settings, safety scans

Base: `dev` with M12.1, M12.2 and M12.3 merged, and any M11 review work
on `Program.cs`/`TrayApp.cs` already merged (ef4d7e8 is on `dev`; if

## Goal

Make auto-update work in the real app (SPEC §20.9, §20.11, §6.2, §6.3,
§6.7, §14, §15):
- `UpdateRestarter` is the updater's one `Process.Start`. It starts only
  the installed exe and wraps the process as `IUpdateProcess`. It also
  reads an exe's `ProductVersion`.
- `Program` runs `UpdateStartup.Prepare` before anything starts and
  installs a staged update right there. After the tray and server are
  up, it confirms a fresh update and shows notices. It runs
  `UpdateService`, and after a normal shutdown it releases the mutex
  and runs the handover when the service asked for an install.
- The tray gets **About Clippy's Revenge…** and an `AboutForm`.
  Settings → General gets the **Updates** drop-down and **Check now**.
- The safety source scan gets the §15 additions.

## Hard rules that apply here

- **The only new process start** is `UpdateRestarter.Start`, which
  starts `paths.ExePath` and nothing else: `UseShellExecute = false`, no
  `Arguments`/`ArgumentList`, no `Verb`, working directory
  `paths.InstallDir`. It never starts Outlook, a shell, `install.ps1` or
  a script, and never elevates. `Kill()` only targets that process.
- **Never launch Outlook** is unchanged. `OutlookLauncher` and
  `TrayApp.ShellOpen` are untouched. `AboutForm` opens its two links
  through `TrayApp.ShellOpen` with the URLs from `AboutModel` only
  (constants, or built from a validated tag).
- **Localhost-only server** is unchanged. The updater's only network
  access is through `UpdateClient` (Core).
- The mutex, the pipe and the server port are released **before** the
  new exe starts (SPEC §14): `host` disposed in the existing shutdown,
  then `instance.Dispose()`, then the handover.
- No `.Result`/`.Wait()` except the documented entry-point waits in
  `Program` (§B.6).

## Public API

### `UpdateRestarter.cs`

```csharp
namespace ClippysRevenge.App;

/// <summary>Starts the installed Clippy exe for an update handover (SPEC 20.11). The updater's only Process.Start.</summary>
internal static class UpdateRestarter
{
    /// <summary>Starts paths.ExePath with UseShellExecute = false, no arguments, WorkingDirectory = paths.InstallDir.</summary>
    /// <exception cref="ArgumentException">Path.GetFullPath(path) isn't Path.GetFullPath(paths.ExePath) (OrdinalIgnoreCase).</exception>
    /// <exception cref="InvalidOperationException">Process.Start returned null.</exception>
    /// <exception cref="System.ComponentModel.Win32Exception">The exe couldn't be started.</exception>
    public static IUpdateProcess Start(UpdatePaths paths, string path);

    /// <summary>FileVersionInfo.GetVersionInfo(path).ProductVersion, cut at the first '+', trimmed; null when blank or
    /// on any I/O / format error.</summary>
    public static string? ReadExeVersion(string path);
}
```

Shape of `Start` (pins the scan's expectations):

```csharp
public static IUpdateProcess Start(UpdatePaths paths, string path)
{
    if (!string.Equals(Path.GetFullPath(path), Path.GetFullPath(paths.ExePath), StringComparison.OrdinalIgnoreCase))
    {
        throw new ArgumentException("The updater only starts the installed Clippy's Revenge exe.", nameof(path));
    }
    var p = Process.Start(new ProcessStartInfo(paths.ExePath)
    {
        UseShellExecute = false,
        WorkingDirectory = paths.InstallDir,
    }) ?? throw new InvalidOperationException("The new version did not start.");
    return new ProcessHandle(p);
}
```

`ProcessHandle`: `HasExited => p.HasExited`, `Kill() => p.Kill()` (no
`entireProcessTree`), `WaitForExitAsync(ct) => p.WaitForExitAsync(ct)`,
`Dispose() => p.Dispose()`.

## Behavior

### A. `UpdateRestarter.ReadExeVersion`

`FileVersionInfo.GetVersionInfo(path).ProductVersion`, cut at the
first `+`, trimmed. Null or blank → null. Catch `FileNotFoundException`,
`IOException`, `UnauthorizedAccessException` and `ArgumentException` →
null.

### B. `Program` (order matters)

1. **After** the logger exists (`logger.LogInformation("Clippy's Revenge starting.")`)
   and **before** `new ActivityHub()` and `worker.Start()`:
   ```csharp
   var localAppData = Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData);
   var updatePaths = UpdatePaths.Default(localAppData);
   var running = AppVersionInfo.FromAssembly(Assembly.GetEntryAssembly());
   var installed = updatePaths.IsInstalledCopy(Environment.ProcessPath);
   var updateStore = new UpdateStateStore(updatePaths.StateFile, loggerFactory.CreateLogger<UpdateStateStore>());
   logger.LogInformation("Version {Version} ({Commit}), installed copy: {Installed}.", running.Version, running.ShortCommit ?? "-", installed);
   var startupPlan = installed
       ? UpdateStartup.Prepare(updatePaths, updateStore, running.Version, settings.Updates, loggerFactory.CreateLogger("Update"))
       : StartupUpdatePlan.Nothing;
   ```
   Wrap `Prepare` in a `try/catch (Exception)` that logs an Error (type)
   and uses `Nothing`. It shouldn't throw, but a bug here must never
   stop Clippy from starting.
2. **Install before anything runs.** If `startupPlan.InstallNow is { } staged`:
   - `pending = RunBlocking(() => UpdateInstall.BeginAsync(updatePaths, updateStore, staged, running.Version, log: …))`.
   - On success: log Information `"Installing update {Version} at start-up."`,
     `instance.Dispose()`, then
     `outcome = RunBlocking(() => UpdateHandover.RunAsync(updatePaths, updateStore, pending, p => UpdateRestarter.Start(updatePaths, p), log: …))`,
     log the outcome, dispose `loggerFactory` and `fileLog`, and
     `return 0`. Nothing else (worker, tray, host) has started.
   - `UpdateInstallException ex`: log Warning
     `"Update {Version} not installed at start-up: {Reason}"`,
     `updateStore.Update(s => s.LastError = ex.Message)` (I/O errors
     caught), and continue the normal start.
3. **Tray.** Pass `CreateAboutForm: () => new AboutForm(updates ?? throw new InvalidOperationException("Updates are not ready."), TrayApp.ShellOpen, <idle icon>)`.
   `updates` is a local assigned later, like `applier`. For the icon,
   use a new `TrayIcons` instance owned by the form, or expose the tray's
   Idle icon through an internal getter. The coder picks one; the form
   must not dispose a shared icon. `SettingsFormServices` gets
   `ShowAboutAndCheck: () => tray.ShowAbout(checkNow: true)` (a closure
   over the `tray` variable; it runs only after the tray exists).
4. **Service.** After the tray exists (it needs `tray.IsSettingsOpen`):
   ```csharp
   PendingInstall? handover = null;   // set by RequestInstall, read after Application.Run
   var updateClient = new UpdateClient(running.Version);
   updates = new UpdateService(new UpdateServiceOptions(
       () => settings, updateClient, updateStore, updatePaths, running, installed,
       Path.GetDirectoryName(Environment.ProcessPath) ?? AppContext.BaseDirectory,
       IsBusy: () => hub.IsActive(ActivityState.Serving) || hub.IsActive(ActivityState.Drafting)
           || hub.IsActive(ActivityState.AwaitingConfirmation) || tray.IsSettingsOpen,
       ReadExeVersion: UpdateRestarter.ReadExeVersion,
       RequestInstall: async (staged, ct) =>
       {
           try
           {
               var p = await UpdateInstall.BeginAsync(updatePaths, updateStore, staged, running.Version, log: …, ct: ct);
               Volatile.Write(ref handover, p);
               tray.ExitForUpdate();
               return null;
           }
           catch (UpdateInstallException ex) { return ex.Message; }
       },
       hub, balloons, DateTimeOffset.UtcNow /* captured at the top of Main */, Logger: loggerFactory.CreateLogger<UpdateService>()));
   ```
   Capture `startedUtc = DateTimeOffset.UtcNow` as the first statement
   of `Main` and pass it here. `handover` must be a field, or a captured
   local read with `Volatile.Read`, since it is written on the thread
   pool.
5. **After the server start.** Replace `_ = StartHostAsync(…)` with
   `var hostStart = StartHostAsync(…)` and add
   `_ = AfterStartAsync(hostStart, SynchronizationContext.Current!, …)`.
   That is a private static async method that:
   - awaits `hostStart` (it never throws);
   - posts to the UI context (so it runs once the message loop pumps):
     - if `startupPlan.ConfirmAfterStart`:
       `n = UpdateStartup.Confirm(updateStore, running.Version, log)`.
       If `n` isn't null: `balloons.Post(BalloonTexts.Updated(n.ToVersion))`,
       `hub.Event(ActivityKind.Update, UpdateTexts.EventUpdated(n.FromVersion, n.ToVersion))`,
       then `_ = UpdateStartup.CleanupOldAsync(updatePaths, updateStore, running.Version, log: …)`.
     - if `startupPlan.Notice` is `RolledBack`:
       `balloons.Post(BalloonTexts.UpdateRolledBack(n.FromVersion, n.ToVersion))`
       and `hub.Event(Update, UpdateTexts.EventRolledBack(n.FromVersion, n.ToVersion))`.
       An `Updated` notice (not written by M12.3, but handled for safety)
       gets the `Updated` balloon and event.
     - `_ = updates.StartAsync(CancellationToken.None)`. Start it here,
       not earlier, so the first check is 60 s after the tray is up.
6. **Shutdown and handover.** In the existing post-loop
   `Task.Run(async () => { … })`, add `await updates.StopAsync(CancellationToken.None)`
   first. After the existing disposals (`worker`, `indexes`, `hub`) and
   **before** `loggerFactory.Dispose()`:
   ```csharp
   updateClient.Dispose();
   if (Volatile.Read(ref handover) is { } pending)
   {
       instance.Dispose();                     // releases the mutex and the pipe (SPEC 14)
       var outcome = RunBlocking(() => UpdateHandover.RunAsync(updatePaths, updateStore, pending,
           p => UpdateRestarter.Start(updatePaths, p), log: loggerFactory.CreateLogger("Update")));
       logger.LogInformation("Update handover: {Outcome}.", outcome);
   }
   ```
   `instance` is a `using var`; disposing it early is safe (its
   `Dispose` is idempotent). The server port is already free, because
   `host.DisposeAsync()` ran in the shutdown task.

   Entry-point blocking helper (the existing shutdown wait is the
   precedent):
   ```csharp
   /// <summary>Process entry point only: blocks the STA main thread before the message loop starts or after it ended.
   /// Task.Run avoids the WinForms SynchronizationContext.</summary>
   private static T RunBlocking<T>(Func<Task<T>> work) => Task.Run(work).GetAwaiter().GetResult();
   ```
7. `StartupRegistration.Apply` is unchanged. The Run key already points
   at `ClippysRevenge.exe` in the install folder, and the path doesn't
   change across an update.

### C. Tray and About

- **Menu** (SPEC §6.2): add `About Clippy's Revenge…` between
  **Start with Windows** and **Exit**. Its click calls `ShowAbout()`. It
  is disabled when `CreateAboutForm` is null.
- **`ShowAbout(checkNow)`**: `PostToUi`. If an About window is open,
  restore it from minimized and `Activate()`. Otherwise create it with
  `CreateAboutForm()`, dispose it on `FormClosed`, and `Show()`. Then,
  when `checkNow`, call `form.StartCheck()`. Dispose it in
  `TrayApp.Dispose` like `_activity`.
- **`IsSettingsOpen`**: a `volatile bool`, set true right before
  `form.Show()` in `ShowSettings` and false in its `FormClosed`
  handler.
- **`ExitForUpdate()`**: `PostToUi(() => { _notify.Visible = false; ExitThread(); })`.
  Open forms close with the context (their unsaved Settings changes are
  dropped; idle already required Settings to be closed for automatic
  installs).
- **`AboutForm`** (SPEC §6.7): fixed dialog
  (`FormBorderStyle.FixedDialog`, no maximize or minimize, `StartPosition.CenterScreen`,
  `ShowInTaskbar = true`), `Text = UpdateTexts.Title`, the icon at
  32 px plus `ProductName` in bold, then one label per line:
  `VersionLine`, `RuntimeLine`, `LocationLine`, `ModeLine`,
  `LastCheckLine`, `StatusLine` (`AutoSize = false`, wide enough to
  wrap two lines). Then two `LinkLabel`s (`UpdateTexts.DocsLink` →
  `DocsUrl`, `UpdateTexts.NotesLink` → `NotesUrl`) and three buttons:
  **UpdateNowText** (enabled = `UpdateNowEnabled`), **Check for updates**
  (enabled = `CheckEnabled`), **Close** (`CancelButton`).
  - `Bind()` builds `AboutView.Build(updates.Status, RuntimeInformation.FrameworkDescription, RuntimeInformation.OSDescription, DateTimeOffset.UtcNow, TimeZoneInfo.Local)`
    and sets every control. It's called at `Load`, on
    `updates.Changed` (marshalled with `BeginInvoke` when
    `IsHandleCreated && !IsDisposed`; unsubscribed in `FormClosed`), and
    every 30 s by a WinForms `Timer` (for the relative time).
  - Update button → `_ = updates.UpdateNowAsync(CancellationToken.None)`.
    Check → `StartCheck()` → `_ = updates.CheckNowAsync(CancellationToken.None)`.
    Neither awaits on the UI thread; the status line shows progress.
  - Link click → `openLink(model.DocsUrl)` / `openLink(model.NotesUrl)`
    from the **current** model. Catch `Win32Exception` and
    `InvalidOperationException` and show nothing (no browser).
  - Closing the window doesn't cancel a running check or download.
- **Settings → General** (SPEC §6.3), below Log level:
  `Lbl(p, "Updates", 8, 352, 80)`; a `DropDownList` combobox at
  `(100, 352, 170, 24)` filled from `SettingsTexts.UpdateModes` with
  `SettingsTexts.UpdateModeLabel`, bound to `_editor.Draft.Updates`
  like `_logLevel` (staged; applied on OK/Apply); a **Check now** button
  at `(280, 351, 90, 26)` that calls `_s.ShowAboutAndCheck?.Invoke()`
  (disabled when null); and a grey note at `(380, 356)`:
  `Checks GitHub once a week.`. Grow the page or form height if the
  controls don't fit. No other Settings change.

### D. Logging and events

Program logs versions, the installed flag, the plan, the swap and the
handover outcome. `Update` events come from the service and from §B.5.
Never log the token, settings contents or full exception messages from
the update path (type names only).

## Spec changes

None beyond the M12 architect commit. Decisions recorded here:

1. `UpdateService` starts only after the server start was attempted and
   the message loop runs, so the 60 s first-check delay counts from a
   working tray.
2. Settings changes still open in the form are dropped by an install;
   automatic installs never happen while Settings is open (idle rule),
   and **Update now** is the user's own click.
3. `Program` gets one small `RunBlocking` helper for the two entry-point
   waits (the pre-tray install and the post-loop handover), next to the
   existing shutdown wait.
