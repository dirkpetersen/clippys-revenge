# M19.2 Core text extractors: `AttachmentText`, `PdfText`, `OoxmlText`, `PlainText`, `EmlText`

Base: `dev`. No deps. Pure Core, runs beside M19.3 (OneDrive mapping),
M17.1 and M18.1; see "Parallel work" for the disjoint file sets.

## Goal

Turn the bytes of one attachment into plain text for the drafting prompt,
safely and in bounded time and memory, without ever executing, rendering or
following anything in the file (§26.4). `AttachmentText.Extract` picks the
format from the extension, confirms it with magic bytes, and dispatches to
PDF (PdfPig), an own OOXML reader (docx/xlsx/pptx, zip-bomb limits, counting
stream, DTD prohibited), plain text/HTML (`Signatures.Decode`,
`DraftHtml.ToPlainText`) or a minimal `.eml` MIME reader. It also renders an
attached Outlook item that M19.7 reads through COM. It returns
`ExtractedText` with the exact §26.4 skip reasons and never throws except
`OperationCanceledException`. This task adds the one new NuGet package of
M19 (`PdfPig` 0.1.16, already in SPEC §2). Nothing here logs, stores or
caches text (§1.6, CLAUDE.md "Attachment content never enters the index").

SPEC refs: §26.4 (all), §26.12 (Extractors and Zip limits bullets), §2
(PdfPig row), §3 (layout), §1.6, §26.11 (scan rules these files must
already satisfy), §8 (signature decoding), §19.8 (`DraftHtml.ToPlainText`).

## Hard rules that apply here

- **Attachment content never enters the index, logs, Activity or any
  file.** These files take no `ILogger`, write no file, hold no static
  cache of text, and never put file text, names or paths into an exception
  message that escapes (`Extract` catches everything except cancellation).
- **Nothing is executed, rendered or opened with a shell handler.** No
  `Process`, no `HttpClient`/`WebRequest`/`WebClient`, no
  `UseShellExecute`, no `XmlResolver`, no DTDs. Macros
  (`vbaProject.bin`), embedded OLE objects, external relationships
  (`TargetMode="External"`, templates, linked images) and field codes are
  never opened or followed (§26.4, §26.11).
- No reference to `EmailIndex` or `MailboxIndexes` from these files
  (§26.11 scan, added in M19.7; write the code so it already passes).
- Stay small: one Core library. The only new package is `PdfPig` 0.1.16
  (justified below). OOXML uses in-box `System.IO.Compression` and
  `System.Xml`; `DocumentFormat.OpenXml` is **not** added.

## Behavior

### A. `Extract` dispatch

1. `ct.ThrowIfCancellationRequested()`.
2. `format = FormatOf(fileName)`:
   - `Image` → `Skip(AttachmentReasons.Image)`.
   - `UnsupportedNoted` / `Unsupported` → `Skip(AttachmentReasons.CantRead(Extension(fileName)))`.
3. `bytes.Length > MaxFileBytes` → `Skip(AttachmentReasons.TooLarge)`.
4. Inside `try`: dispatch (B–F). `catch (OperationCanceledException) when (ct.IsCancellationRequested)` → rethrow. Any other exception (incl. `ExtractLimitException`, `XmlException`, `InvalidDataException`, PdfPig exceptions, `OutOfMemoryException`) → `Skip(AttachmentReasons.Damaged)`. Never let an exception message out.
5. Result of a reader that produced text: `(text, cut) = Finish(raw)`; status `Truncated` when `cut` or the reader hit any of its caps (pages, sheets, rows, columns, slides, 1 MiB of text, `TextSink.Full`), else `Read`. `Truncated` mirrors the status. Empty text after `Finish` is `Read` with `""` for every format **except PDF** (§26.4 no-text rule, C).

`FormatOf` (case-insensitive extension, `Extension` rules: text after the
last `.` that comes after the last `/` or `\`, trimmed, `ToLowerInvariant`):

| Format | Extensions |
|---|---|
| `Image` | whenever `InlineAttachments.IsImage(null, fileName)` is true (checked first) |
| `Pdf` | `pdf` |
| `Word` | `docx`, `docm`, `dotx` |
| `Excel` | `xlsx`, `xlsm`, `xltx` |
| `PowerPoint` | `pptx`, `pptm`, `ppsx` |
| `Text` | `txt`, `text`, `csv`, `tsv`, `md`, `markdown`, `log`, `json`, `xml`, `ics`, `vcf` |
| `Html` | `html`, `htm` |
| `Eml` | `eml` |
| `UnsupportedNoted` | `doc`, `dot`, `xls`, `xlt`, `xlsb`, `ppt`, `pps`, `rtf`, `odt`, `ods`, `odp`, `pages`, `numbers`, `key`, `zip`, `7z`, `rar` |
| `Unsupported` | everything else, incl. no extension |

`AttachmentReasons.CantRead(ext)`: `$"Clippy can't read .{ext} files"`
when `ext` matches `^[a-z0-9]{1,10}$`, else `UnknownKind` (no extension,
or an odd one like `exe;rm` or 40 characters).

Magic-byte confirmation (mismatch → `Skip(Damaged)`):
- `Pdf`: `%PDF-` (ASCII) at any offset within the first 1,024 bytes.
- `Word`/`Excel`/`PowerPoint`: starts with OLE `D0 CF 11 E0 A1 B1 1A E1`
  → `Skip(PasswordProtected)` (encrypted Office file); else must start
  with `50 4B 03 04` (`PK\3\4`).
- `Text`/`Html`/`Eml`: no magic; `Text`/`Html` refuse NUL (B).
- Zero-length bytes: `Pdf`/OOXML → `Damaged`; `Text`/`Html` → `Read`, `""`; `Eml` → `Damaged` (no header).

### B. Text and HTML (`PlainText`)

- Take `n = min(len, MaxTextBytes)`. When `n < len`: if the bytes start
  with a UTF-16 BOM (`FF FE` / `FE FF`) make `n` even; otherwise back `n`
  off while `bytes[n]` is a UTF-8 continuation byte (`0x80`–`0xBF`), at
  most 3 steps, so a cut never turns valid UTF-8 into Windows-1252.
  `truncated = n < len`.
- `Signatures.Decode(bytes[..n].ToArray())` (internal, same assembly; BOM,
  charset declaration, strict UTF-8, else 1252). Don't copy or change that
  helper.
- Decoded text containing `'\0'` → `null` → `Skip(Damaged)` (binary).
- `Text` → the decoded string. `Html` → `DraftHtml.ToPlainText(decoded)`
  (it drops scripts/styles and caps its own input at 1 MiB chars).
- Then `Finish`.

### C. PDF (`PdfText`)

- Get a `byte[]` without copying when possible
  (`MemoryMarshal.TryGetArray` and the segment covers the whole array),
  else `ToArray()`.
- `using var doc = PdfDocument.Open(array, new ParsingOptions { UseLenientParsing = true, SkipMissingFonts = true });`
- Pages `1..min(NumberOfPages, MaxPdfPages)`: `ct.ThrowIfCancellationRequested()`;
  stop when the sink is full; text `ContentOrderTextExtractor.GetText(page)`
  (namespace `UglyToad.PdfPig.DocumentLayoutAnalysis.TextExtractor`);
  pages joined with `"\n\n"`. `NumberOfPages > MaxPdfPages` → truncated.
- `PdfDocumentEncryptedException` (PdfPig, needs a password) →
  `Skip(PasswordProtected)`. A PDF encrypted with an empty user password
  opens normally and is read.
- All pages read are whitespace-only → `Skip(NoText)`.
- No images, no OCR, no annotations/attachments/forms, no JavaScript.
- If a pinned option or type name differs in 0.1.16, use the 0.1.16
  equivalent and say so in the hand-back; do not change the version.

### D. OOXML (`OoxmlText`)

**Pre-checks, before any entry is opened** (any failure → `Damaged`):
1. Parse the End of Central Directory record (signature `50 4B 05 06`,
   searched backwards in the last 65,557 bytes). Its total-entries field
   must be `<= MaxEntries` and not `0xFFFF` (ZIP64 → refuse). This runs
   before `ZipArchive` is constructed, so a huge central directory is
   never materialized.
2. `new ZipArchive(new MemoryStream(array, writable: false), ZipArchiveMode.Read)`.
   `Entries.Count <= MaxEntries`; `Σ entry.Length <= MaxDeclaredTotal`;
   every entry with `Length > RatioCheckMinBytes` has
   `CompressedLength > 0` and `Length / CompressedLength <= MaxRatio`.
3. Entry lookup: by `FullName` with `\` → `/` and a leading `/` removed,
   `OrdinalIgnoreCase`, first entry wins on duplicates.

**Reading a part** (`OpenXml(name)`): only names reached through the rules
below and ending in `.xml` or `.rels`; record the name in `openedParts`;
`entry.Open()` wrapped in `new LimitedReadStream(stream, MaxPartBytes)`;
`XmlReader.Create(stream, settings)` with `DtdProcessing = Prohibit`,
`XmlResolver = null`, `MaxCharactersInDocument = MaxXmlChars`,
`IgnoreComments = true`, `IgnoreProcessingInstructions = true`,
`CloseInput = true`. A missing required part → `Damaged`.
`ExtractLimitException` (more than 20 MiB actually decompressed, declared
sizes not trusted) → `Damaged`. A DTD → `XmlException` → `Damaged`.

**Relationships** (`<dir>/_rels/<file>.rels`, `Relationship` elements with
`Id`, `Type`, `Target`, `TargetMode`): skip `TargetMode="External"`
(case-insensitive) and any target containing `://` or starting with `\\`;
`Target` is `Uri.UnescapeDataString`-decoded, resolved against the source
part's folder (a leading `/` means the package root), `.`/`..` segments
normalized; a target that climbs above the root is skipped. Types are
matched by suffix so both transitional
(`http://schemas.openxmlformats.org/officeDocument/2006/relationships/…`)
and strict (`http://purl.oclc.org/ooxml/officeDocument/relationships/…`)
work: `/worksheet`, `/sharedStrings`, `/styles`, `/slide`, `/notesSlide`.
Only those types are ever followed. `vbaProject.bin`, `embeddings/*`,
`media/*`, `oleObject*`, `attachedTemplate`, `hyperlink`, `image` and
every other relationship type are never opened.

**Element matching**: by local name and namespace; accept the
transitional and strict namespaces for `w`
(`http://schemas.openxmlformats.org/wordprocessingml/2006/main`,
`http://purl.oclc.org/ooxml/wordprocessingml/main`), `x`
(`…/spreadsheetml/2006/main`, `http://purl.oclc.org/ooxml/spreadsheetml/main`),
`p` (`…/presentationml/2006/main`, `http://purl.oclc.org/ooxml/presentationml/main`),
`a` (`…/drawingml/2006/main`, `http://purl.oclc.org/ooxml/drawingml/main`)
and `r` (the two relationship namespaces above). The subtree of every
`mc:Fallback` (`http://schemas.openxmlformats.org/markup-compatibility/2006`)
is skipped, so text boxes are not doubled. Check `ct` per part, per
sheet row batch (every 50 rows) and per slide; stop when the sink is full
(→ truncated).

**Word** (`word/document.xml`, fixed path):
- `w:t` text appended; `w:tab` → `\t`; `w:br` and `w:cr` → `\n`; end of
  `w:p` → `\n`.
- `w:delText` (deleted text) and `w:instrText` (field codes) are skipped.
- Tables: in a `w:tc`, the end of a `w:p` gives a space instead of `\n`
  (except the cell's last paragraph, which gives nothing); end of `w:tc`
  → `\t` unless it is the row's last cell; end of `w:tr` → `\n`. Nested
  tables follow the same rules (best effort).
- Footnotes, endnotes, comments, headers, footers and `glossary` parts
  are not read.

**Excel** (`xl/workbook.xml` + `xl/_rels/workbook.xml.rels`):
- `workbookPr@date1904` = `1`/`true` → 1904 date system (+1,462 days).
- Shared strings (first `/sharedStrings` relationship, optional): each
  `si` is the concatenation of its `t` descendants, skipping `rPh`
  (phonetic) subtrees.
- Styles (first `/styles` relationship, optional): `numFmts/numFmt`
  (`numFmtId` → `formatCode`) and `cellXfs/xf` (index → `numFmtId`). A
  numFmtId is a **date format** when it is 14–22 or 45–47, or a custom
  code that contains `y`, `Y`, `d` or `D` after removing `"…"` quoted runs,
  `[…]` bracket runs and backslash-escaped characters.
- Sheets: `sheets/sheet` in workbook order with `name` and `r:id`; only
  those whose relationship type is `/worksheet` count (chartsheets etc.
  are ignored and don't count). First `MaxSheets`; a further worksheet →
  truncated.
- Each sheet: line `## <name>` (newlines/tabs in the name → space), then
  one TSV line per `row` that has at least one non-empty cell within the
  first `MaxSheetColumns` columns; at most `MaxSheetRows` such rows, one
  more → truncated, stop reading that sheet. Row numbers aren't padded:
  empty rows are left out.
- Cells: column from the `r` reference letters (`A` = 1); a cell without
  `r` takes the previous column + 1. Columns `> MaxSheetColumns` →
  truncated, cell ignored. Missing cells in between are empty fields;
  trailing empty fields are removed.
- Values: `t="s"` → shared string by index (out of range → empty);
  `t="inlineStr"` → the `is` element's `t` text; `t="str"`, `t="e"`,
  `t="d"` → `v` as stored; `t="b"` → `TRUE`/`FALSE` for `1`/`0`; no `t`
  or `t="n"` → `v` as stored, except when its `s` style is a date format
  and `v` parses (invariant) as a double `0 <= v < 2958466`: then
  `DateTime.FromOADate(v (+1462 when date1904))`, rounded to the nearest
  minute, as `yyyy-MM-dd`, plus ` HH:mm` when the rounded time of day is
  not 00:00. `f` (formula) is never read; its cached `v` is the value.
- Each cell text: `\t`, `\r`, `\n` → space, cut to `MaxCellChars`.
- Sheets separated by a blank line (`"\n\n"`).

**PowerPoint** (`ppt/presentation.xml` + `ppt/_rels/presentation.xml.rels`):
- Slides in `p:sldIdLst/p:sldId` order via `r:id` → `/slide`
  relationships. First `MaxSlides`; more → truncated.
- Each slide: `## Slide <n>` (1-based order), then each non-empty `a:p` as
  one line: its `a:t` texts, `a:br` → `\n`; `a:fld` subtrees (slide
  numbers, dates) skipped.
- Notes: the slide's own rels (`ppt/slides/_rels/<file>.rels`), first
  `/notesSlide` target; its paragraphs with the same rules; when
  non-empty, a line `Notes:` followed by those lines.
- Slides separated by a blank line.

### E. `.eml` (`EmlText`)

- Work on `Encoding.Latin1.GetString(bytes)` (byte-preserving). Header
  block = up to the first empty line (`\r\n\r\n` or `\n\n`); parsed with
  `MailText.Headers(headerBlock)`. No valid header → `Damaged`.
- `Subject` and `From` go through `DecodeWords` (RFC 2047 `=?cs?B?…?=` and
  `=?cs?Q?…?=`; `_` → space in Q; whitespace between adjacent encoded
  words dropped; unknown charset → UTF-8; malformed words left raw).
  `Date` is used raw.
- Content-Type: `type/subtype` + `;`-separated params (names
  case-insensitive, values optionally quoted); missing → `text/plain`.
  Content-Transfer-Encoding: `base64` (whitespace removed,
  `Convert.TryFromBase64String`; failure → that part is treated as having
  no text), `quoted-printable` (`=XX` hex either case; `=` at line end is a
  soft break; a stray `=` stays literal), anything else
  (`7bit`/`8bit`/`binary`/missing/unknown) → raw bytes.
- Charset: `Encoding.GetEncoding(charset)` (unknown or missing → UTF-8).
  `AttachmentText` registers `CodePagesEncodingProvider.Instance` in its
  static constructor (idempotent; don't rely on `Signatures` having run).
- `multipart/*` with a `boundary`: parts between lines `--<boundary>`
  (trailing whitespace allowed) up to `--<boundary>--`; preamble and
  epilogue ignored; the CRLF before a boundary belongs to the boundary.
  The message is depth 0; multiparts are followed while their depth is
  `<= 3`; deeper ones are ignored. No boundary → no parts.
- Parts with `Content-Disposition: attachment` and `message/rfc822`
  parts are never decoded.
- Body = the first `text/plain` part in depth-first order, else the first
  `text/html` part through `DraftHtml.ToPlainText`, else `""`.
- Output `RenderMessage(subject, from, date, null, body)` then `Finish`.

### F. Attached Outlook item (`FromMailItem`)

`RenderMessage(subject, from, sent?.ToString("yyyy-MM-dd HH:mm", CultureInfo.InvariantCulture), attachmentNames, body ?? "")`
then `Finish`; status `Read` or `Truncated`. `sent` is passed as the
caller's local time (M19.4/M19.7 decide); this method doesn't convert.

### G. `RenderMessage`

Lines in order, each only when non-empty after trim: `Subject: <s>`,
`From: <f>`, `Date: <d>`, `Attachments: <names joined ", ">` (non-empty
names only). Then, when the text is non-empty, a blank line and the text.
Header values: `\r`/`\n` → space.

### H. `Finish` (all formats)

1. `\r\n` and lone `\r` → `\n`.
2. Remove every `char.IsControl` character except `\n` and `\t`.
3. Lines that are whitespace-only become empty; leading and trailing
   empty lines are dropped; runs of more than 2 empty lines become 2.
   (Leading tabs of a non-blank line are kept: TSV with an empty first
   cell.)
4. When longer than `MaxFileChars`: the first `MaxFileChars - 1`
   characters (one less if that ends in a high surrogate) + `…`
   (U+2026), `Cut = true`. The result is never longer than
   `MaxFileChars`.

`TextSink` default limit is `2 × MaxFileChars` raw characters, so
normalization still has enough text to fill `MaxFileChars`; reaching it
marks the result truncated (§26.4 "Extraction stops when the text reaches
MaxFileChars").

   not 1–10 characters of `[a-z0-9]`, gets
   `Clippy can't read this kind of file` (no draft note) instead of
   `Clippy can't read .<ext> files`. All §26 reason texts live in
   `AttachmentReasons`.
3. **§26.4 API**: `AttachmentText.FormatOf`/`AttachmentFormat` (format by
   extension; `UnsupportedNoted` = the noted list) and
   `AttachmentText.FromMailItem` (the `Email` kind's rendering) are Core
   helpers for M19.4/M19.5. `Text` is `""` for `Skipped`;
   `Truncated == (Status == Truncated)`. Empty text is `Read` with `""`
   for every format except PDF (no-text skip).
4. **§26.4 OOXML**: before `ZipArchive` is opened, the End of Central
   Directory entry count is checked (`<= 2,000`, ZIP64 refused). Hitting
   the 20 MiB counting-stream limit makes the file `the file seems damaged`.
   `mc:Fallback`, `w:delText`, `w:instrText` and `a:fld` text is not read.

   1904 date system is honoured, custom-format date detection also ignores
   backslash-escaped characters. PowerPoint notes render as a `Notes:`
   line followed by the notes text. Word table cells with several
   paragraphs join them with a space.
5. **§26.4 `.eml`**: RFC 2047 encoded words in `Subject`/`From` are
   decoded; `Content-Disposition: attachment` and `message/rfc822` parts
   are never decoded; header lines that are empty are left out of the
   rendering; the attached-item rendering puts `Attachments: <names>`
   after `Date:` and dates it `yyyy-MM-dd HH:mm`.
6. **§26.4 text limit**: a cut at 1 MiB backs off to a UTF-8 (or UTF-16)
   character boundary so the strict UTF-8 check isn't defeated by the cut.
