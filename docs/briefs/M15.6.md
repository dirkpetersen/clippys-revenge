# M15.6 Live tests for draft-only invites

Base: `dev` with **M15.1–M15.4 merged** (`create_meeting_draft` /
`MeetingInvites.CreateDraftAsync` with `tracker` and `notes`, the
`Clippy draft invite` category set in `OutlookCalendar.CreateMeeting`,
`DraftInvites` + `DraftInvitesStore` + `OutlookDraftInviteCalendar` /
`OutlookCalendar.CheckDraftInvites`, `MeetingNotes` / `MeetingNoteText`,
`OutlookReplyDraftWriter` as `IReplyTargetCheck`). Test-only task: **no
file under `src/` changes.**

## Goal

Prove against the user's real classic Outlook, without sending anything,
that `create_meeting_draft` saves the meeting **unsent** (`MeetingStatus =
olMeeting`, `PidLidFInvited` false or missing), with the `Clippy draft invite`
category on the item and in the master category list (orange when this run
added it); that the production check (`OutlookCalendar.CheckDraftInvites`,
driven by `DraftInvites`) keeps an unsent meeting tracked **without writing
to it**; that the production Categories-only write path (`RemoveCategory`:
set `Categories`, `.Save()`) keeps the meeting unsent, keeps other categories
and puts nothing in Outbox or Sent Items; that with `reply_to_id` on a
synthetic, self-addressed, unsent email the note reply draft lands in the own
Drafts with a `Re:: ` subject, marker `tool` and the exact SPEC §22.4 text; that
the Outbox and Sent Items counts are unchanged across the test; and that the
test deletes only the items it created (by EntryID, run-token subject). The
"sent" branch is **simulated, never produced**: the test calls the
production check with a decide function that marks the real snapshot as
invited, so the real COM write runs on a meeting that is really unsent. A
real sent invite is checked by the user in M15.8.

SPEC refs: §22.7 (Live paragraph), §22.1, §22.2 (category, master list,
"Why a Categories-only save is safe", the live test it names), §22.3 (check
steps 1–3, 5), §22.4 (note text), §15 (live tests: opt-in, `CLIPPY_LIVE=1`,
`[Trait("live","outlook")]`, never in CI), §1.4 (never send), CLAUDE.md
(only the live suite deletes, and only its own items).

## Hard rules that apply here

- **Never send anything.** No `.Send(` anywhere in the test sources — not
  even in a comment or string (`LiveSafetyScanTests.Live_tests_never_send_or_launch`
  scans `Live/` for the literal `.Send(` and `.Display(`). The sent case is
  simulated in the decide function, never by sending.
- **No windows.** Never call `OutlookCalendar.OpenDraftInvite` or `.Display(`
  in a test (same scan). Nothing in this task needs a window, so there is no
  opt-in for one.
- **Attendees: the signed-in user only** (`fx.MeAsync()`), exactly as the
  existing calendar test. No other address appears in any argument.
- **Attach-only.** All COM goes through `fx.RunAsync` / `fx.Worker` (the
  `GetActiveObject` worker). No `new Outlook.Application`, no `Activator`.
- **Delete only own items.** Every created item is recorded with
  `scope.Track(...)` (EntryID + StoreID + a subject that starts with
  `[<RunToken>] `) right after creation, and removed only by the existing
  `LiveOutlook.DeleteAsync` (refuses anything without the run-token prefix).
  No delete by search outside `PurgeDeleted`'s existing run-token purge.
- **Never remove the master-list category.** The test may leave a
  `Clippy draft invite` entry in the user's master category list (SPEC §22.2:
  Clippy never removes it; the user needs it in M15.8). The test never
  recolours or deletes a master-list category.
- No logging/printing of mail bodies; `fx.Result` lines carry only status words.

## Behavior

### §1 Wiring (all production classes except the store path)

```csharp
var tz = TimeZoneInfo.Local;
var ownStore = await fx.RunAsync("reading the store id", app => fx.StoreIdOf(app, ""));
var replyWriter = new OutlookReplyDraftWriter(fx.Worker, fx.Mail, fx.Stores);
var notes = new MeetingNotes(replyWriter, replyWriter, () => null);       // no signature: the test doesn't depend on the user's
var store = new DraftInvitesStore(Path.Combine(fx.TempRoot, "draft-invites", DraftInvitesStore.FileName));
var tracked = new DraftInvites(new OutlookDraftInviteCalendar(fx.Worker), store,
    () => fx.Worker.State == OutlookConnectionState.Available, tz);
var invites = new MeetingInvites(new OutlookMeetingCalendar(fx.Worker, fx.Stores, () => fx.Settings),
    () => fx.Settings, fx.Hub, tz, tracker: tracked, notes: notes);
```

The store lives under `fx.TempRoot` (deleted with the run); the user's real
`%APPDATA%\ClippysRevenge\draft-invites.json` is never touched.

### §2 Times, subjects

- `s = DateTime.Today.AddDays(22).AddHours(5).AddMinutes(30)`, `e = s.AddMinutes(30)`
  (a different slot from `LiveCalendarTests`, so the two meetings of one run
  never look alike). Pass them as `yyyy-MM-ddTHH:mm` (invariant).
- Meeting subject: `$"[{fx.RunToken}] draft invite"`.
- Source email subject: `$"[{fx.RunToken}] meeting request"`.
- Expected note subject: `ReplySubject.Normalize(sourceSubject)` (starts
  with `Re:: `). Tracked (for cleanup) as `$"[{fx.RunToken}] " + expectedNoteSubject`,
  because `LiveDrafts.ReadDraft(..., tag: true)` prefixes it.

### §3 Order of steps (inside `fx.WithCleanupAsync([""], [olFolderCalendar, olFolderDrafts], async scope => { ... })`)

1. **Gate.** `await fx.RequireReadyAsync(ct)` and `var me = await fx.MeAsync()`
   **before** `WithCleanupAsync` (skips when `CLIPPY_LIVE` isn't `1` or Outlook
   isn't usable; never fails, never hangs).
2. **Master list before.** `var catBefore = await fx.RunAsync("reading the category list", app => MasterCategory(app, DraftInvites.CategoryName));`
3. **Sent snapshot for the mid-run check.** `var sentBefore = await fx.SnapshotSentAsync("");`
   (`WithCleanupAsync` takes its own for the final check.)
4. **Synthetic source.** Create a self-addressed unsent mail with the
   production `CreateDraftTool` exactly as `LiveAiDraftTests` 4.1 does
   (`new Signatures(_ => null, Path.Combine(fx.TempRoot, "no-signatures"))`,
   `new OutlookDraftWriter(fx.Worker, fx.Stores)`, `fx.Hub`), to
   `Recipients.Format([me])`, subject from §2, body
   `"Automated Clippy's Revenge live test: please find a time. Never sent; deleted by the test.\n" + fx.RunToken`.
   Track it at once: `scope.Track(new TrackedItem(TrackedKind.Draft, "", src.Id, ownStore, sourceSubject))`.
5. **Reply probe.** `var (probeHtml, probeHr) = await fx.RunAsync("checking Outlook's own reply", app => LiveDrafts.TryOwnReply(app, src.Id, ownStore));`
   `replyToId = probeHtml is null ? null : src.Id`. When null:
   `fx.Result("draft-invite-note", $"skipped: reply to an unsent item failed (HResult 0x{probeHr:x8})")`
   and the note checks in step 9 are skipped (the meeting checks still run).
   Rationale: some profiles can't reply to an unsent item (see `LiveAiDraftTests`).
6. **Create.** `var result = await invites.CreateDraftAsync(Recipients.Format([me]), meetingSubject, S, E, "Automated Clippy's Revenge live test. Never sent; deleted by the test.", null, null, replyToId, ct);`
   Immediately, before any assert:
   - if `result.EntryId.Length > 0`: `scope.Track(new TrackedItem(TrackedKind.Meeting, "", result.EntryId, result.StoreId.Length > 0 ? result.StoreId : ownStore, meetingSubject))`;
   - if `result.NoteDraftId is { } nid`: `scope.Track(new TrackedItem(TrackedKind.Draft, "", nid, ownStore, $"[{fx.RunToken}] " + expectedNoteSubject))`
     and then read+tag it: `var note = await fx.RunAsync("reading the note", app => LiveDrafts.ReadDraft(fx, app, "", nid, tag: true));`
   If `result.EntryId` is empty, fail with
   `"create_meeting_draft returned no EntryId; look for \"[<token>] draft invite\" in the calendar."`
   (cleanup's leftover scan then reports it).
7. **Meeting asserts** (`var m = await fx.RunAsync("reading the meeting", app => ReadMeeting(app, result.EntryId, storeId));`):
   - `result.Status == "saved_as_draft"`, `result.Category == DraftInvites.CategoryName`.
   - `Recipients.Parse(result.Recipients)` has exactly one entry whose
     `Email` equals `me.Email` (OrdinalIgnoreCase).
   - `m.Subject == meetingSubject`, `m.Start == s`, `m.End == e`.
   - `m.Status == Outlook.OlMeetingStatus.olMeeting`.
   - `m.Invited != true` — message `"PidLidFInvited is set: the meeting was invited."`
   - `m.ParentFolderId == fx.DefaultFolderId(app, "", olFolderCalendar)` (read in the same `RunAsync` or a second one).
   - `DraftInviteCategories.Split(m.Categories, CultureInfo.CurrentCulture.TextInfo.ListSeparator)`
     contains `DraftInvites.CategoryName` (OrdinalIgnoreCase).
   - Master list after: `var catAfter = MasterCategory(...)`; `catAfter.Exists` must be true.
     If `!catBefore.Exists`: `catAfter.Color == olCategoryColorOrange`, and
     `fx.Result("draft-invite-category", "ok (added by this run, orange)")`.
     Else: no colour assert (the user may have recoloured it; Clippy must not
     change it) and `fx.Result("draft-invite-category", $"ok (already in the list, colour {catAfter.Color})")`.
8. **Tracking + unsent branch of the check (real `DraftInvites`, no write).**
   - `tracked.Count == 1`; `tracked.Pending[0].Entry.EntryId == result.EntryId`;
     `tracked.Pending[0].Details` equals `new DraftInviteDetails(meetingSubject, s, e)`
     (set by `Track` at creation).
   - `new DraftInvitesStore(store.Path).Load()` has exactly one entry with that EntryId and `Mailbox == ""`.
   - `var lm0 = m.LastModified;` then `var pending = await tracked.CheckAsync(WorkPriority.Interactive, ct);`
   - `tracked.LastCheckUtc is not null` (the check really ran against Outlook;
     if null, `Assert.Skip(SkipTexts.NotResponding("the draft invite check", 30))`).
   - `pending` has exactly one entry, same EntryId, `Details.Subject == meetingSubject`, `Start == s`, `End == e`.
   - Read again: `LastModified == lm0`, categories still contain the category,
     `Status == olMeeting`, `Invited != true` (no write happened).
9. **Note** (only when `replyToId` is not null):
   - `result.NoteError` is null — on failure the assert message is
     `"The note was not saved: " + result.NoteError`.
   - `result.NoteDraftId` not null/empty; `result.Message` ends with
     `MeetingNoteText.SavedSuffix`.
   - From `note` (facts read **before** tagging): `note.Subject == expectedNoteSubject`;
     `Assert.StartsWith("Re:: ", note.Subject, StringComparison.Ordinal)`;
     `!note.Sent`; `note.ParentId == note.DraftsId`; `note.ClippyDraft == DraftMarker.Tool`.
   - Exact text: `var label = TimeZoneLabels.Resolve(fx.Settings.TimeZoneLabel, tz, s);`
     `var expected = MeetingNoteText.Text(s, e, label, meetingSubject, "");`
     Assert `Collapse(note.Text).Contains(Collapse(expected), Ordinal)` where
     `Collapse` replaces every run of whitespace (incl. `\r\n`, NBSP U+00A0)
     with one space and trims. Message: `"The note text in the reply draft is not the SPEC 22.4 text."`
     (Plain `Body` is used because Outlook rewrites the HTML on save.)
   - Highlight: report only, no assert —
     `fx.Result("draft-invite-note", (note.Html.Contains("ffff00", OrdinalIgnoreCase) || note.Html.Contains("yellow", OrdinalIgnoreCase)) ? "ok (highlighted)" : "ok (highlight not found in saved HTML)")`.
   - The source item is unchanged: `LiveDrafts.ReadDraft(fx, app, "", src.Id)` → `!Sent`, `Subject == sourceSubject`.
10. **Categories-only save on the unsent meeting (the RemoveCategory write path).**
    - Add a second category so "others kept" is checked against real COM:
      `SetCategories(app, entryId, storeId, $"{OtherCategory}, {DraftInvites.CategoryName}")`.
    - Run the production check with a forced "sent" decision:
      ```csharp
      var sep = CultureInfo.CurrentCulture.TextInfo.ListSeparator;
      DraftInviteSnapshot? seen = null;
      var entry = new DraftInviteEntry(result.EntryId, storeId, "", DateTimeOffset.UtcNow);
      var outcomes = await fx.RunAsync("the forced category removal", app =>
          OutlookCalendar.CheckDraftInvites(app, [entry], snap =>
          {
              seen = snap;
              // Simulates "the user sent it". Nothing is sent: only the decision is changed.
              return DraftInvites.Decide(snap with { Invited = true }, DateTime.Now, sep);
          }, null));
      ```
    - Real snapshot (`seen`), proving the COM reader sees an unsent meeting:
      `Lookup == Found`, `!InDeletedItems`, `MeetingStatus == 1`,
      `Invited != true`, `!OpenInInspector`, categories contain the category,
      and `DraftInvites.Decide(seen, DateTime.Now, sep)` is `(Keep, Unsent)`.
    - Outcome: single; `Decision.Action == RemoveCategory`, `Decision.Reason == Sent`,
      `Decision.NewCategories == OtherCategory`, `Applied == true`.
    - Read again: `Categories == OtherCategory` (trimmed, exact), `Status == olMeeting`,
      `Invited != true`, `ParentFolderId` still the Calendar,
      `Subject`/`Start`/`End` unchanged.
    - `await fx.AssertNothingSentAsync(sentBefore);` (counts and token subjects in Outbox and Sent Items).
    - `fx.Result("draft-invite-category-save", "ok (still unsent, nothing in Outbox/Sent)")`.
11. **End.** Leave the rest to `WithCleanupAsync`: it deletes the tracked
    items (meeting, source draft, note draft) by EntryID, purges this run's
    token items from Deleted Items, checks Calendar **and** Drafts for token
    leftovers, and asserts the Outbox and Sent Items counts and token subjects
    are unchanged across the whole test.

### §4 Edge cases

- `OutlookNotRespondingException`/`OutlookUnavailableException` anywhere go
  through `fx.RunAsync` and become skips (existing fixture behaviour); the
  calls to `invites.CreateDraftAsync` and `tracked.CheckAsync` that don't go
  through `fx.RunAsync` are wrapped: catch `OutlookNotRespondingException`
  → `Assert.Skip(SkipTexts.NotResponding("create_meeting_draft", 30))`;
  `OutlookUnavailableException` → `Assert.Skip(SkipTexts.NotRunning)`. Put
  the skip **after** the tracking of anything already created (skips inside
  the `WithCleanupAsync` body still run its cleanup).
- `ModelContextProtocol.McpException` from `CreateDraftAsync` (e.g. the
  user's own address doesn't resolve) is a test failure with its message.
- `seen` is captured on the worker thread and read after `RunAsync` returns;
  that's fine (the await is the happens-before).
- `SetCategories` and `CheckDraftInvites` are the only writes the test makes
  to the meeting; both are Categories + `Save()`.
- If the master category didn't exist before and `EnsureDraftCategory` had
  already run in this process (static `s_draftCategoryKnown`, e.g. after
  `LiveCalendarTests`), the "before" snapshot already sees it and only the
  existence is asserted. That's intended.
- Don't use `FindMeetings`-style token searches to identify the meeting;
  use `result.EntryId` (both calendar tests share one `RunToken`).
