## Public API

```csharp
namespace ClippysRevenge.Core;

/// <summary>search_emails filters for one mailbox (SPEC §11.1). Null/blank = no filter.</summary>
public sealed record SearchFilter
{
    public const int DefaultLimit = 50;
    public const int MaxLimit = 200;

    public string? Query { get; init; }
    public string? Sender { get; init; }
    public string? Recipient { get; init; }
    public string? Subject { get; init; }
    public DateTimeOffset? DateFrom { get; init; }   // inclusive
    public DateTimeOffset? DateTo { get; init; }     // inclusive
    public string? Folder { get; init; }
    public bool? HasAttachment { get; init; }
    public string? AttachmentName { get; init; }
    public string? AttachmentExt { get; init; }
    public bool? Unread { get; init; }
    public int Limit { get; init; } = DefaultLimit;
    public int Offset { get; init; }
}

/// <summary>One search hit. Date is UTC (offset 0); the tool converts to local.</summary>
public sealed record EmailSummary(
    string Id,                 // Outlook EntryID (emails.entry_id)
    string Folder,
    DateTimeOffset Date,       // from emails.event_time
    string From,               // sender_name
    string SenderEmail,
    string To,                 // to_addrs
    string Subject,
    bool HasAttachments,       // non-inline only (column value)
    IReadOnlyList<IndexedAttachment> Attachments, // all attachments, inline included, by Position
    string Snippet)
{
    public string Mailbox { get; init; } = "";
}

public static class SearchDates
{
    /// <summary>Parses date_from. Null/blank → null. Date-only → local midnight.
    /// Throws FormatException (message below) for anything else.</summary>
    public static DateTimeOffset? ParseFrom(string? text, TimeZoneInfo tz);

    /// <summary>Parses date_to. Null/blank → null. Date-only → the last second of
    /// that local day (next local midnight − 1 s). Throws FormatException.</summary>
    public static DateTimeOffset? ParseTo(string? text, TimeZoneInfo tz);
}

public sealed partial class EmailIndex   // (or plain class, matching M2.1)
{
    /// <summary>Clamps Limit to 1..200 and Offset to >= 0, then calls SearchPage.</summary>
    public IReadOnlyList<EmailSummary> Search(SearchFilter filter);   // ArgumentNullException on null

    internal IReadOnlyList<EmailSummary> SearchPage(SearchFilter filter, int skip, int take);
    // ArgumentNullException on null filter; ArgumentOutOfRangeException when skip < 0 or take < 0.
    // take == 0 returns an empty list without querying.
}
```

`Search` never throws for any filter content (odd text, SQL/FTS syntax,
inverted date range). Only `SqliteException`s from a broken/locked
database propagate. `SearchDates` throws only `FormatException`.

Null DB text columns map to `""`; null `size` → 0; null `is_inline`/
`has_attachments` → false.

## Behavior

### Query shape

- One SQL statement per call, built from **fixed SQL fragments** joined with
  `AND`; every user value is a **bound parameter** (Dapper or
  `SqliteCommand`, whichever M2.1 uses). No user text is ever concatenated
  into SQL.
- With an FTS expression (`FtsQuery.Build(filter.Query)` is non-null):
  `FROM emails_fts JOIN emails e ON e.id = emails_fts.rowid WHERE emails_fts MATCH @q AND …`
  and select
  `snippet(emails_fts, -1, '**', '**', '…', 16)`.
- Without one (Query null/blank, or `Build` returns null, e.g. `"--- ***"`):
  `FROM emails e WHERE …`, no MATCH, no FTS table referenced; select
  `substr(e.body, 1, 1000)` for the body snippet.
- Attachments come back in the same statement as a JSON column:
  `(SELECT json_group_array(json_object('p', a.position, 'n', a.filename, 's', a.size, 'i', a.is_inline)) FROM attachments a WHERE a.email_id = e.id)`,
  parsed with `System.Text.Json` and **sorted by position in C#**. No
  attachments → empty list (not null).
- `ORDER BY e.event_time DESC, e.id DESC LIMIT @take OFFSET @skip`.
  Newest first; ties broken by `id` so paging is stable. No rank ordering.

### Filters (all ANDed; blank after `Trim()` = no filter)

`Like(s)` below means the pattern `'%' + escaped + '%'` with `\`, `%`, `_`
escaped by `\`, used as `LIKE @p ESCAPE '\'`. SQLite `LIKE` is
case-insensitive for ASCII only; that is accepted.

| Filter | SQL rule |
|---|---|
| `Query` | `emails_fts MATCH @q` with `@q = FtsQuery.Build(Query)` (covers subject, body, sender, to, cc, attachment names) |
| `Sender` | `(e.sender_name LIKE @s ESCAPE '\' OR e.sender_email LIKE @s ESCAPE '\')`, `@s = Like(Sender.Trim())` |
| `Recipient` | see below |
| `Subject` | `e.subject LIKE @subj ESCAPE '\'` |
| `DateFrom` | `e.event_time >= @from`, `@from = DateFrom.Value.ToUnixTimeSeconds()` |
| `DateTo` | `e.event_time <= @to`, `@to = DateTo.Value.ToUnixTimeSeconds()` |
| `Folder` | `e.folder = @folder COLLATE NOCASE` with `@folder = NormalizeFolder(Folder)` |
| `HasAttachment` | `COALESCE(e.has_attachments, 0) = @ha` (1/0). Inline attachments never count (they don't set the column) |
| `AttachmentName` | `EXISTS (SELECT 1 FROM attachments a WHERE a.email_id = e.id AND a.filename LIKE @an ESCAPE '\')`, any attachment, inline included |
| `AttachmentExt` | `EXISTS (… a.filename LIKE @ext ESCAPE '\')` with `@ext = '%.' + escaped(ext)`; `ext` = trimmed value with **one** leading `.` removed. `pdf`/`.pdf`/`PDF` match `a.PDF`; `pdf` does not match `a.pdf.zip` or `pdf` (no dot). Blank after normalizing (`"."`) = no filter |
| `Unread` | `COALESCE(e.unread, 0) = @u` (1/0) |
| inverted range | `DateFrom > DateTo` just returns an empty list |

**Recipient.** Trim. If the value contains `;` or `<`, try
`Recipients.Parse(value)`. If it succeeds with ≥ 1 entry, the filter is
`(… OR …)` over each parsed email `i`:
`(e.to_addrs LIKE @r{i} ESCAPE '\' OR e.cc_addrs LIKE @r{i} ESCAPE '\')`
with `@r{i} = Like(email)`, i.e. mail involving **any** of the addresses.
Otherwise (no `;`/`<`, `FormatException`, or zero entries) use a single
plain substring `Like(value)` over `to_addrs OR cc_addrs`. Never throws.
Cap parsed addresses at 50 (ignore the rest) to bound the statement size.

**NormalizeFolder.** Trim; replace `/` with `\`; trim leading and trailing
`\`; then `inbox` (any case) → `Inbox`, `sent` or `sent items` (any case) →
`Sent Items`; otherwise keep the path. Comparison is case-insensitive and
exact: `inbox` does **not** include `Inbox\Projects`. Empty after
normalizing = no filter.

### Paging

- `Search`: `take = Math.Clamp(Limit, 1, 200)`, `skip = Math.Max(Offset, 0)`.
- `SearchPage`: uses `skip`/`take` as given (no cap).
- Offset past the end → empty list.

### Snippet

- FTS path: the `snippet()` value. If it is null or blank after whitespace
  collapsing, fall back to the body rule (select both `snippet(...)` and
  `substr(e.body,1,1000)` in the FTS path).
- Body rule: collapse every run of whitespace (`char.IsWhiteSpace`,
  includes `\r\n`, tabs, NBSP) to one space, trim, then cut to the first
  **200** chars; don't split a surrogate pair (if char 200 would be a high
  surrogate's partner, cut at 199). Null body → `""`.
- Collapse whitespace in the FTS snippet the same way (no 200 cut; the
  16-token window bounds it). Highlight markers are `**` … `**`, ellipsis `…`.

### `SearchDates`

Accepted (invariant culture, exact formats; `T` may also be a single space):

- `yyyy-MM-dd`
- `yyyy-MM-ddTHH:mm`, `yyyy-MM-ddTHH:mm:ss`, `yyyy-MM-ddTHH:mm:ss.FFFFFFF`
- any of the date-time forms followed by `Z` (UTC) or `±HH:mm` (that
  offset is honored as given).

Rules:

- Input is trimmed first; null/blank → `null`.
- Without an offset the value is a wall-clock time in `tz`:
  `new DateTimeOffset(dt, tz.GetUtcOffset(dt))` with `dt` of kind
  `Unspecified`. For a DST-gap or ambiguous time this uses whatever
  `GetUtcOffset` returns (no exception).
- `ParseFrom` date-only → local midnight of that day.
- `ParseTo` date-only → (local midnight of the next day) − 1 second,
  each midnight using its own `GetUtcOffset`. Date-time `ParseTo` is the
  instant itself (inclusive; `event_time` is whole seconds).
- Anything else (e.g. `03/01/2026`, `2026-3-1`, `yesterday`, `2026-02-30`)
  throws `FormatException` with exactly
  `` `<param> "<text>" is not a valid date. Use an ISO date like 2026-03-01 or a date-time like 2026-03-01T14:30 (local time).` ``
  where `<param>` is `date_from` for `ParseFrom` and `date_to` for
  `ParseTo`, and `<text>` is the trimmed input.
- `tz` null → `ArgumentNullException`.

## Spec changes (proposed)

Decisions below are low-risk and reversible; the coordinator should apply
them to SPEC.md.

1. §11.1, append after the paragraph that ends "otherwise it is the first
   200 characters of the body.":

> Filter details (M2.2): text filters are trimmed, and blank means no
> filter. `sender`, `recipient`, `subject` and `attachment_name` are
> case-insensitive substring matches (SQLite `LIKE`, ASCII case folding,
> with `%`, `_` and `\` matched literally). `recipient` is treated as a list
> when it contains `;` or `<` and `Recipients.Parse` accepts it; otherwise
> it is one substring. `folder` is compared case-insensitively and exactly
> with the stored folder path (`inbox` = `Inbox`, `sent` = `Sent Items`,
> `/` is accepted for `\`); subfolders are not included. `attachment_name`
> and `attachment_ext` look at every attachment, inline ones included;
> only `has_attachment` ignores inline attachments. `date_from`/`date_to`
> accept `yyyy-MM-dd` and `yyyy-MM-ddTHH:mm[:ss[.fffffff]]` (a space may
> replace `T`) in local time, or a date-time ending in `Z` or `±hh:mm`,
> which is honored. Both ends are inclusive. Anything else is an error:
> `date_from "<text>" is not a valid date. Use an ISO date like 2026-03-01 or a date-time like 2026-03-01T14:30 (local time).`
