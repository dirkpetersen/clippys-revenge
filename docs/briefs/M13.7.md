# M13.7 Live tests: `find_free_times` offers and meeting times in a real AI draft

Base: `dev` with **M13.1–M13.6 merged, M13.4 included** (this brief uses
M13.4's `DraftWorkerServices.FreeBusy` and step 6a). This task adds
**tests only**: no file under `src/` changes, no csproj change (every App
source needed is already linked), and no change to `scripts/run-live-tests.ps1`
(its `-Claude` switch already sets both variables). Nothing new runs in CI
except the pure helper tests in §T1, which run on Windows CI like
`LiveClaudeGuardTests`.

## Goal

Prove on the user's PC that meeting times work end to end against real
Outlook and the real Claude CLI (SPEC §21.9 "Live", using §21.5, §21.6,
§21.8, §11.8, §19.7 step 6a, §19.12, §15):

1. **`find_free_times` with `offer_cet=true`** (`[Trait("live","outlook")]`)
   for the current user only returns `offers` and an `offer_text` whose
   lines have the exact §21.5 shape, with consistent numbering, lists,
   ranking, CET part and office-hours split. The same call with
   `offer_cet=false` has no CET part and no second list.
2. **Manual AI draft with meeting times** (`[Trait("live","outlook")]` +
   `[Trait("live","claude")]`): a synthetic, self-addressed, unsent
   "can we meet next week for 30 minutes?" email goes through the
   production manual path (`DraftWorker.DraftSelectedAsync`) with
   `MeetingTimes` on and the real `OutlookFreeBusySource`. The saved reply
   draft has §21.5 option lines and no `[[meeting_times]]` left. Free/busy
   is read only for the user's own address, only after the model call
   returned, at `Interactive` priority. Nothing is sent; only the two
   items the test created are deleted.

Both are skipped, not failed, unless `CLIPPY_LIVE=1` (and, for 2,
`CLIPPY_LIVE_CLAUDE=1`) is set. Test 2 uses `claude-haiku-5-5` with effort
`low` and one model call, like M11.10.

## Hard rules that apply here

- **Never send.** The reply draft is made only by `OutlookReplyDraftWriter`
  (`.Save()` only) behind `RecordingReplyWriter`; the source by
  `OutlookDraftWriter` via `CreateDraftTool`. `WithCleanupAsync` asserts
  Sent Items/Outbox counts are unchanged and no run-token item reached
  either. Test code calls no `.Send(`, `.Display(`, `.Move(`.
- **Never delete mail.** No new delete code. Items are `Track`ed and
  deleted by `WithCleanupAsync` (entry id + `"[RunToken] "` subject only).
- **Attach-only.** Everything goes through the fixture's `OutlookWorker`.
- **`Re:: `**: the reply subject check stays
  `Assert.StartsWith("Re:: ", …)` and `== ReplySubject.Normalize(subject)`.
- **Claude credentials**: only `LiveClaude.CreateModel` / `CheckAsync`
  (unchanged). The model gets no tools; free/busy is read by Clippy after
  the call (§21.1), which `GuardedFreeBusySource` (§A.2) enforces.
- **Privacy (§19.11).** No times, dates, addresses, mail text, prompts or
  model output in `LIVE-RESULT` lines, skip texts or assertion messages.
  Use `Assert.True(cond, "<fixed text>")`; never `Assert.Equal`/`Contains`
  on offer lines, `offer_text`, bodies or prompts (they print on failure).
  Result lines carry counts, durations in minutes and yes/no flags only.
  No logger passed to `DraftWorker`, `ClaudeCliModel` or `FreeTimeFinder`.
- **Other people's calendars are never read.** Test 1 passes no
  recipients; test 2's free/busy guard refuses every address but the
  user's own (§A.2).

## Behavior

### A.1 `LiveMeetingChecks.Parse`

Use one `[GeneratedRegex]` (`CultureInvariant`, 1000 ms timeout; on
`RegexMatchTimeoutException` return null), anchored, matching the §21.5
format exactly (`–` is U+2013; single and double spaces as written):

```
^(?<n>[1-9][0-9]?)\. (?<ddd>Mon|Tue|Wed|Thu|Fri|Sat|Sun) (?<m>1[0-2]|[1-9])/(?<d>3[01]|[12][0-9]|[1-9])  (?<s>(?:[01][0-9]|2[0-3]):[0-5][0-9])–(?<e>(?:[01][0-9]|2[0-3]):[0-5][0-9])(?: (?<label>[^\s()]+(?: [^\s()]+)*))?(?:  \((?<cs>(?:[01][0-9]|2[0-3]):[0-5][0-9])–(?<ce>(?:[01][0-9]|2[0-3]):[0-5][0-9]) CET\))?$
```

Times are parsed with `TimeOnly.ParseExact(…, "HH:mm", InvariantCulture)`.
The label may not contain `(`, `)` or a double space (that keeps a
malformed CET part out of the label). Whether `Start < End` is not
checked here (midnight end is legal).

### A.2 `GuardedFreeBusySource`

As in the signatures. Reason order in `GetFreeBusyAsync`: `address`
first, then `before-model`. `Tripped` keeps the first reason. Calls are
sequential in practice; use plain fields (no locking needed, but
`Priorities` is a `List<WorkPriority>` exposed read-only).

### A.3 `GuardedModel(…, bool? meetingNote = null)`

After the existing `style` check and before `signature`:
- `meetingNote == true` and the system prompt does not contain both
  `"Meeting times:\n"` and `"[[meeting_times]]"` → reason `"meeting-note"`.
- `meetingNote == false` and the system prompt contains `"Meeting times:\n"`
  → reason `"meeting-note"`.
- `null` → no check (existing callers unchanged).

Use `DraftPrompt.MeetingNote`'s first line rather than a new literal where
practical (`DraftPrompt.MeetingNote[..DraftPrompt.MeetingNote.IndexOf('\n') + 1]`
is `"Meeting times:\n"`); `[[meeting_times]]` may be a literal.
