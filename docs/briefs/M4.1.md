# M4.1 `Program`: single instance, host, Kestrel on loopback, `/mcp` behind `BearerAuth`, `index_status` stub, tool-call activity filter

## Goal

Build the process shell (SPEC §1.2, §2, §3, §4, §7 last bullet, §11, §11.10,
§13, §14). `Program.Main` takes the single-instance mutex
`Local\ClippysRevenge` (a second launch tells the first one to open Settings
over a named pipe and exits), then starts the host: an ASP.NET Core
`WebApplication` (that is the generic host, `IHost`) with Kestrel bound to
`IPAddress.Loopback:Port` only, `BearerAuth` in front of `MapMcp("/mcp")`, a
call-tool filter that wraps every tool call in
`using (hub.Begin(Serving, toolName))` and records a `Tool` event with the
duration, and one stub tool `index_status`. Then it runs the WinForms message
loop on the STA main thread (an empty `ApplicationContext` until M4.3 brings
`TrayApp`).

Everything that doesn't need WinForms, COM or the registry goes in **Core**,
so the whole HTTP/MCP path (auth, binding check, filter, restart on port
change) and the single-instance pipe are tested on Linux with a real Kestrel
on an ephemeral loopback port. App only keeps `Program.cs` (wiring) and
`McpTools.cs` (the stub tool).

// McpHttpHost.cs
using Microsoft.Extensions.DependencyInjection;   // IMcpServerBuilder, IServiceCollection
using Microsoft.Extensions.Logging;

public sealed class McpHostOptions
{
    public required TokenHolder Tokens { get; init; }
    public required ActivityHub Hub { get; init; }
    /// Registers tools (App: b => b.WithTools<McpTools>()). Null = no tools.
    public Action<IMcpServerBuilder>? ConfigureMcp { get; init; }
    /// Extra app services (singleton instances that must outlive a restart,
    /// later hosted services such as SyncService). Null = none.
    public Action<IServiceCollection>? ConfigureServices { get; init; }
    /// Called after Logging.ClearProviders(). Null = no logging (tests).
    public Action<ILoggingBuilder>? ConfigureLogging { get; init; }
    public TimeProvider Time { get; init; } = TimeProvider.System;
}

public sealed class McpHttpHost : IAsyncDisposable
{
    public const string McpPath = "/mcp";
    public const string ServerName = "clippy";
    public const int MaxToolLabelLength = 64;

    /// <exception cref="ArgumentNullException">options, Tokens or Hub null.</exception>
    public McpHttpHost(McpHostOptions options);

    /// Actual bound port while running, else null (port 0 → the ephemeral port).
    public int? Port { get; }
    public bool IsRunning { get; }

    /// Builds and starts the WebApplication on 127.0.0.1:port.
    /// Returns true on success. Returns false (never throws) when the port is
    /// in use, the binding check fails, or startup throws; then IsRunning is
    /// false and an Error scope is held on the hub (see Behavior).
    /// <exception cref="ArgumentOutOfRangeException">port not 0 and not 1024–65535.</exception>
    /// <exception cref="InvalidOperationException">already running.</exception>
    /// <exception cref="ObjectDisposedException">after DisposeAsync.</exception>
    public Task<bool> StartAsync(int port, CancellationToken ct = default);

    /// Stop (if running) then StartAsync(port). Same return/throw rules,
    /// except "already running" never throws.
    public Task<bool> RestartAsync(int port, CancellationToken ct = default);

    /// Stops and disposes the WebApplication and clears the Error scope.
    /// No-op when not running.
    public Task StopAsync(CancellationToken ct = default);

    /// StopAsync, idempotent. Does NOT dispose Tokens or Hub.
    public ValueTask DisposeAsync();

    /// Binding check (§13). Returns the port of the single address
    /// "http://127.0.0.1:<port>"; throws InvalidOperationException otherwise.
    internal static int ValidateBindings(IReadOnlyCollection<string> addresses);
}

// SingleInstance.cs
public sealed class SingleInstance : IDisposable
{
    public const string DefaultMutexName = @"Local\ClippysRevenge";
    public const string ShowSettingsCommand = "show-settings";
    public const int MaxCommandLength = 64;

    /// "ClippysRevenge-" + Process.GetCurrentProcess().SessionId.
    public static string DefaultPipeName { get; }

    /// Returns null when another instance holds the mutex. Names are
    /// parameters so tests can use unique ones. Does not start the pipe.
    /// <exception cref="ArgumentException">a name is null/empty.</exception>
    public static SingleInstance? TryAcquire(string mutexName = DefaultMutexName, string? pipeName = null);

    /// Starts the background accept loop. onShowSettings runs on a
    /// thread-pool thread (caller marshals to UI). Call at most once.
    /// <exception cref="InvalidOperationException">called twice.</exception>
    /// <exception cref="ObjectDisposedException">after Dispose.</exception>
    public void StartListening(Action onShowSettings);

    /// Client side, synchronous (used from STA Main). Connects to pipeName
    /// (default DefaultPipeName) within timeoutMs (default 2000) and writes
    /// command + "\n". True if written, false on timeout/any IO error. Never throws.
    public static bool SignalExisting(string command, string? pipeName = null, int timeoutMs = 2000);

    /// Stops the loop, closes the pipe, releases the mutex. Idempotent.
    public void Dispose();
}

## Behavior

### A. `McpHttpHost.StartAsync` (build order matters)

1. Validate `port` (0 or 1024–65535), disposed, already running — under a
   `SemaphoreSlim(1,1)` that serializes Start/Stop/Restart/Dispose.
2. Dispose any held Error scope (a new attempt clears the old error).
3. Build:
   - `WebApplication.CreateSlimBuilder(new WebApplicationOptions { Args = [], ContentRootPath = AppContext.BaseDirectory })`,
     then `builder.Configuration.Sources.Clear()` so `ASPNETCORE_URLS`,
     `Kestrel__Endpoints__*` and similar can't add bindings.
   - `builder.Logging.ClearProviders(); options.ConfigureLogging?.Invoke(builder.Logging);`
   - `builder.WebHost.ConfigureKestrel(k => { k.Listen(IPAddress.Loopback, port); k.AddServerHeader = false; })`.
     Never `Any`/`IPv6Any`/`localhost`/`UseUrls`.
   - `HostOptions.ShutdownTimeout = 5 s`.
   - Register `options.Tokens`, `options.Hub`, `options.Time` as singleton
     **instances** (the container must not dispose them; they survive restarts),
     then `options.ConfigureServices?.Invoke(builder.Services)`.
   - `builder.Services.AddMcpServer(o => o.ServerInfo = new Implementation { Name = "clippy", Version = <Core assembly Version.ToString(3)> })`
     `.WithHttpTransport(t => t.Stateless = true)`
     `.WithRequestFilters(f => f.AddCallToolFilter(<activity filter, §B>))`,
     then `options.ConfigureMcp?.Invoke(mcpBuilder)`.
   - Do not add HTTP logging, W3C logging, CORS, HTTPS or any other endpoint.
4. Pipeline: `app.UseBearerAuth(); app.MapMcp(McpPath);` — auth runs for
   every path, so any request without a valid token gets 401 (unknown paths
   with a valid token get 404).
5. `await app.StartAsync(ct)`, then read
   `app.Services.GetRequiredService<IServer>().Features.Get<IServerAddressesFeature>()!.Addresses`
   and call `ValidateBindings`. On success set `Port`/`IsRunning`, return true.
6. Failures (catch everything except `OperationCanceledException` for `ct`):
   stop + dispose the half-built app, `IsRunning = false`, `Port = null`, hold
   `hub.Begin(ActivityState.Error, label)` until the next Start/Restart/Stop,
   log at Error (never the token), return false. Labels (exact):
   - any exception in the chain is `Microsoft.AspNetCore.Connections.AddressInUseException`
     → `port <n> is in use` (`<n>` = requested port, invariant culture, no separators);
   - `ValidateBindings` threw → `unexpected HTTP binding`;
   - anything else → `HTTP server failed to start`.

`ValidateBindings`: exactly one address; it parses as an absolute `Uri` with
scheme `http`, host `127.0.0.1` and a port 1–65535; returns that port.
Otherwise throws `InvalidOperationException("Refusing to serve: Clippy only listens on http://127.0.0.1:<port>. Found: <comma-joined addresses>")`.

`StopAsync`: `app.StopAsync(ct)`, `DisposeAsync`, clear `Port`/`IsRunning`,
dispose the Error scope. `RestartAsync` is Stop + Start under one semaphore hold.

### B. Tool-call activity filter (§7 last bullet)

```csharp
next => async (ctx, ct) =>
{
    var name = Label(ctx.Params?.Name);           // trimmed; "(unknown)" if blank; cut to 64 chars
    var start = time.GetTimestamp();
    var failed = true;
    using (hub.Begin(ActivityState.Serving, name))
    {
        try { var r = await next(ctx, ct); failed = r.IsError == true; return r; }
        finally { hub.Event(ActivityKind.Tool, failed ? $"{name} failed" : name, time.GetElapsedTime(start)); }
    }
}
```

- The event summary is the tool name only, or `<name> failed` when the call
  threw or returned `IsError = true`. Never arguments, results or error text
  (§6.4: "Events carry tool names, counts and subjects only").
- Exceptions propagate unchanged (the SDK turns them into tool errors).
- The Serving scope is always disposed, so the state returns to `Idle`.

### C. `SingleInstance`

- Mutex: `new Mutex(initiallyOwned: false, mutexName, out var createdNew)`;
  `createdNew == false` → dispose it and return null. Keep the handle for the
  lifetime of the object (no `WaitOne`, so no thread affinity).
- Pipe server: `NamedPipeServerStream(pipeName, PipeDirection.In, 1,
  PipeTransmissionMode.Byte, PipeOptions.Asynchronous | PipeOptions.CurrentUserOnly)`.
  Loop: `WaitForConnectionAsync(token)`, read one line (UTF-8) of at most
  `MaxCommandLength` chars with a 2 s read timeout, disconnect, repeat with a
  fresh server stream. A line equal (ordinal) to `show-settings` invokes the
  callback; anything else (unknown, too long, empty, timeout) is ignored. A
  throwing callback or IO error never ends the loop (catch, continue); only
  `Dispose` ends it.
- Client: `NamedPipeClientStream(".", pipeName, PipeDirection.Out, PipeOptions.CurrentUserOnly)`,
  `Connect(timeoutMs)`, write, flush. Catch everything → false.
- `Dispose`: cancel the loop, dispose the server stream, dispose the mutex.

### D. `Program.Main` (App, `[STAThread] static int Main(string[] args)`)

1. `ApplicationConfiguration.Initialize()`.
2. `using var instance = SingleInstance.TryAcquire();` If null:
   `SingleInstance.SignalExisting(SingleInstance.ShowSettingsCommand)`;
   return 0.
3. Create long-lived objects once: `loggerFactory = LoggerFactory.Create(b => b.AddDebug())`
   (rolling file logging is not part of this task), `var hub = new ActivityHub();`,
   `var settings = new Settings(); // M4.2: SettingsStore.Load()`,
   `var tokens = new TokenHolder(AuthToken.Generate()); // M4.2: persisted DPAPI token`.
   Never log the token.
4. Hook `Application.ThreadException`, `AppDomain.CurrentDomain.UnhandledException`
   and `TaskScheduler.UnobservedTaskException` to log at Critical
   (`SetUnhandledExceptionMode(CatchException)`).
5. `instance.StartListening(() => logger.LogInformation("Second launch asked to open Settings."));`
   (M4.3/M9.2 replace this with a UI post).
6. `var host = new McpHttpHost(new McpHostOptions { Tokens = tokens, Hub = hub,
   ConfigureMcp = b => b.WithTools<McpTools>(), ConfigureServices = s => s.AddSingleton(settings),
   ConfigureLogging = b => b.AddDebug() });`
   Start it without blocking the UI thread: `_ = StartHostAsync(host, settings.Port, logger);`
   where `StartHostAsync` awaits `host.StartAsync` and logs the bound port or
   the failure (the Error scope is already on the hub). It must not throw.
7. `Application.Run(new ApplicationContext()); // M4.3: new TrayApp(...)`.
8. After the loop exits: `Task.Run(() => host.DisposeAsync().AsTask()).Wait(TimeSpan.FromSeconds(5));`
   then dispose `hub` and `loggerFactory`; return 0. This is the one allowed
   blocking wait (process entry point after the message loop ends; `Task.Run`
   avoids the WinForms `SynchronizationContext`). Comment it as such.

No Outlook, COM, registry or `Process.Start` code in this task.

### E. `index_status` stub

Returns `new IndexStatusResult(hub.State.ToString(), null, [], "The email index is not available yet.")`
and ignores `mailbox`. The `state` will read `Serving` (the filter is active
during the call); that's expected. M7.1 replaces the body.

## Cross-task dependencies

- **M4.2 `SettingsStore`** (comes after; not needed now): M4.1 uses
  `new Settings()` and `AuthToken.Generate()`. M4.2 replaces the two lines
  marked `// M4.2:` in `Program.cs` and must use `AuthToken.Generate()` for
  the first-run token. Port changes later call `host.RestartAsync(newPort)`
  and token changes call `tokens.Set(...)` — no host restart.
- **M4.3 `TrayApp`**: replaces `new ApplicationContext()` with
  `new TrayApp(...)` and the `StartListening` callback (post to UI). It reads
  `hub`, `tokens.Current` and `host.Port` from `Program`. M4.3 owns those
  edits; M4.1 just leaves the marked seams.
- **M6.1 `SyncService`** registers via `McpHostOptions.ConfigureServices`
  (`AddHostedService`), so a host restart restarts HTTP and sync together (§14).
- **M7.1** replaces the `index_status` body.
