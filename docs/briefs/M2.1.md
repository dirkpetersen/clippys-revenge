# M2.1 `EmailIndex` schema, migrations, external-content FTS + triggers, `UpsertBatch`, `Delete`, `SetUnread`, `Get`

## Goal

Add the per-mailbox SQLite index to Core (SPEC §3 `EmailIndex.cs`, §9.1,
§9.2, §15 "EmailIndex" row). This task builds the schema exactly as in §9.1
(including the external-content `emails_fts` table and its sync triggers), a
small version-keyed migration runner on `meta.schema_version`, the
per-connection pragmas from §9.2, and the write/read primitives
`UpsertBatch`, `Delete`, `SetUnread` and `Get`. It also adds the data types
that cross the Core/App boundary: `IndexedEmail` (what `ReadForIndex`
produces, §8), `AttachmentInfo` and `EmailDetail` (what `get_message`
returns, §11.2). Hard rule: **attachment content never enters the index**,
only file names (§1.6, §9.1). `Search` (M2.2), `PurgeOlderThan` / `Status` /
sync state / `Close` (M2.3) and `MailboxIndexes` (M2.4) are not built here.

## Cross-task dependencies

Provided by this task, assumed by later tasks (M2.2, M2.3, M2.4, M6, M7):

- `EmailIndex` is a `public sealed class` in `ClippysRevenge.Core`. Its API
  is **synchronous**, matching the SPEC §9.2 signatures. (Microsoft.Data.Sqlite
  has no real async I/O; its `*Async` methods complete synchronously. Callers
  in async code call these directly. That's not a `.Result`/`.Wait()`.)
- `internal SqliteConnection OpenConnection()` returns an **open**
  connection with all four pragmas applied. M2.2 (`Search`) and M2.3
  (`PurgeOlderThan`, `Status`, sync state) must use it for every connection
  they open. They don't build their own connection strings.
- `internal string ConnectionString { get; }`, which M2.3 `Close()` passes to
  `SqliteConnection.ClearPool(new SqliteConnection(ConnectionString))`.
- `public string DbPath { get; }`.
- `public const int SchemaVersion = 1;`. A later task that changes the
  schema adds a migration step and bumps this (see Behavior, Migrations).
- `AttachmentInfo` is **the** attachment record for the whole project.
  M2.2's `EmailSummary.Attachments` should be `IReadOnlyList<AttachmentInfo>`
  rather than a new type.
- `EmailDetail` carries `StoreId` and `InternetMessageId`, which M2.4
  `Locate` and M5.3 `GetItem` (§8 fallback chain) need.
- Column names, the trigger names `emails_ai` / `emails_ad` / `emails_au`,
  and the `attachments` table are fixed as in §9.1 and below. M2.2 queries
  them directly.
- The `meta` keys `mailbox_smtp`, `store_id` and `retention_months` exist in
  the schema, but this task writes only `schema_version`. Writing the other
  keys belongs to M2.3/M2.4.

Consumed: `FtsQuery.Build` (M1.2), **only in tests**, to check that FTS
matches.

## Public API

```csharp
namespace ClippysRevenge.Core;

/// <summary>One attachment's metadata. Never its content (SPEC §1.6, §9.1).</summary>
public sealed record AttachmentInfo(int Position, string FileName, long? Size, bool IsInline);

/// <summary>One email as read from Outlook for indexing (SPEC §8 ReadForIndex).</summary>
public sealed record IndexedEmail
{
    public required string EntryId { get; init; }
    public string? StoreId { get; init; }
    public string? InternetMessageId { get; init; }
    public required string Folder { get; init; }
    public string? Subject { get; init; }
    public string? SenderName { get; init; }
    public string? SenderEmail { get; init; }
    public string? To { get; init; }
    public string? Cc { get; init; }
    public required DateTimeOffset EventTime { get; init; }      // ReceivedTime (Inbox) / SentOn (Sent)
    public DateTimeOffset? LastModified { get; init; }
    public bool Unread { get; init; }
    public string? Body { get; init; }
    public IReadOnlyList<AttachmentInfo> Attachments { get; init; } = [];
}

/// <summary>One indexed email as stored (SPEC §9.2 Get, §11.2 get_message).</summary>
public sealed record EmailDetail
{
    public required long RowId { get; init; }                   // emails.id
    public required string EntryId { get; init; }
    public string? StoreId { get; init; }
    public string? InternetMessageId { get; init; }
    public required string Folder { get; init; }
    public string? Subject { get; init; }
    public string? SenderName { get; init; }
    public string? SenderEmail { get; init; }
    public string? To { get; init; }
    public string? Cc { get; init; }
    public required DateTimeOffset EventTime { get; init; }     // UTC, offset zero, whole seconds
    public DateTimeOffset? LastModified { get; init; }          // UTC, offset zero, whole seconds
    public required bool Unread { get; init; }
    public required bool HasAttachments { get; init; }          // non-inline only
    public required IReadOnlyList<AttachmentInfo> Attachments { get; init; } // ordered by Position
    public string? Body { get; init; }
}

/// <summary>SQLite + FTS5 index for one mailbox (SPEC §9).</summary>
public sealed class EmailIndex
{
    public const int SchemaVersion = 1;

    /// Creates the file (and its parent directory) if missing, then creates or migrates the schema.
    /// Throws ArgumentException (null/empty/whitespace path),
    /// InvalidOperationException (DB schema_version newer than SchemaVersion, or not an integer),
    /// SqliteException (file is not a SQLite database, I/O errors), passed through.
    public EmailIndex(string dbPath);

    public string DbPath { get; }
    internal string ConnectionString { get; }

    /// Opens a pooled connection and applies the §9.2 pragmas. Caller disposes.
    internal SqliteConnection OpenConnection();

    /// One transaction for the whole batch. Throws ArgumentNullException (null list or null element),
    /// ArgumentException (validation, see Behavior) before anything is written.
    public void UpsertBatch(IReadOnlyList<IndexedEmail> emails);

    /// Returns the number of emails deleted. ArgumentNullException for a null sequence.
    public int Delete(IEnumerable<string> entryIds);

    /// Returns the number of rows that matched an entry id. ArgumentNullException for a null sequence.
    public int SetUnread(IEnumerable<(string entryId, bool unread)> changes);

    /// Null when not indexed. ArgumentException for null/empty entryId.
    public EmailDetail? Get(string entryId);
}
```

Use `ArgumentException.ThrowIfNullOrWhiteSpace` / `ArgumentNullException.ThrowIfNull`
for argument checks.

## Behavior

### Connections (§9.2)

- Connection string: `new SqliteConnectionStringBuilder { DataSource = fullPath, Mode = SqliteOpenMode.ReadWriteCreate, Pooling = true }.ToString()`,
  where `fullPath = Path.GetFullPath(dbPath)`. `DbPath` returns `fullPath`.
- `OpenConnection()` opens it and runs, outside any transaction:
  `PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL; PRAGMA foreign_keys=ON; PRAGMA busy_timeout=5000;`
  on **every** open, pooled or not.
- Every public operation opens its own connection with `using` and disposes
  it before returning. No connection is held in a field. The instance is
  safe to use from several threads at once.
- Write transactions use `connection.BeginTransaction()`. In
  Microsoft.Data.Sqlite that's `BEGIN IMMEDIATE`, which avoids
  read-to-write lock upgrade deadlocks between concurrent writers. Don't
  pass `deferred: true`.

### Migrations

- The constructor does `Directory.CreateDirectory(Path.GetDirectoryName(fullPath)!)`,
  then opens a connection and starts **one** transaction. Inside it, it reads
  the current version: 0 if the `meta` table doesn't exist
  (`SELECT 1 FROM sqlite_master WHERE type='table' AND name='meta'`) or has no
  `schema_version` row. Otherwise it's `int.Parse` of the value
  (`CultureInfo.InvariantCulture`).
- A non-integer value or a version greater than `SchemaVersion` throws
  `InvalidOperationException` with exactly:
  `Index database '<fullPath>' has schema version <v>, but this version of Clippy's Revenge supports up to <SchemaVersion>. Update Clippy's Revenge or rebuild the index.`
  (for a non-integer value, `<v>` is the raw string). The file is left untouched (rollback).
- Migrations are a private ordered list: step `n` upgrades `n-1 → n`. Run
  every step with `n > current`, in order, in the same transaction, then
  upsert `meta('schema_version', SchemaVersion.ToString(CultureInfo.InvariantCulture))`
  and commit. If any step fails, the whole migration rolls back.
- Reading the version inside the `IMMEDIATE` transaction makes two
  instances that open the same new file concurrently safe: the second
  instance sees version 1 and does nothing.
- If the version equals `SchemaVersion`, nothing is written.
- **Step 1** is the full §9.1 DDL, verbatim (same tables, columns, types,
  constraints and indexes, `tokenize='unicode61 remove_diacritics 2'`), plus
  these three triggers (the standard external-content pattern):

```sql
CREATE TRIGGER emails_ai AFTER INSERT ON emails BEGIN
  INSERT INTO emails_fts(rowid, subject, body, sender_name, sender_email, to_addrs, cc_addrs, attachment_names)
  VALUES (new.id, new.subject, new.body, new.sender_name, new.sender_email, new.to_addrs, new.cc_addrs, new.attachment_names);
END;
CREATE TRIGGER emails_ad AFTER DELETE ON emails BEGIN
  INSERT INTO emails_fts(emails_fts, rowid, subject, body, sender_name, sender_email, to_addrs, cc_addrs, attachment_names)
  VALUES ('delete', old.id, old.subject, old.body, old.sender_name, old.sender_email, old.to_addrs, old.cc_addrs, old.attachment_names);
END;
CREATE TRIGGER emails_au AFTER UPDATE OF subject, body, sender_name, sender_email, to_addrs, cc_addrs, attachment_names ON emails BEGIN
  INSERT INTO emails_fts(emails_fts, rowid, subject, body, sender_name, sender_email, to_addrs, cc_addrs, attachment_names)
  VALUES ('delete', old.id, old.subject, old.body, old.sender_name, old.sender_email, old.to_addrs, old.cc_addrs, old.attachment_names);
  INSERT INTO emails_fts(rowid, subject, body, sender_name, sender_email, to_addrs, cc_addrs, attachment_names)
  VALUES (new.id, new.subject, new.body, new.sender_name, new.sender_email, new.to_addrs, new.cc_addrs, new.attachment_names);
END;
```

  `emails_au` is restricted to the FTS columns (`UPDATE OF …`) so that
  `SetUnread`, which touches only `unread`, doesn't rewrite FTS rows. Any
  `UPDATE` that sets one of those columns, as the upsert's `DO UPDATE` does,
  still fires it. That keeps it correct.
- **Don't add any column the spec doesn't list.** In particular, no column
  for attachment content or attachment bytes, in either table.

### `UpsertBatch` (§9.2)

- Validate the **whole batch first**. Write nothing if any check fails:
  - list and elements non-null (`ArgumentNullException`);
  - `EntryId` and `Folder` non-null and not whitespace;
  - `Attachments` non-null, no null element, `FileName` non-null (empty is allowed);
  - attachment `Position` values unique within one email.
  Failures throw `ArgumentException` whose message contains the offending
  `EntryId` (when there is one) and the reason, e.g.
  `Email '<entryId>' has duplicate attachment position 2.`
- An empty list returns without opening a connection.
- One connection, one transaction for the whole batch. For each email, in
  list order:
  1. `INSERT INTO emails (entry_id, store_id, internet_message_id, folder, subject, sender_name, sender_email, to_addrs, cc_addrs, event_time, last_modified, unread, has_attachments, attachment_names, body) VALUES (…) ON CONFLICT(entry_id) DO UPDATE SET <every column except id and entry_id> = excluded.<col> RETURNING id`.
     **Never** `INSERT OR REPLACE` or `REPLACE`, and never delete-then-insert
     the email row: the `id` of an existing `entry_id` must not change.
  2. `DELETE FROM attachments WHERE email_id = @id`, then insert one row per
     attachment `(email_id, position, filename, size, is_inline)`.
- Column mapping:
  - `event_time` = `EventTime.ToUnixTimeSeconds()`. `last_modified` =
    `LastModified?.ToUnixTimeSeconds()` (NULL when null). Sub-second parts
    are truncated.
  - `unread` = 1/0.
  - `has_attachments` = 1 if any attachment has `IsInline == false`, else 0.
  - `attachment_names` = the file names of **all** attachments (inline
    included), ordered by `Position`, joined with `"\n"`. NULL when there
    are no attachments. Empty file names are skipped in the join, and an
    all-empty result is NULL.
  - All other strings are stored as given. NULL stays NULL, and `""` stays `""`.
- Duplicate `EntryId` within one batch: processed in order, so the last one
  wins (there's still one row).
- If anything throws mid-transaction, roll back and rethrow. The batch is
  all-or-nothing.

### `Delete`

- Skip null/empty ids. Run one transaction with
  `DELETE FROM emails WHERE entry_id = @e` per id, summing the affected
  rows, and return the sum. Attachment rows go through `ON DELETE CASCADE`
  (needs `foreign_keys=ON`), and FTS rows through `emails_ad`. Unknown ids
  count 0. If no valid ids remain, return 0 without opening a connection.

### `SetUnread`

- Skip null/empty ids. Run one transaction with
  `UPDATE emails SET unread = @u WHERE entry_id = @e` per change, summing
  the affected rows. It touches no other column (`last_modified` is
  unchanged). If no valid ids remain, return 0 without opening a connection.

### `Get`

- `entry_id` matching is exact and ordinal: SQLite's default `BINARY`
  collation. Outlook EntryIDs are passed through as-is.
- Return `null` when no row exists. Otherwise build `EmailDetail` from the
  row: times come from `DateTimeOffset.FromUnixTimeSeconds` (offset zero),
  `unread` NULL→false, `has_attachments` NULL→false, and `Attachments` are
  read from `attachments` `ORDER BY position`. `IsInline` NULL→false.
- Use Dapper with private row classes holding `long`/`long?` columns, then
  convert. Don't register global Dapper type handlers (they're process-wide
  state).

## Spec changes (proposed)

Low-risk, reversible. Proposed for the architect or user to merge into SPEC.md.

1. §9.1, replace the trigger comment lines with:
   ```
   -- kept in sync by triggers emails_ai (AFTER INSERT), emails_ad (AFTER DELETE) and
   -- emails_au (AFTER UPDATE OF subject, body, sender_name, sender_email, to_addrs,
   -- cc_addrs, attachment_names): the standard external-content pattern ('delete'
   -- with old values, then insert). SetUnread doesn't touch FTS.
   ```
2. §9.2, append after the `Get` bullet:
   ```
   - The API is synchronous (Microsoft.Data.Sqlite has no real async I/O).
     `Delete` and `SetUnread` return the number of rows affected; unknown
     ids are ignored. `UpsertBatch` validates the whole batch first
     (non-empty entry id and folder, unique attachment positions) and
     writes nothing on an `ArgumentException`. Times are stored as whole
     unix seconds and read back as UTC. `has_attachments` counts non-inline
     attachments only, and `attachment_names` holds every name, inline
     included, in position order. A database whose `schema_version` is
     newer than the app's makes the constructor throw; it is never
     modified or deleted automatically.
   ```
