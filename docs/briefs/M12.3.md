# M12.3 Swap, handover, rollback and the start-up decision

Base: `dev` with M12.1 merged. Core only. It runs in parallel with M12.2;
it doesn't use `UpdateClient` or `UpdateService`.

## Goal

Implement the file side of SPEC §20.9 in Core, so all of it is tested in
temp folders on Linux:
- `UpdateInstall.BeginAsync` checks the staged file and swaps it in
  (rename the running exe to `.old`, move the staged exe into place),
  then writes `Pending`.
- `UpdateHandover.RunAsync` runs in the old process after shutdown. It
  starts the new exe through an injected starter, waits for the new
  instance to confirm, and otherwise kills it, restores the old exe,
  remembers the failed version and starts the old exe again.
- `UpdateStartup` runs at every start of the installed copy. `Prepare`
  resolves a pending or failed handover, cleans the install folder,
  returns any notice and decides "install now". `Confirm` marks the new
  version as started. `CleanupOldAsync` deletes `.old`.

The App (M12.4) supplies the real process starter (`UpdateRestarter`)
and calls these from `Program`.

## Hard rules that apply here

- **Only the installed exe is ever started.** `UpdateHandover` calls
  `start(paths.ExePath)` and nothing else. It never builds a path from
  the state file, the network or settings. The App's starter refuses
  any other path (M12.4).
- File operations are `File.Move`, `File.Delete` and `File.Exists` on
  `paths.ExePath`, `paths.OldExePath` and files inside
  `paths.StagingDir`, plus the state file through `UpdateStateStore`.
  Nothing else is deleted. Nothing here touches Outlook, mail, the
  index, settings, the token or credentials.
- No `Process`, no `.Kill(` in Core: killing goes through
  `IUpdateProcess.Kill()`, which only the App implements.
- No `.Wait()`/`.Result`. Everything is `async` with `TimeProvider`
  delays. M12.4 owns the two entry-point blocking waits in `Program`.

## Public API

```csharp
namespace ClippysRevenge.Core;

/// <summary>The process started for a handover. The App wraps System.Diagnostics.Process (M12.4).</summary>
public interface IUpdateProcess : IDisposable
{
    bool HasExited { get; }
    /// <summary>Kills this process only (not its tree). May throw if it already exited; callers catch.</summary>
    void Kill();
    Task WaitForExitAsync(CancellationToken ct);
}

/// <summary>Message = an UpdateTexts reason (SPEC 20.10). The old exe is in place when this is thrown.</summary>
public sealed class UpdateInstallException : Exception
{
    public UpdateInstallException(string reason, Exception? inner = null);
}

public static class UpdateInstall
{
    public static readonly TimeSpan RetryFor = TimeSpan.FromSeconds(10);
    public static readonly TimeSpan RetryEvery = TimeSpan.FromMilliseconds(500);

    /// <summary>SPEC 20.9 "Swap": verify size + SHA-256, delete a leftover .old, rename exe → .old, move the staged
    /// file → exe (restore on failure), then Pending = {running, staged, now, false} and Staged = null.</summary>
    /// <exception cref="UpdateInstallException">Any failure; the installed exe is unchanged.</exception>
    /// <exception cref="OperationCanceledException">ct was cancelled before the first rename.</exception>
    public static Task<PendingInstall> BeginAsync(UpdatePaths paths, UpdateStateStore store, StagedUpdate staged,
        SemVersion running, TimeProvider? time = null, ILogger? log = null, CancellationToken ct = default);
}

public enum HandoverOutcome { Confirmed, RolledBack, RollbackFailed }

public static class UpdateHandover
{
    public static readonly TimeSpan ConfirmTimeout = TimeSpan.FromSeconds(60);
    public static readonly TimeSpan Poll = TimeSpan.FromMilliseconds(250);
    public static readonly TimeSpan KillWait = TimeSpan.FromSeconds(5);
    public static readonly TimeSpan RestoreRetryFor = TimeSpan.FromSeconds(10);

    /// <summary>SPEC 20.9 "Handover" and "Rollback". Never throws except OperationCanceledException for ct.</summary>
    /// <param name="start">Starts the exe at the given path. Called only with paths.ExePath.</param>
    public static Task<HandoverOutcome> RunAsync(UpdatePaths paths, UpdateStateStore store, PendingInstall pending,
        Func<string, IUpdateProcess> start, TimeProvider? time = null, ILogger? log = null, CancellationToken ct = default);
}

/// <param name="InstallNow">The staged update to install before anything else starts, or null.</param>
/// <param name="ConfirmAfterStart">This process is the new version of a pending handover.</param>
/// <param name="Notice">A notice to show once after the tray is up (already cleared from the state), or null.</param>
public sealed record StartupUpdatePlan(StagedUpdate? InstallNow, bool ConfirmAfterStart, UpdateNotice? Notice)
{
    public static StartupUpdatePlan Nothing { get; }   // (null, false, null)
}

public static class UpdateStartup
{
    public static readonly TimeSpan OldDeleteRetryFor = TimeSpan.FromSeconds(60);
    public static readonly TimeSpan OldDeleteRetryEvery = TimeSpan.FromSeconds(1);

    /// <summary>SPEC 20.9 "UpdateStartup.Prepare". Call only for the installed copy. Never throws: I/O errors are
    /// logged and the step is skipped.</summary>
    public static StartupUpdatePlan Prepare(UpdatePaths paths, UpdateStateStore store, SemVersion running,
        UpdateMode mode, ILogger? log = null);

    /// <summary>Pending for this version and not yet confirmed → Confirmed = true; returns
    /// Notice(Updated, Pending.FromVersion, Pending.ToVersion). Otherwise null. Never throws (I/O errors → logged, null).</summary>
    public static UpdateNotice? Confirm(UpdateStateStore store, SemVersion running, ILogger? log = null);

    /// <summary>Deletes paths.OldExePath, retrying every second for up to 60 s, then clears a confirmed Pending for
    /// this version. Never throws except OperationCanceledException for ct.</summary>
    public static Task CleanupOldAsync(UpdatePaths paths, UpdateStateStore store, SemVersion running,
        TimeProvider? time = null, ILogger? log = null, CancellationToken ct = default);
}
```

## Behavior

### A. `RetryAsync` (private helper)

`RetryAsync(Action op, TimeSpan retryFor, TimeSpan every, TimeProvider time, CancellationToken ct)`:
it runs `op`, catches `IOException` and `UnauthorizedAccessException`,
waits `every` (`Task.Delay(every, time, ct)`) and tries again until
`retryFor` has passed since the first try. Then it rethrows the last
exception. `FileNotFoundException` and `DirectoryNotFoundException` are
**not** retried (they derive from `IOException`, so filter them out).

### B. `UpdateInstall.BeginAsync`

1. `v = SemVersion.Parse(staged.Version)` (a bad value →
   `UpdateInstallException(ReasonStagedMissing)`). `src = paths.StagedExePath(v)`.
2. `!File.Exists(src)` → clear `Staged` in the store → throw
   `ReasonStagedMissing`.
3. `new FileInfo(src).Length != staged.Size` → delete `src` (best
   effort), clear `Staged` → throw `ReasonSizeMismatch`.
4. `!UpdateHash.Same(await UpdateHash.OfFileAsync(src, ct), staged.Sha256)`
   → delete `src`, clear `Staged` → throw `ReasonHashMismatch`. An I/O
   error while hashing → `ReasonReplaceFailed(type)` (keep the file).
5. `!File.Exists(paths.ExePath)` →
   `ReasonReplaceFailed("FileNotFoundException")`.
6. `File.Exists(paths.OldExePath)` → `RetryAsync(() => File.Delete(old))`.
   Failure → `ReasonOldInUse`.
7. `RetryAsync(() => File.Move(exe, old))`. Failure →
   `ReasonReplaceFailed(type)`. From here on, `ct` is no longer
   honoured: pass `CancellationToken.None`, so a half-done swap can't
   be left behind.
8. `RetryAsync(() => File.Move(src, exe))`. On failure:
   `RetryAsync(() => File.Move(old, exe))` to restore. If the restore
   also fails, log Critical
   `"Update swap failed and the old exe could not be restored; run install.ps1 to repair."`.
   Throw `ReasonReplaceFailed(type of the first failure)`.
9. `pending = new PendingInstall(running.ToString(), v.ToString(), now, false)`.
   `store.Update(s => { s.Pending = pending; s.Staged = null; s.LastError = null; })`.
   An I/O error here is logged (Warning) and ignored: the files are
   already swapped, and without `Pending` the new instance starts as a
   normal start, with `.old` cleaned at the next start.
10. Log Information `"Update swap: {From} -> {To}"` and return `pending`.

"Clear `Staged`" is a `store.Update(s => s.Staged = null)` whose I/O
errors are logged and ignored.

### C. `UpdateHandover.RunAsync`

1. `p = start(paths.ExePath)`. Any exception (not `ct` cancellation) →
   log Error (type) → `Rollback(null)`.
2. `deadline = now + ConfirmTimeout`. Loop:
   - `if (store.TryLoad(out var s) && IsConfirmed(s, pending))` →
     dispose `p`, log Information `"Update handover: {To} confirmed"`,
     return `Confirmed`.
   - `p.HasExited` → log Warning `"Update handover: {To} exited before confirming"`
     → `Rollback(p)`.
   - `now >= deadline` → log Warning `"Update handover: {To} did not confirm within 60 s"`
     → `Rollback(p)`.
   - `await Task.Delay(Poll, time, ct)`.
   - `IsConfirmed(s, pending)` = `s.Pending is null || (s.Pending.ToVersion == pending.ToVersion && s.Pending.Confirmed)`.
     A failed `TryLoad` (file being replaced) means "not yet".
3. **`Rollback(p)`**:
   - If `p` isn't null and hasn't exited: `p.Kill()` (catch any
     exception other than `OperationCanceledException`), then wait for
     `p.WaitForExitAsync` up to `KillWait`. `p?.Dispose()`.
   - `!File.Exists(paths.OldExePath)` → log Critical → return
     `RollbackFailed` (state unchanged).
   - Retry for up to `RestoreRetryFor`, every
     `UpdateInstall.RetryEvery`:
     `if (File.Exists(exe)) File.Delete(exe); File.Move(old, exe);`.
     Failure → log Critical
     `"Update rollback failed; run install.ps1 to repair."` → return
     `RollbackFailed` (state unchanged, so the next start sees
     `Pending`).
   - `store.Update(s => { s.FailedVersion = pending.ToVersion; s.Pending = null; s.Staged = null; s.Notice = new UpdateNotice(UpdateNoticeKind.RolledBack, pending.ToVersion, pending.FromVersion); })`.
     I/O errors are logged and ignored.
   - `start(paths.ExePath).Dispose()` (don't wait; exceptions logged).
   - Log Warning `"Update to {To} rolled back to {From}"`. Return
     `RolledBack`.
4. `ct` cancellation → `OperationCanceledException`. `Program` passes
   `CancellationToken.None`; the token is for tests.

### D. `UpdateStartup.Prepare`

All on the calling thread, synchronous, using `store.Load()`. Each file
step catches `IOException`/`UnauthorizedAccessException`, logs them
(Information, type) and continues. In order:
1. `s = store.Load()`. `notice = s.Notice`, `s.Notice = null`.
   `confirm = false`.
2. `s.Pending` not null:
   - `ToVersion == running.ToString()` → `confirm = true` (keep
     `Pending`).
   - Otherwise → `s.FailedVersion = Pending.ToVersion`,
     `notice = new UpdateNotice(RolledBack, Pending.ToVersion, running.ToString())`,
     `s.Pending = null`. Log Warning `"Update to {To} didn't take; staying on {Running}"`.
3. `s.Pending == null && File.Exists(exe) && File.Exists(old)` → one
   `File.Delete(old)`.
4. Staging: if `s.Staged` is set, keep it only when its version parses,
   `UpdatePolicy.IsUpdate(v, running, s.FailedVersion)`, and its file
   exists with `Length == Size`; else `s.Staged = null`. If
   `paths.StagingDir` exists, delete every `*.partial` file and every
   file whose name parses with `TryParseStagedFileName` and isn't the
   kept `Staged` file. Leave other files and subfolders alone.
5. `store.Save(s)` (I/O error → log Warning; the plan still uses `s`).
6. `installNow = mode == UpdateMode.Install && !confirm ? s.Staged : null`.
7. Return `new StartupUpdatePlan(installNow, confirm, notice)`. Log
   Information `"Update start-up: install {InstallNow}, confirm {Confirm}, notice {Kind}"`
   (versions or `-`).

`Prepare` doesn't hash: `BeginAsync` does that right before the swap.

### E. `UpdateStartup.Confirm`

`store.Update(s => …)`: when `s.Pending?.ToVersion == running.ToString()`
and `!Confirmed`, set `Confirmed = true` and capture
`new UpdateNotice(Updated, Pending.FromVersion, Pending.ToVersion)`.
Return the captured notice, or null. A second call returns null. I/O
errors → log Warning, return null. (The old process may then time out
and roll back. That's the safe outcome.)

### F. `UpdateStartup.CleanupOldAsync`

Until `OldDeleteRetryFor` has passed: if `!File.Exists(old)`, stop;
else `File.Delete(old)`, and on `IOException`/`UnauthorizedAccessException`
wait `OldDeleteRetryEvery`. Afterwards, if `old` is gone,
`store.Update(s => { if (s.Pending is { Confirmed: true } p && p.ToVersion == running.ToString()) s.Pending = null; })`.
If it's still there, log Information `"ClippysRevenge.exe.old is still in use; it is deleted at the next start."`.
It never touches `exe`.

## Tests

Harness: `root` = a new temp folder; `paths = UpdatePaths.Default(root)`;
create `paths.InstallDir`, write `exe` = bytes `"MZold"`, a staged file
`paths.StagedExePath(0.0.6)` = `"MZnew" + 2 MiB of zeros` with its real
SHA-256 and size; `store = new UpdateStateStore(paths.StateFile)`;
`ManualTimeProvider`. Tests that advance time drive the delays by
advancing the fake clock from the test. Delete `root` in `Dispose`.

### T1 `UpdateInstallTests`
1. Happy path: after `BeginAsync`, `exe` has the new bytes, `old` has
   `"MZold"`, the staged file is gone, and the state has
   `Pending = (0.0.5, 0.0.6, now, false)`, `Staged` null and `LastError`
   null. The returned `PendingInstall` equals the stored one.
2. A leftover `old` is deleted first, then the swap works.
3. Staged file missing → `ReasonStagedMissing`, `exe` unchanged,
   `Staged` cleared.
4. Wrong size → `ReasonSizeMismatch`, staged file deleted, `exe`
   unchanged. Wrong hash (same size, one byte flipped) →
   `ReasonHashMismatch`, same checks.
5. `exe` missing → `ReasonReplaceFailed("FileNotFoundException")`.
6. Windows-only (`[Trait("os","windows")]`): `old` held open with
   `FileShare.None` → after the 10 s of retries (advance the fake
   clock) → `ReasonOldInUse`, and `exe` unchanged.
7. Windows-only: the staged file held open with `FileShare.Read` while
   `File.Move(src, exe)` runs → the move fails → `exe` is restored from
   `old` with `"MZold"`, `old` is gone, `ReasonReplaceFailed(...)`.
8. A store whose folder is read-only, or a store path that is a
   directory → the swap still completes and returns `Pending`; no
   exception.
9. `ct` cancelled before the call → `OperationCanceledException`, no
   file changed.

### T2 `UpdateHandoverTests`

`ExitWhenKilled` flag. The starter records each path, returns the next
scripted process, or throws.

3. A state file that can't be read during one poll (write `{` for one
   poll, then the confirmed state) → keeps polling, then `Confirmed`.
4. Early exit: the process reports `HasExited = true` before confirming
   → `RolledBack`. `exe` again has `"MZold"`, `old` is gone, the
   state has `FailedVersion = 0.0.6`, `Pending` null, `Staged` null and
   `Notice = (RolledBack, "0.0.6", "0.0.5")`. The starter was called a
   second time with `paths.ExePath`.
5. Timeout: never confirms, never exits; advance the clock by 60 s →
   `Kill()` called, then `RolledBack` as above.
6. The starter throws on the first call → `RolledBack` without a kill,
   and a second start of the restored exe.
7. `old` missing when rolling back → `RollbackFailed`, the state still
   has `Pending`, no second start.
8. Windows-only: `exe` held open (`FileShare.None`) for the whole
   restore window → `RollbackFailed` after 10 s; `old` still exists.
9. The starter is only ever called with `paths.ExePath` (assert on

7. `InstallNow`: mode `Install`, `Staged` 0.0.6 valid, running 0.0.5 →

   file is deleted. `Staged` 0.0.5 with running 0.0.5 → null, deleted.
   Wrong size → null, deleted. File missing → null, `Staged` cleared.
8. A store file that can't be read → treated as empty, nothing thrown.
9. `Confirm`: matching unconfirmed `Pending` → returns

10. `CleanupOldAsync`: `old` deletable → deleted, and the confirmed

11. Round trip of the full flow on Linux: `BeginAsync` → a fake new
    process whose start callback runs `Prepare` (confirm),
    `Confirm` and `CleanupOldAsync` against the same store → the
    handover returns `Confirmed`, `old` gone, `Pending` null.

### T4 `RunningExeRenameTests` (`[Trait("os","windows")]`)
Proves the Windows behavior that §20.9 relies on. Copy
`%SystemRoot%\System32\PING.EXE` to a temp folder as `ClippysRevenge.exe`,
then start it with `-n 30 127.0.0.1` (`UseShellExecute = false`,
`CreateNoWindow = true`). While it runs:
- `File.Delete(path)` throws `UnauthorizedAccessException`;
- `File.Move(path, path + ".old")` succeeds;
- a new file can be written at `path`.
Then kill the process in a `finally`, wait for it to exit, and delete
the folder. (Test code may start processes; the safety scan only
covers `src/`.)

## Spec changes

None beyond the M12 architect commit. Decisions recorded here:

1. A rollback `Notice` uses `FromVersion` = the failed version and
   `ToVersion` = the version running again (SPEC §20.7 states this).
2. `Confirm` doesn't store a notice. The new process shows the
   `Updated` balloon directly (SPEC §20.9).
3. After the first rename the swap ignores cancellation, so the
   install folder is never left without an exe by a cancel.
