# M5.3 `OutlookMail` reads: `ReadForIndex`, `IsInline`, Table enumeration, DASL dates, `GetItem` chain

## Goal

Build the read side of the Outlook mail layer (SPEC §8 bullets `GetItem`,
`ReadForIndex`, `EnumerateChanged`/`EnumerateRange`, `ListEntryIds`,
`IsInline`; §4 COM release rule; §5.2 `IndexedFolders` path rules; §9.1
what the index stores; §10 steps 3–5 for how sync calls it; §15 live-test
row "the DASL date helper"; §17 Table-scan performance). Almost all of the
logic goes in **Core** as pure functions over plain values: DASL filter
strings, Table column lists, raw-row → `MailTableRow` mapping, exact
filtering and tie-safe paging, Outlook date conversion, folder-path
canonicalization, the inline-attachment rule, SMTP address selection, and
the `GetItem` fallback chain behind a small `IMailItemSource<TItem>`
interface. Core tests cover all of it on Linux. The **App** part
(`OutlookMail.cs`) is a thin COM layer: it opens folders and Tables, streams
`GetArray` rows into Core, opens `MailItem`s, reads properties, and
releases every COM object. Every App method runs **on the worker thread**:
callers wrap them in `OutlookWorker.RunAsync` (M6.1, M6.2, M7.x).

## Hard rules that apply here

- No `.Send()`, no `.Save()`, no `.Delete()`, no `.Move()`, no property
  writes. This task only reads.
- Never launch Outlook. Don't write `new Application(`,
  `new Outlook.Application(`, `Activator.CreateInstance` or
  `CoCreateInstance` anywhere, not even in comments (M10.1 scans text).
- **Attachment content never enters the index.** Read only `Type`,
  `FileName`, `DisplayName`, `Size`, `Index` and three metadata properties
  (hidden flag, content id, MIME tag). Never `SaveAsFile`, never
  `PR_ATTACH_DATA_BIN` (`0x37010102`), never `PR_ATTACH_DATA_OBJ`.
- **"Gone" errors must reach the worker.** Every `catch` of
  `COMException` (or of `Exception`) in COM code uses
  `when (!ComErrors.IsOutlookGone(ex))`, so a disconnect still drops the
  instance (M5.1). `ComSafe.Try` below does this for you.
- Release every COM object you get (`Folder`, `Table`, `Columns`, `Store`,
  `NameSpace`, `MailItem`, `Attachments`, `Attachment`, `PropertyAccessor`,
  `Recipients`, `Recipient`, `AddressEntry`, `ExchangeUser`, `Folders`) with
  `Marshal.ReleaseComObject` in `finally`, and **inside loops** for
  per-row/per-item objects (§4).
- No file paths here, so `PathPolicy` is not involved. Don't add any.

## Behavior

### 1. `OutlookDates`

- `TruncateToSecond(t)`: `t.ToUniversalTime()`, then drop sub-second ticks
  (`ticks - ticks % TimeSpan.TicksPerSecond`), offset zero.
- **Outlook's "no date"** is 4501-01-01. A value is "none" when its year
  is ≥ 4501, or it is ≤ 1601-01-01 (covers `DateTime.MinValue` and the
  FILETIME zero).
- `FromTableValue(v)`: `null`, `DBNull`, a non-`DateTime` → null. "None" →
  null. `Kind` `Utc` or `Unspecified` is taken as UTC; `Local` is
  converted with `ToUniversalTime()`. Then `TruncateToSecond`.
- `FromLocal(dt, zone)`: "none" → null. Otherwise
  `utc = DateTime.SpecifyKind(dt, Unspecified) - zone.GetUtcOffset(dt)`
  (never `ConvertTimeToUtc`, which throws in the DST gap), then
  `TruncateToSecond(new DateTimeOffset(utc, TimeSpan.Zero))`.
  `ArgumentNullException` for a null zone.

### 2. DASL filters (the "single helper", §8)

- `Literal(t)`: `t.ToUniversalTime()`, seconds and below dropped,
  `ToString("yyyy-MM-dd HH:mm", CultureInfo.InvariantCulture)`. DASL
  compares dates in UTC. The literal is never built from the current
  culture, so Hijri/Buddhist calendars and `dd.MM.yyyy` locales don't
  matter.
- **Widen, then filter exactly.** Every date bound in a filter is moved
  outward by `Margin` (1 day): lower bounds use `Literal(bound - Margin)`,
  upper bounds `Literal(bound + Margin)`. The DASL result is therefore a
  superset no matter whether Outlook compares at minute precision or
  reads the literal as local time (offsets are at most 14 h). The exact
  bounds are applied in Core (`MailTableQueries`) on the UTC row values.
- Every filter also restricts the item class. Exact strings (`P(x)` is the
  property URL in double quotes):

  ```text
  Changed: @SQL=(P(LastModifiedProp) >= '<Literal(modifiedFrom - 1d)>') AND (P(EventTimeProp(field)) >= '<Literal(cutoff - 1d)>') AND (P(MessageClassProp) LIKE 'IPM.Note%')
  Range:   @SQL=(P(EventTimeProp(field)) >= '<Literal(from - 1d)>') AND (P(EventTimeProp(field)) < '<Literal(to + 1d)>') AND (P(MessageClassProp) LIKE 'IPM.Note%')
  Since:   @SQL=(P(EventTimeProp(field)) >= '<Literal(since - 1d)>') AND (P(MessageClassProp) LIKE 'IPM.Note%')
  ```

  Example, `Changed(Received, 2026-03-10T12:00:30Z, 2025-03-10T00:00:00Z)`:

  ```text
  @SQL=("http://schemas.microsoft.com/mapi/proptag/0x30080040" >= '2026-03-09 12:00') AND ("http://schemas.microsoft.com/mapi/proptag/0x0E060040" >= '2025-03-09 00:00') AND ("http://schemas.microsoft.com/mapi/proptag/0x001A001F" LIKE 'IPM.Note%')
  ```

- `ByMessageId(imid)`: the SPEC §8 form, with `'` doubled inside the
  literal and the value otherwise unchanged (not trimmed):
  `@SQL="http://schemas.microsoft.com/mapi/proptag/0x1035001F" = '<imid>'`.
- No other code builds DASL or Jet date strings. Don't use `Restrict`,
  `Find` or `Items` anywhere in this task.

### 3. Rows (`MailTable.ToRow`)

Values arrive in `Columns(field)` order:
`[EntryID, LastModified, EventTime, UnRead, InternetMessageId, MessageClass]`.

- `EntryId`: `values[0] as string`, trimmed. Null/empty/`DBNull` → row is
  null.
- `MessageClass`: `values[5] as string`; `!IsIndexedClass` → null.
  `IsIndexedClass`: equals `IPM.Note`, or starts with `IPM.Note.`
  (OrdinalIgnoreCase). So `IPM.Note.SMIME` yes; `IPM.NoteX`,
  `IPM.Schedule.Meeting.Request`, `REPORT.IPM.Note.NDR` no.
- `EventTime`: `FromTableValue(values[2])`; null → row is null (an item
  with no received/sent time is not indexed).
- `LastModified`: `FromTableValue(values[1])` ?? `EventTime`.
- `Unread`: `values[3] is bool b && b`.
- `InternetMessageId`: `values[4] as string`, trimmed; empty → null.

### 4. Paging (`MailTablePager.Take`) and the caller recipes

- Walk `sortedRows` once. Check order on **every** row (kept or not)
  against the previous row's `key`: ascending needs `key >= previous`,
  descending `key <= previous`; a violation throws
  `InvalidOperationException("Table rows are not sorted.")`.
- Skip rows where `keep` is false (they don't count).
- Add kept rows. Once `maxRows` rows are in the page, keep adding rows
  whose key **equals** the last added key (a page never splits a group of
  equal keys). Stop at the first further kept row with a different key:
  `HasMore = true`. Don't read past that row. When the source ends,
  `HasMore = false`.
- Dispose the enumerator (use `foreach`), so the App iterator's `finally`
  releases the Table even when the page stops early.
- `MailTableQueries`: map with `ToRow`, drop nulls, then:
  - `Changed`: `mf = TruncateToSecond(modifiedFrom)`, `c = TruncateToSecond(cutoff)`;
    keep `row.LastModified >= mf && row.EventTime >= c`; key `LastModified`,
    ascending.
  - `Range`: `f`, `t` truncated likewise. If `f >= t` return an empty page
    (`HasMore = false`) without enumerating. Keep `f <= row.EventTime < t`;
    key `EventTime`, descending.
  - `EntryIds`: `s` truncated; keep `row.EventTime >= s`; no order check;
    return `MailEntryState(EntryId, Unread)`, first occurrence wins.
- **Recipes for callers (document them in XML docs on the App methods;
  M6.1 follows them):**
  - Changes pass: call with `modifiedFrom = watermark`. If `HasMore`, call
    again with `modifiedFrom = last.LastModified + 1 s` (lossless, because
    the page holds the whole last tie group). When `HasMore` is false,
    store `watermark = last.LastModified` (inclusive, so an item changed
    later in that same second is seen next cycle). Rows whose
    `LastModified` equals the index's `last_modified` for that entry id are
    unchanged: don't open them (§8 "open the full MailItem only for rows
    that are new or changed").
  - Backfill: call with `to = oldest_synced`. Next call
    `to = last.EventTime` (exclusive, lossless for the same reason). Stop
    when `HasMore` is false.

### 5. Folders (`MailFolderPath`, `ResolveFolder`)

- `Parse(path)`: null → `ArgumentNullException`. Replace `/` with `\`,
  split on `\`, trim each segment, drop empty segments. None left →
  `ArgumentException("Folder path is empty.", nameof(path))`. If the
  first segment equals `Inbox` (OrdinalIgnoreCase) → root `Inbox`,
  canonical first segment `Inbox`. `Sent Items` likewise → `SentItems`,
  `Sent Items`. Otherwise root `StoreRoot` and every segment is in
  `SubPath`, kept as typed. `Canonical` = segments joined with `\`.
- `TimeFieldFor`: `SentItems` root (the folder or any subfolder) → `Sent`;
  everything else → `Received`. (§8 says `SentOn` for Sent; this extends
  it to Sent Items subfolders.)
- `IndexedFoldersFor(settings, mailbox)`: key = `MailboxIndexes.Normalize(mailbox)`.
  `""` → `settings.IndexedFolders`; otherwise
  `settings.FindSharedMailbox(key)?.IndexedFolders`, null → `[]`. Copy the
  list first (`ToArray()`), skip null/blank and entries `Parse` rejects,
  canonicalize, dedupe OrdinalIgnoreCase keeping first-seen order. Null
  lists → `[]`. Never throws for bad entries. `ArgumentNullException` for
  null settings.
- `FromOutlook(folderPath, inboxName, sentItemsName)`: null/blank → null.
  Strip leading `\` characters, split on `\`, drop empty segments. The
  first segment is the store name: drop it. None left → null. If the next
  segment equals `inboxName` (OrdinalIgnoreCase, both non-blank) replace
  it with `Inbox`; else if it equals `sentItemsName` replace with
  `Sent Items`. Return `Parse(joined).Canonical`.
- `MailFolderNotFoundException` message, `<where>` being
  `your own mailbox` for `""` and `mailbox "<smtp>"` otherwise:
  `Folder "<path>" was not found in <where>. Check the indexed folders in the Clippy tray settings.`
- **App `ResolveFolder(app, mailbox, path)`**: `key = MailboxIndexes.Normalize(mailbox)`,
  `p = MailFolderPath.Parse(path)`, `store = stores.Get(app, key)`
  (its `McpException` propagates). Start folder: `Inbox` →
  `store.GetDefaultFolder(olFolderInbox)`, `SentItems` →
  `store.GetDefaultFolder(olFolderSentMail)`, `StoreRoot` →
  `store.GetRootFolder()`. For each `SubPath` segment, iterate the
  current folder's `Folders` (1-based) and pick the first whose `Name`
  equals the segment (OrdinalIgnoreCase); release every non-matching child
  inside the loop, and the parent once you've moved on. No match →
  `MailFolderNotFoundException(key, p.Canonical)`. Result:
  `new ResolvedFolder(key, p.Canonical, folder.EntryID, store.StoreID, TimeFieldFor(p))`.
  Release folder and store in `finally`.
- `OpenFolder(app, rf)`: `app.Session.GetFolderFromID(rf.FolderEntryId, rf.StoreId)`
  as `Outlook.Folder`. A non-gone `COMException` →
  `MailFolderNotFoundException(rf.Mailbox, rf.Path)`. Release the
  `NameSpace`.

### 6. Table enumeration (App)

For `EnumerateChanged`, `EnumerateRange` and `ListEntryIds`:

1. `folder = OpenFolder(app, rf)`.
2. `table = folder.GetTable(<DaslFilter…>, OlTableContents.olUserItems)`.
3. `cols = table.Columns; cols.RemoveAll();` then `cols.Add(c)` for each of
   `MailTable.Columns(rf.TimeField)`. Release `cols`.
4. Sort: Changed → `table.Sort(MailTable.SortLastModified, false)`; Range →
   `table.Sort(MailTable.EventTimeSort(rf.TimeField), true)`; ListEntryIds
   → no sort.
5. Stream rows with an iterator: loop `while (!table.EndOfTable)`:
   `var arr = (object[,])table.GetArray(200);` and yield each row as an
   `object?[]` of 6 values (use `GetLowerBound`/`GetUpperBound`, don't
   assume 0- or 1-based). An empty array ends the loop. The iterator's
   `finally` releases the table.
6. Hand the stream to `MailTableQueries.Changed/Range/EntryIds`. Release
   `folder` in `finally`.

`EnumerateRange` with `from >= to` returns an empty page without opening
anything. `maxRows` is validated before any COM call (same
`ArgumentOutOfRangeException` as the pager).

`ListEntryIds` reads every matching row in one call. It runs once a day per
folder (§10 step 5); that's acceptable.

### 8. Inline rule (`InlineAttachments`, §8 `IsInline`)

1. `Type == OlOle` → true (htmlBody not called).
2. `Hidden` → true (not called).
3. If `IsImage(MimeTag, FileName)` and `ContentId` is non-blank →
   `IsReferenced(htmlBody(), ContentId)`.
4. Otherwise false (not called).

- `IsImage`: MIME tag starts with `image/` (OrdinalIgnoreCase), or the file
  extension (after the last `.`, OrdinalIgnoreCase) is one of `png jpg
  jpeg jpe gif bmp dib tif tiff webp svg ico emf wmf heic`.
- `IsReferenced(html, cid)`: null/blank html or cid → false. Trim the cid,
  strip one pair of surrounding `<` `>`, trim again; blank → false. Find
  every occurrence of `cid:` + cid (OrdinalIgnoreCase); true when one is
  followed by end of text or a char that is **not** a letter, digit, or
  one of `. @ _ - % +`. So `cid:image001.png@01DA"` matches cid
  `image001.png@01DA`, but `cid:image001.png@01DA2` doesn't.
- `FileNameFor`: trimmed `fileName` if non-blank, else trimmed
  `displayName` if non-blank, else `attachment-<position>`. The name is
  stored as-is; `FileNames.SafeFileName` is applied only when saving (M7.2).

### 9. Addresses (`MailAddresses`)

- `LooksLikeSmtp(s)`: trimmed, non-empty, exactly one `@`, not first or
  last, no whitespace inside. (`/o=ExchangeLabs/...` → false.)
- `ChooseSenderSmtp` / `ChooseRecipientSmtp`: candidates in the order given
  in the API, each func evaluated only if the earlier candidates failed;
  return the first candidate that `LooksLikeSmtp`, trimmed; else null.
  Case is kept.
- `FormatList`: take the first `MaxRecipientsPerField` entries. Per entry:
  trim both; smtp present and `LooksLikeSmtp` → name blank or equal to the
  smtp (OrdinalIgnoreCase) → `smtp`, else `Name <smtp>` (same output as
  `Recipients.Format` for one `Recipient`; reuse it). No smtp → the name;
  both blank → skipped. Join with `"; "`. Nothing left → null.

### 9b. `ComSafe.Try`

`try { return f(); } catch (COMException ex) when (!ComErrors.IsOutlookGone(ex)) { return default; }`.
`ArgumentNullException` for a null `f`. Use it for **optional** reads only
(properties that may be missing). Required reads (`EntryID`, `Subject`,
`Body`, …) are not wrapped, so a broken item fails as a whole and
`ReadBatch` lists it as missing.

### 10. `GetItem` chain (`MailItemResolver.Resolve`, §8)

`key` below is always the mailbox key from `locate` or `mailboxes`.

0. `id` trimmed; null/blank → `ItemNotFoundException(id)` with no source
   calls.
1. `located = locate(id)`.
2. **Located:** `storeId = located.Email.StoreId` if non-blank, else
   `source.StoreIdFor(located.Mailbox)`. If `storeId` is null → step 5.
   - `item = source.TryGetById(id, storeId)` → found: return
     `(item, located.Mailbox, id, storeId)`.
   - Else, if `located.Email.InternetMessageId` is non-blank: for each
     folder in `indexedFolders(located.Mailbox)` (in order):
     `newId = source.FindByMessageId(located.Mailbox, folder, imid)`;
     non-null → `item = TryGetById(newId, storeId)`; found → return
     `(item, located.Mailbox, newId, storeId)`; null → next folder.
   - Then step 5.
3. **Not located** (not indexed yet, §11.2): for each `m` in `mailboxes`
   (own first, as `MailboxIndexes.Mailboxes` orders them):
   `sid = StoreIdFor(m)`; null → next; `item = TryGetById(id, sid)`;
   found → return `(item, m, id, sid)`.
4. (no internet-message-id search for unindexed ids: there's nothing to
   search by.)
5. Throw `ItemNotFoundException(id)`.

- The resolver catches nothing: exceptions from `source` propagate.
- **`ItemNotFoundException` message** (`<id>` = trimmed id, cut to 200
  chars plus `…` when longer):
  `Email "<id>" was not found in Outlook. It may have been deleted or moved to a folder that isn't indexed. Run search_emails again to get a current id.`
- **App `ComItemSource`** (private, worker thread):
  - `StoreIdFor(m)`: `stores.Get(app, m)` → `StoreID`, release; catch
    `McpException` → null; non-gone `COMException` → null.
  - `TryGetById(entryId, storeId)`: `Session.GetItemFromID(entryId, storeId)`;
    non-gone `COMException` → null (covers `MAPI_E_NOT_FOUND` and bad ids);
    not a `MailItem` → release, null.
  - `FindByMessageId(m, path, imid)`: `rf = ResolveFolder(app, m, path)`
    (catch `MailFolderNotFoundException` → null), open it, `GetTable(DaslFilter.ByMessageId(imid), olUserItems)`,
    columns `EntryID` only, first row's entry id or null. Release all.
- `Resolve(app, id)`: `MailItemResolver.Resolve(id, indexes.Locate,
  indexes.Mailboxes, m => MailFolderPath.IndexedFoldersFor(settings, m),
  new ComItemSource(this, app))`.
- `GetItem` returns `.Item`; the caller releases it.
- `ReadById(app, id)`: `r = Resolve(app, id)`; `ReadForIndex(r.Item)`
  (derives the folder); release the item in `finally`; return
  `new LiveEmail(r.Mailbox, email)`.

## Spec changes (proposed)

The architect doesn't edit SPEC.md in this parallel run. Proposed text:

1. **§3 Core list**, add:
   ```
       MailTable.cs            DASL date filters, Table columns/rows, tie-safe paging, Outlook dates
       MailFolders.cs          indexed-folder paths (Inbox/Sent Items canonical), ResolvedFolder
       MailItemRead.cs         inline rule, SMTP choice, To/CC format, GetItem chain, ItemNotFoundException
   ```
2. **§8**, after the `IsInline` bullet, add **"Details (M5.3)"**:
   > - `OutlookMail` methods run on the worker thread and take the
   >   `Outlook.Application`; callers wrap them in `RunAsync`. Folders
   >   are resolved once to a `ResolvedFolder` (mailbox, canonical path,
   >   folder EntryID, store id, time field) and reopened with
   >   `GetFolderFromID`. `Inbox`/`Sent Items` and their subfolders use
   >   the store's default folders; `Sent Items` and its subfolders use
   >   `SentOn`, every other folder `ReceivedTime`.
   > - Only `IPM.Note` and `IPM.Note.*` items are indexed (meeting
   >   requests, reports and other classes are skipped). Items without a
   >   received/sent time are skipped by the Table passes.
   > - DASL date literals are UTC `yyyy-MM-dd HH:mm` (invariant culture),
   >   built only by `DaslFilter`. Every bound is widened by one day and
   >   the exact bounds are applied in Core on the Table's UTC values, so
   >   neither minute precision nor local/UTC interpretation can drop
   >   items. Table date columns are added by MAPI property tag, so they
   >   come back in UTC; all times are truncated to whole seconds. A
   >   date of 4501-01-01 means "none".
   > - `EnumerateChanged` (ascending `LastModificationTime`, inclusive
   >   lower bound) and `EnumerateRange` (newest first, `from` inclusive,
   >   `to` exclusive) return pages of at most 500 rows that never split
   >   a group of equal times, plus `HasMore`. The next changes page uses
   >   `last + 1 s`; the next backfill page uses `to = last`.
   > - `To`/`CC` are stored as `Name <smtp>; …` (at most 500 recipients
   >   per field). SMTP addresses come from `PR_SMTP_ADDRESS` /
   >   `PR_SENDER_SMTP_ADDRESS`, the address itself, or the Exchange
   >   user, in that order (sender: Exchange user first for `EX`).
   > - `IsInline` image test: MIME type `image/*` or an image file
   >   extension, and `cid:<content id>` appears in the HTML body as a
   >   whole token. `HTMLBody` is read only when needed.
   > - `GetItem` for an id that isn't indexed tries
   >   `GetItemFromID(id, storeId)` in each enabled mailbox, own first.
   >   `ItemNotFoundException` is an `McpException`:
   >   `Email "<id>" was not found in Outlook. It may have been deleted or moved to a folder that isn't indexed. Run search_emails again to get a current id.`
   >   A configured folder that doesn't exist gives
   >   `Folder "<path>" was not found in <your own mailbox | mailbox "<smtp>">. Check the indexed folders in the Clippy tray settings.`
