# M9.2 `SettingsForm` (all tabs, validation messages, Test connection via `initialize`)

## Goal

Build the Settings window (SPEC §6.3) with its four tabs (Connection,
Index, Scheduling, General) over the existing `Settings` model and
`Settings.Validate()` (§5.2), with every validation message shown next to
its field. Changes are staged in a draft and take effect only on **OK** or
**Apply**; **Cancel** discards them (§6.3). Applying is live (§5.2
"Applied" column): port change restarts Kestrel in-process, a regenerated
token is swapped into `TokenHolder`, retention/folder/mailbox changes reach
`SyncService`/`MailboxIndexes`, Start with Windows writes the Run key, and
`LogLevel` takes effect on the M9.4 file log at once. **Test connection**
sends an MCP `initialize` to `POST http://127.0.0.1:<port>/mcp` without and
with the token and expects `401` and a JSON-RPC result with `serverInfo`
(§6.3, §13). The window warns before a port change or token regeneration
(§6.3 last paragraph). All logic that doesn't need WinForms or COM
(draft/diff, applying, error routing, stats text, the connection test)
goes in **Core** and is tested on Linux; the App gets the form, a COM
folder lister, and wiring.

The 2026-11-12 smoke test showed the first COM call can hang for minutes
when Outlook is "Not Responding". So **the form never waits on COM on the
UI thread**: everything COM-backed (mounted mailboxes, folder tree) loads
asynchronously with a 15 s limit and degrades to "configured values only".
The worker-side timeout is M9.5's job, not this task's.

## Hard rules that apply here

- **Token never logged**, never put in an exception message, `ToString()`,
  activity event or connection-test message. `ConnectionTester` results
  mention the port and HTTP status only, never the token or response body.
- The connection test talks to `127.0.0.1` only (literal IP, no
  `localhost`), with `UseProxy = false`, and **never sends an `Origin`
  header**. It does not weaken `BearerAuth` in any way.
- No COM on the UI thread; COM only through `OutlookWorker.RunAsync(...,
  WorkPriority.Interactive, ct)`. No new way to get an
  `Outlook.Application`. No `.Send(`, no `.Display(` in any file of this
  task (the M10.1 scan matches text, comments included).
- Every folder path the user types/browses (`AttachmentDir`,
  `AllowedFolders`) is validated by the existing `Settings.Validate()`
  rules (fully qualified, no UNC/device). Tools keep enforcing them through
  `PathPolicy`; this task doesn't touch `PathPolicy`.
- No `.Result` / `.Wait()` anywhere in this task. WinForms event handlers
  may be `async void` but must catch everything and show it in the form.

## Cross-task dependencies (parallel work)

- **M9.4** (file log, parallel): assume a `RollingFileLoggerProvider` whose
  options take `Func<LogLevel> MinLevel`. Program must pass
  `() => settings.LogLevel` (the **live** instance), so `CopyFrom` on Apply
  changes the level with no extra call. If M9.4 landed with a snapshot
  value instead, change only the Program wiring to a `Func`; don't touch
  the provider.
- **M9.1** (shared-mailbox submenu, parallel) also enables/disables shared
  mailboxes. If M9.1 has already landed a Core helper that does
  "enable → `MailboxIndexes.Add` / disable → `MailboxIndexes.Remove(smtp,
  deleteFile)`", call it from `SettingsApplier` instead of duplicating; if
  not, `SettingsApplier` owns it and the M9 reviewer folds M9.1 onto it.
- **M9.3** and **M9.1** edit `TrayApp.cs`/`TrayServices` too. Keep the
  `TrayApp` edit to: one new optional trailing record parameter, the body
  of `ShowSettings`, and disposing the open form. Nothing else.
- **M9.5** will add a COM watchdog and cache `OutlookStores.List`. This task
  only adds its own 15 s `WaitAsync` on the UI side; don't build a worker
  timeout here.

## Behavior

### Editor and diff (Core)

- `SettingsEditor(live)` clones; the form edits only `Draft`. Opening the
  form, Cancel, or closing with the title-bar X never touches live state.
- `TrySetInt` field names are the `SettingsError.Field` names:
  `Port`, `RetentionMonths`, `SyncIntervalSeconds`, `WorkStartHour`,
  `WorkEndHour`, `InviteConfirmTimeoutSeconds`,
  `SharedMailboxes[i].RetentionMonths`. Integer fields are plain
  `TextBox`es (not `NumericUpDown`, which would clamp silently and hide the
  spec's messages).
- `Errors()` returns the messages from `Settings.Validate()` unchanged
  (e.g. `"Must be between 1024 and 65535."`). Don't invent new range texts.
- `Changes(live)`:
  - `PortChanged`: `Draft.Port != live.Port`. `TokenChanged`:
    `PendingToken is not null`.
  - `StartWithWindowsChanged`: values differ.
  - `RetentionChanged`: global `RetentionMonths` differs, or a shared
    mailbox (matched by normalized SMTP) present in both has a different
    `RetentionMonths` (null vs value counts).
  - `SyncPlanChanged`: `SyncIntervalSeconds` differs, or own/shared
    `IndexedFolders` differ as sets of canonical paths
    (`MailFolderPath.IndexedFoldersFor`, case-insensitive, order ignored),
    or `EnabledMailboxes`/`DisabledMailboxes` is non-empty.
  - `EnabledMailboxes` / `DisabledMailboxes` compare the enabled sets by
    `EmailAddress.Normalize(Smtp)`. `DeleteIndexes` =
    `PendingIndexDeletes ∩ DisabledMailboxes` (a delete for a mailbox that
    is enabled again in the draft is dropped).
  - `Any`: `Draft.ToJson() != live.ToJson()` or `TokenChanged` or
    `DeleteIndexes` non-empty.
- `MailboxChoices()` lists enabled shared mailboxes only. Disabled entries
  stay in `Draft.SharedMailboxes` (M1.7 decision: unchecking keeps the
  entry) and come back through **Add**, keeping their folders/retention.

### Apply (Core `SettingsApplier.ApplyAsync`)

Runs under a `SemaphoreSlim(1,1)`. Steps, in this order:

1. `errors = editor.Errors()`. Non-empty → return them, nothing applied.
2. `changes = editor.Changes(Live)`. `!changes.Any` → return OK, nothing done.
3. **Port** (if changed): `oldRunning = ServerPort()`;
   `ok = await RestartServer(Draft.Port)`. If `!ok`: if `oldRunning` was
   not null, `await RestartServer(Live.Port)` (clears the host's Error
   scope); return error `("Port", $"Port {Draft.Port} is in use or can't be opened. The server stays on port {Live.Port}.")`.
   Nothing else applied. A throw from `RestartServer` is treated as `!ok`
   (logged with `LogWarning`, exception message not shown).
4. **Save**: `Store.Save(editor.Draft)`. On `IOException` /
   `UnauthorizedAccessException`: if step 3 moved the port, restart back
   on `Live.Port`; return error `("", "Couldn't save settings: " + ex.Message)`.
5. **Token** (if pending): `Store.SaveToken(PendingToken)` then
   `Tokens.Set(PendingToken)`. If saving throws IO/UnauthorizedAccess:
   warning `"Couldn't save the new auth token; the old one still works."`,
   don't `Set`. (Order matters: the old token keeps working until the new
   one is on disk.)
6. `Live.CopyFrom(editor.Draft)`.
7. **Mailboxes** (only when `Indexes` is not null): for each
   `EnabledMailboxes` key → `Indexes.Add(key)`; on exception warning
   `$"Couldn't open the index for {key}: {ex.Message}"`. For each
   `DisabledMailboxes` key → `Indexes.Remove(key, deleteFile: DeleteIndexes.Contains(key))`;
   on `IOException`/`UnauthorizedAccessException` warning
   `$"Couldn't delete the index file for {key}; it was kept."`.
8. **Start with Windows** (if changed): `SetStartWithWindows(Live.StartWithWindows)`;
   any exception → warning `"Couldn't update the Windows startup entry: " + ex.Message`.
9. **Sync**: if `RetentionChanged` → `RetentionChanged?.Invoke()` (it
   wakes the loop itself). Else if `SyncPlanChanged` → `SyncNow?.Invoke()`.
   Never call `NotifySettingsChanged` for non-retention changes (M6
   review: it cancels the running cycle).
10. Log one `Information` line: `"Settings applied: {Fields}"` with the
    changed top-level property names only (no values, never the token).
    Warnings are logged at `Warning`.

`LogLevel`, `NotifyOnErrors`, scheduling and path settings need no extra
step: every consumer reads the live instance (or `() => settings`), so
step 6 is enough.

### Connection test (Core `ConnectionTester`)

- Request body (exact):
  `{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"clippy-settings","version":"1"}}}`
  `Content-Type: application/json`, `Accept: application/json, text/event-stream`.
  No `Origin`, no cookies. URL `http://127.0.0.1:{port}/mcp`.
- Step 1 without `Authorization`; step 2 with
  `Authorization: Bearer <token>`. Each step has its own `timeout`
  (default 5 s). Read at most `MaxResponseBytes` of the body.
- `ReadServerName`: media type `application/json` → parse whole body;
  `text/event-stream` → the `data:` lines of the first event (joined with
  `\n`, `data:` prefix and one optional space stripped). Returns
  `result.serverInfo.name` when it is a JSON string; any parse failure →
  null.
- Results (exact strings; `<port>` invariant):

| Case | Ok | Message |
|---|---|---|
| `port` null | false | `✗ The server isn't running. Check the tray icon for the reason.` |
| connect refused / other `HttpRequestException` | false | `✗ Nothing answers on 127.0.0.1:<port>.` |
| a step times out | false | `✗ The server on 127.0.0.1:<port> didn't answer within 5 s.` (whole seconds of `timeout`, rounded up, invariant) |
| step 1 status ≠ 401 | false | `✗ The server answered without a token (HTTP <code>). Another program may be using port <port>.` |
| step 2 status 401 | false | `✗ The server rejected the token (HTTP 401).` |
| step 2 other non-200 | false | `✗ The server answered HTTP <code> to initialize.` |
| step 2 200, name null | false | `✗ The server answered, but not with an MCP initialize result.` |
| step 2 200, name ≠ `McpHttpHost.ServerName` | false | `✗ Another MCP server (<name>) is answering on port <port>.` — name cut to 40 chars, control chars removed |
| step 2 200, name = `clippy` | true | `✓ Connection works: 127.0.0.1:<port> needs the token and answers MCP.` |

- The test always uses the **running** server: `ServerPort()` and
  `Tokens.Current`, not the draft. If the draft has a pending port or
  token change, the form shows, under the result, `Testing the running
  server. Press Apply first to test your changes.`

### Form (App `SettingsForm`)

General:
- Modeless, one instance (TrayApp keeps the reference; `ShowSettings`
  activates and `SelectTab`s an open one). `FormBorderStyle.FixedDialog`,
  `ShowInTaskbar = true`, title `Clippy's Revenge — Settings`
  (`BalloonTexts.Title + " — Settings"`).
- Bottom row: **OK**, **Cancel**, **Apply**, and a status label left of
  them. `AcceptButton = null` (Enter in a text box must not apply),
  `CancelButton = Cancel`.
- **OK / Apply**: (1) `editor.Errors()`; if any, set an `ErrorProvider`
  error on each field's control with the message, switch to `TabFor` of
  the first error, for `SharedMailboxes[i]…` select that mailbox in the
  picker, and stop. (2) If `changes.PortChanged`, ask
  `SettingsTexts.PortChangeQuestion` (OK/Cancel, Warning icon, Cancel
  default); Cancel → stop, nothing applied. (3) Disable the three buttons,
  `await Applier.ApplyAsync(editor)`. (4) On errors: show them like (1).
  On success: replace the editor with `new SettingsEditor(GetSettings())`,
  rebind the controls (keep tab and picker selection), show warnings (if
  any) in the status label, or `Saved.` otherwise. OK closes the form only
  on success.
- Re-run `editor.Errors()` on every field's `Validated` event and refresh
  all `ErrorProvider` entries (cheap; no COM).
- Closing the form cancels any pending COM loads/stat refreshes (a
  `CancellationTokenSource` cancelled in `OnFormClosed`); late results are
  ignored when `IsDisposed`.

**Connection** tab:
- Port text box (`Port`).
- Token text box, read-only, `UseSystemPasswordChar = true`, shows
  `editor.PendingToken ?? Tokens.Current`. **Show** toggles masking
  (button text Show/Hide). **Copy** puts the shown token on the clipboard.
  **Regenerate…** asks `SettingsTexts.RegenerateQuestion` (OK/Cancel,
  Warning, Cancel default); OK → `editor.RegenerateToken()`; nothing is
  saved until OK/Apply.
- Command box, read-only, multi-line: while the token is masked it shows
  `SettingsTexts.MaskedMcpAddCommand(port)`; after **Show** it shows
  `TrayText.McpAddCommand(port, token)`. `port` is the draft port when it
  parses, else the live port. **Copy** always copies the full
  `TrayText.McpAddCommand` and shows `BalloonTexts.Copied` in the status
  label. Clipboard `ExternalException` → status `Couldn't reach the clipboard — try again.`
- **Test connection**: disabled while running; runs
  `ConnectionTester.TestAsync(ServerPort(), Tokens.Current)`; shows the
  message in a label next to it (green for ✓, red for ✗).
- WSL box: read-only multi-line `SettingsTexts.WslHelp(live port)`.

**Index** tab:
- Mailbox picker (`ComboBox`, DropDownList) from `editor.MailboxChoices()`.
- **Add…** opens a `ContextMenuStrip` below the button. While loading it
  shows a disabled `Loading…` item; it runs
  `Worker.RunAsync(app => Stores.List(app), Interactive, cts.Token).WaitAsync(15 s)`.
  Items = `StoreCatalog.SharedOnly(...)` minus mailboxes enabled in the
  draft, label `DisplayName <smtp>`. Empty → disabled
  `SettingsTexts.NoOtherMailboxes`. `OutlookUnavailableException`,
  timeout, or `IsOutlookUnavailable()` beforehand → disabled
  `SettingsTexts.StartOutlookForMailboxes`. Clicking an item →
  `editor.AddMailbox(smtp, displayName)`, select it in the picker.
- **Remove…** (disabled for My mailbox): a `TaskDialog` with heading
  `SettingsTexts.StopIndexingQuestion(label)` and buttons
  **Delete its index**, **Keep index file**, **Cancel** (Cancel default;
  same as §6.2). Delete/Keep → `editor.RemoveMailbox(smtp, deleteIndex)`;
  the mailbox leaves the picker. Applied on OK/Apply.

## Spec changes (proposed)

1. **§6.3, after "Cancel discards them."** add:
   "Regenerate in the Connection tab only stages a new token; it replaces
   the old one on OK/Apply. Rebuild and Test connection act at once. A
   port change asks `Change the port from <old> to <new>?` before
   applying. If the new port can't be bound, the server goes back to the
   old port, nothing is saved, and the Port field shows
   `Port <n> is in use or can't be opened. The server stays on port <old>.`
   If the tray changes a setting while the window is open, the window's
   values win on Apply."

   (`Bearer ••••••••`) until **Show** is pressed; **Copy** always copies
   the full command." (Safer default: the token isn't shown on screen
   unasked.)

   and token), not unsaved changes, against `http://127.0.0.1:<port>/mcp`
   with no proxy and no `Origin` header, 5 s per request. With the token
   it expects HTTP 200 and `result.serverInfo.name` = `clippy`; another
   name means another MCP server holds the port." Plus the result table
   from this brief.
4. **§6.3 Index**: "The picker lists enabled shared mailboxes. **Add**
   lists mounted mailboxes not enabled (re-enabling keeps a disabled
   entry's folders and retention); **Remove** is the tray's uncheck
   (`Stop indexing <name>?`, Delete its index / Keep index file /

   from Outlook in the background, at most 15 s; if Outlook doesn't
   answer, the tree shows only the configured folders with
   `Outlook didn't answer, so only the configured folders are shown.`
   The window never waits on Outlook."
