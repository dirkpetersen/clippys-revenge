# M6.2 Daily reconcile; retention changes

## Goal

Add the two maintenance passes of `SyncService` that M6.1 leaves out
(SPEC §10 step 5 and "Changing RetentionMonths", plus §5.2 `RetentionMonths`
"Live" and §9.1 `sync_state.last_reconcile` / `meta.retention_months`).
**Reconcile**: once a day per indexed folder, compare Outlook's entry ids
for the folder (`ListEntryIds(folder, cutoff)`, §8) with the index, delete
rows for mail that is gone, add mail that is missing, and refresh `unread`
with `SetUnread` (§9.2, §17, §18 open question 1). **Retention changes**: when
a mailbox's effective `RetentionMonths` differs from the value recorded in
its index, a larger value re-opens the backfill and a smaller one purges at
once. All decision logic lives in Core behind one small interface
(`IReconcileSource`), tested with fakes and real SQLite; the App only adds
a thin COM adapter and two calls in `SyncService`.

## Cross-task dependencies (assumed, not built here)

- **M5.1 `OutlookWorker`** (App): `Task<T> RunAsync<T>(Func<Outlook.Application, T> work, Priority p, CancellationToken ct)`
  with `Priority.Background`. Background work **waits** while Outlook is
  unavailable (it does not throw); it throws `OperationCanceledException`
  when `ct` is cancelled. Each `RunAsync` call is one queue item, so the
  adapter must keep each call to at most 50 items (§4).
- **M5.2 `OutlookStores`** (App): `Get(string mailbox)` → `Outlook.Store`
  (`""` = own), throws `McpException` if not configured (§8).
- **M5.3 `OutlookMail`** (App): `ListEntryIds(folder, since)` → entry id +
  `UnRead` from a Table (§8), returning **only the item classes that
  `ReadForIndex` indexes** (the same filter `EnumerateChanged` uses), and
  `ReadForIndex(MailItem)` → `IndexedEmail` whose `Folder` is the configured
  folder path (`Inbox`, `Sent Items`, `Inbox\Projects`). If M5.3 resolves
  folders by something other than the configured path, the adapter maps it.
  The adapter opens items with `Session.GetItemFromID(entryId, store.StoreID)`.
- **M6.1 `SyncService`** (App) and its per-folder loop. M6.1 provides, per
  mailbox: the key (`""` or lower-cased SMTP), the `EmailIndex`, the
  effective retention months, the cutoff, and for each indexed folder its
  `sync_state` row (`FolderKey` = folder EntryID, `FolderPath`). M6.2
  inserts two calls into it (see Files). **`last_reconcile` is owned by
  M6.2**: M6.1 must update `SyncState` with `state with { … }` from a fresh
  `GetSyncState`, never by constructing a new record that drops
  `LastReconcile`.
- **M6.1 meta helpers** on `EmailIndex`: `string? GetMeta(string key)` and
  `void SetMeta(string key, string value)` (upsert into `meta`), and M6.1
  writes `retention_months` (carry-forward note). If they don't exist when
  M6.2 is implemented, add them to `EmailIndex` with exactly these
  signatures (`ArgumentException.ThrowIfNullOrEmpty(key)`; `SetMeta`
  throws `ArgumentNullException` for a null value). Don't add a second
  pair under another name.
- **Cutoff helper.** If M6.1 already added a helper that computes
  `now - RetentionMonths`, use it in `RetentionApplier`. Otherwise add
  `Retention.Cutoff` below; don't add two.

## Public API

```csharp
namespace ClippysRevenge.Core;

/// One row of Outlook's ListEntryIds table.
public sealed record OutlookEntry(string EntryId, bool Unread);

/// One indexed row's reconcile-relevant columns.
public sealed record IndexedEntry(string EntryId, bool Unread, DateTimeOffset EventTime);

/// A folder as SyncService knows it: sync_state key (folder EntryID) + configured path.
public sealed record ReconcileFolder(string FolderKey, string FolderPath);

public sealed record ReconcilePlan(
    IReadOnlyList<string> ToDelete,                      // index's stored entry ids
    IReadOnlyList<string> ToAdd,                         // Outlook's entry ids
    IReadOnlyList<(string EntryId, bool Unread)> UnreadChanges, // index's stored ids, Outlook's value
    bool DeletesSuppressed,
    int SuppressedCount);                                // candidates kept when suppressed, else 0

public sealed record ReconcileResult(
    string FolderPath,
    bool Ran,                // false when not due (or not eligible); counts are then 0
    int Deleted,
    int Added,
    int Skipped,             // ToAdd ids the source could not read
    int UnreadUpdated,
    bool DeletesSuppressed);

/// The COM side of reconcile. Implemented in App; faked in tests.
public interface IReconcileSource
{
    /// Entry id + UnRead for every indexable item in the folder whose event time is >= since.
    Task<IReadOnlyList<OutlookEntry>> ListEntryIdsAsync(
        string mailbox, ReconcileFolder folder, DateTimeOffset since, CancellationToken ct);

    /// Reads at most 50 items for the index. Ids that can't be opened or aren't
    /// indexable are left out of the result (no exception). Order is not significant.
    Task<IReadOnlyList<IndexedEmail>> ReadForIndexAsync(
        string mailbox, ReconcileFolder folder, IReadOnlyList<string> entryIds, CancellationToken ct);
}

public static class ReconcilePlanner
{
    public const int SuppressDeleteThreshold = 20;
    public static readonly TimeSpan EdgeMargin = TimeSpan.FromDays(1);

    /// Pure. Throws ArgumentNullException for null lists.
    public static ReconcilePlan Plan(
        IReadOnlyList<OutlookEntry> outlook,
        IReadOnlyList<IndexedEntry> indexed,
        DateTimeOffset cutoff);
}

public sealed class MailboxReconciler
{
    public const int BatchSize = 50;
    public static readonly TimeSpan Interval = TimeSpan.FromDays(1);

    public MailboxReconciler(IReconcileSource source, ActivityHub hub, TimeProvider? time = null);

    /// True when state is backfill-complete and LastReconcile is null or >= Interval ago.
    public bool IsDue(SyncState? state);

    /// Runs reconcile for one folder when IsDue(index.GetSyncState(folder.FolderKey)).
    /// Throws ArgumentNullException / ArgumentException (empty key/path/mailbox is allowed: "" = own).
    /// Propagates OperationCanceledException and source exceptions; LastReconcile is then not written.
    public Task<ReconcileResult> ReconcileIfDueAsync(
        string mailbox, EmailIndex index, ReconcileFolder folder, DateTimeOffset cutoff, CancellationToken ct);
}

public static class Retention
{
    /// now.ToUniversalTime().AddMonths(-months). Throws ArgumentOutOfRangeException outside 1–120.
    public static DateTimeOffset Cutoff(DateTimeOffset now, int months);
}

public enum RetentionChangeKind { None, Recorded, Grew, Shrank }

public sealed record RetentionChange(
    RetentionChangeKind Kind, int? PreviousMonths, int Months,
    int Purged, int FoldersReopened);

public sealed class RetentionApplier
{
    public const string MetaKey = "retention_months";

    public RetentionApplier(ActivityHub hub, TimeProvider? time = null);

    /// Compares meta.retention_months with effectiveMonths and applies the change.
    /// Throws ArgumentNullException (index), ArgumentOutOfRangeException (months outside 1–120).
    public RetentionChange Apply(string mailbox, EmailIndex index, int effectiveMonths);
}
```

`EmailIndex` addition:

```csharp
/// Every row whose folder equals `folder` (COLLATE NOCASE), any event time.
/// Throws ArgumentException for null/empty folder. Order: event_time DESC, id DESC.
public IReadOnlyList<IndexedEntry> ListEntries(string folder);
```

Folder matching uses the stored value as-is with `COLLATE NOCASE` (no
`Inbox`/`sent` aliasing; that is the search filter's job). The query must
use `ix_emails_folder_time`: `SELECT entry_id, unread, event_time FROM emails WHERE folder = @f COLLATE NOCASE ORDER BY event_time DESC, id DESC`.

## Behavior

### ReconcilePlanner.Plan

Inputs: Outlook entries (listed with `since = cutoff`), all index rows for
the folder (any age), and the cutoff.

1. Drop Outlook entries with a null/empty/whitespace `EntryId`. De-duplicate
   by entry id, **case-insensitively** (`StringComparer.OrdinalIgnoreCase`);
   the first occurrence wins.
2. Entry ids are matched case-insensitively throughout. Output lists use
   the **index's stored** id for `ToDelete` and `UnreadChanges` (so the
   SQL `WHERE entry_id = @e` hits), and Outlook's id for `ToAdd`.
3. `ToAdd` = Outlook ids with no index row in this folder. (A row that sits
   under another folder with the same id is re-added here; `UpsertBatch`
   then moves it.) Order: as listed by Outlook.
4. Delete candidates = index rows with `EventTime >= cutoff + EdgeMargin`
   that Outlook did not list. Rows older than that are left to
   `PurgeOlderThan`, so DASL minute precision at the retention edge never
   deletes live mail.
5. **Empty-list guard**: if, after step 1, Outlook listed **zero** entries
   and there are `>= SuppressDeleteThreshold` (20) delete candidates,
   `ToDelete` is empty, `DeletesSuppressed = true` and `SuppressedCount` =
   the number of candidates (otherwise `SuppressedCount = 0`). Fewer than 20
   candidates are deleted normally (an emptied small folder still cleans up).
6. `UnreadChanges` = rows present in both whose `Unread` differs, with
   Outlook's value. Rows that match are not listed.
7. Never throws except `ArgumentNullException`.

### MailboxReconciler.ReconcileIfDueAsync

1. `state = index.GetSyncState(folder.FolderKey)`. If `!IsDue(state)`,
   return `Ran = false` with zero counts. **Not eligible** means: no state,
   `BackfillComplete == false`, or `LastReconcile` within the last 24 h
   (`now - LastReconcile < Interval`, `now` from `TimeProvider`). A folder
   whose backfill isn't complete is not reconciled: the backfill adds the
   missing mail itself, newest first.
2. `using var scope = hub.Begin(ActivityState.Syncing, $"Reconciling {folder.FolderPath}")`.
3. `outlook = await source.ListEntryIdsAsync(mailbox, folder, cutoff, ct)`,
   `indexed = index.ListEntries(folder.FolderPath)`, `plan = Plan(…)`.
4. Apply in this order: `index.SetUnread(plan.UnreadChanges)` →
   `index.Delete(plan.ToDelete)` → adds. Use the counts the index returns
   for `UnreadUpdated` and `Deleted`.
5. Adds: chunks of `BatchSize` (50) in `ToAdd` order. For each chunk:
   `ct.ThrowIfCancellationRequested()`, `await source.ReadForIndexAsync(…)`,
   keep only returned emails whose `EntryId` is in the chunk
   (case-insensitive) and whose `Folder` is non-empty, then
   `index.UpsertBatch(those)`, `Added += those.Count`,
   `Skipped += chunk.Count - those.Count`, `hub.Report(doneSoFar, ToAdd.Count)`.
   Skip the `UpsertBatch` call when the chunk read nothing.
6. Only after all steps succeed: re-read the state and write
   `index.SetSyncState(fresh with { LastReconcile = now })`, where `now` is
   the time read in step 1 (whole seconds are fine; storage truncates).
   On any exception (including cancellation) `LastReconcile` is **not**
   written, so the next cycle retries; the work done so far is kept and the
   re-run is idempotent.
7. Event: when `Deleted + Added + UnreadUpdated > 0`, call
   `hub.Event(ActivityKind.Sync, $"Reconciled {FolderPath}: {Deleted} removed, {Added} added, {UnreadUpdated} read-state updated", duration, mailboxTag)`.
   When `DeletesSuppressed`, also
   `hub.Event(ActivityKind.Sync, $"Reconcile {FolderPath}: Outlook listed no items, kept {n} indexed emails", null, mailboxTag)`
   with `n` = `plan.SuppressedCount`. `mailboxTag` is
   `null` for `""` and the SMTP key otherwise. When nothing changed, no
   event. When `Skipped > 0`, the first summary gets `, {Skipped} unreadable`
   appended at the end (e.g. `Reconciled Inbox: 0 removed, 1 added, 0 read-state updated, 2 unreadable`),
   and that event is emitted even if the other counts are 0.
8. Index calls are synchronous SQLite; call them directly (the sync loop is
   already off the UI thread). No `.Result` / `.Wait()`.

### RetentionApplier.Apply

`now` from `TimeProvider`; `cutoff = Retention.Cutoff(now, effectiveMonths)`.
`previous = int.TryParse(index.GetMeta("retention_months"), Invariant)`.

- **No previous value** (missing or unparsable): `SetMeta` to
  `effectiveMonths`, return `Recorded`. Nothing else happens; the normal
  cycle's purge applies the cutoff.
- **Equal**: return `None`, write nothing.
- **Larger** (`effectiveMonths > previous`): for each `sync_state` row with
  `OldestSynced is { } o && o > cutoff`, write
  `state with { BackfillComplete = false }`; `FoldersReopened` = how many.
  Rows with null `OldestSynced` are untouched. Then `SetMeta`. Event
  `hub.Event(ActivityKind.Sync, $"Retention changed to {m} months: backfilling older mail", null, mailboxTag)`.
  Return `Grew`. (The backfill pass then runs again because
  `oldest_synced > cutoff`, §10.)
- **Smaller**: first, for each `sync_state` row with `OldestSynced < cutoff`,
  write `state with { OldestSynced = cutoff }` (so a later increase
  re-backfills the purged range instead of thinking it is still there;
  `BackfillComplete` stays as it was). Then, inside
  `hub.Begin(ActivityState.Purging, "Purging")`, `Purged = index.PurgeOlderThan(cutoff)`.
  Then `SetMeta`. Event `hub.Event(ActivityKind.Purge, $"Retention changed to {m} months: purged {Purged} emails", duration, mailboxTag)`.
  Return `Shrank`.
- Every step is idempotent, and meta is written **last**, so a crash in the
  middle re-applies the whole change on the next call.
- Needs a way to enumerate `sync_state` rows. Add
  `public IReadOnlyList<SyncState> ListSyncStates()` to `EmailIndex`
  (ordered by `folder_key`) unless M6.1 already added an equivalent; reuse
  the existing `SyncRow` mapping.

### Integration in SyncService (App)

- **Retention**: call `retention.Apply(key, index, effectiveMonths)` for
  the own mailbox (global `RetentionMonths`) and each enabled shared one
  (`SharedMailbox.EffectiveRetentionMonths(global)`):
  (a) at the start of each mailbox's cycle, before any folder pass, and
  (b) on a settings-change wake-up **even when sync is paused or Outlook is
  unavailable** (it needs no COM), so "a smaller value runs a purge
  immediately" (§10) holds. It runs on the sync loop, never concurrently
  with a cycle on the same index. Wrap in `Task.Run` only if the loop runs
  on a thread that must not block.
- **Reconcile**: step 5 of the per-folder cycle, after the backfill pass:
  `await reconciler.ReconcileIfDueAsync(key, index, new(state.FolderKey, state.FolderPath!), cutoff, ct)`.
  Skip folders whose `FolderPath` is null. The cycle's own `ct` (pause,
  shutdown, rebuild) is passed through.
- A source exception from reconcile is handled the same way M6.1 handles
  a failure in the changes pass for that folder (log + continue with the
  next folder); it must not abort the other folders or mailboxes.

### OutlookReconcileSource (App)

- `ListEntryIdsAsync`: one `worker.RunAsync(app => …, Priority.Background, ct)`
  that resolves the store via `OutlookStores.Get(mailbox)`, the folder by
  `FolderKey` (`Session.GetFolderFromID(folderKey, store.StoreID)`), calls
  `OutlookMail.ListEntryIds(folder, since)` and maps to `OutlookEntry`.
  Release every COM object it opens (`Marshal.ReleaseComObject`, in
  `finally`).
- `ReadForIndexAsync`: throws `ArgumentOutOfRangeException` for more than
  50 ids. One `RunAsync(…, Background, ct)` per call; per id,
  `Session.GetItemFromID(id, store.StoreID)`; if that throws
  `COMException` or the item is not a `MailItem`, skip it; else
  `OutlookMail.ReadForIndex(item)` with the folder path from `folder`;
  release the item in the loop.
- Never `.Send()`, never create an `Application`, no file paths.

## Spec changes (proposed)

Architect to apply to SPEC.md when the parallel batch is merged:

1. §10, replace step 5 with:
   "5. **Reconcile, once a day:** only for a folder whose backfill is
   complete and whose `last_reconcile` is empty or at least 24 h old.
   `ListEntryIds(folder, cutoff)` compared with every index row of that
   folder (entry ids match case-insensitively). Add mail that is missing,
   refresh `unread` with `SetUnread`, and delete rows for mail that is gone,
   but only rows at least one day newer than the cutoff (older ones are left
   to the purge). If Outlook lists no items at all while 20 or more rows
   would be deleted, nothing is deleted that day. `last_reconcile` is set
   only when the whole pass succeeds. Read-state changes may not update
   `LastModificationTime`; this catches them either way (§17)."
2. §10, replace "Changing RetentionMonths" with:
   "**Changing RetentionMonths:** each index records the value it was synced
   with in `meta.retention_months`. At the start of each mailbox cycle, and
   on a settings change even while paused or while Outlook is unavailable,
   the effective value is compared with it. A larger value clears
   `backfill_complete` for folders whose `oldest_synced` is after the new
   cutoff, so the backfill pass runs again. A smaller value raises
   `oldest_synced` to the new cutoff and runs a purge immediately. The meta
   value is written last."
3. §18 Decided: "Sync (M6.2): reconcile and retention logic live in Core
