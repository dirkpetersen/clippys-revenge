# M19.4 Attachment plan and budget: `EmailIndex.ThreadAttachments`, `DraftAttachmentPlan`, `AttachmentBudget`, `IAttachmentSource`, `DraftAttachments.CollectAsync`

Base: `dev` (M19.1, M19.2, M19.3 merged). Deps: M19.2, M19.3. Pure Core.
Runs beside M18.2 → M18.3: this task touches **no** `DraftPrompt*.cs`,
`DraftWorker*.cs`, `IndexModels.cs` or `EmailIndex.Ai.cs`; see
"Parallel work".

## Goal

Build the Core half of "attachment content in AI drafts" that sits between
the extractors (M19.2), the OneDrive mapping (M19.3) and the prompt (M19.5):
given the email being answered (the anchor) and its thread rows from the
index, **plan** which attachments, cloud attachments and OneDrive/SharePoint
links to read (sources, three priority tiers, mention detection, dedupe,
the 20-item cap, the host rule and the sender rule for links), **read** them
one at a time in tier order through a COM seam (`IAttachmentSource`) or from
the synced local copy (`SyncedFileReader`) within a 20 s per-prompt budget
and a 10 s per-file timeout, **extract** their text (`AttachmentText`),
**share** a 40,000-character budget across them by tier
(`AttachmentBudget.Allocate`), and return the prompt items plus the draft
notes they call for. Nothing is stored, cached or logged except counts and
exception type names. It is not wired into any drafting path yet (M19.6),
and the prompt block and note texts are M19.5.

SPEC refs: §26 intro (nothing stored, re-read on demand), §26.1, §26.2,
§26.3 (host rule, sender rule, cloud attachments, Files-On-Demand, reading
a synced file), §26.4 (size and format reasons), §26.5, §26.7 (which items
get which note; texts are M19.5), §26.8, §26.11, §26.12 (Plan, Allocate,
Collect bullets), §19.6 (internal rule), §1 rules 6 and 8 (attachment
content never stored; every path through `PathPolicy`).

The user's standing decisions that this task enforces:
- Links and cloud attachments are considered only on Microsoft hosts
  (`OneDriveLinks.IsMicrosoftFileHost`, after Safe Links unwrapping) **and**
  only when the message that carries them is from the user or the user's
  own domain (sender rule; standing default).
- Normal by-value file attachments and attached emails are always read,
  whoever sent them.
- Earlier-thread attachments are read again from Outlook for every prompt;
  there is no cache of any kind.
- There is no budget **setting**. The "budget" of this task is the fixed
  40,000-character / 20 s attachment budget of §26.5 (constants). §19.13
  and §26.10 both say "no budget setting"; this brief adds none.

## Hard rules that apply here

- **Attachment content never enters the index, settings, logs or Activity.**
  Extracted text lives only in the returned `AttachmentSet`. No static
  field, no cache, no dictionary that outlives one `CollectAsync` call.
- **No network.** No `HttpClient`, `WebRequest`, `WebClient`, `Socket`,
  `Dns`, `Process`, `UseShellExecute` in the new files. Links are only
  mapped (`OneDriveMap.Map`) and read from disk (`SyncedFileReader`, which
  runs `PathPolicy` with the mount as the only root).
- **No index writes.** `DraftAttachments*.cs` don't reference `EmailIndex`
  or `MailboxIndexes` at all (the caller, M19.6, passes the thread rows).
  `EmailIndex.ThreadAttachments` is a read-only `SELECT`.
- **AI-file scans** (§19.12; file names start with `Draft`): no `.Send(`,
  `.Display(`, `.Move(`, `.MoveTo(`, `Delete(`, `PermanentDelete(` anywhere
  in `DraftAttachments*.cs`, and no `Outlook.`, `Marshal`, standalone
  `MailItem` identifier or `CreateReplyDraft` in their code (comments and
  strings are stripped by the scan, but avoid them anyway).
- **Logs**: only literals, counts and exception type names. One Warning
  shape is allowed (below). Never a file name, URL, path, reason or text.

## Behavior

### A. `EmailIndex.ThreadAttachments`

- `topic` trimmed; null/blank → `[]` with no query (same helper as
  `Thread`, the private `Trimmed`).
- Query 1 (emails): `SELECT e.id, e.entry_id, e.event_time, e.sender_name,
  e.sender_email, substr(e.body, 1, MaxThreadBodyChars) FROM emails e WHERE
  e.conversation_topic = @t COLLATE NOCASE AND e.event_time <= @upTo AND
  e.entry_id <> @x ORDER BY e.event_time DESC, e.id DESC LIMIT @max`.
- Query 2 (only when query 1 returned rows): `SELECT email_id, position,
  filename, size, is_inline FROM attachments WHERE email_id IN @ids ORDER BY
  email_id, position` (Dapper list expansion; at most 100 ids). `size` NULL
  stays `null` (do **not** reuse `ParseAttachments`, which maps NULL to 0);
  `is_inline` NULL → `false`.
- Both queries on one connection; no transaction, no write. No
  `attachment_names`, no other column.

### B. `DraftAttachmentPlan.Build(request, roots)`

1. **Own text**: `ownText = MailText.OwnText(request.AnchorBody ?? "", request.SignatureText)`.
2. **Anchor items** (tier 1, origin `Email`, the anchor's `EntryId`,
   sender and time): every attachment with `!IsInline`, in position order;
   then `OneDriveLinks.Find(request.AnchorBody)` in body order.
3. **Thread items**: `request.Thread` sorted by `EventTime` descending
   (stable; rows whose `EntryId` equals `AnchorEntryId` ordinal are
   dropped). Per message: non-inline attachments in position order, then
   `OneDriveLinks.Find(row.Body)` in body order. Origin `Thread`. Tier 2
   when `IsMentioned(request.AnchorSubject, ownText, name)`, else tier 3.
4. Stable sort by tier (1, 2, 3); within a tier the order of steps 2–3
   stands (newest message first, then attachments by position, then links
   by body order).
5. **`SharedAllowed`** = `MayOpenShared(message sender email, request.Identity, request.Mailbox)`,
   computed per message for every item (used for links here and for cloud
   attachments at read time).
6. **Links, pre-read** (in sorted order): `!SharedAllowed` → `SkipReason`
   `FromOutside`, not mapped. Else `Mapped = OneDriveMap.Map(link.Url, roots)`;
   `Unmappable` → `SkipReason` `NotSynced`.
7. **Attachments, pre-read by format** (`AttachmentText.FormatOf(name)`):
   `Image` → `SkipReason` `AttachmentReasons.Image`; `Unsupported` or
   `UnsupportedNoted` **and** the extension isn't `msg` →
   `AttachmentReasons.CantRead(AttachmentText.Extension(name))`. A `.msg`
   name is always read (it may be an attached Outlook item). These items
   need no COM call. Kind stays `File`.
8. **Dedupe** (in sorted order, first occurrence wins = best tier, then
   newest):
   - attachments: key = name (trimmed, `OrdinalIgnoreCase`) + size, only
     when `Size` is not null and > 0 (unknown sizes never dedupe);
   - links: key = `FoundLink.NormalizedUrl` (ordinal), and for a `Local`
     mapping also the mapped `Path` (`OrdinalIgnoreCase`). A link matching
     either key of an earlier kept link is dropped.
   - Files and links never dedupe against each other. Dropped duplicates
     are removed entirely (not listed).
9. **Cap**: walking in order, count the items with no `SkipReason` (the
   ones that need a read). The 21st and later such items get `SkipReason`
   `TooManyFiles`. Items with a pre-read `SkipReason` stay listed and don't
   use a slot.

`IsMentioned(subject, ownText, name)`: candidates are the trimmed name and,
when the name has an extension (`AttachmentText.Extension` non-empty), the
name without its last `.ext` (trimmed). A candidate counts only when it is
at least 4 characters. A candidate matches when it occurs in `subject` or
`ownText` (`OrdinalIgnoreCase`, every occurrence tried) with no letter or
digit (`char.IsLetterOrDigit`) immediately before or after it.

`MayOpenShared`: `sender = senderEmail?.Trim()`; not `LooksLikeSmtp` →
false. Equal (`OrdinalIgnoreCase`) to `identity.OwnSmtp` (when non-blank) or
to `mailbox` (when non-empty) → true. Else `own = domain(identity.OwnSmtp)`
(text after the last `@`, trimmed, lower-invariant, one trailing `.`
removed; null when OwnSmtp has no `@` or the domain is empty) and
`d = domain(sender)`: true when `d == own` or `d.EndsWith("." + own)`
(ordinal). Note: the parent-domain direction of `DontDraftRules.IsOwnDomain`
is **not** used (a sender at a parent domain is outside).

### C. `DraftAttachments.CollectAsync(request, ct)`

1. `ArgumentNullException.ThrowIfNull(request)`; `ct.ThrowIfCancellationRequested()`.
   `start = time.GetTimestamp()`.
2. `roots = source.SyncedRoots()` exactly once per call (wrap in
   try/catch: an exception → `[]` and one Warning, type only). Then
   `plan = DraftAttachmentPlan.Build(request, roots)`. Empty plan →
   `AttachmentSet.Empty` with `ElapsedMs` filled in; the source's
   `ReadAsync` is never called.
3. Walk the plan in order, **one item at a time** (no parallel reads; the
   bytes of one item are dropped before the next starts):
   - `ct.ThrowIfCancellationRequested()`.
   - Item with a `SkipReason` → skipped with that reason, no read.
   - After an `OutlookUnavailableException` (below) → skipped
     `OutlookNotRunning` (every remaining item that needs a read, links
     included; pre-skipped items keep their own reason).
   - `time.GetElapsedTime(start) >= TimeBudget` → skipped `OutOfTime`.
   - **Attachment item**:
     - Its message is already known gone in this call → skipped
       `EarlierEmailGone` for origin `Thread`, `NotOnEmail` for origin
       `Email` (no second `ReadAsync` for that EntryId).
     - `r = await source.ReadAsync(request.Mailbox, item.EntryId, item.Attachment, AttachmentText.MaxFileBytes, request.Priority, ct)`.
       `OutlookUnavailableException` → this item and all later unread items
       skipped `OutlookNotRunning`. `OperationCanceledException` when
       `ct.IsCancellationRequested` → rethrow. Any other exception →
       skipped `Damaged`, Warning (type only).
     - `null` → mark the EntryId gone; skipped as in the "known gone" bullet.
     - `File(bytes)`: kind `File`; `bytes.Length > MaxFileBytes` →
       `TooLarge`; else extract with the per-file timeout (D) using
       `item.Attachment.FileName`.
     - `Item(...)`: kind `Email`; `AttachmentText.FromMailItem(subject, from,
       sent converted with TimeZoneInfo.ConvertTime(sent, request.Zone), body, names)`,
       inline (no timeout; it's pure in-memory work).
     - `Cloud(url, displayName)`: kind `Cloud`; name = `displayName`
       trimmed, or the attachment's file name when blank. Then in order:
       url blank, or not an absolute `https` URL → `NotSynced`;
       `!OneDriveLinks.TryParse(url, out link)` → `NotMicrosoftLink`;
       `!item.SharedAllowed` → `FromOutside`; `link.NormalizedUrl` already
       in this call's seen-URL set → **dropped** (not listed, not counted);
       `OneDriveMap.Map(link.Url, roots)` `Unmappable` → `NotSynced`;
       `Local` whose `Path` is in the seen-path set → dropped; else add both
       keys to the seen sets and read it as a link (D). `SaveAsFile`-style
       downloading never happens here; the seam only reports the URL.
     - `TooLarge` → `TooLarge`. `NotOnEmail` → `NotOnEmail`.
       `Failed` → `Damaged`.
   - **Link item** (already sender-checked and `Local`): when its
     `NormalizedUrl` or `Path` is already in the seen sets (an earlier
     cloud attachment) → dropped; else add both keys, then read (D).
     Kind `Link`, name `FoundLink.Name`.
   - The two seen sets (normalized URLs ordinal, local paths
     `OrdinalIgnoreCase`) start empty and are filled as the walk goes:
     every link item adds its keys when it is walked (also when it is
     skipped for time or Outlook), and a cloud attachment adds its keys
     once mapped. A cloud attachment that matches an earlier link or
     cloud is dropped; a link walked after a cloud attachment for the
     same file (same URL or path) is dropped too.
4. **Budget**: items with status `Read`/`Truncated` → `BudgetItem(tier, text.Length)`;
   `AttachmentBudget.Allocate`. `null` → `Skipped`, `TooMuchText`, text `""`.
   A keep shorter than the text → `Cut(text, keep)`, status `Truncated`.
5. **Notes**: `NoteFor` over the final items, in order; nulls left out.
6. **Counts**: by final status; `Links` = kind `Link` or `Cloud`; `Chars` =
   Σ text lengths; `ElapsedMs` = `(long)time.GetElapsedTime(start).TotalMilliseconds`.

### D. Per-file read and extraction (thread pool, 10 s)

```csharp
using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);
var work = Task.Run(() => /* read synced (links only) + extract */, CancellationToken.None);
try { result = await work.WaitAsync(PerFileTimeout, time, ct); }
catch (TimeoutException) { cts.Cancel(); /* skipped TookTooLong */ }
// on timeout: _ = work.ContinueWith(t => _ = t.Exception, TaskScheduler.Default);  (no unobserved exception)
```

- For a link (or mapped cloud attachment) the 10 s covers
  `readSynced(local, AttachmentText.MaxFileBytes, cts.Token)` **and** the
  extraction (Files-On-Demand hydration counts, §26.3).
  `SyncedFileResult.Bytes` → `extract(bytes.FileName, bytes.Data, token)`
  (the local file name picks the format; the display name stays the link
  name); `NotSynced` → `NotSynced`; `TooLarge` → `TooLarge`; `Failed` →
  `Damaged`.
- For a COM `File` the 10 s covers the extraction only (the COM read has
  the worker's own timeout).
- `ExtractedText` maps 1:1: `Read`/`Truncated` keep `Text`; `Skipped`
  keeps `Reason`.
- A thrown `OperationCanceledException` while `ct` is cancelled → rethrow;
  inside the task because of the timeout → `TookTooLong`; any other
  exception from the work → `Damaged` (Warning, type only).

### E. `NoteFor(item)` (§26.7)

Null when `Tier == 3`, or `Status == Read`. `Shared` = kind `Link` or
`Cloud`. `Truncated` status → `Truncated`. `Skipped` by reason:

| Reason (`AttachmentReasons.`) | Note kind |
|---|---|
| `NotSynced` | `NotSynced` |
| `FromOutside` | `FromOutside` |
| `EarlierEmailGone` | `EarlierEmailGone` (only reachable in tier 2) |
| `PasswordProtected` | `PasswordProtected` |
| `TooLarge` | `TooLarge` |
| `NoText` | `NoText` |
| `CantRead(ext)` with `FormatOf(name) == UnsupportedNoted` | `Format`, `Extension = ext` |
| `Damaged` | `Damaged` |
| `TookTooLong`, `OutOfTime` | `TookTooLong` |
| `TooMuchText`, `TooManyFiles` | `TooMuch` |
| `Image`, `UnknownKind`, other `CantRead`, `NotMicrosoftLink`, `NotOnEmail`, `OutlookNotRunning` | none |

### F. `AttachmentBudget.Allocate(items, total)`

`R = total`. For tier 1, 2, 3 in turn, over that tier's items in input order:
- `Σ len ≤ R` → every item keeps `len`; `R -= Σ len`. (This applies even
  when `R < MinShareChars`: a tier that fits is never cut.)
- else find the largest whole `L ≥ 0` with `Σ min(lenᵢ, L) ≤ R` (binary
  search on `0..max len`). `L ≥ MinShareChars` → each keeps `min(lenᵢ, L)`,
  `R -= Σ`. Else, in order: while `R ≥ MinShareChars` an item keeps
  `k = min(len, MinShareChars)` and `R -= k`; once `R < MinShareChars` the
  item and the rest of the tier get `null`.
- Later tiers that don't fit when `R < MinShareChars` therefore get `null`
  for every item. `Length == 0` items always keep 0.

### G. Logging

(the one shape, used for the source/roots/work exceptions above). No Debug
count line here (M19.6 writes it from `AttachmentCounts`).

## Spec changes

Not applied by this brief (the caller asked for the brief only); to be
recorded in `SPEC.md` (§26.1, §26.2, §26.5, §26.7, §26.8). All are
low-risk clarifications of the existing rules; none touches a hard rule.

1. **§26.8 files and types**: `DraftAttachments.cs` (`AttachmentKind`,
   `AttachmentOrigin`, `AttachmentRequest`, `IAttachmentSource`,
   `AiAttachmentRead`, `PromptAttachment`, `AttachmentNoteKind`,
   `AttachmentNote(Kind, Name, Shared, Extension)`, `AttachmentCounts`,
   `AttachmentSet`, `DraftAttachments`), `DraftAttachments.Plan.cs`
   (`PlannedAttachment`, `DraftAttachmentPlan.Build/MayOpenShared/IsMentioned`),
   `DraftAttachments.Budget.cs` (`BudgetItem`, `AttachmentBudget.Allocate/Cut`).
   `AttachmentRequest` carries the thread rows; the caller (M19.6) calls
   `EmailIndex.ThreadAttachments`, so `DraftAttachments*.cs` never
   reference `EmailIndex`. `CollectAsync` returns **all** notes; M19.5
   applies the 5-note limit. `SyncedRoots()` is called once per
   `CollectAsync`.
2. **§26.8 Index**: `ThreadAttachments(topic, upTo, excludeEntryId, maxMessages = 50)`
   lives in `EmailIndex.ThreadAttachments.cs` (record there too),
   `maxMessages` 1–100, includes messages without attachments (for links),
   returns inline rows flagged, keeps unknown sizes as null.
3. **§26.1 mention detection**: the 4-character minimum applies to both
   candidates (the whole name and the name without extension).
4. **§26.1 order inside a message** (tiers 2 and 3): attachments by
   position, then links in body order (as tier 1).
5. **§26.1 cap**: the 20 slots count only items that need a read. Items
   skipped before any read (images, unreadable formats except `.msg`,
   links from outside the organization, unmappable links) are listed but
   use no slot, and need no COM call. `.msg` names are always read.
6. **§26.1 dedupe**: size ≤ 0 counts as unknown. Links dedupe at plan
   time (normalized URL, then mapped path); a cloud attachment, whose URL is
   known only after the COM read, that matches a link or cloud attachment
   already walked is dropped (not listed, not counted).
7. **§26.2**: when the **anchor** itself can't be opened, its attachments
   are skipped with `not on the email any more` and no note.
   `not on the email any more` never gets a note.
8. **§26.3 cloud attachments**: name = `DisplayName`, falling back to the
   index file name; checks in order: URL missing → `not synced to this PC`;
   host rule → `not a OneDrive or SharePoint link`; sender rule →
   `from outside your organization`; mapping. A by-value read that fails
   (`Failed`) or a synced read that fails → `the file seems damaged`.
9. **§26.5 allocation**: a tier whose lengths fit in the remaining budget
   keeps them in full even when less than 2,000 remain; in the floor
   branch each item keeps `min(len, 2,000)` while at least 2,000 remain. A
   cut text keeps exactly its allotted length, ending in `…`.
10. **§26.5 timeouts**: for links the 10 s per-file limit covers the
    synced-file read (Files-On-Demand hydration) and the extraction; for
    COM files it covers the extraction; an attached item's rendering runs
    inline. An unexpected exception from a read → `the file seems damaged`
    plus one Warning with the exception type.
11. **§26.8 Outlook gone**: every remaining item that needs a read, links
    included, is skipped with `Outlook isn't running`; items already
    skipped before any read keep their reason. The time-budget check
    likewise applies only to items that need a read.
12. **§26.3 sender rule**: the internal test is "equal to or a subdomain
    of the own SMTP domain" (§19.6); a sender at a parent domain is
    outside (unlike `DontDraftRules.IsOwnDomain`).
13. **§26.3 / M19.3**: `OneDriveMap.NotSyncedReason` now refers to
    `AttachmentReasons.NotSynced` (the one reason text).
