# M11.3 `MailText` and `DraftHtml`

## Goal

Add the two pure text helpers that the AI-drafting feature builds on
(SPEC §19.6, §19.7 "Rules"/"Drafting prompt", §19.8, §19.12):

1. **`MailText`** (Core). `OwnText` cuts quoted history and the signature
   from a plain-text mail body, so style samples (§19.6) and thread
   excerpts (§19.7) carry only what the sender wrote. `Redact` replaces
   addresses, links and phone numbers. `Headers` parses
   `PR_TRANSPORT_MESSAGE_HEADERS` for the `list` and `auto` rules (§19.7).
2. **`DraftHtml`** (Core). `Sanitize` turns untrusted model HTML into a
   fragment that uses only the allow-listed tags, has no attributes, and
   highlights `[[…]]` placeholders (§19.8). `ToPlainText` is a small
   companion that turns the user's HTML signature into the plain
   `signatureText` that `OwnText` needs. It shares the tokenizer (see
   Spec changes).

Both are `net10.0`, need no Windows and have **no new package**. SPEC
§19.8 already says "a small tokenizer (no HTML library)". That is the
right call: the allow-list is 11 tag names with zero attributes, so a
hand-written tokenizer of about 250 lines is easier to audit than
AngleSharp or HtmlAgilityPack. It also avoids a parser that would
"repair" input into structures we then have to filter again. The only
BCL helper used is `System.Net.WebUtility.HtmlDecode`.

Nothing in this task calls the model, COM or the index. M11.6
(`StyleCorpus`, the style re-redaction) and M11.7 (`DraftPrompt`,
`DraftRules`, `DraftWorker`) are the consumers.

## Hard rules that apply here

- Model output is untrusted (§19.5). `Sanitize` is the only path from
  `body_html` to a draft. Its output may contain **only** the 11 allowed
  tags without attributes, plus the one highlight `<span>` that Clippy
  adds itself. No `href`, `src`, `style` (except that span), event
  handlers, URLs in attributes, `<a>`, `<img>`, CSS or scripts.
- Nothing here logs. These functions get mail text, so they must never
  write to a logger or `ActivityHub` (§19.11).
- No `.Send(`, `.Display(`, `.Move(` or `Delete(` in `DraftHtml.cs`. The
  M11.9 scan covers files named `Draft*`. Watch for `Delete(` in names
  like `DeleteRange(`, and don't use them.
- Pure and deterministic. No `DateTime.Now`, no randomness, no I/O.

## Public API

```csharp
namespace ClippysRevenge.Core;

/// <summary>Plain-text mail helpers for AI drafting (SPEC 19.6, 19.7). Pure; never logs.</summary>
public static partial class MailText
{
    public const string EmailToken = "<email>";
    public const string LinkToken  = "<link>";
    public const string PhoneToken = "<phone>";

    /// <summary>
    /// The sender's own text of a plain-text body: quoted history and signature cut, line endings "\n",
    /// trailing blank lines removed, result trimmed. "" when nothing is left.
    /// </summary>
    /// <param name="signatureText">Plain text of the user's default signature (DraftHtml.ToPlainText of it), or null.</param>
    /// <exception cref="ArgumentNullException">body is null.</exception>
    public static string OwnText(string body, string? signatureText = null);

    /// <summary>Replaces URLs with &lt;link&gt;, email addresses with &lt;email&gt;, phone-like runs with &lt;phone&gt;.</summary>
    /// <exception cref="ArgumentNullException">text is null.</exception>
    public static string Redact(string text);

    /// <summary>
    /// Parses RFC 5322 transport headers: unfolded, names case-insensitive (OrdinalIgnoreCase),
    /// first value wins. Null/empty/garbage → empty dictionary. Never throws.
    /// </summary>
    public static IReadOnlyDictionary<string, string> Headers(string? transportHeaders);
}

/// <summary>Model HTML → safe draft fragment (SPEC 19.8). Pure; never throws; never logs.</summary>
public static partial class DraftHtml
{
    public const int MaxInputChars = 200_000;       // longer input is cut to this before tokenizing
    public const int MaxDepth = 64;                 // deeper allowed start tags are dropped (text kept)
    public const int MaxPlaceholderChars = 200;     // inner length of [[…]]
    public const string HighlightOpen  = "<span style=\"background-color:#ffff00\">";
    public const string HighlightClose = "</span>";

    /// <summary>Allow-list sanitizer plus placeholder highlight. "" when there is no visible text. Null → "".</summary>
    public static string Sanitize(string? modelHtml);

    /// <summary>
    /// HTML → plain text for signature matching: dropped-with-content elements removed, block tags and
    /// &lt;br&gt; become line breaks, entities decoded, HTML whitespace collapsed. Null → "". Never throws.
    /// </summary>
    public static string ToPlainText(string? html);
}
```

`ToPlainText` accepts a whole `.htm` document (with `<head>`) or a body
fragment such as `DraftBody.SignatureContent(...)`, and handles both.

## Behavior

### A. `MailText.OwnText(body, signatureText)`

**0. Normalize.** Replace `\r\n` with `\n`, then a lone `\r` with `\n`,
and split into lines. The output joins lines with `\n`.

**1. History cut.** Find the **first** line index `k` that is a marker
(rules below) and keep lines `0..k-1`. If there is no marker, keep
everything.

For marker tests, a line is first **left-trimmed** of spaces, tabs and
U+00A0 (call the result `t`). Lines whose `t` is longer than 400
characters are never markers. Every pattern below uses
`RegexOptions.IgnoreCase | RegexOptions.CultureInvariant` and is
anchored to the whole of `t` (`^…$`). In the patterns, `\s` includes
U+00A0, and `'` also matches `’`.

| # | Marker | Pattern / rule |
|---|---|---|
| M1 | Original-message separator | `^-{3,}\s*(Original Message\|Ursprüngliche Nachricht\|Message d['’]origine\|Mensaje original\|Oorspronkelijk bericht\|Messaggio originale\|Forwarded message\|Weitergeleitete Nachricht\|Message transféré\|Mensaje reenviado)\s*-{3,}\s*$`. This covers Outlook's `-----Original Message-----` and Gmail's `---------- Forwarded message ---------`. |
| M2 | Underscore line | `^_{8,}\s*$`. Outlook's plain-text rendering of `<div id="divRplyFwdMsg">` / the `border-top` separator is a line of 32 `_`. |
| M3 | Attribution line | One of these, with the lazy part bounded so backtracking stays linear: EN `^On\s.{1,300}?\swrote:\s*$`. DE `^Am\s.{1,300}?\sschrieb\b.{0,300}:\s*$`. FR `^Le\s.{1,300}?\sa\s+écrit\s*:\s*$`. ES `^El\s.{1,300}?\sescribió\s*:\s*$`. NL `^Op\s.{1,300}?\sschreef\b.{0,300}:\s*$`. IT `^Il\s.{1,300}?\sha\s+scritto\s*:\s*$`. **Two-line wrap** (Gmail breaks long attributions): when `t` starts with `On`, `Am`, `Le`, `El`, `Op` or `Il` followed by whitespace and doesn't match on its own, test `t + " " + nextLine.Trim()` (if a next line exists). A match marks line `i`. |
| M4 | Header block | `t` matches the From label `^\*?(From\|Von\|De\|Van\|Da)\*?\s*:\*?(\s\|$)`, **and** among lines `i+1..i+4` (only those that exist; blank lines count toward the 4) there is one matching the date label `^\*?(Sent\|Date\|Gesendet\|Datum\|Envoyé\|Enviado\|Fecha\|Verzonden\|Inviato\|Data)\*?\s*:` **and** one matching the to/subject label `^\*?(To\|Subject\|An\|Betreff\|À\|A\|Objet\|Para\|Asunto\|Aan\|Onderwerp\|Oggetto)\*?\s*:`. These lines are left-trimmed the same way. The optional `*` covers the `*From:*` bold style of plain-text renderings. French Outlook writes `De :` / `Envoyé :` / `À :` / `Objet :`, with a space or U+00A0 before the colon. |
| M5 | Trailing `>` quote | `t` starts with `>`, and every later line `j > i` either is blank after a full trim, has a left-trimmed form starting with `>`, or is a marker of kind M1–M4. Scanning stops at the first M1–M4 line, and the line qualifies. Interleaved replies (`> Q` / `A` / `> Q` / `A`) never qualify, so they stay. |

Compute this in one forward pass. For M5, precompute from the end a
boolean "the rest is only quotes, blanks or a marker", so the pass stays
O(n).

**2. Signature cut**, on the kept lines, in this order:

1. **Delimiter.** Find the first line that is exactly `-- ` or exactly
   `--`. This is the raw line, not trimmed, so ` -- ` and `---` don't
   count. Keep the lines before it.
2. **Known signature**, when `signatureText` is not null and not
   whitespace:
   - `sig` = the non-blank lines of `signatureText` (after the same line
     normalization), each **canonicalized**: trimmed, and runs of
     whitespace (including U+00A0) collapsed to one space. Take the
     first two, or the first one when there is only one.
   - Canonicalize each kept body line the same way and compare with
     `StringComparison.OrdinalIgnoreCase`.
   - With two signature lines: find the **last** body line index `k`
     whose canonical form equals `sig[0]`, where the next **non-blank**
     body line after `k` equals `sig[1]`. With one signature line: the
     last `k` whose canonical form equals `sig[0]`.
   - If found, keep the lines before `k`.

**3. Finish.** Drop trailing lines that are blank after trimming, join
with `\n`, and return `result.Trim()`.

**Notes**
- `OwnText` works on **plain text** only. The callers pass
  `MailItem.Body` or the index body. Outlook's HTML quote containers
  (`divRplyFwdMsg`, `border-top:solid #E1E1E1` divs, `<blockquote>`)
  reach it already rendered as M2, M4 or `>` lines. Don't add HTML
  detection.
- If the very first line is a marker, the result is `""`. That's correct
  for a forward with no text of its own.

### B. `MailText.Redact(text)`

Three passes, in this order, each with `Regex.Replace` and a
`MatchEvaluator`. Every pattern starts with a negative lookbehind, so a
match can't begin in the middle of a word or address. This keeps each
pass linear.

1. **Links.** `(?<![\p{L}\p{N}_@/])<?(?:(?:https?|ftp)://|www\.)[^\s<>"]+>?` (IgnoreCase).
   - Trailing `.`, `,`, `;`, `:`, `!`, `?`, `'`, `"` are not part of the
     URL. Neither is a trailing `)` or `]` while the URL has more closing
     than opening ones of that kind. The evaluator returns
     `LinkToken + <the stripped trailing chars>`.
   - A surrounding `<…>` pair is consumed only when both brackets are
     present (`<https://x>` → `<link>`). A lone `>` that isn't closing a
     leading `<` is left as text.
   - `https://user@host/` becomes `<link>`, not `<email>`, because links
     run first.
2. **Emails.** `(?<![\p{L}\p{N}._%+'\-])<?[\p{L}\p{N}._%+'\-]+@[\p{L}\p{N}\-]+(?:\.[\p{L}\p{N}\-]+)+>?`.
   The `<…>` pair is consumed only when both are present. A trailing `.`
   is never part of the match: the final label can't be empty. →
   `EmailToken`.
3. **Phones.** `(?<![\p{L}\p{N}_.\-+/])(?:\+[ \t]?)?\(?\d(?:[ \t.()\-]{0,2}\d)*(?![\p{L}\p{N}_:])`.
   - The evaluator counts the digits. With **7 or more** digits, and the
     match not a date, it returns `PhoneToken`. Otherwise it returns the
     match unchanged.
   - Dates are `^\(?\d{4}[-./]\d{1,2}[-./]\d{1,2}$` and
     `^\d{1,2}[-./]\d{1,2}[-./]\d{2,4}$`, tested on the match.
   - Separators are spaces and tabs only, never newlines, so a run can't
     span lines.

The result is idempotent: `Redact(Redact(x)) == Redact(x)`.

### C. `MailText.Headers(transportHeaders)`

- Null or empty → an empty dictionary
  (`new Dictionary<string,string>(StringComparer.OrdinalIgnoreCase)`,
  returned as `IReadOnlyDictionary`).
- Normalize line endings as in A.0. Parsing **stops at the first empty
  line** (the end of the header section).
- A line that starts with a space or tab continues the previous header.
  Append one space, then the line with its leading whitespace removed. A
  continuation with no current header (at the start, or after an invalid
  line) is ignored.
- A header line is `name:value`. `name` is non-empty and every char is
  in `!`..`~` except `:`. Lines without a valid name are ignored.
- The value is trimmed after unfolding. An empty value is allowed (`""`).
- The first occurrence of a name wins. Later duplicates (`Received`) are
  ignored.
- No RFC 2047 decoding, and no limit beyond the 64 KiB the COM side
  already applies (§19.9).

### D. `DraftHtml` tokenizer (private, shared)

The tokenizer scans the input left to right and yields **Text**,
**StartTag(name, selfClosing)** and **EndTag(name)** tokens. It drops
comments and declarations itself.

- At `<`:
  - `<!--` → skip to after the next `-->`, or to the end of input.
  - `<!` or `<?` → skip to after the next `>`, or to the end.
  - `</` + ASCII letter → end tag.
  - `<` + ASCII letter → start tag.
  - Anything else → the `<` is Text.
- **Tag name**: `[A-Za-z][A-Za-z0-9:_\-]*`, lower-cased (invariant). The
  rest of the tag up to the closing `>` is skipped quote-aware: `"…"` and
  `'…'` may contain `>`. If no `>` is found before the end of input, the
  `<` is emitted as Text and scanning resumes at the next char, so
  `<script` without a `>` shows up as escaped text. A tag whose last
  char before `>` is `/` is `selfClosing`.
- **Dropped with content**: `script`, `style`, `head`, `title`,
  `iframe`, `object`, `embed`, `svg`, `math`, `template`, `noscript`,
  `textarea`. On their start tag, skip raw input up to and including the
  next `</name` (case-insensitive) that is followed by whitespace, `/` or
  `>`, then up to its `>`. If there is none, skip to the end of input.
  This also applies when the tag is self-closing. An end tag of these
  names on its own is dropped.

### E. `DraftHtml.Sanitize(modelHtml)`

1. Null → `""`. Cut the input to `MaxInputChars`.
2. **Emit** from tokens, with a stack of open allowed elements:
   - Allowed set: `p`, `br`, `ul`, `ol`, `li`, `b`, `strong`, `i`, `em`,
     `u`, `blockquote`. They are re-emitted lower-case with **no
     attributes**.
   - `br`: its start tag emits `<br>` and isn't pushed. `</br>` is
     dropped.
   - Other allowed start tags: if the stack depth is `< MaxDepth`, emit
     `<name>` and push. Otherwise drop the tag (its text is still kept).
     `selfClosing` is ignored, so `<p/>` is a start tag, as in HTML.
   - Allowed end tag: if `name` is on the stack, pop and emit end tags
     down to and including the topmost `name` (this closes intermediate
     ones). Otherwise drop it (a stray end tag).
   - Any other tag (start or end): drop it and keep the text. Exception
     (see Spec changes): a start or end tag of `div`, `h1`–`h6`, `table`,
     `tr`, `pre`, `hr`, `section`, `article`, `header`, `footer` or
     `address` sets `pendingBreak`. Before the next Text token that
     contains visible text, if `pendingBreak` is set and the last thing
     emitted was Text, emit `<br>`. Every emitted tag clears
     `pendingBreak`. So `<div>a</div><div>b</div>` → `a<br>b`, with no
     leading or trailing `<br>`.
   - **Text**: remove C0 controls except `\t`, `\n` and `\r`, and remove
     U+007F. Then escape:
     - `&` starts a valid entity when it is followed by one of these:
       - a **named** entity `[A-Za-z][A-Za-z0-9]{1,31};` for which
         `WebUtility.HtmlDecode("&name;") != "&name;"`;
       - a **decimal** entity `#[0-9]{1,7};`;
       - a **hex** entity `#[xX][0-9A-Fa-f]{1,6};`.

       A numeric entity's value must be in 0x20..0x10FFFF, or be 0x09,
       0x0A or 0x0D, and must not be a surrogate (0xD800..0xDFFF) or
       0x7F..0x9F.
     - A valid entity is copied as-is. Any other `&` becomes `&amp;`.
       `<` becomes `&lt;` and `>` becomes `&gt;`. Quotes stay as they
       are, because text is never inside an attribute.
3. Close every element still on the stack, in reverse order.
4. **Visible text check.** The result is `""` when the emitted text has
   no visible char. To check, decode each text run with
   `WebUtility.HtmlDecode`. Visible means not `char.IsWhiteSpace` and not
   U+200B, U+200C, U+200D, U+2060 or U+FEFF. Check this before step 5.
5. **Placeholders.** On the output string, replace every match of
   `\[\[([^\]\r\n<]{1,200})\]\]` with `HighlightOpen + match + HighlightClose`.
   The inner part can't contain `<`, so a placeholder never spans tags.
   The length is counted on the output, including escapes. `[[]]`, a
   placeholder that spans a newline, and an inner part of more than 200
   chars are left alone.

A highlight `<span>` from the model is dropped like any other span, and
Clippy re-adds exactly one. The output contains no `<` except allowed
tags and the highlight span. A test checks this invariant.

### F. `DraftHtml.ToPlainText(html)`

- Null → `""`. Cut the input to 1,048,576 chars. Use the tokenizer from
  D, so dropped-with-content elements (including `<head>` and `<style>`)
  disappear.
- These produce a **soft break**: `br` (start), and the start or end of
  `p`, `div`, `li`, `tr`, `table`, `ul`, `ol`, `blockquote`, `h1`–`h6`,
  `pre` and `hr`. Consecutive soft breaks collapse to one `\n`, except
  that each `br` always adds its own `\n`. Every other tag (including
  `o:p` and `span`) emits nothing.
- Text runs: decode with `WebUtility.HtmlDecode`, map U+00A0 to a space,
  remove C0 controls, and collapse runs of `[ \t\r\n\f]` to one space.
- Finish:
  - Trim each line.
  - Collapse runs of 2 or more blank lines to one blank line.
  - Trim the whole result.

## Spec changes (proposed, for the spec owner to apply)

These are low-risk, reversible, and don't change any hard rule or
security boundary.

1. **§19.6, own-text markers, broader languages.** Append:
   "Besides English, German and French, the markers also recognize
   Spanish, Dutch and Italian forms: `-----Message d'origine-----`,
   `-----Mensaje original-----`, `-----Oorspronkelijk bericht-----`,
   `-----Messaggio originale-----`, and Gmail's
   `---------- Forwarded message ---------` (and its German, French and
   Spanish forms). Attribution lines `El … escribió:`,
   `Op … schreef … :` and `Il … ha scritto:` also count, and an
   attribution wrapped onto two lines is joined first. Header-block
   labels also include `Datum:`, `Van:`/`Verzonden:`/`Aan:`/`Onderwerp:`,
   `Da:`/`Inviato:`/`Data:`/`A:`/`Oggetto:` and
   `Enviado:`/`Fecha:`/`Para:`/`Asunto:`, optionally wrapped in `*…*`,
   with optional whitespace before the colon. Marker lines may be
   indented. Exact patterns: M11.3 brief." (Why: users in those locales
   would otherwise get quoted history in their style samples. More
   cutting only removes text, so it can't leak more.)
2. **§19.6, known-signature matching.** Append: "Lines are compared
   trimmed, with whitespace runs collapsed and case ignored. With a
   one-line signature, that one line must match a whole line. The
   signature's plain text comes from `DraftHtml.ToPlainText` of the
   default reply signature's body (`Signatures.Default(Reply)`)." (Why:
   the spec says `signatureText` is "the plain text" of the signature,
   but `Signatures` only yields HTML, and nothing produced the text.)
3. **§19.6, `Redact` details.** Append: "A surrounding `<…>` is replaced
   with the token. Trailing punctuation stays outside `<link>`. Dates
   (`yyyy-mm-dd`, `dd.mm.yyyy` and similar) aren't phone numbers. Phone
   runs don't cross line breaks."
4. **§19.8, block separators.** Append: "Dropped block-level tags (`div`,
   `h1`–`h6`, `table`, `tr`, `pre`, `hr`, `section`, `article`, `header`,
   `footer`, `address`) leave a single `<br>` between text runs, so
   `<div>a</div><div>b</div>` doesn't merge into `ab`. A placeholder's
   inner text is 1–200 characters and contains no `<`, so it never spans
   tags. Input over 200,000 characters is cut. Nesting deeper than 64
   allowed elements drops the extra tags (the text is kept). Numeric
   entities for control characters, surrogates or values above U+10FFFF
   are treated as a bare `&`."
5. **§3 layout, `DraftHtml.cs` line.** Change it to: "allow-list HTML
   sanitizer for model output, `[[placeholder]]` highlight, HTML →
   plain text for signature matching (§19.8)".
