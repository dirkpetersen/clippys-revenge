# M15.5 Attention badge on the tray icon

Base: `dev` with **M15.2 merged** (`DraftInvites` with `Count`, `Changed`,
`Track`, `CheckAsync`; `DraftInvitesStore`; the `draftInvites` local in
`Program.cs`). Design against `docs/briefs/M15.2.md` §D/§H/§I. If M15.2
landed with different names, adapt the names, not the behavior. M15.4 (tray
**Draft invites (n)** submenu) runs in parallel and also edits `TrayApp.cs`
and `TrayServices`. Keep the M15.5 changes there small (one record member,
two fields, the `Render`/`SetIcon`/`Dispose` edits below) so the merge is
mechanical. If M15.4 landed first, keep everything it added.

## Goal

When something needs the user (for now only tracked draft invites), the tray
icon shows a small yellow badge with the count (`1`…`9`, `9+`) in the
top-right corner (every state; decided by the user, option (b) below). The badge sits on top of whatever state icon is current,
including every backfill animation frame, and the tooltip gets a suffix
` · <n> draft invite(s) need(s) your attention`. The count comes from a
generic `AttentionCount` (Core) that adds up `IAttentionSource`s. M15 has
one source, `DraftInvites`, which keeps its last count while Outlook is
unavailable. All text, layout and pixel blending is pure Core code and is
tested on Linux. The App's `TrayBadgeRenderer` only draws the badge layer
with GDI+, builds an `Icon` that owns its handle, caches per
(state icon/frame, text) and disposes everything. A Windows-only test checks
the pixels and that 1,000 swaps don't grow the process's GDI/USER object
counts.

SPEC refs: §22.6 (all), §6.1 (icon states, 16/20/24/32 px icons, animation
frames, tooltip ≤127 chars, invariant numbers), §22.3 ("When": count changes
on create and after checks), §22.7 (attention badge test bullet), §3
(file layout).

## Hard rules that apply here

- Nothing here touches Outlook: no COM, no new `OutlookWorker` call. The
  badge reads `DraftInvites.Count` only, and that never does COM.
- Never send, never delete, never launch Outlook: unchanged (no new calls).
- No P/Invoke in product code for this task. The Icon is built from an
  in-memory `.ico`, so .NET owns and destroys its handle. No `GetHicon`, no
  `Icon.FromHandle`, so no `DestroyIcon` is needed (Spec change 3).
- Logs: exception **type** only, no counts tied to subjects, no entry ids.

## Public API

### Core: `AttentionBadge.cs`

```csharp
namespace ClippysRevenge.Core;

/// <summary>Something that can need the user's attention (SPEC §22.6). Count is >= 0 and cheap (no I/O, no COM).</summary>
public interface IAttentionSource
{
    int Count { get; }
    /// <summary>Raised on any thread after Count may have changed.</summary>
    event Action? Changed;
}

/// <summary>Sum of all attention sources (SPEC §22.6). Thread-safe. Lives as long as the process.</summary>
public sealed class AttentionCount
{
    /// <exception cref="ArgumentNullException">sources is null.</exception>
    /// <exception cref="ArgumentException">an element is null.</exception>
    /// <remarks>Subscribes to every source's Changed and computes Total once, here.</remarks>
    public AttentionCount(IEnumerable<IAttentionSource> sources, ILogger? logger = null);

    /// <summary>Last computed sum. Negative source counts count as 0; saturates at int.MaxValue.</summary>
    public int Total { get; }

    /// <summary>Raised (any thread) only when Total changed. Each handler called separately; exceptions caught and
    /// logged (Warning, type only).</summary>
    public event Action? Changed;
}

public readonly record struct PixelRect(int X, int Y, int Width, int Height)
{
    public int Right => X + Width;      // exclusive
    public int Bottom => Y + Height;    // exclusive
    public bool Contains(int x, int y) => x >= X && x < Right && y >= Y && y < Bottom;
    public PixelRect Inset(int d) => new(X + d, Y + d, Width - 2 * d, Height - 2 * d);
}

/// <param name="Badge">The whole badge (outline included), flush with the icon's right and top edges.</param>
/// <param name="Inner">Badge inset by Outline: the yellow area.</param>
/// <param name="TextBox">Inner inset by 1: the digits are scaled and centered to fit here.</param>
/// <param name="FontPx">Em size in pixels before fitting.</param>
public sealed record BadgeLayout(int IconPx, PixelRect Badge, int Outline, PixelRect Inner, PixelRect TextBox, int FontPx);

public static class AttentionBadge
{
    public const int MaxShown = 9;
    public static readonly (byte R, byte G, byte B) Fill = (0xFF, 0xD4, 0x00);
    public static readonly (byte R, byte G, byte B) Ink = (0x1A, 0x1A, 0x1A);

    /// <summary>"" for 0, "1".."9", "9+" above 9.</summary>
    /// <exception cref="ArgumentOutOfRangeException">count &lt; 0.</exception>
    public static string Text(int count);

    /// <summary>The icon size to render for a system small-icon size: the smallest of 16/20/24/32 that is
    /// >= requestedPx, else 32.</summary>
    /// <exception cref="ArgumentOutOfRangeException">requestedPx &lt; 1.</exception>
    public static int PickIconSize(int requestedPx);

    /// <summary>Badge geometry (table in Behavior §B). Wide (for "9+") when text has 2 characters.</summary>
    /// <exception cref="ArgumentOutOfRangeException">iconPx is not 16, 20, 24 or 32.</exception>
    /// <exception cref="ArgumentNullException">text is null.</exception>
    /// <exception cref="ArgumentException">text is "" or longer than 2 characters.</exception>
    public static BadgeLayout Layout(int iconPx, string text);

    /// <summary>
    /// Returns a new RGBA buffer: baseRgba with layerRgba blended over it (straight alpha, source-over) inside
    /// <paramref name="area"/> only. Pixels outside area, and inside pixels whose layer alpha is 0, are copied from
    /// baseRgba byte for byte. Inputs are not modified.
    /// </summary>
    /// <exception cref="ArgumentNullException">a buffer is null.</exception>
    /// <exception cref="ArgumentException">a buffer's length isn't iconPx*iconPx*4.</exception>
    /// <exception cref="ArgumentOutOfRangeException">iconPx &lt; 1, or area not inside [0, iconPx)².</exception>
    public static byte[] Composite(byte[] baseRgba, byte[] layerRgba, int iconPx, PixelRect area);

    /// <summary>"" for 0; " · 1 draft invite needs your attention"; " · <n> draft invites need your attention"
    /// with n in invariant N0 ("1,240").</summary>
    /// <exception cref="ArgumentOutOfRangeException">count &lt; 0.</exception>
    public static string TooltipSuffix(int count);
}
```

## Behavior

### §A Text, size pick, tooltip suffix

- `Text`: `0` → `""`; `1..9` → the digit; `> 9` → `"9+"` (so `10`, `250`,
  `int.MaxValue` → `"9+"`).
- `PickIconSize`: `≤16` → 16, `≤20` → 20, `≤24` → 24, else 32. At 175 %
  (`SmallIconSize` 28) that's 32, and the shell scales it down, the same way
  it already scales the plain icons.
- `TooltipSuffix(n)`: `" · " + n.ToString("N0", Invariant) + (n == 1 ? " draft invite needs your attention" : " draft invites need your attention")`.
  The separator is `" · "` (space, U+00B7, space), as in the idle tooltip.
  For n = 1..9 the suffix is 38 characters.
- The wording names draft invites because that is the only source in M15.
  When the spec adds a second source, it has to define new wording (Spec
  change 6).

### §B `Layout(iconPx, text)`: exact numbers

Height `H = round(0.6 × px)` (≥ 9). Single digit: a circle (`W = H`).
`9+`: a capsule. Always flush top-right: `Badge = (px − W, 0, W, H)`.
`Inner = Badge.Inset(Outline)`, `TextBox = Inner.Inset(1)`.

| px | H | W (1 char) | W (`9+`) | Outline | FontPx | Badge 1 char | Badge `9+` |
|---|---|---|---|---|---|---|---|
| 16 | 10 | 10 | 15 | 1 | 9 | (6,0,10,10) | (1,0,15,10) |
| 20 | 12 | 12 | 18 | 1 | 11 | (8,0,12,12) | (2,0,18,12) |
| 24 | 14 | 14 | 21 | 1 | 13 | (10,0,14,14) | (3,0,21,14) |
| 32 | 19 | 19 | 28 | 2 | 17 | (13,0,19,19) | (4,0,28,19) |

Examples: 16/`1`: Inner (7,1,8,8), TextBox (8,2,6,6). 32/`9+`: Inner
(6,15,24,15), TextBox (7,16,22,13). Implement as a `switch` over the four
sizes; don't derive it with a formula.

### §C `Composite` and `AttentionCount`

- `Composite`: for each pixel `(x, y)` in `area` with layer alpha
  `la > 0`: `sa = la/255`, `da = ba/255`, `oa = sa + da(1 − sa)`; colour
  `c = (lc·sa + bc·da·(1 − sa)) / oa` per channel (0 when `oa == 0`); bytes
  rounded as `TrayIconArt` does (`(byte)(int)(v*255 + 0.5)` on the 0..1
  values). Layer alpha 255 gives the layer pixel exactly. Everything else
  is copied from base.
- `AttentionCount`: holds the sources in order and, under a `Lock`, the last
  `Total`. On a source's `Changed`: recompute the sum under the lock. Read
  each `Count` in a `try`: if it throws, log a Warning
  `Attention count could not be read ({Type}).` and keep the previous total
  (no event). Compare with the last total, store it, and raise `Changed`
  **outside** the lock only when it differs. A source raising `Changed`
  with an unchanged count raises nothing (DraftInvites also raises on
  Details-only changes).
- "Last count while Outlook is unavailable" holds because
  `DraftInvites.Count` doesn't change when a check fails or Outlook is
  away (M15.2 §I). `AttentionCount` adds no Outlook-state logic and never
  resets to 0. At start-up `Total` = the stored list's size, because
  `DraftInvites` loads the store in its constructor.

### §D Tooltip

- `TrayPresenter.Update(..., attentionCount)`: `suffix =
  AttentionBadge.TooltipSuffix(attentionCount)`. `Build` sets
  `Tooltip = TrayText.AppendSuffix(rawTooltip, suffix)` in place of
  `TrayText.Truncate(tooltip)`. This covers both callers: the Serving-pulse
  early return and the normal path. With count 0 the result is identical to
  today.
- `StatusLine` (the first menu line) does **not** get the suffix. The menu
  shows **Draft invites (n)** instead (Spec change 4).
- `AppendSuffix`: `suffix == ""` → `Truncate(text, max)`. If
  `text.Length + suffix.Length <= max`, return the concatenation. Otherwise
  return `Truncate(text, max − suffix.Length) + suffix`, so the base ends
  in `…` right before ` · `. The result is always ≤ 127, and `NotifyIcon.Text`
  throws above 127.

### §E `TrayBadgeRenderer`

**RenderLayer(px, text)** (GDI+; dispose every object with `using`):

1. `l = AttentionBadge.Layout(px, text)`.
   `using var bmp = new Bitmap(px, px, PixelFormat.Format32bppArgb)`,
   `using var g = Graphics.FromImage(bmp)`. Then `g.Clear(Color.Transparent)`,
   `SmoothingMode.AntiAlias`, `PixelOffsetMode.HighQuality` (integer
   coordinates are pixel edges, so a rect 6..16 covers pixels 6–15),
   `CompositingMode.SourceOver`, `CompositingQuality.HighQuality`.
2. Outline and fill without a `Pen`: fill the capsule of `l.Badge` with
   `Ink`, then fill the capsule of `l.Inner` with `Fill`. A capsule is
   `AddEllipse(rect)` when `W == H`. Otherwise it is two `AddArc`
   half-circles of diameter `H` joined by straight edges, with
   `CloseFigure()`. Each capsule is its own `using GraphicsPath`. Both
   `SolidBrush`es are `using`.
3. Digits: `using var family` = `new FontFamily("Segoe UI")`. On
   `ArgumentException` (font missing) use `FontFamily.GenericSansSerif`
   (also disposed). Use style `Bold` if
   `family.IsStyleAvailable(FontStyle.Bold)`, else `Regular`.
   `using var fmt = new StringFormat(StringFormatFlags.NoWrap | StringFormatFlags.NoClip)`.
   `using var path = new GraphicsPath()`, then
   `path.AddString(text, family, (int)style, l.FontPx, PointF.Empty, fmt)`.
   Let `b = path.GetBounds()` and
   `k = min(1, TextBox.Width / b.Width, TextBox.Height / b.Height)`. With
   `using var m = new Matrix()`, apply `Translate(−b.X − b.Width/2, −b.Y − b.Height/2)`,
   then `Scale(k, k, Append)`, then
   `Translate(TextBox.X + TextBox.Width/2f, TextBox.Y + TextBox.Height/2f, Append)`.
   Call `path.Transform(m)` and fill it with the `Ink` brush. Centering on
   the glyph bounds, not on `DrawString`'s line box, keeps the digit
   centered whatever the font's internal leading. Text rendering hints
   don't apply because only paths are filled, which also avoids ClearType
   fringes on a transparent bitmap.
4. Read back with `bmp.LockBits(full, ReadOnly, Format32bppArgb)`: per
   row, `Marshal.Copy(scan0 + y*stride, row, 0, px*4)`, convert BGRA to
   RGBA into the result. Call `UnlockBits` in a `finally`.
5. Before returning, set every pixel outside `l.Badge` to `(0,0,0,0)`.
   That's a guard: AA never reaches past the rect.

**ComposeRgba(key, px, text)**:
`AttentionBadge.Composite(TrayIconArt.RenderRgba(key, px), RenderLayer(px, text), px, Layout(px, text).Badge)`.

**Get(key, text)** and the cache:

- State: `_text` (the current generation's text, `""` initially),
  `_current: Dictionary<TrayIconKey, Icon>`, `_retired: List<Icon>`, and
  `_layers: Dictionary<string, byte[]>` (layer per text, at most 10 texts,
  no handles). Layers are the same for every state. Only the base differs.
- `text == ""` → `ArgumentException`. Disposed → `ObjectDisposedException`.
- When `text != _text`: dispose every icon in `_retired`, move
  `_current`'s icons to `_retired`, clear `_current`, set `_text = text`.
  That's two generations. The icon the `NotifyIcon` shows right now
  belongs to the previous text, and `NotifyIcon` re-reads `Icon.Handle`
  whenever its `Text` changes, so that icon must not be disposed until
  the caller has assigned the new one. One generation later it is never
  shown again. This is how §22.6's "the cache is cleared when the count
  changes" is implemented (Spec change 5). Counts that map to the same
  text (10 → 11, both `9+`) don't rebuild anything.
- On a cache hit for `key`, return it. Otherwise:
  `rgba = Composite(RenderRgba(key, px), layer(text), px, Layout(px, text).Badge)`
  and `ico = IcoEncoder.Encode([(px, rgba)])`. Then
  `using var ms = new MemoryStream(ico)` and
  `icon = new Icon(ms, px, px)`. Read `icon.Handle` once so a bad image
  fails here and not inside `NotifyIcon`. Store and return it. The `Icon`
  owns its HICON and `Dispose` destroys it, so there is no `GetHicon`,
  `FromHandle` or `DestroyIcon`.
- The cache is bounded: at most 10 icons per generation (one per
  `TrayIconKey`, frames included), 2 generations.
- `Dispose`: dispose `_current` and `_retired` icons, clear `_layers`, set
  disposed. Idempotent.

### §F `TrayApp`

- Fields: `TrayBadgeRenderer? _badge` and `string _badgeText = ""`
  (wanted), `string _shownBadge = ""` (on screen).
- Constructor, after `_icons`: if `_s.Attention is not null`, set
  `_badge = new TrayBadgeRenderer(AttentionBadge.PickIconSize(SystemInformation.SmallIconSize.Width))`
  and subscribe `_s.Attention.Changed += OnHubChanged` (the existing
  coalescing UI-thread render). The process's DPI mode stays as it is.
  `SmallIconSize` is what `TrayIcons` already uses.
- `Render()`: `var count = _s.Attention?.Total ?? 0;`. Pass
  `attentionCount: count` to `_presenter.Update`. Set
  `_badgeText = AttentionBadge.Text(count)` **before** the `SetIcon`
  calls. In the animated branch, when the animation is already running,
  call `SetIcon(TrayIconKey.Backfill0 + _frame)` so a count change shows at
  once and not only on the next 250 ms tick. The tick handler stays as
  it is.
- `SetIcon(key)`: return when `key == _shownKey && _badgeText == _shownBadge`.
  Otherwise: `icon = _icons.Get(key)` when `_badgeText == ""` or `_badge`
  is null, else `_badge.Get(key, _badgeText)`. Catch `ExternalException`,
  `ArgumentException`, `OutOfMemoryException` (GDI+ failures) around the
  badge path: dispose the renderer, set `_badge = null` (no retry every
  tick), and use the plain icon. Then set `_notify.Icon = icon`,
  `_shownKey = key`, `_shownBadge = _badgeText` (`""` after a fallback).
- `Dispose`: unsubscribe `_s.Attention.Changed`, then dispose `_badge`
  **after** `_notify.Dispose()` (next to `_icons.Dispose()`).
- No other menu, balloon or status-line change. The **Draft invites (n)**
  submenu is M15.4.

### §A `AttentionBadgeTests`

1. `Text`: 0 → `""`, 1 → `"1"`, 9 → `"9"`, 10 → `"9+"`, 250 → `"9+"`,
   `int.MaxValue` → `"9+"`; −1 → `ArgumentOutOfRangeException`.
2. `PickIconSize`: 1→16, 16→16, 17→20, 20→20, 21→24, 24→24, 25→32,
   28→32, 32→32, 48→32; 0 → `ArgumentOutOfRangeException`.
3. `Layout_exact` (theory, 8 rows): the Badge, Outline and FontPx of the
   §B table for px ∈ {16,20,24,32} × text ∈ {`"1"`,`"9+"`}. Also the
   Inner/TextBox of the two worked examples.
4. `Layout_invariants` (all 8): `Badge.Right == px`, `Badge.Bottom == px`,
   `Badge.X >= 0`, `Badge.Height >= 9`,
   `Badge.Height == (int)Math.Round(0.6 * px)`,
   `Inner == Badge.Inset(Outline)`, `TextBox == Inner.Inset(1)`,
   `TextBox.Width > 0`, `FontPx < Badge.Height`; the wide width is
   greater than the narrow one at the same height; Outline is 1 except 2
   at 32.
5. `Layout_errors`: px 15, 28, 64 → `ArgumentOutOfRangeException`; text
   `null` → `ArgumentNullException`; `""`, `"123"` →
   `ArgumentException`. `"7"` and `"9+"` are fine.
6. `Composite_outside_area_is_base`: base all `(10,20,30,128)` at 16 px,
   layer all `(255,0,0,255)`, area (6,6,10,10). Pixels outside the area
   are `(10,20,30,128)`, pixels inside are `(255,0,0,255)`. The inputs are
   unchanged (compare with copies).
7. `Composite_zero_alpha_copies_base`: layer alpha 0 everywhere, area =
   the whole icon → the result equals the base byte for byte.

## Spec changes

None made by this brief (the caller owns `SPEC.md` for this run). Proposed
low-risk choices for the caller to record in §22.6:

1. **Layout signature and numbers**: `AttentionBadge.Layout(iconPx, text)`
   (the text decides narrow or wide), with the §B table. A single digit is
   a circle and `9+` is a capsule, flush bottom-right. Outline 1 px (2 px
   at 32 px). `PickIconSize` maps the system small-icon size to
   16/20/24/32.
2. **Composition split**: GDI+ draws only the badge layer (two filled
   capsules and the digits as a glyph path, so there are no `Pen` or
   `Font` objects). The blend over the state icon is pure Core
   (`AttentionBadge.Composite`) on `TrayIconArt.RenderRgba` pixels, which
   are identical to the embedded `.ico` files. That makes the pixels
   outside the badge provably unchanged.
3. **Icon handles**: the badged `Icon` is built from an in-memory `.ico`
   (`IcoEncoder`), so the `Icon` owns its HICON and `Dispose` destroys it.
   The code has no `GetHicon`/`Icon.FromHandle`, so no `DestroyIcon` is
   needed, and a scan enforces this. §22.6's `DestroyIcon` sentence then
   reads "the code never creates an Icon from a raw handle".
4. **Tooltip only**: the suffix goes on the tooltip, not on the first
   menu status line (the menu has **Draft invites (n)**). The count uses
   invariant `N0`.
5. **Cache clearing**: per (state icon incl. frame, badge text), two
   generations. The previous text's icons are disposed on the next text
   change, because the `NotifyIcon` still references the shown icon until
   the new one is assigned. Counts with the same text (`9+`) don't
   rebuild.
6. **Wording**: the tooltip suffix names draft invites. A future second
   source needs its own wording in the spec.
