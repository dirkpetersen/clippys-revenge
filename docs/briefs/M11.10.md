# M11.10 Live tests: Claude CLI and the Outlook + Claude manual-draft round trip

Base: `dev` with M11.1–M11.9 merged. This task adds **tests only**, a
small refactor inside `tests/…/Live/`, one line in the test csproj and a
switch in `scripts/run-live-tests.ps1`. No file under `src/` changes.
Nothing here runs in CI: every new live test carries `[Trait("live","claude")]`,
which the M11.9 filter `live!=outlook&live!=claude` already excludes.

## Goal

Prove on the user's own PC that the AI drafting path works end to end
against real software, while spending almost no Claude usage and never
sending mail (SPEC §19.12 "Live", §15 live tests, §19.3, §19.7 "Manual",
§19.8, §19.9, §19.11). There are two parts:

1. **Claude only** (`[Trait("live","claude")]`): the CLI is found, its
   status is `Ready`, and one tiny structured-output call (`{"ok": true}`
   schema) succeeds. It runs on `claude-haiku-5-5` with effort `low`.
2. **Outlook + Claude round trip** (`[Trait("live","outlook")]` +
   `[Trait("live","claude")]`). The test creates a synthetic,
   self-addressed, **unsent** source email in the own Drafts folder and
   runs the production manual path `DraftWorker.DraftSelectedAsync` on
   it. The path uses the real `OutlookAiMailbox`, `OutlookReplyDraftWriter`
   and `ClaudeCliModel`, also on Haiku/`low`. The test then checks:
   - the reply draft is in Drafts and `Sent == false`;
   - the subject is `Re:: …`;
   - the `ClippyDraft` marker is `ai`;
   - the inserted body is sanitized;
   - the Sent Items and Outbox counts are unchanged.

   It deletes only the two items it created.

Both parts are skipped, not failed, unless `CLIPPY_LIVE=1` **and**
`CLIPPY_LIVE_CLAUDE=1` are set (Spec changes #3). The app's default model
stays `claude-opus-5-5`. Only these tests override it.

## Hard rules that apply here

- **Never send.** The round trip reaches Outlook only through
  `OutlookReplyDraftWriter` → `OutlookMail.CreateReplyDraft`, which only
  calls `.Save()`. The source email is created with `create_draft`'s
  writer (`OutlookDraftWriter`, `.Save()` only). The test code calls no
  `.Send(`, `.Display(` or `.Move(`.
  - `RecordingReplyWriter` (§A.4) refuses, before any COM, a plan whose
    marker isn't `ai`, whose id isn't the source, or whose `Mailbox`
    isn't null.
  - `LiveOutlook.WithCleanupAsync` asserts that the Sent Items and
    Outbox counts didn't change and that no run-token item reached
    either folder.
- **Never delete mail.** The only deletes are the existing
  `LiveOutlook.DeleteAsync`/`PurgeDeleted`. They delete by recorded entry
  id, and only when the subject starts with `"[RunToken] "`. The new
  tests add no delete code. They `Track` what they create and let
  `WithCleanupAsync` clean up.
- **Attach-only.** Everything goes through the fixture's `OutlookWorker`
  (`GetActiveObject`). Nothing starts Outlook.
- **Re:: .** The check is
  `Assert.StartsWith("Re:: ", subject, StringComparison.Ordinal)` and
  `subject == ReplySubject.Normalize(sourceSubject)`. The test file has
  no other reply-subject literal.
- **Claude credentials.** The tests use only `ClaudeCliLocator.Default`,
  `ClaudeCliRunner` and `ClaudeCliModel`. Sign-in state comes from
  `claude auth status --json`, through `CheckAsync`. The tests never read
  `.credentials.json`, an environment token or the credential store, and
  never pass `--bare`. The model gets no tools: `ClaudeCliArgs.Build`
  passes `--tools ""`.
- **Privacy (§19.11).** Test output, `LIVE-RESULT` lines and assertion
  messages never contain:
  - mail text, prompts or model output;
  - the user's name, SMTP address, Claude auth method or subscription
    type;
  - full paths under the user profile.

  Concretely:
  - Don't use `Assert.Contains(x, html)`, `Assert.Equal(expected, body)`
    or anything else that prints a body or prompt when it fails. Use
    `Assert.True(cond, "<fixed text>")`.
  - Don't pass a logger to `ClaudeCliModel`, `ClaudeCliRunner` or
    `DraftWorker` (null).
  - Never print `ModelStatus.Text` when it is `Ready`, because it carries
    the auth method and subscription. The not-ready texts are fixed
    strings and may appear in skip messages.
- **Minimal data to Claude.** The round trip sends only:
  - the synthetic source;
  - the user's display name and SMTP in the system prompt, as production
    does;
  - `DraftPrompt.NoStyleGuideText` instead of the user's style skill;
  - no signature;
  - an empty `<thread>`.

  `GuardedModel` (§A.3) enforces this **before** the CLI runs.

## Behavior

### A. Helpers

**A.1 Gate and model.**
- `IsEnabled`: `isWindows && env("CLIPPY_LIVE") == "1" && env("CLIPPY_LIVE_CLAUDE") == "1"`.
  `"true"`, `" 1"` and the like don't count.
- `ModelFrom`: read `CLIPPY_LIVE_CLAUDE_MODEL`. Null or blank →
  `claude-haiku-5-5`. Otherwise trim it, and return it when
  `ClaudeCliArgs.IsValidModel` accepts it (that method is `internal`;
  `InternalsVisibleTo` covers the tests), else return null. The override
  exists only in case the Haiku alias changes. Its value is printed in
  `LIVE-RESULT` lines (a model name isn't personal data).
- Every live Claude test **starts** with `LiveClaude.RequireEnabled()`,
  before any COM, process start or file I/O.

**A.2 `FixedSelectionMailbox`.** This is the test seam the manual path
needs. `DraftWorkerServices.Mailbox` is already an interface, so the
seam is a test-side decorator and production stays unchanged. There is
no new member on `IAiMailbox`, `DraftWorker` or `OutlookAiMailbox`, and
no `#if`. `GetSelectedAsync` returns the fixed `SelectedEmail` and
counts the call. `ShowDraftsAsync` returns `false` and never calls
`inner`, so the test can't change the user's Outlook window. The other
three members call `inner` with the same arguments.

**A.3 `GuardedModel`.** In `RunAsync`, check these in order. On the
first failure, set `Tripped` and return `new ModelResult.Failed(ModelFailure.BadInput, null)`
**without** calling `inner`:

| Check | `Tripped` |
|---|---|
| `Calls >= 1` (one call per test) | `"second call"` |
| `request.Model != expectedModel` (Ordinal) | `"model"` |
| `request.Effort != "low"` | `"effort"` |
| `!request.UserPrompt.Contains(requiredToken, Ordinal)` | `"token"` |
| `!request.UserPrompt.Contains("<thread>\n</thread>", Ordinal)` | `"thread"` |
| `!request.SystemPrompt.Contains(DraftPrompt.NoStyleGuideText, Ordinal)` | `"style"` |
| `request.UserPrompt.Contains("signature_added: yes", Ordinal)` | `"signature"` |

When every check passes, increment `Calls`, time the call with
`Stopwatch`, then `LastResult = await inner.RunAsync(request, ct)`, set
`LastDuration`, and return it. `CheckAsync` is a pass-through. The guard
never logs or stores the request.

**A.4 `RecordingReplyWriter`.** Check the plan before calling `inner`
(see the signature). Then `made = await inner.ReplyAsync(plan, ct)`, add
the plan to `Plans`, call `onCreated(made)` and return `made`. If
`onCreated` throws, let the exception propagate. The test's callback
only calls `scope.Track`, which doesn't throw.

**A.5 `AiHtmlChecks`.** These are pure. Tag scan: every match of
`<[^>]*>` must be in the allowed set (see the signature). A `<` not
followed by a closing `>` makes the result false. `Active` uses the
three regexes from the signature with `IgnoreCase | CultureInvariant`
and a 1 s timeout. A named anchor such as `<a name="_MailEndCompose">`
isn't a link.

### B. Moving `ReadDraft`

Move the private record `DraftFacts`, `ReadDraft`, `ReadMarker` and
`Rel` from `LiveDraftTests` into `LiveDrafts`, word for word. The only
changes:
- `fx` becomes a parameter;
- the record gains `Text` (`item.Body ?? ""`, read right after
  `HTMLBody`).

`LiveDraftTests` calls `LiveDrafts.ReadDraft(fx, app, …)` and
`LiveDrafts.Rel(…)`. Its tests and assertions stay the same. Don't
create a second reader.

### C. `run-live-tests.ps1 -Claude`

- New `[switch]$Claude`, documented in the help block:
  `.PARAMETER Claude  Also run the live Claude tests (sets CLIPPY_LIVE_CLAUDE=1). They use a little of your Claude usage (two small Haiku calls).`
- When it's set (and `-AllowClosed` isn't), the filter is
  `live=outlook|live=claude`, and `CLIPPY_LIVE_CLAUDE=1` is set. Without
  it, `CLIPPY_LIVE_CLAUDE` is **removed** from the process environment,
  so a plain run never spends Claude usage, even when the variable is
  set in the user's shell. The round trip then shows as skipped with
  `NotEnabled`.
- Add `CLIPPY_LIVE_CLAUDE` to the save/restore list. `-DryRun` prints
  `  CLIPPY_LIVE_CLAUDE=1` when `-Claude` is set.
- Don't preflight Claude in the script. The tests do it, and the script
  never starts `claude`.
- With `-AllowClosed`, `-Claude` is ignored.

### D. Results lines

These keys go through `fx.Result(key, value)`. Each value is exactly one
of the forms below. Numbers use invariant culture.

| Key | Value |
|---|---|
| `claude-status` | `ready, version <v>, safe-mode listed=<true\|false>, exe=<file name only>` (safe-mode listed = the status text doesn't contain `ClaudeCliStatusTexts.UpdateHint`) |
| `claude-call` | `ok in <s:0.0> s, tokens <in\|?>/<out\|?>, model <model>` |
| `ai-reply-baseline` | `ok` or `skipped: reply to an unsent item failed (HResult 0x<hex>)` |
| `ai-roundtrip` | `drafted in <s:0.0> s, model <model>, confidence <c:0.00>, placeholders=<yes\|no>, links=<n>` (`links` = `Active(fragment).Links`, always 0 when sanitized) |

No other output. Skip messages are the fixed texts above.

### T3 `LiveAiDraftTests.Manual_draft_round_trip_saves_ai_reply_and_sends_nothing` (live)

```csharp

[Trait("live", "outlook")]
[Trait("live", "claude")]
[Trait("os", "windows")]
public sealed class LiveAiDraftTests(LiveOutlook fx)
// [Fact(Timeout = 300_000)]
```

Set the cost note in the class `<summary>`: "Uses claude-haiku-5-5
with effort low (one call), not the app default claude-opus-5-5."

Steps, in this order (`ct = TestContext.Current.CancellationToken`):

1. `var model = LiveClaude.RequireEnabled();` then
   `await fx.RequireReadyAsync(ct);` then `var me = await fx.MeAsync();`.
2. `var ai = LiveClaude.Settings(model, DateTimeOffset.UtcNow);`
   `var s = fx.Settings.Clone(); s.AiDrafting = ai;`. The fixture's
   `Settings` is never changed.
   `var cli = LiveClaude.CreateModel(() => s.AiDrafting, Path.Combine(fx.TempRoot, "ai"));`
   `await LiveClaude.RequireReadyAsync(cli, ct);`. This happens before
   anything is created in Outlook.
3. `var ownStore = await fx.RunAsync("reading the store id", app => fx.StoreIdOf(app, ""));`
4. `await fx.WithCleanupAsync([""], Outlook.OlDefaultFolders.olFolderDrafts, async scope => { … })`:
   1. **Synthetic source.** `subject = $"[{fx.RunToken}] AI round trip"`.
      Body (plain text, `Html: false`), lines joined with `\n`:
      `Hi,` / `` / `Could you tell me which day next week works for a 30-minute call about the test plan? Please include the link https://example.org/plan in your answer.` / `` / `Thanks,` / `Sam` / `` / `{fx.RunToken}`.
      Create it with
      `new CreateDraftTool(fx.Settings, new Signatures(_ => null, Path.Combine(fx.TempRoot, "no-signatures")), new OutlookDraftWriter(fx.Worker, fx.Stores), fx.Hub).RunAsync(new CreateDraftArgs(Recipients.Format([me]), subject, body), ct)`,
      so it is self-addressed, saved in own Drafts, never sent, and has
      no signature. Then **at once**
      `scope.Track(new TrackedItem(TrackedKind.Draft, "", src.Id, ownStore, subject))`.
   2. **Reply baseline (no Claude yet).** On the worker: open the source
      by `GetItemFromID(src.Id, ownStore)`, then `r = item.Reply()`, read
      `r.HTMLBody`, `Close(OlInspectorClose.olDiscard)` in a try/catch,
      and release everything. This saves nothing. Keep
      `baseline = AiHtmlChecks.Active(html)`. If `Reply()` throws a
      `COMException` that isn't "gone", write `ai-reply-baseline:
      skipped: …` and `Assert.Skip("Outlook can't reply to an unsent test item on this profile, so the AI round trip can't run here. Nothing was sent.")`.
      Otherwise write `ai-reply-baseline: ok`.
   3. **Wiring.** Every service is real except the selection and the
      guards:
      ```csharp
      var aiMailbox = new FixedSelectionMailbox(
          new OutlookAiMailbox(fx.Worker, fx.Mail, fx.Stores), new SelectedEmail(src.Id, ownStore));
      var guard = new GuardedModel(cli, model, fx.RunToken);
      var writer = new RecordingReplyWriter(new OutlookReplyDraftWriter(fx.Worker, fx.Mail, fx.Stores), src.Id,
          made => scope.Track(new TrackedItem(TrackedKind.Draft, "", made.EntryId, ownStore, $"[{fx.RunToken}] {made.Subject}")));
      using var hub = new ActivityHub();
      using var drafts = new DraftWorker(new DraftWorkerServices(() => s, fx.Indexes, aiMailbox, writer, guard,
          NoStyleGuide.Instance, () => null, hub, new BalloonCenter(),
          () => fx.Worker.State == OutlookConnectionState.Available, () => false, TimeZoneInfo.Local));
      ```
      `StartAsync` is never called, so there's no automatic loop, and
      `Enabled` is false anyway.
   4. **Run.** `var result = await drafts.DraftSelectedAsync(ct);`
   5. **Tag first.** If `writer.Plans.Count == 1`, read and tag the
      reply at once:
      `f = await fx.RunAsync("reading the AI reply", app => LiveDrafts.ReadDraft(fx, app, "", made.EntryId, tag: true))`.
      Keep `made` from the callback. `f` holds the facts from before
      tagging.
   6. **Outcome.** In this order:
      - `guard.Tripped is not null` → `Assert.Fail("The live guard refused the Claude request (" + guard.Tripped + "). Nothing was sent to Claude.")`.
      - `guard.LastResult is ModelResult.RateLimited` → `Assert.Skip(UsageLimit)`.
      - `result.Message.StartsWith("Claude isn't ready: ")` →
        `Assert.Skip(NotReady(…))`.
      - Otherwise `Assert.True(result.Drafted, "Manual draft failed: " + result.Message)`.
        The message is one of the fixed `DraftTexts`; it holds no mail
        data.
   7. **Assertions:**
      - `result.Message == DraftTexts.ManualDone`.
      - `aiMailbox.SelectionCalls == 1`. `guard.Calls == 1`.
        `guard.LastResult is ModelResult.Ok`.
      - `writer.Plans` has exactly one plan: `Id == src.Id`,
        `Mailbox == null`, `Marker == DraftMarker.Ai`,
        `Priority == WorkPriority.Interactive`, `SignatureAdded == false`.
      - `AiHtmlChecks.FragmentIsSanitized(plan.HtmlFragment)`. Message:
        `"The AI fragment has a tag outside the allow-list."`
      - `f.Subject == ReplySubject.Normalize(subject)`, and it starts
        with `"Re:: "` (Ordinal).
      - `f.Sent == false`. `f.ParentId == f.DraftsId` (in own Drafts).
        `f.ClippyDraft == DraftMarker.Ai`.
      - `AiHtmlChecks.Active(f.Html)`: `Scripts == 0`,
        `Links <= baseline.Links`, `Images <= baseline.Images`. Message:
        `"The saved reply has more links/images than Outlook's own reply."`
      - `AiHtmlChecks.StartOfFragmentIn(plan.HtmlFragment, f.Text)`.
        Message: `"The AI text is not in the saved reply."`
      - The source is unchanged: reading it again gives
        `Sent == false` and `Subject == subject`.
      - Decision row:
        `fx.Indexes.For("").GetDecision(src.Id)` has `Outcome == Drafted`,
        `ModelCalls == 1`, `Attempts == 0`,
        `DraftEntryId == made.EntryId`, `ConversationTopic == null`.
        `drafts.ModelCallsToday() >= 1`.
      - `hub.GetEvents()` contains exactly one `ActivityKind.Draft`
        event, with text `DraftTexts.DraftCreated(made.Subject)`.
   8. Write `ai-roundtrip` (§D). `placeholders` is `yes` when the
      fragment contains `DraftHtml.HighlightOpen`.
5. `WithCleanupAsync` then:
   - deletes the source and the tagged reply, by entry id and token;
   - purges them from Deleted Items;
   - checks that no token item is left in Drafts;
   - asserts the Sent Items and Outbox counts are unchanged and that no
     token item is in either folder.

Don't add a second Sent/Outbox check. That one is the assertion.

If the test fails after the reply was created but before step 5 tagged
it, cleanup refuses to delete the untagged reply (the existing
safeguard). It then reports it as `LIVE-LEFTOVER` / "still in Drafts".
That's acceptable; doing step 5 first keeps the window small.

## Spec changes (proposed)

These are low-risk and test-only. None relaxes a hard rule or changes
app behavior.

1. **§19.12 round-trip source.** "Build a synthetic email the same way as
   the M10.2 reply-draft test" doesn't work as written: M10.2 replies to
   a real synced Inbox mail, and using one here would send real mail
   content to Claude. Replace it with:
   - The source is a self-addressed, unsent `MailItem` that the test
     saves in the own Drafts folder through `create_draft`'s writer,
     with no signature and the run token in the subject and body.
   - Before any Claude call, the test checks that Outlook can `Reply()`
     to it (in memory, discarded). If it can't, the test is skipped.
2. **§19.12 selection seam.** The live test replaces only the UI
   selection, with a test-side `IAiMailbox` decorator over the real
   `OutlookAiMailbox` (`GetSelectedAsync` returns the source's entry id;
   `ShowDraftsAsync` is a no-op). Production code has no test seam.
3. **§19.12 / §15 gating.** Every live Claude test needs `CLIPPY_LIVE=1`
   **and** `CLIPPY_LIVE_CLAUDE=1`, and runs on Windows only (`Live/`
   compiles only there). Before this, SPEC said Claude-only tests need
   just `CLIPPY_LIVE_CLAUDE=1`. Missing variables, Claude not
   found/not signed in/too old, and a usage limit give a **skip** with a
   fixed text, the same way "Outlook not running" does.
4. **§19.12 cost.** Live Claude tests use `claude-haiku-5-5` with effort
   `low` (override: `CLIPPY_LIVE_CLAUDE_MODEL`). Each run makes at most
   two model calls. The round trip sends no style skill, no signature
   and no thread. A guard enforces this before the CLI runs. The app
   default stays `claude-opus-5-5`.
5. **§19.12 "the body has no `<script>`/`<a>`"** means two checks:
   - the fragment Clippy inserted uses only allow-listed tags (plus the
     placeholder highlight);
   - the saved `HTMLBody` has no `<script>` and no more `href` links or
     images than Outlook's own reply to the same source. Outlook's reply
     header may contain `mailto:` links, so "no `<a>` anywhere" would
     fail on a correct draft.
6. **§15 / §16 runner.** `scripts/run-live-tests.ps1` gets `-Claude`
   (filter `live=outlook|live=claude`, sets `CLIPPY_LIVE_CLAUDE=1`).
   Without it, the script clears `CLIPPY_LIVE_CLAUDE`, so a plain live
   run never uses Claude.

No blocking questions.
