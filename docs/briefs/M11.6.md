# M11.6 Writing-style skill: `StyleCorpus`, style prompt, `SKILL.md` writer, weekly trigger, prompt reader

Base: `dev` with M11.2 (`ee4e861`), M11.3 (`995e0e7`) and M11.4
(`ede2804`) merged. M11.5 is being built in parallel and touches
`AnthropicApiModel.cs` and the csproj only; this task touches neither.
M11.7 (drafting pipeline) is briefed in parallel and **consumes the

Don't rename it.

## Goal

Add the writing-style skill of SPEC §19.6. Clippy samples the user's own
sent mail from the index, leaving out AI-originated mail (§19.4), and
redacts the samples. It asks the model once, with no tools, for a Markdown
style guide, then writes `SKILL.md` with Clippy's own frontmatter to the
Claude Code user skills folder and to an app copy, plus `state.json` with
the hash. It detects hand edits and never overwrites them without asking.
It decides when the automatic weekly refresh is due, and it gives the
drafting prompt the skill body, or the "No style guide yet" line.

SPEC refs: §1.10, §3 (`StyleSkill.cs`), §5.1 (skill paths), §6.4 (`Ai`
events), §19.1, §19.2 (`AutoRegenerateStyle`, consent), §19.3 (style
request: 16,000 tokens, 600 s), §19.4 (AI-originated), §19.5, §19.6 (all
of it), §19.10 (Regenerate needs consent), §19.11, §19.12 (`StyleCorpus`
and skill-writer tests), §18 open question 7 (shared mailboxes use the own
style).

Everything is Core and runs on Linux. The clock is a `TimeProvider`. The
file locations come in as a `StylePaths` value, so tests use temp
folders. The model is an injected `IDraftModel` (tests use a fake, never a
real model). The index is an injected `Func<EmailIndex>`. Nothing is wired
into `Program`: M11.7 constructs `StyleSkill` and calls it at the start of
each drafting pass, and M11.8 calls `RegenerateAsync` and `GetStatus`.

## Hard rules that apply here

- **No credentials (§1.10).** This code never reads anything under
  `~/.claude` except its own `skills/my-email-style/SKILL.md`. It never
  touches `.credentials.json`, settings or any other file there. No
  string literal may contain `.credentials`, `claudeAiOauth`,
  `oauthAccount` or `sk-ant-oat`.
- **The model gets no tools.** The only model access is
  `IDraftModel.RunAsync` with `DraftModel.StyleSchema`. Backends already
  pass `--tools ""` / no tool definitions (M11.4/M11.5). Don't build CLI
  arguments here.
- **Model output only becomes the skill body.** Clippy writes the
  frontmatter. The model's `body_markdown` is validated, redacted again,
  and written as the body. It is never executed, logged or put in an event.
- **Sent mail, never other mail.** The corpus comes **only** from
  `EmailIndex.SentForStyle` of the **own** mailbox. That query already
  drops `clippy_marker` rows and replies to `drafted` `ai_decisions`
  sources (§19.4). Don't add a second, weaker query.
- **No mail is touched.** No COM, no `.Send(`, `.Display(`, Outlook
  `.Move(` or `Delete(`. File replacement uses exactly `File.Move(` and
  temp cleanup uses exactly `File.Delete(`. Write those literally, not
  `System.IO.File.Move`. The existing scans
  (`NeverDeletesOutlookItems`, `OnlyMoveIsNewReplyDraftIntoDrafts`)
  exempt `File.`/`Directory.` calls, and M11.9's §19.12 scan needs the
  same exemption (see "Spec changes" #1).
- **Privacy (§19.11).** Logs and activity events never contain sample
  text, the prompt, the corpus, model output, the skill body or the
  user's display name. They may contain counts, durations, outcome kinds
  and failure kinds.
- **`PathPolicy`.** The three paths are fixed app paths built from
  `%USERPROFILE%` and the app data folder (§19.6: "not tool paths, so
  `PathPolicy` doesn't apply"). No path here ever comes from a tool, the
  model, mail or settings.

## Behavior

### A. Eligibility and own text (`StyleCorpus`)

`OwnText(body, sigs)`: `body ?? ""`. When `sigs` is null or empty →
`MailText.OwnText(body, null)`. Otherwise apply `MailText.OwnText` once
per signature, in order, feeding each result into the next. (Sent mail
may carry the *new* or the *reply* signature.)

A row is **eligible** when both hold:
- `OwnText(row.Body, sigs).Length >= MinOwnTextChars` (20; measured
  before redaction);
- `(row.Subject ?? "").TrimStart()` doesn't start with any
  `AutoSubjectPrefixes` entry (`OrdinalIgnoreCase`). `Re: Accepted: x`
  is eligible.

`CountEligible` applies exactly these two rules (no window), so the
weekly check and `Build` agree.

`SignatureTexts(signatureHtml)`: call it for `SignatureKind.New`, then
`Reply`, and take `DraftHtml.ToPlainText` of each. Drop blank results and
ordinal duplicates.

### B. `StyleCorpus.Build(rows, ownSmtp, now, seed, sigs)`

1. Validate as in the API. `ownDomain` = the part after the last `@` of
   `ownSmtp.Trim()`, lower-case invariant.
2. **Window.** Keep rows with `now.AddMonths(-MonthsBack) <= EventTime <= now`.
   The caller already queries that window; this is defensive.
3. **Eligible** rows (§A). Compute each row's own text once.
   `NewestSentUtc` = the max `EventTime` over eligible rows.
4. **Classify** each eligible row:
   - *First To address*: split `To ?? ""` on `;` and trim. For each
     non-empty entry, the candidate is the text inside the last `<…>` when
     the entry ends with `>`, else the whole entry. The first candidate
     where `MailItemRead.LooksLikeSmtp` is true is the address
     (lower-case invariant).
   - *Audience*: `Internal` when the address's domain equals `ownDomain`
     or ends with `"." + ownDomain`. `External` otherwise. When **no**
     To entry has an address (name-only entries are unresolved Exchange
     recipients), `Internal`.
   - *Recipient key* for the cap: the address. With no address, the first
     non-empty To entry lower-cased. With no To at all, `""`.
   - *Recipients*: the count of non-empty `;` entries in `To` plus `Cc`.
   - *Length*: own-text length (before redaction) `< 300` → `Short`,
     `> 1,500` → `Long`, else `Medium`.
5. **Buckets.** Use 6 lists keyed by (audience, length). Within each,
   order by `EventTime` descending, then by input index ascending
   (stable).
6. **Bucket order.** Start from the fixed order Internal/Short,
   Internal/Medium, Internal/Long, External/Short, External/Medium,
   External/Long. Permute it once with `new Random(seed)` using
   Fisher–Yates (`for i = 5..1: j = rng.Next(i + 1); swap(i, j)`).
   (`new Random(int)` is the stable seeded algorithm across .NET
   versions.)
7. **Round-robin.** Repeat over the permuted buckets until
   `MaxSamples` (200) are selected or every bucket is exhausted. On each
   bucket's turn, take its next row. If that row's recipient key already
   has `MaxPerRecipient` (3) selected, discard it and take the next one
   from the **same** bucket, until one is selected or the bucket is
   empty. Empty buckets are skipped.
8. **Too small.** When fewer than `MinSamples` (20) are selected →
   `TooSmall(selected)`.
9. **Sample text**: `MailText.Redact(ownText)`. If it's longer than
   1,500 chars, cut it to its first 1,499 chars (1,498 if char 1,498 is
   a high surrogate) and append `…` (U+2026). Recipient names in
   greetings stay.
10. **Render** each, in selection order:

    ```
    <sample audience="internal" recipients="2" length="short">
    <escaped text>
    </sample>
    ```

    The values are lower-case `internal|external` and
    `short|medium|long`, and `recipients` is invariant digits. The text is
    escaped with `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;` (in that order),
    **after** redaction. So the redaction tokens show as `&lt;email&gt;`
    etc., and mail can't close the element (§19.5).
11. **Budget.** Join with `"\n"`. Walk the rendered samples in order and
    keep a running length (the sample's length, plus 1 for the separator
    before every sample except the first). Stop at the first sample that
    would push the total over `MaxCorpusChars` (150,000). That sample and
    all later ones are dropped. `Samples` holds only the kept ones. (With
    the 1,500-char cap, at least 20 samples always fit, so the
    `TooSmall` check in step 8 is final.)
12. Return `Built(text, samples, NewestSentUtc)`.

`Build` is pure and deterministic for the same `rows` (same order),
`ownSmtp`, `now`, `seed` and `sigs`. It never logs.

### D. `SKILL.md` text (`StyleSkillText.Render`)

This is exactly §19.6. `\n` endings, one blank line between the comment
and the body, and a final `\n`:

```
---
name: my-email-style
description: "<N>'s email writing style: greetings, sign-offs, tone, length and phrasing by audience. Use when drafting or replying to email as <N>."
---
<!-- Generated by Clippy's Revenge on <yyyy-MM-dd> from <n> sent emails. You can edit this file; Clippy won't replace your edits without asking. -->

<body>
```

`<N>` is the `displayName` argument, used as-is. The caller passes it
through `CleanDisplayName` first. `Render` itself doesn't clean, so tests
can pin the text. `<yyyy-MM-dd>` is `generatedLocalDate`, invariant.
`<n>` is invariant digits. `<body>` is the body with trailing whitespace
trimmed.

`CleanDisplayName`: remove every `"` and `\`. Replace each
`char.IsControl` char (CR and LF included) with a space. Collapse
whitespace runs to one space, then trim. If the result is longer than 80
chars, cut it to 80 (79 if char 79 is a high surrogate). An empty result
gives `the user`. (Only `"` and `\` are in §19.6. Control characters
would break the YAML line; see "Spec changes" #4.)

`ParseBody(output)` returns null unless all of these hold:
1. `output` is an object with a `body_markdown` string. Other properties
   are ignored.
2. `s` = the value, with CRLF/CR changed to `\n`, then `Trim()`.
3. Tolerance: if `s`'s first line starts with ```` ``` ```` (e.g.
   ```` ```markdown ````) and its last line is exactly ```` ``` ````,
   drop both lines and `Trim()` again.
4. `MinBodyChars <= s.Length <= MaxBodyChars` (200–30,000).
5. `s` doesn't start with `---`.

Then return `MailText.Redact(s)`. Catch everything; a failure is null.

`StripHeader(fileText)`:
1. Drop a leading U+FEFF and change CRLF/CR to `\n`.
2. If the first line, trimmed at the end, is exactly `---`, find the next
   line that, trimmed, is exactly `---`. If there is one, drop everything
   up to and including it. If there isn't, keep the whole text (broken
   frontmatter is treated as body).
3. Skip leading blank lines. If the next line, trimmed at the start,
   starts with `GeneratedCommentStart`, drop lines from there up to and
   including the first line (it may be the same line) that contains
   `-->`, but only within 5 lines. If there's no `-->` within 5 lines,
   drop nothing.
4. Return the rest, `Trim()`med.

### E. Files (`StylePaths`, `StyleSkillFiles`)

`StylePaths.Default(userProfileDir, appDataDir)`:
- `UserSkillFile` = `Path.Combine(userProfileDir, ".claude", "skills", "my-email-style", "SKILL.md")`;
- `AppCopyFile` = `Path.Combine(appDataDir, "my-email-style", "SKILL.md")`;
- `StateFile` = `Path.Combine(appDataDir, "my-email-style", "state.json")`.

**`Write(fileText, generatedUtc, sampleCount, newestSentUtc)`:**
1. `bytes = new UTF8Encoding(false).GetBytes(fileText)`.
   `hash = Convert.ToHexStringLower(SHA256.HashData(bytes))`.
2. For `AppCopyFile`, then `UserSkillFile`, call
   `WriteAtomic(path, bytes)`:
   - `Directory.CreateDirectory(dir)`. This creates `~/.claude/skills/...`
     if missing, which is fine for API-key users too.
   - `tmp = Path.Combine(dir, Path.GetFileName(path) + "." + Guid.NewGuid().ToString("N") + ".tmp")`.
   - `File.WriteAllBytes(tmp, bytes)`, then
     `File.Move(tmp, path, overwrite: true)`.
   - On any exception, `File.Delete(tmp)` (swallowing errors) and
     rethrow.
3. Write the state JSON to `StateFile` the same way:
   `{"hash":"<64 hex>","generatedUtc":"<ISO 8601 O, UTC>","sampleCount":<n>,"newestSentUtc":"<ISO 8601 O, UTC>"}`
   (UTF-8 no BOM, property names exactly these, `System.Text.Json` with a
   private DTO).
4. Return the new `StyleSkillState`.

Order rationale: the state is written last, so a failed run never leaves
a state that matches a file Clippy didn't fully write. If the state write
fails after the user file was replaced, the next check sees the user file
as *edited*. That's the safe direction: Clippy stops overwriting until
the user presses Regenerate. Accept it.

**`ReadState()`**: missing file, an I/O error, invalid JSON, a missing
property, a hash that isn't 64 hex chars (either case is accepted, then
compared lower-cased), `sampleCount < 0`, or an unparseable date → null.

**`UserFileHash()`**: stream the user file into `SHA256.HashData(stream)`.
A missing file, a directory at that path, or an I/O/access error → null.

**`IsEdited()`**: `File.Exists(user)` is false → false. Otherwise
`hash = UserFileHash()`; when `hash` is null (exists but unreadable) →
true. When `ReadState()` is null → true. Otherwise `hash != state.Hash`
(ordinal, lower-case). So a skill the user wrote themselves at that path,
before Clippy, counts as edited and is never overwritten automatically.

**`GetStatus()`**:
- `IsEdited()` → `Edited`, with the state's date and count when there is
  a state (else nulls).
- Else a state exists and either file exists → `Generated(state.GeneratedUtc, state.SampleCount)`.
- Else `NotGenerated`.

`StyleStatus.Text(zone)`: `Generated 2026-11-13 from 143 sent emails`
(local date in `zone`, invariant), `Edited by you`, or
`Not generated yet`.

### F. Reading for prompts (`ReadBodyForPrompt`): the M11.7 contract

For `UserSkillFile`, then `AppCopyFile`:
1. If it doesn't exist as a file (`File.Exists`), go to the next.
2. If its length is over `MaxReadBytes` (65,536 bytes; exactly 65,536
   is fine), go to the next. Re-check the length of the bytes actually
   read.
3. Read the bytes. An `IOException` or `UnauthorizedAccessException` →
   go to the next.
4. Decode as UTF-8 (strip a BOM; invalid bytes become U+FFFD) and run
   `StripHeader`.
5. **Return the result, even if it's empty.** An empty body from a usable
   file gives `NoStyleGuideLine` rather than falling through to the next
   file. The user file is the user's choice, and §19.6 picks the file by
   existence and size, not by content.

If neither file is usable → `StyleSkillText.NoStyleGuideLine`.

The result is raw Markdown. **`DraftPrompt` (M11.7) owns wrapping it in
`<writing_style>…</writing_style>` and any escaping.** The method takes
no lock, so it never waits for a running generation. A rename-based write
means it sees either the old file or the new one. There's no caching:
the file is at most 64 KiB and is read once per drafting call. For
shared-mailbox drafts M11.7 uses the same (own) skill (§18 open
question 7).

`ReadSkillText()` uses the same source choice (steps 1–3) and returns the
whole decoded text (frontmatter included) of the first usable file, or
null.

### G. Generation (shared by §H and §I, private `GenerateAsync(owner, trigger, replaceEdits, ct)`)

The caller holds the run gate (§H/§I).
1. `now = time.GetUtcNow()`, `start = time.GetTimestamp()`, `s = settings()`.
2. `rows = ownIndex().SentForStyle(now.AddMonths(-12), now)` (default
   max 5,000). Any exception except `OperationCanceledException` →
   `Failed(IndexFailed)`.
3. `sigs = signatureTexts()`. An exception gives `[]`.
4. `corpus = StyleCorpus.Build(rows, owner.Email, now, StyleCorpus.WeekSeed(now), sigs)`.
   `TooSmall(n)` → event `TooFewEvent(n)` → `TooFewEmails(n)`. **No
   model call.**
5. `result = await model().RunAsync(StylePrompt.Request(corpus, s, now, time.LocalTimeZone), ct)`.
   Then `ct.ThrowIfCancellationRequested()`: on shutdown or cancel, throw
   with no event.
6. Map the result:
   - `RateLimited` → `UsageLimit`.
   - `NotSignedIn` → `NotSignedIn`.
   - `Failed(k, _)` → `CallFailed(k)`.
   - `Ok(output, …)` → `body = StyleSkillText.ParseBody(output)`. Null →
     `BadAnswer`.

   A failure reason gives event `FailedEvent(reason)` and returns
   `Failed(reason)`.
7. **Re-check edits after the call.** The call can take up to 10 min,
   and the user may have edited the file meanwhile. If `Files.IsEdited()`
   and not (`trigger == Regenerate && replaceEdits`) → the edited
   handling of §H (automatic) or plain `Edited` with no event
   (Regenerate). Nothing is written.
8. `text = StyleSkillText.Render(StyleSkillText.CleanDisplayName(owner.Name),
   DateOnly.FromDateTime(TimeZoneInfo.ConvertTime(now, time.LocalTimeZone).DateTime),
   corpus.Samples.Count, body)`.
9. `Files.Write(text, now, corpus.Samples.Count, corpus.NewestSentUtc)`.
   `IOException`/`UnauthorizedAccessException` → `FailedEvent(SaveFailed)`
   → `Failed(SaveFailed)`.
10. `duration = time.GetElapsedTime(start)`. Event
    `UpdatedEvent(n, duration)` with `duration` also passed as the
    event's `Duration`. Clear the "edit reported" memory (§H). Return
    `Updated(n, duration)`.

All events: `activity.Event(ActivityKind.Ai, summary, duration?, mailbox: null)`.
Log once per run at Information:
`"Writing style: {Outcome}, {Samples} samples, {Ms} ms"`, where
`Outcome` is the `StyleRunResult` case name, plus `Failed:<ModelFailure>`
for model failures. Nothing else.

Style calls are **not** recorded in `ai_decisions` and don't count toward
`DailyCap` (§19.6).

### H. Automatic (`RunIfDueAsync(owner, ct)`)

Validate `owner` (API). Then:
1. `s = settings()`. Unless `s.Enabled && s.AutoRegenerateStyle && s.HasConsent`
   → `NotDue`.
2. If `now < _nextAutoAttemptUtc` → `NotDue` (failure back-off, below).
3. If the run gate (`SemaphoreSlim(1)`, `Wait(0)`) is taken → `Busy`.
   Release it in a `finally`.
4. **Due?**
   - Neither `UserSkillFile` nor `AppCopyFile` exists → due ("no skill":
     before the first drafting pass).
   - Else `Files.IsEdited()` → **edited handling**: `h = Files.UserFileHash()`.
     If `h != _editReportedHash` (including null vs a value), record event
     `StyleTexts.EditedEvent` and set `_editReportedHash = h`. Return
     `Edited`. This gives one event per distinct edit, in memory, so a
     restart may log it once more (accepted).
   - Else `state = Files.ReadState()`. If it's null (an app copy without
     a state and no user file) → due.
   - Else, if `now - state.GeneratedUtc < AutoInterval` (7 days) →
     `NotDue`.
   - Else, if `now < _nextRefreshCheckUtc` → `NotDue`.
   - Else `n = StyleCorpus.CountEligible(ownIndex().SentForStyle(state.NewestSentUtc.AddSeconds(1), now), signatureTexts())`.
     `SentForStyle`'s `from` is inclusive and the index stores whole
     seconds, so `+1 s` means "newer than". If `n >= MinNewSentForRefresh`
     (20) → due. Else set `_nextRefreshCheckUtc = now + RefreshCheckInterval`
     (1 h) → `NotDue`. An index exception → `NotDue`, with a Debug log
     of the exception type only.
5. Due → `GenerateAsync(owner, Automatic, replaceEdits: false, ct)`.
6. After `GenerateAsync`: `Updated` resets `_nextAutoAttemptUtc` and
   `_nextRefreshCheckUtc` to `MinValue`. `TooFewEmails` and `Failed` set
   `_nextAutoAttemptUtc = now + AutoRetryAfterFailure` (24 h), so a
   failing or too-small run isn't retried, and its event isn't repeated,
   on every 15-minute pass. `Edited` leaves both unchanged.

### I. On demand (`RegenerateAsync(owner, replaceEdits, ct)`)

Validate `owner`. Then:
1. `!settings().HasConsent` → `NoConsent`. `Enabled` isn't required
   (§19.6: on demand needs consent only).
2. Run gate taken → `Busy`.
3. `Files.IsEdited() && !replaceEdits` → `Edited` with **no event** (the
   user chose *Keep mine*; M11.8 normally doesn't call in that case).
4. `GenerateAsync(owner, Regenerate, replaceEdits, ct)`.
5. `Updated` also resets the automatic timers, as in §H.6. Failures
   don't set the automatic back-off.

The dialog itself (`StyleTexts.ReplaceQuestion`, **Replace** / **Keep
mine**, with Keep mine as the default) is M11.8. M11.8 asks only when
`GetStatus().Kind == Edited`.

## Spec changes (proposed, not applied)

All are low-risk and reversible. None changes a hard rule.

1. **§19.12 / §15 safety scan wording (for M11.9).** "Files named …
   `Style*` … contain no `.Move(` or `Delete(`" must exempt `File.` and
   `Directory.` calls, as the existing `NeverDeletesOutlookItems` /
   `OnlyMoveIsNewReplyDraftIntoDrafts` scans do. `StyleSkill.cs` uses
   `File.Move(tmp, path, overwrite: true)` for the atomic replace, and
   `File.Delete(tmp)` for cleanup. This is the same issue as M11.4's
   spec change #1.
2. **§19.6 Sampling, pinned details:**
   - `seed` permutes the 6-bucket visiting order once (Fisher–Yates over
     `new Random(seed)`); the service uses `WeekSeed(now)`.
   - Within a bucket, ties are broken by input order.
   - The first To *address* is the first `;` entry that has an SMTP
     address. With none (name-only, unresolved Exchange recipients) the
     audience is `internal`.
   - The per-recipient key falls back to the first entry's text.
   - `recipients` counts To + CC entries.
   - The length bucket and the 20-char minimum use the own text before
     redaction.
   - Signatures: both the new and the reply signature are cut, in turn.
   - Samples are cut to 1,499 chars + `…`.
   - Sample text is XML-escaped (`&`, `<`, `>`) **after** redaction. The
     element layout is `<sample …>\n…\n</sample>`, joined with `\n`.
   - The 150,000 budget counts the rendered samples plus separators, and
     drops the first sample that doesn't fit and all after it.
   - `found` in `TooSmall` is the number selected after the caps.
   - `newestSentUtc` is the newest eligible row.
3. **§19.6 Generation:** the system prompt (Behavior §C) and the user
   prompt `<context>today/samples</context><samples>…</samples>` are
   pinned here. `body_markdown` is CRLF-normalized and trimmed, and one
   surrounding code fence is tolerated; the 200–30,000 rule applies after
   that.
4. **§19.6 Display name:** control characters also become spaces
   (they'd break the YAML line), whitespace is collapsed, and a blank name
   becomes `the user`.
5. **§19.6 Files:** the write order is app copy, user file, then
   `state.json` (a partial failure errs toward "edited"). Temp names are
   `<file>.<guid>.tmp` in the same folder. `state.json` uses ISO 8601
   UTC strings. A state with a malformed hash or a negative count is
   ignored. An unreadable user file counts as edited. A pre-existing
   user-authored `my-email-style/SKILL.md` (no state) counts as edited, so
   it's never overwritten automatically.
6. **§19.6 When it runs:**
   - "No skill" = neither the user file nor the app copy exists.
   - The 7 days count from `generatedUtc` (a Regenerate restarts them).
   - The "20 newer eligible" check runs at most hourly.
   - After a failed or too-small automatic run, the next automatic attempt
     is 24 h later. This is in memory, and Regenerate isn't affected.
   - "Once per edit" means once per distinct user-file hash per process.
   - The edit check repeats after the model call, before writing.
   - Regenerate needs consent but not `Enabled`, and runs nothing when
     edited unless `replaceEdits`.
   - A style run in progress makes other calls return `Busy`.
   - Cancellation is silent (no event).
7. **§19.6 Events, `<failure>` texts:** `Claude's usage limit was
   reached`, `Claude isn't signed in`, `a Claude call failed (<Kind>)`,
   `Claude's answer wasn't usable`, `couldn't save the skill file`,
   `couldn't read the index`. `<duration>` uses
   `ActivityView.FormatDuration`.
8. **§19.6 Use in drafting:** both files are limited to 64 KiB. A usable
   user file wins even when its body is empty (then the "No style guide
   yet" line). An unreadable user file falls through to the app copy.
   The body is returned raw, and `DraftPrompt` (M11.7) does the
   wrapping/escaping. The reader API is
   `StyleSkill.ReadBodyForPrompt()` / `StyleSkillFiles.ReadBodyForPrompt()`.
9. **§19.10 status line:** the date in `Generated <date> from <n> sent emails`
   is the local `yyyy-MM-dd`. Add `StyleSkillFiles.ReadSkillText()` for
   **View**.

## Notes for the user (not blocking)

- **CLAUDE.md wording.** The hard rule says "AI output only ever becomes
  a saved reply draft". §19.6 (user-approved with M11) also turns model
  output into the body of `SKILL.md`. This brief follows the spec. The
  model still has no tools, Clippy writes the frontmatter, and the body
  is redacted. Suggest the CLAUDE.md line read "…becomes a saved reply
  draft or the body of the writing-style skill (§19.6)". The user should
  confirm that wording; this brief doesn't change it.
- **Residual risk to know about.** `~/.claude/skills/my-email-style/SKILL.md`
  is loaded by the user's *interactive* Claude Code sessions, which do
  have tools. Its body is model output derived from the user's own sent
  text, with quoted history cut and links, addresses and phone numbers
  redacted. The system prompt treats samples as data. It is still the one
  place where mail-derived text reaches a tool-enabled context. The
  manual's security page (M11.11) should say so. A future option would be
  a setting to write only the app copy.
