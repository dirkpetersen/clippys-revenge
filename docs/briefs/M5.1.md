# M5.1 `OutlookWorker`: STA thread, two queues, attach-only, backoff, Start Outlook

## Goal

Build the one thread that owns all Outlook COM (SPEC §4 item 3, including
the new "Details (M5.1)" list), the `OutlookUnavailable` tray state
(§6.1, §7), and the tray's **Start Outlook** item (§6.2 "Outlook not
running", §6.5 balloon, §1 rule 7, §15 Safety row). Almost all of it goes
in **Core** as a generic `ComWorker<TApp>` driven by an
`IComAttacher<TApp>`, so the queues, priorities, fail-fast, backoff,
HRESULT classification, probe, state transitions and chunking are tested
on Linux with a fake attacher. The **App** adds only the STA thread
setup, the `GetActiveObject` P/Invoke attacher, the App Paths lookup +
`Process.Start` for Start Outlook, and the wiring in `Program` and
`TrayApp`.

## Hard rules that apply here

- **Attach-only.** The only way to get the Application object is
  `oleaut32!GetActiveObject` after `ole32!CLSIDFromProgID("Outlook.Application")`.
  Do **not** write the strings `new Application(`, `new Outlook.Application(`,
  `Activator.CreateInstance` or `CoCreateInstance` **anywhere**, not even
  in comments or XML docs: the M10.1 source scan matches text.
- `OutlookLauncher.TryStart` is the **only** `Process.Start` of Outlook in
  the codebase, and it runs only from the tray click.
- No `.Send()`, no Graph, no token in logs (the worker logs nothing about
  tokens; it never sees one).
- No `.Result`/`.Wait()` outside the COM worker thread. `Dispose` may
  `Thread.Join` (shutdown only).

### Core: `OutlookConnection.cs` (namespace `ClippysRevenge.Core`)

```csharp
public enum WorkPriority { Interactive, Background }

public enum OutlookConnectionState { Unknown, Available, Unavailable }

/// <summary>How the worker reaches the COM server. Every member is called on the worker thread only.</summary>
public interface IComAttacher<TApp> where TApp : class
{
    /// Returns the running instance, or null when none is running / not installed.
    /// Throws for any other failure (the worker treats a throw like null and logs it at Warning).
    /// Must never start the server.
    TApp? TryAttach();

    /// One cheap cross-process call. Throws (COMException) when the server is gone.
    void Probe(TApp app);

    /// Releases the instance (FinalReleaseComObject). Must not throw; the worker also catches.
    void Release(TApp app);
}

public sealed class AttachBackoff
{
    public static readonly TimeSpan DefaultInitial = TimeSpan.FromSeconds(1);
    public static readonly TimeSpan DefaultMax = TimeSpan.FromSeconds(60);

    /// Throws ArgumentOutOfRangeException when initial <= 0 or max < initial.
    public AttachBackoff(TimeSpan? initial = null, TimeSpan? max = null);

    /// Returns the current delay, then doubles it (capped at max). 1,2,4,8,16,32,60,60… s by default.
    public TimeSpan Next();

    /// The next Next() returns initial again.
    public void Reset();
}

public static class ComErrors
{
    public const int MK_E_UNAVAILABLE = unchecked((int)0x800401E3);
    public const int RPC_E_DISCONNECTED = unchecked((int)0x80010108);
    public const int RPC_E_SERVERCALL_RETRYLATER = unchecked((int)0x8001010A);
    public const int RPC_S_SERVER_UNAVAILABLE = unchecked((int)0x800706BA);
    public const int CO_E_CLASSSTRING = unchecked((int)0x800401F3);
    public const int REGDB_E_CLASSNOTREG = unchecked((int)0x80040154);

    /// True when hr is one of the four "gone" HRESULTs above (SPEC §4 Details).
    public static bool IsGoneHResult(int hr);

    /// True when ex, or any exception in its InnerException chain, is a COMException
    /// whose HResult satisfies IsGoneHResult. Non-COMException types never match, even
    /// with the same HResult. Throws ArgumentNullException (ex null).
    public static bool IsOutlookGone(Exception ex);

    /// Attach result meaning "not running / not installed": MK_E_UNAVAILABLE,
    /// CO_E_CLASSSTRING, REGDB_E_CLASSNOTREG.
    public static bool IsNotRunning(int hr);
}
```

### Core: `ComWorker.cs`

```csharp
public sealed class ComWorkerOptions
{
    public TimeSpan InitialBackoff { get; init; } = AttachBackoff.DefaultInitial;
    public TimeSpan MaxBackoff { get; init; } = AttachBackoff.DefaultMax;
    public TimeSpan ProbeInterval { get; init; } = TimeSpan.FromSeconds(15);
    /// Called once on the new thread object before Start (App: SetApartmentState(STA)). Null = none.
    public Action<Thread>? ConfigureThread { get; init; }
    public string ThreadName { get; init; } = "OutlookWorker";
    public ILogger? Logger { get; init; }
}

public class ComWorker<TApp> : IDisposable where TApp : class
{
    public const int MaxBackgroundChunk = 50;

    /// Throws ArgumentNullException (attacher, hub); ArgumentOutOfRangeException
    /// (bad backoff per AttachBackoff, ProbeInterval <= 0). Does not start the thread.
    public ComWorker(IComAttacher<TApp> attacher, ActivityHub hub, ComWorkerOptions? options = null);

    /// Volatile read; safe from any thread.
    public OutlookConnectionState State { get; }

    /// Raised on the worker thread after each change of State. Subscriber exceptions are swallowed.
    public event Action<OutlookConnectionState>? StateChanged;

    /// Creates the background thread (IsBackground = true, Name = ThreadName), applies ConfigureThread, starts it.
    /// Throws InvalidOperationException ("The worker is already started.") on a second call,
    /// ObjectDisposedException after Dispose.
    public void Start();

    /// Queues work. Throws synchronously: ArgumentNullException (work),
    /// ArgumentOutOfRangeException (undefined priority), ObjectDisposedException (after Dispose).
    /// Already-cancelled ct => returns a cancelled task, work never runs.
    /// The task faults with OutlookUnavailableException, or with whatever work threw (unchanged).
    public Task<T> RunAsync<T>(Func<TApp, T> work, WorkPriority priority, CancellationToken ct = default);

    /// Splits items into chunks of at most chunkSize (default MaxBackgroundChunk), queues each chunk as
    /// one Background item, awaits them in order, and concatenates the results.
    /// Throws ArgumentNullException (items, work), ArgumentOutOfRangeException (chunkSize < 1 or > MaxBackgroundChunk).
    /// Empty items => empty list, nothing queued. A failing chunk's exception propagates; later chunks aren't queued.
    public Task<IReadOnlyList<TOut>> RunChunkedAsync<TIn, TOut>(
        IReadOnlyList<TIn> items,
        Func<TApp, IReadOnlyList<TIn>, IReadOnlyList<TOut>> work,
        CancellationToken ct = default,
        int chunkSize = MaxBackgroundChunk);

    /// Any thread. When not Available: reset the backoff and attempt an attach as soon as the
    /// worker is free. No-op when Available or disposed.
    public void Nudge();

    /// Stops the loop, faults every queued item with ObjectDisposedException, releases the
    /// instance on the worker thread, ends the hub scope, joins the thread (5 s max). Idempotent.
    public void Dispose();
}
```

## Behavior

### Queues and loop (`ComWorker`)

- Two FIFO queues of items (`Interactive`, `Background`) guarded by one
  lock, plus a wake signal (`SemaphoreSlim(0)` or `AutoResetEvent`).
  Each item owns a
  `TaskCompletionSource<T>(TaskCreationOptions.RunContinuationsAsynchronously)`
  (continuations must never run on the worker thread).
- `RunAsync` registers `ct` so cancellation calls `TrySetCanceled(ct)`.
  Dispose the registration when the item completes. The loop skips
  items whose task is already completed. Cancellation never interrupts
  work that has started; its result is then dropped.
- `RunAsync` before `Start()` is allowed: items wait until the loop runs.
- The loop, on the worker thread, until disposed. "now" is
  `Stopwatch.GetTimestamp`-based; waits use real time.
  1. Apply a pending `Nudge` (Interlocked flag): if no instance, reset
     the backoff and set `nextAttempt = now`.
  2. If the interactive queue has a live item, dequeue it:
     - No instance: make one attach attempt (`AttachNow(scheduled: false)`).
     - Still no instance: fault the item with
       `new OutlookUnavailableException()`. Go to 1.
     - Otherwise run it (see **Run**). Go to 1.
  3. If there's an instance and the background queue has a live item,
     dequeue and run it. Go to 1.
  4. No instance and `now >= nextAttempt`: `AttachNow(scheduled: true)`.
     Go to 1.
  5. Instance present and `now - lastActivity >= ProbeInterval`: probe
     (see **Probe**). Go to 1.
  6. Otherwise wait for the signal, with a timeout until `nextAttempt`
     (no instance) or `lastActivity + ProbeInterval` (instance), min 0.
- Background items are **never** dequeued without an instance: they
  wait (§4). Interactive items are always taken first (§4). Initial
  `nextAttempt` is "now", so the first attempt happens as soon as the
  loop starts.
- **AttachNow(scheduled)**: call `TryAttach()` inside try/catch.
  - Non-null: keep it, `backoff.Reset()`, `lastActivity = now`, set state
    `Available`.
  - Null or a throw (log the throw at Warning with the exception; log
    nothing for null): set state `Unavailable`. Only when `scheduled`:
    `nextAttempt = now + backoff.Next()`. An interactive attempt leaves
    `nextAttempt` and the backoff unchanged.
- **Run**: invoke `work(instance)`; `TrySetResult`. On an exception `ex`:
  - `ComErrors.IsOutlookGone(ex)`: **Drop** the instance, then
    `TrySetException(new OutlookUnavailableException(ex))`. Same for both
    priorities; never retried.
  - Otherwise `TrySetException(ex)` unchanged; the instance is kept.
  - Afterwards `lastActivity = now`.
- **Probe**: `attacher.Probe(instance)` in try/catch. Gone → **Drop**.
  Any other exception: log at Debug, keep the instance. Afterwards
  `lastActivity = now`.
- **Drop**: `attacher.Release(instance)` in try/catch, instance = null,
  `backoff.Reset()`, `nextAttempt = now + backoff.Next()` (= 1 s by
  default), set state `Unavailable`.
- **Set state** (worker thread only), only when the value changes, in
  this order:
  1. write the volatile `State`;
  2. hub: entering `Unavailable` →
     `_scope ??= hub.Begin(ActivityState.OutlookUnavailable, "")`; leaving
     it → `_scope?.Dispose(); _scope = null`;
  3. log at Information: `Outlook connection: {State}`;
  4. raise `StateChanged` (each delegate separately, exceptions
     swallowed, as in `ActivityHub.Raise`).

  Writing `State` before touching the hub means the tray render that
  `hub.Changed` triggers already sees the new value.
- `Unknown` only exists before the first attempt. There is no transition
  back to `Unknown`.
- **Dispose**: set the disposed flag and signal. The loop exits after the
  current item. Then, still on the worker thread: fault every queued
  item with `ObjectDisposedException(nameof(ComWorker<TApp>))`, Release
  the instance, and dispose the hub scope. `Dispose()` joins the thread
  for up to 5 s. If `Start()` was never called, do the same cleanup on
  the calling thread. A second `Dispose` is a no-op. `RunAsync` after
  Dispose throws `ObjectDisposedException`.
- A bug in the loop itself must not kill the thread silently: wrap each
  iteration's non-work code in try/catch, log at Error, and continue.

### `RunChunkedAsync`

`items.Chunk(chunkSize)` style, in order. Each chunk is
`await RunAsync(app => work(app, chunk), WorkPriority.Background, ct)`.
Validate that each chunk's result is non-null
(`InvalidOperationException("Chunk work returned null.")`) and append it.
Because chunks are separate items, an interactive item queued during a
chunked run executes before the next chunk.

### `AttachBackoff`

`current = initial`. `Next()` returns `current`, then sets
`current = min(current * 2, max)`. `Reset()` sets `current = initial`.
Not thread-safe (worker thread only).

### `ComErrors.IsOutlookGone`

Walk `for (var e = ex; e is not null; e = e.InnerException)`; return true
at the first `e is COMException c && IsGoneHResult(c.HResult)`.
`AggregateException` needs no special case beyond `InnerException`.

### `OutlookAppPath.Normalize`

1. Null, empty or whitespace → null.
2. Trim whitespace. If the result starts and ends with `"` and has
   length ≥ 2, strip one pair and trim again.
3. Reject (null) if it contains any char `< 0x20` or any of `"<>|*?/`,
   or doesn't start with a drive root: an ASCII letter `A–Z` / `a–z`,
   then `:\`. Hard-code this set, because `Path.GetInvalidPathChars()`
   differs on Linux. UNC (`\\…`), device (`\\?\`), relative paths and
   forward slashes are rejected.
4. The file name is the text after the last `\`. It must equal
   `OUTLOOK.EXE` (`OrdinalIgnoreCase`). Otherwise null.
5. Return the trimmed, unquoted string unchanged.

Use manual string logic, not `Path.IsPathFullyQualified` or
`Path.GetFileName`: they treat `\` differently on Linux, where the tests
run.

### `OutlookAttacher` (App, worker thread)

- `TryAttach()`:
  1. `hr = CLSIDFromProgID("Outlook.Application", out clsid)`. If
     `hr < 0`: return null when `ComErrors.IsNotRunning(hr)`, otherwise
     `Marshal.ThrowExceptionForHR(hr)`.
  2. `hr = GetActiveObject(ref clsid, IntPtr.Zero, out var obj)`. If
     `hr < 0`: same rule. `MK_E_UNAVAILABLE` → null.
  3. `obj is Outlook.Application app` → return it. Otherwise release
     `obj` with `Marshal.ReleaseComObject` if it's a COM object, and
     throw `InvalidOperationException("The running object is not Outlook.Application.")`.
- `Probe(app)`: `_ = app.Name;`. This property doesn't trigger the
  object-model guard.
- `Release(app)`: `Marshal.FinalReleaseComObject(app)` in try/catch.
- `OutlookWorker`'s `ConfigureThread` calls
  `t.SetApartmentState(ApartmentState.STA)`. Don't add a message filter
  or Outlook events in this task.

### Start Outlook (App, §6.2)

- `FindOutlookExe()`: for `RegistryView.Registry64`, then
  `RegistryView.Registry32`:
  `using var root = RegistryKey.OpenBaseKey(RegistryHive.LocalMachine, view); using var k = root.OpenSubKey(AppPathsKey);`.
  Read the default value (`k?.GetValue(null) as string`), apply
  `OutlookAppPath.Normalize`, then `File.Exists`. Return the first hit.
  Catch `SecurityException`, `UnauthorizedAccessException` and
  `IOException` per view and continue.
- `TryStart()`: `path = FindOutlookExe()`. If null, return false.
  Otherwise
  `Process.Start(new ProcessStartInfo(path) { UseShellExecute = false, WorkingDirectory = Path.GetDirectoryName(path)! })?.Dispose()`
  and return true. Catch the exceptions listed in the API and return
  false.
- `TrayApp`:
  - `_startOutlook`: `Enabled = _s.StartOutlook is not null`. Remove the
    `TODO(M5.1)`.
  - In `Render()`, set `_startOutlook.Visible = _s.IsOutlookUnavailable();`
    instead of `view.ShowStartOutlook`. Leave `TrayPresenter` and
    `TrayView` unchanged.
  - Click: `if (_s.StartOutlook?.Invoke() == false) _s.Balloons.PostUserFeedback(BalloonTexts.OutlookNotFound);`.
    No other balloon on success: the state change updates the tray.
- `Program`:
  - Create `var worker = new OutlookWorker(hub, loggerFactory.CreateLogger("OutlookWorker"));`
    after the hub, then call `worker.Start()` before `Application.Run`.
  - Register the worker in the host:
    `ConfigureServices = s => s.AddSingleton(settings).AddSingleton(balloons).AddSingleton(worker)`.
    Later tools take it from DI. `McpTools` is unchanged in this task.
  - Tray delegates:
    `IsOutlookUnavailable: () => worker.State == OutlookConnectionState.Unavailable`.
    `StartOutlook: () => { var ok = OutlookLauncher.TryStart(); if (ok) worker.Nudge(); return ok; }`.
    Log the outcome at Information (`Start Outlook: {Result}`).
  - Shutdown order after `Application.Run` returns: dispose the host (as
    today), then `worker.Dispose()`, then `hub.Dispose()`.

## Tests

All tests are Core tests and run on Linux, with no
`[Trait("os","windows")]`. There are no live tests in this task. The
test project can't reference the Windows App, so the real attach is
covered by M10.2 and by the manual check below.

**`FakeAttacher : IComAttacher<FakeApp>`** (private nested in
`ComWorkerTests`; `FakeApp` is an empty class):

- `volatile bool Running`;
- `int AttachCalls`, `ReleaseCalls`, `ProbeCalls` (Interlocked);
- `Exception? AttachThrows`, `Exception? ProbeThrows`;
- a `ConcurrentBag<int>` of the thread ids of every call.

`TryAttach` returns `Running ? new FakeApp() : null` (or throws
`AttachThrows`).

**Waiting.** Use a `WaitUntil(Func<bool>, TimeSpan timeout = 5 s)`
helper that polls every 5 ms and fails the test on timeout. Never use
fixed sleeps as assertions. Fast options unless a case says otherwise:
`InitialBackoff = 10 ms`, `MaxBackoff = 40 ms`, `ProbeInterval = 1 h`.
Every test disposes its worker.

### `ComWorkerTests`

1. **Runs on one dedicated thread**:
   - `Running = true`; `ConfigureThread` records the thread and is
     called once.
   - Five `RunAsync` calls return `Environment.CurrentManagedThreadId`.
     All five equal the worker thread's id and differ from the test
     thread's id.
   - Every `FakeAttacher` call happened on that thread.
   - The thread name is `OutlookWorker`.
2. **Result and plain exceptions**:
   - `RunAsync(_ => 42, Interactive)` returns 42.
   - Work that throws `InvalidOperationException("x")` faults with that
     same instance.
   - `State` stays `Available` and `ReleaseCalls == 0`.
3. **Interactive first**:
   - Item G (Interactive) blocks on a `ManualResetEventSlim` gate.
   - While G runs, queue B1 and B2 (Background), then I1 and I2
     (Interactive). Each appends its name to a list.
   - Open the gate. Expected order: `G, I1, I2, B1, B2`.
4. **Starts unavailable**:
   - `Running = false`, `InitialBackoff = 10 min`.
   - `WaitUntil(State == Unavailable)`. Then `hub.State == OutlookUnavailable`
     and `hub.Progress.Label == ""`.
5. **Fail fast**: continuing from 4, `RunAsync(_ => 1, Interactive)`
   faults within 1 s with `OutlookUnavailableException`. Its `Message`
   equals
   `Outlook is not running. Ask the user to start Outlook (tray → Start Outlook) and try again.`.
   It is an `McpException`, and `AttachCalls` went up by exactly 1.
6. **Interactive attaches at once**:
   - `InitialBackoff = 10 min`, starts with `Running = false`, and
     reaches `Unavailable`.
   - Set `Running = true`. `RunAsync(_ => 7, Interactive)` returns 7.
   - `State == Available`, and `hub.State == Idle`.
7. **Background waits, then runs**:
   - `Running = false`. Queue a Background item. It hasn't completed
     after `WaitUntil(AttachCalls >= 3)`, which proves the retries.
   - Set `Running = true`. The item completes with its value, and
     `State == Available`.
8. **"Gone" during work** (theory over `0x800401E3`, `0x80010108`,
   `0x8001010A`, `0x800706BA`):
   - Work throws `new COMException("gone", hr)`. The task faults with
     `OutlookUnavailableException` whose `InnerException` is that
     `COMException`.
   - `ReleaseCalls == 1`. `State == Unavailable`, and `hub.State == OutlookUnavailable`.
     Use `InitialBackoff = 10 min` here, so the scheduled reattach can't
     race these asserts.
   - Run once Interactive and once Background (two `InlineData` sets, or
     a nested loop).
9. **Gone, nested**: work throws
   `new InvalidOperationException("wrap", new COMException("x", RPC_E_DISCONNECTED))`.
   This counts as gone, as in 8.
10. **Not gone**: work throws `new COMException("fail", unchecked((int)0x80004005))`.
    The task faults with that `COMException`, `State == Available` and
    `ReleaseCalls == 0`.
11. **Reattach after gone**:
    - With the fast options (`InitialBackoff = 10 ms`) and `Running = true`
      throughout, work throws `COMException(RPC_E_DISCONNECTED)`. Then
      wait until `State == Available` again (scheduled retry after about
      10 ms).
    - `AttachCalls == 2`.
12. **Nudge**:
    - `InitialBackoff = 10 min`, `Running = false`, and reaches
      `Unavailable` with `AttachCalls == 1`.
    - Set `Running = true` and call `Nudge()`. `WaitUntil(State == Available)`.
    - `Nudge()` while `Available` doesn't change `AttachCalls`. Check it
      after a short `WaitUntil` on a queued no-op item.
13. **Probe detects gone**:
    - `ProbeInterval = 20 ms`, `Running = true`. Reaches `Available`.
    - Set `ProbeThrows = new COMException("x", RPC_S_SERVER_UNAVAILABLE)`
      and `Running = false`. Without any work queued:
      `WaitUntil(State == Unavailable)` and `ReleaseCalls == 1`.
14. **Probe, other error**: `ProbeThrows = new COMException("x", unchecked((int)0x80004005))`.
    After `WaitUntil(ProbeCalls >= 3)`, `State == Available` and
    `ReleaseCalls == 0`.
15. **Attach throws**: `AttachThrows = new UnauthorizedAccessException()`.
    - The worker reaches `Unavailable` and keeps retrying
      (`WaitUntil(AttachCalls >= 3)`).
    - Clearing it and setting `Running = true` reaches `Available`.
16. **StateChanged**:
    - The sequence recorded from `Running = false` → `Running = true` +
      `Nudge()` is exactly `[Unavailable, Available]`.
    - A first subscriber that throws doesn't stop the second one or the
      worker. A later `RunAsync` still works.
17. **Cancellation**:
    - A pre-cancelled token gives `IsCanceled == true`, and the work
      never runs (a flag stays false).
    - While unavailable, queue a Background item with a CTS and cancel
      it. The task is canceled.
    - Then set `Running = true` and `Nudge()`, and run an interactive
      no-op. The cancelled work's flag stays false.
18. **Argument checks**:
    - `RunAsync<int>(null!, …)` throws `ArgumentNullException`.
    - `(WorkPriority)5` throws `ArgumentOutOfRangeException`.
    - The ctor with a null attacher or null hub throws
      `ArgumentNullException`.
    - `ProbeInterval = TimeSpan.Zero` throws `ArgumentOutOfRangeException`.
    - `Start()` twice throws `InvalidOperationException`.
19. **Queued before Start**: `RunAsync` before `Start()` is not
    completed. After `Start()` (`Running = true`), it completes.
20. **Dispose**:
    - While unavailable, two Background items are queued. `Dispose()`
      faults both with `ObjectDisposedException`.
    - `hub.State == Idle` after it.
    - `RunAsync` afterwards throws `ObjectDisposedException`.
    - A second `Dispose()` doesn't throw.
    - With an instance attached, `Dispose()` gives `ReleaseCalls == 1`,
      called on the worker thread id.
    - `Dispose()` without `Start()` faults queued items and doesn't
      throw.
21. **RunChunkedAsync**:
    - 120 ints with work `(app, chunk) => chunk.Select(x => x * 2).ToList()`
      records chunk sizes `[50, 50, 20]`. The result is 120 values in
      input order.
    - An empty list returns empty, and the work is never called.
    - `chunkSize: 0` and `chunkSize: 51` throw
      `ArgumentOutOfRangeException`.
    - Chunk work that returns null faults with `InvalidOperationException`.
    - Chunk 2 throwing `InvalidOperationException` propagates it, and
      chunk 3 is never called.
22. **Interactive between chunks**:
    - Chunk 1 blocks on a gate. While it blocks, queue an Interactive
      item, then open the gate.
    - Recorded order: `chunk1, interactive, chunk2, chunk3` (130 items,
      `chunkSize` 50).
23. **Continuations off the worker thread**: an `await worker.RunAsync(...)`
    in the test continues on a thread whose id differs from the worker
    thread's id.
