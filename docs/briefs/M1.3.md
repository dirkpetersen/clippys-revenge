# M1.3 `SlotFormatter`, `TimeZoneLabels` + tests

## Goal

Add two pure Core helpers used by `find_free_times` (§11.8, step 5) and the
invite confirmation dialog (§6.6). `SlotFormatter` turns a free slot into a
short label like `1. Tue 10/15 1-3 PT` (§12). `TimeZoneLabels` turns the
local Windows time zone into a short label (`PT`, `MT`, `CT`, `ET`, `AKT`,
`HT`, else an abbreviation or `UTC±hh:mm`), and the `TimeZoneLabel`
setting overrides it (§5.2, §12). Tests follow §15 rows `SlotFormatter` and
`TimeZoneLabels`. Time zones are local Windows time only (§18). Nothing
here touches COM, the registry or WinForms, so both helpers go in Core and
their tests run on Linux.

## Cross-task dependencies

None. Nothing in this task depends on a sibling task's type. Callers that come
later (M8.2 `find_free_times`, M8.3 `InviteConfirmForm`) pass in
`Settings.WorkStartHour` / `WorkEndHour` / `TimeZoneLabel` (M1.7) as plain
`int`/`string?` values. Do **not** reference `Settings`, `FreeBusy` or any
slot record type from this task.

## Public API

```csharp
namespace ClippysRevenge.Core;

public static class SlotFormatter
{
    /// "1. Tue 10/15 1-3 PT"
    /// windowStartHour/windowEndHour: the working-hours window used for the
    /// search (earliest_hour/latest_hour, or WorkStartHour/WorkEndHour).
    /// Throws ArgumentOutOfRangeException: n < 1; windowStartHour < 0;
    ///   windowEndHour > 24; windowStartHour >= windowEndHour.
    /// Throws ArgumentException: end <= start; end is not on start's
    ///   calendar day (except exactly 00:00 of the next day).
    public static string Format(int n, DateTime start, DateTime end, string? tzLabel,
                                int windowStartHour, int windowEndHour);

    /// True when the window is wider than 7am-7pm:
    /// windowStartHour < 7 || windowEndHour > 19. No argument validation.
    public static bool NeedsAmPm(int windowStartHour, int windowEndHour);
}

public static class TimeZoneLabels
{
    /// Label for a zone. `at` picks the UTC offset for the UTC±hh:mm
    /// fallback; null means tz.BaseUtcOffset.
    /// Throws ArgumentNullException when tz is null.
    public static string For(TimeZoneInfo tz, DateTime? at = null);

    /// The TimeZoneLabel setting wins when it is non-blank (returned trimmed);
    /// otherwise For(tz, at).
    /// Throws ArgumentNullException when tz is null (even with an override).
    public static string Resolve(string? overrideLabel, TimeZoneInfo tz, DateTime? at = null);
}
```

## Behavior

### SlotFormatter.Format

Output: `"{n}. {ddd} {M/d} {startTime}-{endTime}"`, followed by `" " + tzLabel.Trim()`
when `tzLabel` is not null or whitespace. When the label is blank, nothing
is appended and there is no trailing space.

- Do all formatting with `CultureInfo.InvariantCulture`, so the output is
  the same on every machine (for example, `/` stays `/` and the weekday is English).
- Weekday: `start.ToString("ddd", Invariant)` → `Tue`. Date:
  `start.ToString("M/d", Invariant)` → `10/15` (no leading zeros).
- Use the wall-clock values of `start`/`end` as given. Ignore
  `DateTime.Kind`, and don't convert anything. The caller passes local times.
- Time `t` (hour `H` 0–23, minute `m`):
  - `h12 = H % 12 == 0 ? 12 : H % 12`.
  - Text is `h12` when `m == 0`, else `h12:mm` (`9:30`, `1:05`). Seconds and
    smaller units are ignored (truncated).
  - An `end` of exactly 00:00 on the next day is treated as hour 0, so it
    prints `12` (`12am` with am/pm).
- am/pm: only when `NeedsAmPm(windowStartHour, windowEndHour)`. Suffixes are
  lowercase `am`/`pm` (hour < 12 → `am`). When both times have the same
  suffix, put it on the end time only (`9-11am`, `1:30-3pm`). When they
  differ, put a suffix on each (`11am-1pm`, `11pm-12am`). Without am/pm no
  suffix is added (`1-3`).
- The window is exactly 7–19 → no am/pm. 6–19 or 7–20 → am/pm.
- `windowStartHour`/`windowEndHour` are validated (see Public API), but the
  slot is **not** checked against the window. That is `FreeBusy`'s job.
- Validation order: `n`, then window hours, then `end <= start`, then the
  same-day rule. Exception messages:
  - `n`: `"Slot number must be 1 or greater."` (paramName `n`)
  - window: `"Window hours must satisfy 0 <= start < end <= 24."` (paramName
    of the offending argument)
  - `"Slot end must be after its start."` (paramName `end`)
  - `"Slot must start and end on the same day."` (paramName `end`)

The `text` field of `find_free_times` (§11.8) is just
`string.Join("\n", labels)` in M8.2. Don't add a helper for it here.

### TimeZoneLabels.For

Rules, in order:

1. **US zones.** Look up `tz.Id` in one static
   `Dictionary<string,string>(StringComparer.OrdinalIgnoreCase)` that holds
   exactly these entries.

   | Label | Windows ids | IANA ids |
   |---|---|---|
   | `PT` | `Pacific Standard Time` | `America/Los_Angeles`, `US/Pacific` |
   | `MT` | `Mountain Standard Time`, `US Mountain Standard Time` | `America/Denver`, `America/Boise`, `America/Phoenix`, `US/Mountain`, `US/Arizona` |
   | `CT` | `Central Standard Time` | `America/Chicago`, `America/Indiana/Knox`, `America/Indiana/Tell_City`, `America/Menominee`, `America/North_Dakota/Center`, `America/North_Dakota/New_Salem`, `America/North_Dakota/Beulah`, `US/Central` |
   | `ET` | `Eastern Standard Time`, `US Eastern Standard Time` | `America/New_York`, `America/Detroit`, `America/Kentucky/Louisville`, `America/Kentucky/Monticello`, `America/Louisville`, `America/Indiana/Indianapolis`, `America/Indianapolis`, `America/Indiana/Vincennes`, `America/Indiana/Winamac`, `America/Indiana/Marengo`, `America/Indiana/Petersburg`, `America/Indiana/Vevay`, `US/Eastern`, `US/East-Indiana`, `US/Michigan` |
   | `AKT` | `Alaskan Standard Time` | `America/Anchorage`, `America/Juneau`, `America/Sitka`, `America/Nome`, `America/Yakutat`, `America/Metlakatla`, `US/Alaska` |
   | `HT` | `Hawaiian Standard Time` | `Pacific/Honolulu`, `US/Hawaii` |

   Exclude the Mexican and Canadian variants (`Central Standard Time (Mexico)`,
   `Mountain Standard Time (Mexico)`, `Pacific Standard Time (Mexico)`,
   `Canada Central Standard Time`) and `Aleutian Standard Time` / `America/Adak`.
   They fall through to the rules below. Don't call
   `TimeZoneInfo.TryConvert*` (the result depends on ICU and the OS), so
   the table alone decides.
2. **UTC itself.** If `tz.Id` is one of `UTC`, `Etc/UTC`, `Etc/UCT`,
   `Etc/Zulu`, `Etc/GMT`, `Coordinated Universal Time` (case-insensitive),
   return `UTC`.
3. **Abbreviation.** If `tz.StandardName.Trim()` matches `^[A-Z]{2,5}$`
   (ordinal, ASCII uppercase only), return it. Examples: `CET`, `JST`,
   `AEST`. Windows display names such as `W. Europe Standard Time` do
   not match, and that is intended.
4. **Offset.** `offset = at is null ? tz.BaseUtcOffset : tz.GetUtcOffset(at.Value)`.
   Return `"UTC" + sign + hh:mm`, where the sign is `+` for offsets >= 0
   and `-` otherwise, and `hh:mm` is the absolute value with two digits
   each. Examples: `UTC+05:30`, `UTC-03:00`, `UTC+00:00`, `UTC+05:45`.

### TimeZoneLabels.Resolve

`string.IsNullOrWhiteSpace(overrideLabel) ? For(tz, at) : overrideLabel.Trim()`.
Check `tz` for null first, in both branches. The override isn't validated
any further here. Length and character checks belong to `Settings.Validate`
(M1.7).

## Spec changes (proposed)

These are low-risk, reversible decisions. They don't affect a hard rule or
security. They make the §12 signatures implementable and the §11.8 example
consistent.

1. §12, replace the `SlotFormatter` bullet's first line
   ``- `SlotFormatter.Format(n, start, end, tzLabel)` → `"1. Tue 10/15 1-3 PT"`:``
   with
   ``- `SlotFormatter.Format(n, start, end, tzLabel, windowStartHour, windowEndHour)` → `"1. Tue 10/15 1-3 PT"`:``
   and append these sub-bullets to it:
   ```
     - The window is the search's working hours (`earliest_hour`/`latest_hour`
       or `WorkStartHour`/`WorkEndHour`); "wider than 7am–7pm" means
       start < 7 or end > 19. Suffixes are lowercase `am`/`pm`, written once
       on the end time when both times share it (`9-11am`, `11am-1pm`).
     - Formatting uses the invariant culture and the wall-clock values as
       given. A blank `tzLabel` omits the label.
   ```
2. §12, replace the `TimeZoneLabels` bullet with:
   ```
   - `TimeZoneLabels.For(TimeZoneInfo, DateTime? at = null)`: `PT`, `MT`, `CT`,
     `ET`, `AKT`, `HT` for the US zones (a fixed table of Windows and IANA ids,
     no Mexican/Canadian/Aleutian variants); `UTC` for UTC itself; otherwise
     the standard name when it is an abbreviation (2–5 capital letters), else
     `UTC±hh:mm` using the offset at `at` (base offset when null).
     `TimeZoneLabels.Resolve(override, tz, at)`: the `TimeZoneLabel` setting,
     trimmed, wins when non-blank. All scheduling math uses the local Windows
     time zone.
   ```
3. §11.8 example: change `"2026-10-15T13:00:00-07:00"` and
   `"2026-10-15T15:00:00-07:00"` to `"2024-10-15T13:00:00-07:00"` and
   `"2024-10-15T15:00:00-07:00"`, because 2026-10-15 is a Thursday, not a
   Tuesday.
