# M13.4 Drafting integration: meeting times in AI drafts (`DraftWorker` step 6a), visible low-confidence skips

Base: `dev` with **M13.1, M13.2 and M13.3 merged**. This brief is written
against M13.2's signatures (`IFreeBusySource` methods take
`WorkPriority priority` right before `ct`; `FreeTimeFinder.CetMissingWarning`).
Don't start before M13.2 is on `dev`. M13.5 and M13.6 are done; M14.2 runs
in parallel and touches none of these files.

## Goal

Make AI drafts offer concrete meeting times (SPEC §21.6, §19.7 step 6a,
§19.11, using §21.2–§21.5 through the M13.1 primitives). After the model
returns and the body is sanitized, when `AiDrafting.MeetingTimes` is on and
the reply asks for a meeting (`DraftReply.Meeting`) or the body has the
`[[meeting_times]]` placeholder, Clippy picks the attendees and the date
range, decides whether the sender is in Europe (step 2's facts headers in
automatic passes; one `GetFactsAsync(…, Interactive)` in the manual path),
reads free/busy through `IFreeBusySource` at the path's priority
(`Background` / `Interactive`), and inserts the options, or one of the two
"nothing to offer" placeholders, with `MeetingTimesHtml`. Outlook going away
during this step is handled like step 7 (automatic) or gives
`I couldn't draft that reply: Outlook isn't running` (manual). The system
prompt gets the M13.3 meeting note (`DraftPrompt.SystemPrompt(…, meetingTimes: ai.MeetingTimes)`)
**in the same change**, so the model is only told about `[[meeting_times]]`
once Clippy fills it. `DraftWorkerServices` gains `FreeBusy`, and `Program`
wires the one `OutlookFreeBusySource` into both MCP and drafting.

**Added by the user (2026-11-14):** low-confidence skips become visible. They
are counted apart from "no reply needed" in `DraftPassResult`, the pass
summary event and the pass log line, and each one records an `Ai` Activity
event with the confidence, the threshold and what the user can do. No
subject, sender or body anywhere in those texts.

## Hard rules that apply here

- **Never send, never delete, never move.** Nothing here saves anything but
  the existing reply-draft path. `DraftMeetingTimes.cs` falls under the
  AI-file scan (name starts with `Draft`): no `.Send(`, `.Display(`,
  `.Move(`, `Delete(` in it.
- **The model never sees or types times** (§21.1). Free/busy is read only
  **after** the model call returns, and nothing about the calendar goes
  into any prompt. The model still gets no tools.
- **Attach-only COM**: free/busy goes through the existing
  `OutlookFreeBusySource` → `OutlookWorker.RunAsync`. No new COM code.
- **Privacy (§19.11):** logs and events carry counts, outcomes, confidences
  and thresholds only. Never times, dates of offers, addresses, the Date
  header, subjects, bodies or model output in a log line. The new
  low-confidence Activity event carries no subject, sender or body
  (user's requirement), only the received time.
- Reply subjects, markers and the reply-draft path are unchanged (`Re:: `,
  marker `ai`).

## Behavior

### A. `DraftMeetingTimes` (pure parts)

**`OtherAttendees`** (§21.6 "Attendees"):
1. Entries in order: `senderEmail` as one entry; then, only when
   `replyAll`, every `;`-separated entry of `to`, then of `cc`.
2. Each entry goes through `Recipients.TryParseEntry` (reuse it; don't
   write another parser). An entry without a valid address (`Bob`,
   `<bad>`, an Exchange DN, blank) is skipped.
3. Left out (`OrdinalIgnoreCase`, trimmed): `ownSmtp`, `mailboxKey` when
   not blank, and duplicates (first one wins).
4. At most `MaxOtherAttendees` (10) are returned. The sender is first when
   it is valid and not left out.

**`Range`** (§21.6 "Range"; `today = localNow.Date`):
1. `start = today + 1 day` (start of the next local day). If
   `ask?.EarliestDate` is later than `start`'s date, `start` = that date at
   00:00.
2. `end`: if `ask?.LatestDate` is set and `>= DateOnly(start)`,
   `end` = the day after `LatestDate` at 00:00; otherwise
   `end = start + DefaultRangeDays` (10) days.
3. Cap: `end = min(end, today + MaxRangeDays)` (60 days, same as
   `find_free_times`' `MaxDaysAhead`).
4. Return `new MeetingRange(start, end)`. It can be empty (an
   `earliest_date` 60 or more days ahead); see ApplyAsync step 3.

**`IsWanted`**: as in the signature. `MeetingTimes = false` → false, even
with a placeholder in the body (the body stays as `Sanitize` left it).

### B. `DraftMeetingTimes.ApplyAsync`

1. `localNow = TimeZoneInfo.ConvertTime(request.NowUtc, zone).DateTime`;
   `range = Range(localNow, request.Ask)`;
   `others = OtherAttendees(SenderEmail, To, Cc, ReplyAll, OwnSmtp, MailboxKey)`;
   `checked = 1 + others.Count`;
   `duration = request.Ask?.DurationMinutes ?? MeetingAsk.DefaultDurationMinutes`;
   `count = Math.Clamp(request.Settings.AiDrafting.MeetingTimeOptions, 1, 10)`.
2. `source` null, or `OwnSmtp` blank → **CalendarUnreadable** (no calls).
3. `range.IsEmpty` → **NoFreeTime** with `NoFreeTime(range.FirstDay, range.LastDay)`
   (no calls).
4. `needed = (int)Math.Ceiling((range.To - range.From).TotalMinutes / IntervalMinutes)`.
5. **Owner first**: `fb = await source.GetFreeBusyAsync(OwnSmtp.Trim(), range.From, range.To, IntervalMinutes, priority, ct)`.
   `null`, empty, shorter than `needed`, or `FreeBusy.BusyIntervals`
   throwing `FormatException` → **CalendarUnreadable** (no further calls).
   Otherwise keep `owner = OwnerCalendar.FromFreeBusy(fb, range.From, IntervalMinutes)`
   and the owner's busy list `FreeBusy.BusyIntervals(fb, range.From, IntervalMinutes, Settings.TentativeIsBusy)`.
6. **Others**, in order, same call. `null`/empty/short/invalid → that
   attendee is left out (unknown, as in §11.8). Readable = 1 + known others.
7. `blocks = FreeBusy.FreeSlots(busyLists, range.From, range.To, Settings.WorkStartHour, Settings.WorkEndHour, Settings.BusinessDaysOnly, duration, localNow, IntervalMinutes)`.
   Empty → **NoFreeTime** with `NoFreeTime(range.FirstDay, range.LastDay)`.
8. `cet = request.Europe ? centralEurope() : null` (invoke the func only
   when `Europe`). `set = MeetingOffers.Build(blocks, owner, duration, count, zone, Settings.TimeZoneLabel, request.Europe, cet)`.
   `set.Count == 0` → NoFreeTime as in step 7.
9. **Offered**: `Html = MeetingTimesHtml.Insert(SanitizedHtml, set, request.Ask?.OutsideHoursHeading)`,
   `Offered = set.Count`, `CetMissing = set.CetMissing`.

Failure outcomes:
- **CalendarUnreadable**: `Html = MeetingTimesHtml.InsertPlaceholder(SanitizedHtml, MeetingTimesHtml.CalendarUnreadable)`.
- **NoFreeTime**: `Html = MeetingTimesHtml.InsertPlaceholder(SanitizedHtml, MeetingTimesHtml.NoFreeTime(first, last))`,
  i.e. `[[add meeting times: no free time found between <yyyy-MM-dd> and <yyyy-MM-dd>]]`.

Exceptions: steps 5–9 run in one `try`.
- `OutlookUnavailableException` (any subclass) → rethrown.
- `OperationCanceledException` when `ct.IsCancellationRequested` → rethrown.
- Any other exception (from the source, or from `FreeSlots`/`Build`/`Insert`
  on odd settings) → **CalendarUnreadable** with `ErrorType = ex.GetType().Name`
  (§19.7 step 6a "any other error gives the 'couldn't read your calendar'
  placeholder"). This includes an exception for another attendee, not just
  the owner.
- `IFreeBusySource.GetCurrentUserAsync` is **never** called (the owner is
  the identity's SMTP).

### C. `DraftWorker`, automatic path (`ProcessCandidateAsync`)

1. `BuildRequest` passes the flag:
   `DraftPrompt.SystemPrompt(identity.DisplayName, userSmtp, manual, _s.Style.ReadForPrompt(), ai.MeetingTimes)`.
   (Both paths go through `BuildRequest`; `ai` is the candidate's /
   manual call's snapshot.)
2. **Step 6a** goes after the `failure is { } kind` block and before
   step 7 (the re-check), only when
   `DraftMeetingTimes.IsWanted(ai, reply!, html)`:
   - `europe = SenderRegion.IsEurope(c.SenderEmail, facts!.TransportHeaders)`
     (step 2's facts; no extra COM call).
   - `mt = await _meetings.ApplyAsync(new MeetingTimesRequest(html, reply.Meeting, userSmtp, key, c.SenderEmail, c.To, c.Cc, reply.ReplyAll ?? false, europe, now, cur), WorkPriority.Background, ct)`;
     `html = mt.Html`; then log (section E).
   - `catch (OutlookUnavailableException)` →
     `Write(p, index, c, factsImid, prior, AiOutcome.Failed, calls: 1, failed: 1)`,
     return `DraftPassEnd.OutlookUnavailable` (like step 7; no model
     backoff, no `Ai` event).
   - `catch (OperationCanceledException) when (ct.IsCancellationRequested)`
     → same `Failed` row, return `DraftPassEnd.Cancelled`.
   - The draft is still created for NoFreeTime and CalendarUnreadable.
3. Steps 7 and 8 are unchanged and use the new `html`.

### D. `DraftWorker`, manual path (`ManualCoreAsync`, `ModelResult.Ok` branch)

After `html` is non-empty and before `_s.Writer.ReplyAsync`, when
`DraftMeetingTimes.IsWanted(ai, reply, html)`:
1. **Europe**: `facts = await _s.Mailbox.GetFactsAsync(key, e.EntryId, WorkPriority.Interactive, ct)`;
   `europe = SenderRegion.IsEurope(e.SenderEmail, facts?.TransportHeaders)`.
   - `OutlookUnavailableException` → `text = ManualFailed("Outlook isn't running")`,
     `break` (no draft; `called` stays true, so the existing
     `WriteManualRow(index, e, prior, null, now, null)` counts the call).
   - `OperationCanceledException` when cancelled →
     `WriteManualRow(index, e, prior, null, now, null)` then rethrow
     (same as the writer's cancellation handling).
   - Any other exception → `europe = SenderRegion.IsEurope(e.SenderEmail, null)`
     (TLD rule alone) and log Debug `AI drafts: reading the email's headers for meeting times failed ({Type}).`
   - Facts are read **only** here; a manual draft without a meeting makes
     no `GetFactsAsync` call (the existing `Assert.Empty(h.Mailbox.FactCalls)`
     keeps passing).
2. `mt = await _meetings.ApplyAsync(new MeetingTimesRequest(html, reply.Meeting, userSmtp, key, e.SenderEmail, e.To, e.Cc, reply.ReplyAll ?? false, europe, now, cur), WorkPriority.Interactive, ct)`;
   `html = mt.Html`; log (section E).
   - `OutlookUnavailableException` → `text = ManualFailed("Outlook isn't running")`, `break` (call counts).
   - cancellation → `WriteManualRow(…)` then rethrow.
3. Then the existing writer call with the new `html`.

`userSmtp` in the manual path can be `""` (identity unknown) →
CalendarUnreadable placeholder, draft still created.

### E. Logging (meeting times)

After each `ApplyAsync` that returned (both paths):
- `Offered` → Debug `AI drafts: offered {Count} meeting times ({Readable} of {Checked} attendees readable)`
  (formats as `AI drafts: offered 3 meeting times (2 of 2 attendees readable)`, §21.6).
- `NoFreeTime` → Debug `AI drafts: no free meeting times to offer ({Readable} of {Checked} attendees readable)`.
- `CalendarUnreadable` → Debug `AI drafts: couldn't read the calendar for meeting times ({Type})`
  with `mt.ErrorType ?? "unknown"`.
- `mt.CetMissing` → Warning `FreeTimeFinder.CetMissingWarning` (reuse the
  M13.2 constant), **once per `DraftWorker` instance** (`int _cetWarned`
  with `Interlocked.Exchange`).

Nothing else. No times, dates, addresses or headers.

### F. Low-confidence skips (user requirement 2026-11-14)

1. `PassState` gets `LowConfidence` (int), `HighestLow` (double) and
   `LowMinimum` (double). `Write`'s switch: `NoReply → p.NoReply++`,
   `LowConfidence → p.LowConfidence++` (no longer into `NoReply`).
2. At the low-confidence branch (step 6, `reply.Confidence < ai.MinConfidence`),
   after the existing `Write`: set `p.HighestLow = max(p.HighestLow, reply.Confidence)`
   (start at 0), `p.LowMinimum = ai.MinConfidence`, and record
   `_s.Hub.Event(ActivityKind.Ai, DraftTexts.LowConfidence(c.EventTime, _s.Zone, reply.Confidence, ai.MinConfidence), mailbox: key.Length == 0 ? null : key)`.
3. **Event text**, exact (`<received>` is `c.EventTime` in `_s.Zone`,
   invariant `yyyy-MM-dd HH:mm`; numbers via `DraftTexts.Confidence`):
   ```
   AI drafts: no draft for the email received <received>: Claude's confidence <confidence> is below your minimum of <minimum>. To draft it anyway, select it in Outlook and use "Draft a reply to the selected email" in the tray menu, or lower Minimum confidence in Settings → AI drafts.
   ```
   e.g. `AI drafts: no draft for the email received 2026-11-13 11:50: Claude's confidence 0.50 is below your minimum of 0.60. To draft it anyway, select it in Outlook and use "Draft a reply to the selected email" in the tray menu, or lower Minimum confidence in Settings → AI drafts.`
   (`→` is U+2192, straight double quotes.) No subject, sender, body or
   `reason`.
4. **Summary event** (`DraftTexts.Summary`): parts in this order, parts
   that are 0 left out except `drafted`:
   `AI drafts: <d> drafted, <n> no reply needed, <l> low confidence, <s> skipped, <f> failed (<duration>)`.
   Duration format unchanged. A pass with only a low-confidence skip has
   `p.Rows > 0`, so it records `AI drafts: 0 drafted, 1 low confidence (<x> s)`.
5. **Pass log line** (Information), template:
   ```
   AI drafts pass: {End}, {Drafted} drafted, {NoReply} no reply, {LowConfidence} low confidence{LowConfidenceDetail}, {Skipped} skipped, {Failed} failed, {Calls} calls in {Ms} ms
   ```
   with `LowConfidenceDetail = DraftTexts.LowConfidenceLogDetail(p.LowConfidence, p.HighestLow, p.LowMinimum)`.
   Formatted examples:
   `AI drafts pass: Completed, 0 drafted, 0 no reply, 1 low confidence (0.50 < 0.60), 0 skipped, 0 failed, 1 calls in 12 ms`;
   `…, 2 low confidence (highest 0.55 < 0.60), …`;
   `…, 0 low confidence, …` when none.
6. `DraftPassResult` returns `p.LowConfidence`; `Ended(end)` passes 0.
   `NoReply` no longer includes low-confidence skips.
7. The manual path is unchanged (it ignores `MinConfidence`).
8. Backoff reset and the `low_confidence` row are unchanged.
