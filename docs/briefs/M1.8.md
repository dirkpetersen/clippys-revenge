# M1.8 `FreeBusy`: busy intervals, free slots, 28-day chunk joining

## Goal

Add the pure scheduling logic behind `find_free_times` to Core, as specified
in SPEC §12 (`FreeBusy.BusyIntervals`, `FreeBusy.FreeSlots`), §8
(`GetFreeBusy` fetches **28-day chunks** and joins them), §11.8 (steps 3–4)
and §15 (`FreeBusy` test row). The input is Outlook's free/busy string,
one digit per interval. The output is merged busy intervals and the free
blocks inside working hours that are at least `minMinutes` long, with
everything before "now" (rounded up to the next interval) cut off. The
COM call (`OutlookCalendar.GetFreeBusy`) is M8.2. This task adds only the
Core helpers that M8.2 will call: `ChunkStarts` to plan the chunked fetch
and `JoinChunks` to stitch the strings together.

## Cross-task dependencies

None. This task defines its own `TimeRange` type and does not use
`Settings` (M1.7), `Recipients` (M1.1) or `SlotFormatter` (M1.3). The
caller (M8.2) passes the setting values in as plain arguments.

## Public API

Namespace `ClippysRevenge.Core`, file-scoped.

```csharp
namespace ClippysRevenge.Core;

/// Half-open [Start, End) in local wall-clock time.
public readonly record struct TimeRange(DateTime Start, DateTime End)
{
    public TimeSpan Duration => End - Start;
}

public static class FreeBusy
{
    public const int ChunkDays = 28;
    public const int DefaultIntervalMinutes = 30;

    /// ArgumentNullException: fb null.
    /// ArgumentOutOfRangeException: intervalMinutes <= 0.
    /// FormatException: a char outside '0'..'4'.
    public static IReadOnlyList<TimeRange> BusyIntervals(
        string fb, DateTime start, int intervalMinutes, bool tentativeIsBusy);

    /// ArgumentNullException: busyPerAttendee or any element null.
    /// ArgumentOutOfRangeException: hours, minMinutes or intervalMinutes out of range.
    public static IReadOnlyList<TimeRange> FreeSlots(
        IEnumerable<IReadOnlyList<TimeRange>> busyPerAttendee,
        DateTime from, DateTime to,
        int startHour, int endHour,
        bool businessDaysOnly,
        int minMinutes,
        DateTime now,
        int intervalMinutes = DefaultIntervalMinutes);

    /// Midnight of from, then every 28 days, while < to. Empty when to <= from.
    public static IReadOnlyList<DateTime> ChunkStarts(DateTime from, DateTime to);

    /// ArgumentNullException: chunks or any element null.
    /// ArgumentOutOfRangeException: intervalMinutes <= 0 or 1440 % intervalMinutes != 0.
    /// ArgumentException: a non-last chunk shorter than one 28-day chunk.
    public static string JoinChunks(IReadOnlyList<string> chunks, int intervalMinutes);
}
```

`FreeSlots` has one trailing optional parameter, `intervalMinutes`, which
the §12 signature leaves out. See "Spec changes (proposed)".

## Behavior

### Time model

- All `DateTime`s are local wall-clock times (SPEC §12: "All scheduling
  math uses the local Windows time zone"). `Kind` is ignored and never
  converted. Arithmetic is plain `AddMinutes`/`AddDays` with no DST
  adjustment, which matches how Outlook lays out the free/busy string (one
  char per local interval from local midnight). The output keeps the
  `Kind` that the arithmetic produces from the inputs. Tests compare only
  the tick values (`Unspecified` kind everywhere).
- `TimeRange` is half-open. Two ranges *touch* when `a.End == b.Start`.

### `BusyIntervals`

- Char `i` covers `[start + i*interval, start + (i+1)*interval)`.
- Codes: `0` free, `1` tentative, `2` busy, `3` out of office, `4`
  working elsewhere. Busy means `2` or `3`, plus `1` when `tentativeIsBusy`
  is set. `4` counts as free.
- Runs of consecutive busy chars, of any mix of busy codes, become one
  interval ("Adjacent busy intervals are merged"). The output is sorted
  and has no overlapping or touching ranges.
- `""` gives an empty list.
- Any other char throws
  `FormatException($"Unexpected free/busy code '{c}' at position {i}.")`
  (0-based position). The caller (M8.2) treats that attendee as unknown.
  Never guess "free" for unknown data.
- `start` is used as given. It is not truncated to midnight. Outlook's
  string starts at local midnight of the requested date, so M8.2 must pass
  the chunk start from `ChunkStarts` (which is midnight).

### `FreeSlots`

Validation (before any work):
- `0 <= startHour < endHour <= 24`, else `ArgumentOutOfRangeException`
  (param name `startHour` or `endHour`).
- `minMinutes >= 1`, else `ArgumentOutOfRangeException(nameof(minMinutes))`.
- `intervalMinutes >= 1`, else `ArgumentOutOfRangeException(nameof(intervalMinutes))`.
- `busyPerAttendee` and each element non-null, else `ArgumentNullException`.

Algorithm:
1. If `from >= to`, return empty.
2. Union all attendees' busy ranges: flatten, sort by start, and merge
   overlapping **or touching** ranges. The input lists may be unsorted and
   may overlap.
3. `cutoff` = `now` rounded **up** to the next multiple of
   `intervalMinutes` since `now.Date` (midnight). If `now` is already on a
   boundary (whole ticks), `cutoff == now`. Example: interval 30, 10:07 →
   10:30, 10:30 → 10:30, 10:30:00.001 → 11:00, 23:50 → next day 00:00.
4. For each calendar day `d` from `from.Date` to `(to - 1 tick).Date`
   inclusive:
   - Skip Saturday and Sunday when `businessDaysOnly`.
   - Window = `[d + startHour h, d + endHour h)`, clipped to
     `[max(from, cutoff), to)`. Skip it if it is empty.
   - Subtract the merged busy ranges. Each remaining gap is one maximal
     free block (it is not split into `minMinutes` pieces).
   - Keep the gaps with `Duration >= minMinutes`.
5. Return all kept blocks in chronological order.

Free time before `cutoff` is **clipped**, not dropped with its whole
block. A block from 08:00 to 17:00 with `now` = 10:07 becomes 10:30 to
17:00, and the `minMinutes` check applies after clipping. See "Spec changes".

`max_suggestions`, attendee resolution, `unknown_attendees` and formatting
are M8.2's job, not this function's.

### `ChunkStarts`

- Returns `from.Date`, `from.Date + 28d`, `from.Date + 56d`, …, every value
  `< to`. If `to <= from`, it returns empty. Exactly 28 days is one chunk.
- M8.2 calls `GetFreeBusy(email, chunkStart, interval)` for each start,
  then calls `JoinChunks` and `BusyIntervals(joined, starts[0], interval, …)`.
  If any chunk returns null, the attendee is unknown.

### `JoinChunks`

- `slotsPerChunk = 28 * 1440 / intervalMinutes`.
- For every chunk except the last, take exactly the first `slotsPerChunk`
  chars. Outlook returns about 30 days, and the overlap past day 28 is
  dropped because the next chunk covers it. Append the last chunk whole.
- If a non-last chunk is shorter than `slotsPerChunk`, throw
  `ArgumentException($"Free/busy chunk {i} has {len} slots; expected at least {slotsPerChunk}.", nameof(chunks))`
  (0-based `i`). Padding would misalign the later chunks, and padding
  with `0` would report busy time as free.
- An empty list returns `""`. A single chunk is returned unchanged.
- Validate `intervalMinutes` first: `ArgumentOutOfRangeException` when it
  is `<= 0` or does not divide 1440.

## Tests

`tests/ClippysRevenge.Core.Tests/FreeBusyTests.cs`, class `FreeBusyTests`,
namespace `ClippysRevenge.Core.Tests`. All tests are cross-platform, with
no traits. Use a helper `static DateTime T(int day, int h, int m = 0) =>
new(2026, 10, day, h, m, 0)`. Mon = 2026-10-12, Fri = 10/16, Sat = 10/17,
Sun = 10/18, Mon = 10/19. Unless a test says otherwise, `now = T(11, 12)`
(before everything), interval 30, hours 8–17, `businessDaysOnly = true`
and `minMinutes = 60`. Write `[a,b)` for `new TimeRange(a, b)`.

### `BusyIntervals` (start = `T(12,0)` unless noted)

1. `""` → empty.
2. `"0000"`, interval 30 → empty.
3. `"0220"`, 30 → `[T(12,0,30), T(12,1,30))`.
4. `"2302"`, 30 → `[T(12,0), T(12,1))`, `[T(12,1,30), T(12,2))` (2 and 3 merge).
5. `"0120"`, 30, tentative true → `[T(12,0,30), T(12,1,30))`. Tentative false → `[T(12,1), T(12,1,30))`.
6. `"040"`, 30 → empty (working elsewhere is free).
7. `"002"`, 60 → `[T(12,2), T(12,3))` (busy run at the end is closed).
8. Start `T(12,9)`, `"2"`, 15 → `[T(12,9), T(12,9,15))` (start is not truncated).
9. `"02x"` → `FormatException` with message `Unexpected free/busy code 'x' at position 2.`.
10. Interval 0 → `ArgumentOutOfRangeException`. `fb` null → `ArgumentNullException`.

### `FreeSlots`

11. No attendees (empty enumerable), from `T(12,0)` to `T(13,0)` → `[T(12,8), T(12,17))`.
12. Overlaps across attendees: A = `[9,10)`, `[12,13)`, B = `[9:30,11)`, `[12:30,14)` on Mon, from `T(12,0)` to `T(13,0)` →
    `[8,9)`, `[11,12)`, `[14,17)` on Mon.
13. Unsorted input: A = `[14,15)`, `[9,10)` (in that order) → `[8,9)`, `[10,14)`, `[15,17)`.
14. minMinutes: A = `[8:30,17)` → empty with min 60. With min 30 → `[8,8:30)`.
15. Weekends: from `T(16,0)` to `T(20,0)`, no busy. Business days → Fri and Mon `[8,17)` (2 slots). Not business days → Fri, Sat, Sun, Mon (4 slots).
16. Work-hour edges: busy `[7,8)` and `[17,18)` Mon → `[8,17)` unchanged. Busy `[7:30,8:30)` → `[8:30,17)`.
17. Busy across midnight: `[T(12,16), T(13,9))`, from `T(12,0)` to `T(14,0)` → `[T(12,8), T(12,16))`, `[T(13,9), T(13,17))`.
18. "now" cut-off, from `T(12,0)` to `T(13,0)`:
    - now `T(12,10,7)` → `[T(12,10,30), T(12,17))`.
    - now `T(12,10,30)` exactly → `[T(12,10,30), T(12,17))`.
    - now `T(12,16,31)` → empty (cutoff 17:00).
    - now `T(12,16,1)`, min 30 → `[T(12,16,30), T(12,17))`. Min 60 → empty.
    - now `T(12,10,7)`, interval 15 → starts `T(12,10,15)`.
    - now `T(14,0)` (after `to`) → empty.
19. Partial day range: from `T(12,13)` to `T(12,15)` → `[T(12,13), T(12,15))`.
20. `from >= to` → empty.
21. Full-day window: start 0, end 24, not business days, from `T(17,0)` to `T(18,0)` → `[T(17,0), T(18,0))`.
22. Validation → `ArgumentOutOfRangeException` for: (17, 8), (8, 8), (-1, 17), (8, 25), min 0, interval 0. A null attendee list → `ArgumentNullException`.
23. Combined with `BusyIntervals`: attendee strings for Mon at 30-min intervals from `T(12,0)`. A has `'2'` at indices 18–19 (9:00–10:00), B has `'1'` at 20–21 (10:00–11:00). Tentative busy → `[8,9)`, `[11,17)`. Tentative free → `[8,9)`, `[10,17)`.

### Chunk joining

24. `ChunkStarts(T(12,14), T(22,0))` → `[T(12,0)]`.
25. `ChunkStarts(T(12,0), T(12,0).AddDays(60))` → `[2026-10-12, 2026-11-09, 2026-12-07]` (all midnight).
26. `ChunkStarts(T(12,0), T(12,0).AddDays(28))` → one element. `AddDays(28).AddMinutes(1)` → two.
27. `ChunkStarts(T(12,0), T(12,0))` and `to < from` → empty.
28. `JoinChunks([], 60)` → `""`. `JoinChunks(["0120"], 60)` → `"0120"`.
29. Interval 60 (672 slots per chunk): chunk0 = 720 chars of `'0'` with `'2'` at index 671 and `'3'` at index 700. chunk1 = `"2" + new string('0', 99)`. Joined length = 772. `joined[671] == '2'`, `joined[672] == '2'` (from chunk1), and no `'3'` anywhere (past day 28, so dropped).
30. Chunk-boundary merge: `BusyIntervals(joined from 29, T(12,0), 60, true)` → exactly one range, `[T(12,0).AddHours(671), T(12,0).AddHours(673))`.
31. Three chunks at interval 30 (1344 slots), each 1440 chars, with chunk *k* filled with char `'0'+k` → length 1344 + 1344 + 1440, segments in order.
32. Short non-last chunk: `JoinChunks([new('0', 100), "0"], 60)` → `ArgumentException` with message starting `Free/busy chunk 0 has 100 slots; expected at least 672.`. A short **last** chunk is fine.
33. Interval 7 or 0 → `ArgumentOutOfRangeException`. Null list or null element → `ArgumentNullException`.

## Spec changes (proposed)

These are for the orchestrator to apply to SPEC.md §12, replacing the two
`FreeBusy` bullets. They are low-risk clarifications.

```markdown
- `FreeBusy.BusyIntervals(string fb, DateTime start, int intervalMinutes, bool tentativeIsBusy)` → `IReadOnlyList<TimeRange>`:
  - Codes: `0` free, `1` tentative, `2` busy, `3` out of office, `4`
    working elsewhere.
  - Busy means `2` or `3`, plus `1` when `tentativeIsBusy` is set. `4`
    counts as free.
  - Adjacent busy intervals are merged.
  - Any other character throws `FormatException`. The caller treats that
    attendee as unknown, and unknown data is never treated as free.
- `FreeBusy.FreeSlots(busyPerAttendee, from, to, startHour, endHour, businessDaysOnly, minMinutes, now, intervalMinutes = 30)`:
  - For each day, take the working-hours window and remove the busy time.
  - Free time before `now` rounded up to the next `intervalMinutes`
    boundary is clipped off. Then gaps of at least `minMinutes` are kept,
    each as one maximal block.
  - `find_free_times` fetches free/busy at 30-minute intervals
    (`FreeBusy.DefaultIntervalMinutes`).
- `FreeBusy.ChunkStarts(from, to)` / `FreeBusy.JoinChunks(chunks, intervalMinutes)`:
  free/busy is fetched from midnight of `from` in 28-day chunks. Every chunk
  but the last is cut to exactly 28 days before joining. A non-last chunk
  shorter than 28 days is an error, and that attendee is reported as unknown.
```
