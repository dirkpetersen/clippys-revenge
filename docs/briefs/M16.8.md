# M16.8 Live tests for M16 (fingerprint, guard, move to Deleted Items, revisit schema, `opus`)

Base: `dev` with M16.1–M16.5 merged (all are). Runs **beside M16.6**; the
two briefs share no file (see "Parallel work"). Tests and the live-test
script only: no product code changes.

## Goal

Prove the M16.4 COM side against the user's real classic Outlook and the
M16.1/M16.3 model contract against the real Claude CLI (§23.11 "Live"):
the fingerprint returned after `Save()` equals a fresh `ReadAiDraftAsync`
read, also after a Send/Receive and two minutes (**the §23.4 decision
depends on this**); a COM edit gives `Changed` and is never moved; an
unedited, unopened AI draft is moved by the real guarded
`MoveObsoleteAiDraftAsync` into the own store's Deleted Items, unsent, and
the test then removes it from there by EntryID; a draft without the `ai`
marker gives `NotMarked` and stays; an open draft is never moved; Sent
Items and Outbox are unchanged; only items the test created are removed.
Claude: one call with `DraftModel.RevisitSchema` returns output that
`DraftRevisit.Parse` accepts (the CLI accepts `enum`), and a call with
`Model = "opus"` succeeds.

SPEC refs: §23.11 (Live bullet), §23.4, §23.5, §19.12 (live rules), §15
(live tests: opt-in, never sends, deletes only own items), §1 hard rules,
CLAUDE.md "Live Outlook tests".

**If the fingerprint is not stable, stop and report.** The stability test
fails with a fixed message naming the stage and the changed field names;
whoever runs it reports that to the user. Nobody changes §23.4,
`DraftFingerprint`, `ReadDraftFingerprint` or the guard to make it pass.

## Hard rules that apply here

- **Never send anything.** No `.Send(`, `.Display(`, `.Activate(`; no
  meeting items. `Session.SendAndReceive(false)` is called at most once per
  run and only when every store's Outbox is empty (Behavior C.3), so it
  can't deliver anything; Sent Items and Outbox counts are asserted
  unchanged.
- **Delete only what the test created**, and only through the fixture's
  existing token-checked `DeleteAsync` (by recorded EntryID, subject must
  start with `[<RunToken>] `). The tests never call `Delete`, `Move` or
  `PermanentDelete` themselves; the one move is the product's guarded
  `MoveObsoleteAiDraftAsync`.
- **Never open UI windows.** No `Display`, no `Activate`. The open-draft
  test uses `MailItem.GetInspector` (creates an inspector object, shows no
  window) and closes it with `OlInspectorClose.olDiscard`.
- **Never launch Outlook** (attach-only fixture, unchanged).
- Opt-in only: `[Trait("live","outlook")]` with `CLIPPY_LIVE=1`;
  `[Trait("live","claude")]` with `CLIPPY_LIVE=1` and `CLIPPY_LIVE_CLAUDE=1`;
  all `[Trait("os","windows")]`, `[Collection(LiveOutlookCollection.Name)]`.
  CI's filter `live!=outlook&live!=claude` excludes them.
- Synthetic, self-addressed content only; results print no mail text,
  prompts, model text or addresses (field **names**, lengths and short
  hashes only).

## Public API (test-internal)

```csharp
namespace ClippysRevenge.Core.Tests.Live;

/// <summary>Per-field view of the fingerprint inputs: name -> "len:<n> sha:<first 12 hex of SHA-256(UTF-8)>".
/// Keys exactly: subject, to, cc, bcc, html, categories, importance, attachments. Never holds the values.</summary>
internal sealed record FingerprintFields(IReadOnlyDictionary<string, string> Fields)
{
    /// <summary>Names whose entry differs, in the key order above. Empty = same.</summary>
    public IReadOnlyList<string> DiffFrom(FingerprintFields other);
}

/// <summary>A draft in Deleted Items found by its exact subject (worker thread only).</summary>
internal sealed record DeletedDraft(string EntryId, bool Sent, string? Marker, string? MessageClass);

internal static class LiveObsoleteDrafts
{
    public const int StabilitySeconds = 120;

    /// <summary>Creates the synthetic self-addressed source (as LiveAiDraftTests: CreateDraftTool, no signature,
    /// subject "[RunToken] <title>", body with the token), tracks it, and checks Outlook can reply to it
    /// (LiveDrafts.TryOwnReply); Assert.Skip with the LiveAiDraftTests text when it can't. Returns (id, storeId).</summary>
    public static Task<(string Id, string StoreId)> CreateSourceAsync(LiveOutlook fx, LiveOutlook.Scope scope,
        Recipient me, string title, CancellationToken ct);

    /// <summary>A reply draft through the production writer (OutlookReplyDraftWriter): plan
    /// (sourceId, null, false, DraftBody.Fragment("&lt;p&gt;M16 live test " + RunToken + "&lt;/p&gt;", html: true, null),
    /// false, marker, priority). Tracks it at once as TrackedItem(Draft, "", made.EntryId, storeId,
    /// "[" + RunToken + "] " + made.Subject) so a failed test still cleans it up once it is tagged.</summary>
    public static Task<RepliedDraft> CreateReplyAsync(LiveOutlook fx, LiveOutlook.Scope scope, string sourceId,
        string storeId, string marker, WorkPriority priority, CancellationToken ct);

    /// <summary>LiveDrafts.ReadDraft(tag: true): prefixes "[RunToken] " and saves (only while not sent).</summary>
    public static Task TagAsync(LiveOutlook fx, string entryId);

    /// <summary>Worker thread. The eight fingerprint inputs of the item, read like OutlookMail.ReadDraftFingerprint
    /// (attachment FileName null/empty = "?").</summary>
    public static FingerprintFields ReadFields(Outlook.MailItem item);

    /// <summary>Opens the item by id (own store) and returns ReadFields; releases everything.</summary>
    public static Task<FingerprintFields> FieldsAsync(LiveOutlook fx, string entryId, string storeId);

    /// <summary>Worker thread. True when every store of the session that has a default Outbox has 0 items in it
    /// (a store whose GetDefaultFolder(olFolderOutbox) throws COMException is ignored). Releases everything.</summary>
    public static bool AllOutboxesEmpty(Outlook.Application app);

    /// <summary>One work item: "skipped: offline" when Session.Offline; "skipped: Outbox not empty" unless
    /// AllOutboxesEmpty(app); else Session.SendAndReceive(false) and "done". A COMException (not Outlook gone) gives
    /// "skipped: failed (0x……)". Never shows UI.</summary>
    public static Task<string> SendReceiveIfOutboxesEmptyAsync(LiveOutlook fx);

    /// <summary>Worker thread. Appends "&lt;p&gt;edited by the M16 live test&lt;/p&gt;" before "&lt;/body&gt;" (or at the end)
    /// of HTMLBody and saves. The test's own draft only.</summary>
    public static Task EditBodyAsync(LiveOutlook fx, string entryId, string storeId);

    /// <summary>Worker thread. Items in the own store's Deleted Items whose subject equals exactSubject (Restrict on the
    /// run token, then ordinal equality). Releases everything.</summary>
    public static Task<IReadOnlyList<DeletedDraft>> FindInDeletedItemsAsync(LiveOutlook fx, string exactSubject);

    /// <summary>Worker thread. MailItem.GetInspector for the item (no Display), kept open; Close(olDiscard) on dispose
    /// (in a work item), then released. Never throws from DisposeAsync.</summary>
    public static Task<IAsyncDisposable> HoldInspectorAsync(LiveOutlook fx, string entryId, string storeId);
}
```

`IAiMailbox` under test: `new OutlookAiMailbox(fx.Worker, fx.Mail, fx.Stores)`
(production code; mailbox key `""`).

## Behavior

### A. Common shape of every Outlook test

```
ct = TestContext.Current.CancellationToken
await fx.RequireReadyAsync(ct); me = await fx.MeAsync()
storeId = await fx.RunAsync("reading the store id", app => fx.StoreIdOf(app, ""))
await fx.WithCleanupAsync([""], [olFolderDrafts, olFolderDeletedItems], async scope => {
    src  = CreateSourceAsync(...)
    made = CreateReplyAsync(...)
    try { <test body> }
    finally { <tag every reply draft that is still in Drafts: TagAsync> }
})
```
- Tagging changes the subject and therefore the fingerprint, so it always
  happens **after** the assertions that need the creation fingerprint
  (except D.3, which tags on purpose before the move). `TagAsync` failing in
  `finally` is swallowed (`fx.Result("cleanup-tag", "failed")`); the
  ledger/cleanup then reports a leftover rather than hiding the test's
  own failure.
- `WithCleanupAsync` already snapshots Sent Items/Outbox, deletes the
  tracked items by EntryID (token-checked), checks no token item is left in
  Drafts **or Deleted Items**, and asserts nothing was sent.
- Every assertion message is a fixed text (no subjects, ids or bodies).

### B. Fingerprint fields

`ReadFields` reads `Subject`, `To`, `CC`, `BCC`, `HTMLBody`, `Categories`,
`(int)Importance` (invariant decimal) and the attachment file names joined
with `\n` (null/empty name → `?`), null → `""`. Each value →
`"len:" + value.Length + " sha:" + hex(SHA256(UTF8(value)))[..12]`.

### C. Helpers' rules

1. `CreateSourceAsync`: exactly the LiveAiDraftTests 4.1–4.2 pattern
   (CreateDraftTool with `new Signatures(_ => null, Path.Combine(fx.TempRoot, "no-signatures"))`,
   recipient `me`, subject `[{RunToken}] {title}`, body ending in the token;
   `scope.Track(new TrackedItem(Draft, "", id, storeId, subject))`; baseline
   `TryOwnReply` → `Assert.Skip("Outlook can't reply to an unsent test item on this profile, so the M16 live test can't run here. Nothing was sent.")`
   with `fx.Result("m16-baseline", "skipped: …")`).
2. `CreateReplyAsync` asserts `made.Subject == ReplySubject.Normalize(sourceSubject)`
   (starts `Re:: `) is left to the tests; it only creates and tracks.
3. `SendReceiveIfOutboxesEmptyAsync`: one `fx.RunAsync` work item, timeout
   60 s; the Outbox check and the call are in the same work item.
4. `FindInDeletedItemsAsync`: `Restrict("@SQL=\"urn:schemas:httpmail:subject\" LIKE '%<RunToken>%'")`
   on the own Deleted Items, then `Subject == exactSubject` (ordinal); reads
   `EntryID`, `Sent`, the `ClippyDraft` marker (`LiveDrafts.ReadMarker`),
   `MessageClass`; releases each item in the loop.
5. `HoldInspectorAsync`: never calls `Display`/`Activate`; the returned
   disposable closes with `olDiscard` (the draft has no unsaved change, so
   nothing is lost) inside `fx.Worker.RunAsync`, catches `COMException`,
   releases the inspector and item.

### D. Outlook tests (`LiveObsoleteDraftTests`, `[Trait("live","outlook")]`, `[Trait("os","windows")]`)

**D.1 `Ai_draft_fingerprint_is_stable_after_save_send_receive_and_two_minutes`** (`Timeout = 420_000`)

1. `made = CreateReplyAsync(marker: DraftMarker.Ai, priority: WorkPriority.Background)`.
   Assert `DraftFingerprint.IsValid(made.Fingerprint)` ("The AI reply draft
   came back without a fingerprint."), subject `Re:: `, in Drafts.
2. `f0 = FieldsAsync(made.EntryId)`; `i1 = ReadAiDraftAsync("", id, Interactive)`:
   not null; `i1.Fingerprint == made.Fingerprint` (stage `save`);
   `AiDraftGuard.Evaluate(i1, made.Fingerprint) == Movable`; `i1.Open` false,
   `i1.InDrafts` true, `i1.Sent` false, marker `ai`.
3. `sr = SendReceiveIfOutboxesEmptyAsync(fx)`; `fx.Result("m16-send-receive", sr)`.
4. Wait until `StabilitySeconds` (120) have passed since step 1
   (`Task.Delay(remaining, ct)`), then `i2 = ReadAiDraftAsync(...)`,
   `f2 = FieldsAsync(...)`: `i2.Fingerprint == made.Fingerprint` (stage
   `send-receive and 2 min`) and `Evaluate(i2, made.Fingerprint) == Movable`.
5. **Unstable** at any stage → `fx.Result("m16-fingerprint", "UNSTABLE after <stage>; fields: <f0.DiffFrom(fN) joined with ', ' or 'unknown'>; mode <fx.ConnectionMode>")`
   and `Assert.Fail("The AI draft's fingerprint changed without an edit (after <stage>; fields: <names>). Stop: SPEC 23.4's unedited test must be revisited before M16 ships. Nothing was moved or sent.")`.
6. Stable → `fx.Result("m16-fingerprint", "stable for <s> s (send/receive: <sr>), mode <fx.ConnectionMode>")`.
7. Informational, never fails: a plain `item.Save()` with no change (as an
   autosave would), then a read: `fx.Result("m16-resave", "stable" | "changed: <fields>")`.
   (A change here only makes Clippy leave such drafts alone; it is data for
   the §23.4 decision, not a blocker.)
8. `finally`: `TagAsync(made.EntryId)`.

**D.2 `Edited_ai_draft_is_changed_and_never_moved`** (`Timeout = 180_000`)

1. Create (marker `ai`, `Interactive`); `fp0 = made.Fingerprint` (valid).
2. `EditBodyAsync`; `i = ReadAiDraftAsync`: `Evaluate(i, fp0) == Changed`
   (Assert "A COM edit of the body did not give Changed.").
3. `m = MoveObsoleteAiDraftAsync("", id, fp0, Interactive, ct)`:
   `m.Status == Changed`, `m.Subject == made.Subject`.
4. `LiveDrafts.ReadDraft`: `ParentId == DraftsId`, `!Sent`;
   `FindInDeletedItemsAsync(made.Subject)` is empty.
5. `fx.Result("m16-edited", "changed, stayed in Drafts")`. `finally`: tag.

**D.3 `Unedited_ai_draft_moves_to_own_deleted_items_unsent`** (`Timeout = 180_000`)

1. Create (marker `ai`, `Interactive`); `fp0` valid; `Evaluate(Read, fp0) == Movable`.
2. `TagAsync(made.EntryId)` (subject becomes `tagged = "[" + RunToken + "] " + made.Subject`,
   needed so the token-checked cleanup can remove it later).
   `i = ReadAiDraftAsync`: `Evaluate(i, fp0) == Changed` (a subject edit
   counts) and `fpT = i.Fingerprint`; `Evaluate(i, fpT) == Movable`.
3. `m = MoveObsoleteAiDraftAsync("", id, fpT, Interactive, ct)`:
   `m.Status == Moved`, `m.Subject == tagged`.
4. Old id: `ReadAiDraftAsync("", id, …)` is null **or** `InDrafts == false`
   (Exchange may or may not keep the EntryID on a move).
   `LiveDrafts`/Drafts: `TokenSubjectsIn(Drafts)` doesn't contain `tagged`.
5. `found = FindInDeletedItemsAsync(tagged)`: exactly 1; `Sent == false`;
   `Marker == "ai"`; `MessageClass` equals `IPM.Note` (ordinal ignore case).
   `scope.Track(new TrackedItem(Draft, "", found[0].EntryId, storeId, tagged))`
   → cleanup removes it **from Deleted Items by this EntryID** (the
   fixture's `DeleteOne`: `Delete()` on an item in Deleted Items removes
   it; then `PurgeDeleted`).
6. Second guarded move with the old id and `fpT` → status is `Gone` or
   `NotInDrafts` (never `Moved`); `FindInDeletedItemsAsync(tagged)` still
   exactly 1.
7. `await fx.AssertNothingSentAsync(before)` right here too (snapshot taken
   at the start of the test body with `fx.SnapshotSentAsync("")`).
8. `fx.Result("m16-move", "moved to own Deleted Items, unsent; second attempt <status>")`.

**D.4 `Draft_without_ai_marker_is_not_marked_and_stays`** (`Timeout = 180_000`)

1. Create with `marker: DraftMarker.Tool` (the `reply_draft` marker; "not
   `ai`"), `Interactive`. `made.Fingerprint` is valid (any marker, §23.4).
2. `i = ReadAiDraftAsync`: `i.Marker == "tool"`; `Evaluate(i, made.Fingerprint) == NotMarked`.
3. `MoveObsoleteAiDraftAsync(..., made.Fingerprint, …)` → `NotMarked`;
   still in Drafts, unsent; nothing in Deleted Items with its subject.
4. `fx.Result("m16-not-marked", "not marked, stayed in Drafts")`. `finally`: tag.

**D.5 `Open_ai_draft_is_never_moved`** (`Timeout = 180_000`)

1. Create (marker `ai`, `Interactive`); `fp0`.
2. `await using var insp = await HoldInspectorAsync(...)`;
   `i = ReadAiDraftAsync`. When `i.Open` is false →
   `fx.Result("m16-open", "inconclusive: an inspector from GetInspector is not listed in Inspectors")`
   and `Assert.Skip("Outlook didn't list the hidden inspector, so the open-draft check can't run here without opening a window. Nothing was moved or sent.")`
   (dispose first). **Never** call the move unless `i.Open` is true.
3. `Evaluate(i, fp0) == Open`; `MoveObsoleteAiDraftAsync(..., fp0, …)` →
   `Open`; still in Drafts, unsent.
4. Dispose the inspector; informational: `Evaluate(Read, fp0)` →
   `fx.Result("m16-open", "open, stayed in Drafts; after close: <status>")`
   (`Movable` expected; `Changed` is recorded, not failed).
5. `finally`: tag.

## Spec changes

Not applied by this brief (the caller asked for the brief files only); to be
recorded in `SPEC.md` §23.11 by the architect:

1. **Send/Receive in the live test** is `Session.SendAndReceive(false)`,
   called only when every store's Outbox is empty (else, and when offline,
   it's skipped and the result line says so), so the test can never deliver
   anything. A live scan pins this.
2. **Cleanup of the moved draft**: before the move the test prefixes the
   draft's subject with the run token (as every live reply draft is tagged)
   and passes the post-tag fingerprint as the expected one; the tag doubles
   as the "subject edit → `Changed`" check against the creation
   fingerprint. After the move the test finds the item in the own Deleted
   Items by its exact subject and removes it by that EntryID through the
   existing token-checked cleanup.
3. **Statuses not producible live**: `Sent == true` needs a sent item, so it
   stays covered by the Core guard tests; the live analog is a second move
   on the already-moved draft, which must give `Gone` or `NotInDrafts`.
   "Without the marker" uses the `tool` marker (any non-`ai` marker is
   `NotMarked`). `Open` uses a hidden inspector from `GetInspector` and is
   skipped as inconclusive when Outlook doesn't list it.
4. Informational result lines (never failing): a no-change re-`Save()` and
   closing a hidden inspector, each with the changed field names if the
   fingerprint moved.
