# M16.4 App COM: draft fingerprint, `OutlookMail.ObsoleteDraft.cs`, `OutlookAiMailbox` members, safety scan

Base: `dev` with M16.2 and M16.3 merged (both are). Runs **beside M16.5**;
the two briefs share no file (see "Parallel work").

## Goal

The COM half of the obsolete-draft feature. `CreateReplyDraft` reads the
saved draft's fingerprint right after `reply.Save()` and returns it
(`CreatedReply.Fingerprint` → `RepliedDraft.Fingerprint`, §23.4). A new
partial `OutlookMail.ObsoleteDraft.cs` holds `ReadDraftFingerprint` (the one
place the fingerprint is read), the read-only `ReadAiDraft` and the guarded
`MoveObsoleteAiDraft`, which opens the draft, reads `AiDraftInfo`, runs
`AiDraftGuard.Evaluate` and, **only** when that is `Movable`, moves the item
into the Deleted Items of the draft's own store, all in one COM work item
(§23.5). `OutlookAiMailbox` replaces the M16.3 placeholders with delegates.
The safety scan is rewritten so that exactly two Outlook `.Move(` calls
exist and the new file is pinned down (§23.10, §15). This is the code the
CLAUDE.md "Never delete email" exception describes; it must match it
exactly.

SPEC refs: §23.4 (COM read, creation), §23.5 (guard inputs, COM methods,
`Open` check), §23.10 (scan), §1 rule 4, §15, §19.5, §19.9, §19.12 (AI-file
scan, unchanged), §23.11 (Safety scan bullet; the live bullets are M16.8).

## Hard rules that apply here

- **Never send.** No `.Send(` anywhere (unchanged scan).
- **Never delete.** No `Delete(`, `PermanentDelete`, `EmptyDeletedItems` on
  any Outlook object. Deleted Items is never emptied.
- **Exactly one new `.Move(`**: `draft.Move(deletedItems)` in
  `OutlookMail.ObsoleteDraft.cs`, inside `MoveObsoleteAiDraft`, inside the
  block of `if (status == ObsoleteDraftStatus.Movable)`, after
  `var status = AiDraftGuard.Evaluate(...)` in the **same method** (same COM
  work item). `deletedItems` is the draft's **own store's** default Deleted
  Items (a shared mailbox's own Deleted Items), never the own mailbox's by
  default.
- The new file never sets a property, never saves, never closes, copies or
  displays an item (§23.10).
- **Never launch Outlook.** No new attach/launch code; everything runs on
  the existing `OutlookWorker`.
- `Re:: ` is untouched (the reply path keeps `ReplySubject.Normalize`).
- Logs: method names and outcomes/status names only. Never subjects,
  entry ids, addresses, bodies or fingerprints.
- `OutlookAiMailbox.cs` is an AI file (§19.12): no `.Move(`, `.Send(`,
  `.Display(`, `Delete(`. Calling `mail.MoveObsoleteAiDraft(` is fine (the
  scan's `\.\s*Move\s*\(` doesn't match `.MoveObsoleteAiDraft(`).

## Public API (all `internal`, App)

### `OutlookMail.ObsoleteDraft.cs` (new)

```csharp
using System.Runtime.InteropServices;
using ClippysRevenge.Core;
using Outlook = Microsoft.Office.Interop.Outlook;

namespace ClippysRevenge.App;

/// <summary>Clippy's own tracked AI drafts (SPEC 23.4, 23.5). Worker thread only. The one Move here puts an outdated,
/// unedited, unopened AI draft into its own store's Deleted Items, only when AiDraftGuard says Movable. Nothing here
/// sets a property, saves, closes or deletes.</summary>
internal sealed partial class OutlookMail
{
    /// <summary>SPEC 23.4: DraftFingerprint of Subject, To, CC, BCC, HTMLBody, Categories, (int)Importance and the
    /// attachment file names in position order. The one place it is read (at creation and at every check).</summary>
    /// <exception cref="ArgumentNullException">item is null.</exception>
    /// <exception cref="COMException">Any COM read failed (incl. Outlook gone).</exception>
    internal static string ReadDraftFingerprint(Outlook.MailItem item);

    /// <summary>ReadDraftFingerprint, or null when it threw anything other than an Outlook-gone COMException
    /// (which propagates). Used right after Save() in CreateReplyDraft: a failed read never fails the draft.</summary>
    internal static string? TryReadDraftFingerprint(Outlook.MailItem item);

    /// <summary>Read-only (SPEC 23.5). Null when the item can't be found (ItemNotFound) or isn't a MailItem.</summary>
    /// <exception cref="ArgumentNullException">app, mailbox or draftEntryId is null.</exception>
    /// <exception cref="COMException">A COM error other than "not found" (incl. Outlook gone); the caller decides.</exception>
    internal AiDraftInfo? ReadAiDraft(Outlook.Application app, string mailbox, string draftEntryId);

    /// <summary>One work item (SPEC 23.5): open, read AiDraftInfo, AiDraftGuard.Evaluate, and only when Movable
    /// draft.Move(deletedItems) into the draft's own store's Deleted Items. Gone gives (Gone, "").
    /// Deleted Items can't be opened gives (NoDeletedItems, subject), nothing moved. Moved on success.</summary>
    /// <exception cref="ArgumentNullException">Any argument is null.</exception>
    /// <exception cref="COMException">Any other COM error, incl. a failed Move (the caller treats it as "left").</exception>
    internal ObsoleteDraftMove MoveObsoleteAiDraft(Outlook.Application app, string mailbox, string draftEntryId,
        string expectedFingerprint);
}
```

## Behavior

### A. `ReadDraftFingerprint` (§23.4)

1. Read, in this order, with no `ComSafe.Try` (a failure must throw, never
   turn into a value): `item.Subject`, `item.To`, `item.CC`, `item.BCC`,
   `item.HTMLBody`, `item.Categories`, `(int)item.Importance`, then the
   attachment names: `atts = item.Attachments`, `for i in 1..atts.Count`
   `a = atts[i]`, `name = a.FileName`, `Release(a)` **inside the loop**
   (try/finally), `Release(atts)` at the end.
2. A null or empty `FileName` is recorded as `"?"` (Spec change 1: otherwise
   one unnamed attachment would hash like "no attachments", and an edited
   draft could look unedited).
3. Return `DraftFingerprint.Compute(new DraftFingerprintInput(subject, to,
   cc, bcc, html, categories, importance, names))`. No other normalization.
4. `TryReadDraftFingerprint`: `try { return ReadDraftFingerprint(item); }
   catch (Exception ex) when (!(ex is COMException c && ComErrors.IsOutlookGone(c))) { return null; }`.

### B. `CreateReplyDraft` (§23.4 "At creation")

Right after `reply.Save(); saved = true;` and before the existing
`try { return new CreatedReply(...) }`:

```csharp
var fingerprint = markerSet ? TryReadDraftFingerprint(reply) : null;
```

and pass `fingerprint` as the fifth argument. For every marker (`ai`,
`tool`): `null` only when the marker wasn't set or the read failed.
Nothing else in the method changes (subject, body, marker, the
`reply.Move(drafts)` for shared mailboxes, error mapping). An Outlook-gone
COMException from the read propagates exactly like one from the
`EntryID` read below it does today.

`OutlookReplyDraftWriter.ReplyAsync` returns
`new RepliedDraft(r.EntryId, r.Subject, r.Mailbox, r.Fingerprint)`.

### C. `OutlookMail.ObsoleteDraft.cs` (§23.5)

**C.1 `OpenDraft(app, mailbox, draftEntryId)` → `Outlook.MailItem?`**
- `storeId = StoreIdOf(_stores, app, mailbox)` (the existing private static
  helper in `OutlookMail.cs`; null when the mailbox is unknown).
- `ns = app.Session`; `obj = ns.GetItemFromID(draftEntryId, storeId ??
  (object)Type.Missing)`; release `ns` in `finally`.
- `COMException` with `ComErrors.IsItemNotFound(ex)` → `null`. Any other
  COMException (incl. Outlook gone) propagates.
- `obj` not an `Outlook.MailItem` → release it, `null`.

**C.2 `ReadDraftInfo(app, draft)` → `AiDraftInfo`** (never null; the item is open)
- `messageClass = draft.MessageClass`, `sent = draft.Sent`,
  `subject = draft.Subject ?? ""`, `entryId = draft.EntryID`.
- `marker = ReadMarker(draft)`: `PropertyAccessor.GetProperty(DraftMarker.PropertyName) as string`;
  a non-gone COMException (property missing) → `null`. Release the accessor.
- `inDrafts = IsInDrafts(draft)`: `parent = draft.Parent as Outlook.MAPIFolder`,
  `store = parent.Store`, `drafts = store.GetDefaultFolder(Outlook.OlDefaultFolders.olFolderDrafts)`,
  `string.Equals(parent.EntryID, drafts.EntryID, StringComparison.OrdinalIgnoreCase)`.
  Null parent, or a non-gone COMException / `UnauthorizedAccessException`
  anywhere → `false` (fail-safe: `NotInDrafts`, never moved). Release
  `drafts`, `store`, `parent`.
- `open = IsOpenInOutlook(app, entryId)` (C.3).
- `fingerprint = ReadDraftFingerprint(draft)` (throws on failure; C.4).
- `plainBody = draft.Body ?? ""`, cut to `AiDraftInfo.MaxPlainBodyChars`
  (20,000) with `[..20_000]` when longer. A non-gone COMException reading
  `Body` → `""`.
- `new AiDraftInfo(inDrafts, sent, marker, messageClass, open, fingerprint, subject, plainBody)`.

**C.3 `IsOpenInOutlook(app, entryId)` → `bool`** (§23.5 `Open`; fail-safe)
- `insps = app.Inspectors`; for `i in 1..insps.Count`: `insp = insps[i]`,
  `cur = insp.CurrentItem`; when `cur is Outlook.MailItem m` and
  `ComSafe.Try(() => m.EntryID)` equals `entryId` (OrdinalIgnoreCase) →
  open. Release `cur` and `insp` inside the loop (finally).
- `exps = app.Explorers`; for `i in 1..exps.Count`: `exp = exps[i]`,
  `inline = exp.ActiveInlineResponse` (may be null); same EntryID compare.
  Release `inline` and `exp` inside the loop.
- Release `insps`/`exps` in `finally`.
- A per-item `EntryID` that can't be read (`ComSafe.Try` → null/empty) is
  not a match (an unsaved compose item can't be the saved draft).
- Any other non-gone `COMException`, `UnauthorizedAccessException` or
  `InvalidCastException` while enumerating (`Count`, indexer,
  `CurrentItem`, `ActiveInlineResponse`) → return **true** ("that check
  failed" counts as `Open`, §23.5). An Outlook-gone COMException propagates.

**C.4 `ReadAiDraft(app, mailbox, id)`**
`draft = OpenDraft(...)`; null → null. Else `try { return
ReadDraftInfo(app, draft); } finally { Release(draft); }`. Exceptions from
`ReadDraftInfo` (e.g. the fingerprint read) propagate; M16.5 treats them
as "no change, try again next pass".

**C.5 `MoveObsoleteAiDraft(app, mailbox, id, expectedFingerprint)`** — the
shape is pinned (the scan checks it):

```csharp
internal ObsoleteDraftMove MoveObsoleteAiDraft(Outlook.Application app, string mailbox, string draftEntryId,
    string expectedFingerprint)
{
    ArgumentNullException.ThrowIfNull(app);
    ArgumentNullException.ThrowIfNull(mailbox);
    ArgumentNullException.ThrowIfNull(draftEntryId);
    ArgumentNullException.ThrowIfNull(expectedFingerprint);
    var draft = OpenDraft(app, mailbox, draftEntryId);
    if (draft is null) return new ObsoleteDraftMove(ObsoleteDraftStatus.Gone, "");
    Outlook.MAPIFolder? parent = null;
    Outlook.Store? store = null;
    Outlook.MAPIFolder? deletedItems = null;
    object? moved = null;
    try
    {
        var info = ReadDraftInfo(app, draft);
        var status = AiDraftGuard.Evaluate(info, expectedFingerprint);
        if (status == ObsoleteDraftStatus.Movable)
        {
            parent = (Outlook.MAPIFolder)draft.Parent;
            store = parent.Store;
            deletedItems = TryDeletedItems(store);     // null when it can't be opened
            if (deletedItems is null) return new ObsoleteDraftMove(ObsoleteDraftStatus.NoDeletedItems, info.Subject);
            moved = draft.Move(deletedItems);
            return new ObsoleteDraftMove(ObsoleteDraftStatus.Moved, info.Subject);
        }
        return new ObsoleteDraftMove(status, info.Subject);
    }
    finally
    {
        Release(moved);
        Release(deletedItems);
        Release(store);
        Release(parent);
        Release(draft);
    }
}
```

- `TryDeletedItems(store)` (private static, same file) is the **only**
  `olFolderDeletedItems` in the file:
  `try { return store.GetDefaultFolder(Outlook.OlDefaultFolders.olFolderDeletedItems); }`
  `catch (Exception ex) when (ex is UnauthorizedAccessException || (ex is COMException c && !ComErrors.IsOutlookGone(c))) { return null; }`.
- The store is the **draft's parent folder's** store (`parent.Store`), so a
  shared mailbox's draft goes to that mailbox's own Deleted Items.
- A COMException from `draft.Parent`, `parent.Store` or `draft.Move`
  propagates (→ M16.5 "left"). No retry, no fallback folder, no second
  Move.
- No variable named `status` is assigned anywhere else in the method.
- The method never assigns a property, never calls `Save`, `Close`,
  `Copy`, `Display`, `Send`, `Delete`, `PermanentDelete`.

### D. `OutlookAiMailbox` delegates (§23.5 "which only delegates")

```csharp
public async Task<AiDraftInfo?> ReadAiDraftAsync(string mailbox, string draftEntryId, WorkPriority priority, CancellationToken ct)
{
    ArgumentNullException.ThrowIfNull(mailbox);
    ArgumentException.ThrowIfNullOrEmpty(draftEntryId);
    await stores.EnsureResolvedAsync(priority, ct).ConfigureAwait(false);
    var info = await worker.RunAsync(app => mail.ReadAiDraft(app, mailbox, draftEntryId), priority, ct).ConfigureAwait(false);
    log?.LogDebug("AI mailbox: ReadAiDraft {Outcome}", info is null ? "gone" : "ok");
    return info;
}

public async Task<ObsoleteDraftMove> MoveObsoleteAiDraftAsync(string mailbox, string draftEntryId, string expectedFingerprint,
    WorkPriority priority, CancellationToken ct)
{
    ArgumentNullException.ThrowIfNull(mailbox);
    ArgumentException.ThrowIfNullOrEmpty(draftEntryId);
    ArgumentNullException.ThrowIfNull(expectedFingerprint);
    await stores.EnsureResolvedAsync(priority, ct).ConfigureAwait(false);
    var r = await worker.RunAsync(app => mail.MoveObsoleteAiDraft(app, mailbox, draftEntryId, expectedFingerprint), priority, ct)
        .ConfigureAwait(false);
    log?.LogDebug("AI mailbox: MoveObsoleteAiDraft {Status}", r.Status);
    return r;
}
```

No catch blocks: `OutlookUnavailableException` (from the worker) and other
exceptions pass through (§23.5). Logs never hold the id, subject or
fingerprint. The class XML summary changes "Reads only, plus showing the
Drafts folder" to "Reads only, plus showing the Drafts folder and moving an
outdated AI draft of Clippy's own into Deleted Items (SPEC 23.5)".

## Spec changes

Not applied by this brief (the caller asked for the brief only); to be
recorded in `SPEC.md` by the architect:

1. **§23.4**: in `ReadDraftFingerprint`, an attachment whose `FileName` is
   null or empty counts as `?` (else one unnamed attachment would hash
   like "no attachments"). No `ComSafe`: any COM read failure throws.
   At creation the read runs whenever the marker was set (any marker);
   `TryReadDraftFingerprint` turns any non-gone failure into null.
2. **§23.5**: `ReadAiDraft` returns null only for "item not found" or a
   non-MailItem; other COM errors throw (the worker retries next pass, it
   doesn't mark the draft `gone`). `InDrafts` compares the parent folder's
   `EntryID` with its store's default Drafts (case-insensitive); any
   failure → `false`. In the `Open` check, an item whose `EntryID` can't be
   read is not a match; a failure enumerating Inspectors/Explorers counts
   as `Open`. Deleted Items is `parent.Store`'s default folder;
   `GetDefaultFolder` failing (COM or access denied) → `NoDeletedItems`; a
   failing `Move` throws.
3. **§19.12 / §23.10**: the scan `OnlyMoveIsNewReplyDraftIntoDrafts` is
   renamed `OnlyTwoOutlookMoves`; the new-file rules also require
   `var status = AiDraftGuard.Evaluate(` with no other assignment to
   `status`, both the guard and the Move inside `MoveObsoleteAiDraft`, and
   `DraftFingerprint.Compute(` only in `OutlookMail.ObsoleteDraft.cs`.
4. **§3 layout**: add `OutlookMail.ObsoleteDraft.cs` (fingerprint read,
   `ReadAiDraft`, guarded `MoveObsoleteAiDraft`, §23.4, §23.5).
