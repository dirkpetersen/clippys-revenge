## Goal

with no COM and no worker logic: schema version 3 with the tables
`ai_drafts` and `ai_revisits` and the migration 2 → 3 (§9.1 "Schema

`DraftFingerprint` (§23.4) and the setting `AiDraftingSettings.ReviseDrafts`
(§19.2, default `true`, JSON only; the checkbox is M16.7).

SPEC refs: §9.1, §9.2 (AI drafting additions), §19.2 (`ReviseDrafts` row),
§23.2, §23.3, §23.4, §23.11 (Core bullets "`DraftFingerprint`" and

## Hard rules that apply here

- **Never delete email.** Everything here deletes only rows of Clippy's
  own SQLite catalogue (`ai_drafts`, `ai_revisits`, `ai_decisions`).
  Nothing touches Outlook.
- Neither new table holds mail text, subjects, addresses, prompts, model
  output or `reason` (§9.1). `fingerprint` is a SHA-256 hex string;
  `outcome`/`state` are fixed ids.
- `query_index` must not be able to read the new tables. Its authorizer
  already denies every real table it doesn't allow-list (§9.1), so no
  code change; tests prove it.
- `DraftFingerprint.cs` is an "AI file" for the safety scan (name starts
  with `Draft`): no `Outlook.`, `Marshal`, `MailItem`, `CreateReplyDraft`,
  `.Send(`, `.Display(`, `.Move(`, `Delete(` in its code.

## Behavior

### A. `DraftFingerprint` (§23.4)

1. `Canonical` is, in this order, for the names `subject`, `to`, `cc`,
   `bcc`, `html`, `categories`, `importance`, `attachments`, each
   `<name>=<len>:<value>\n`, where `<value>` is the field (null → `""`),
   `<len>` is `value.Length` (UTF-16 code units) in invariant decimal, and
   `\n` is U+000A. `importance` = `Importance.ToString(CultureInfo.InvariantCulture)`
   (so `-1` is `2:-1`). `attachments` = names joined with `"\n"`
   (null list → `""`, null entry → `""`).
2. No trimming, no case change, no line-ending change. Any change counts.
3. `Compute` = `Convert.ToHexStringLower(SHA256.HashData(Encoding.UTF8.GetBytes(Canonical(input))))`.
   `Encoding.UTF8` (no BOM is emitted by `GetBytes`). A lone surrogate is
   encoded as U+FFFD by `Encoding.UTF8`; that is fine (stable).

### B. Validation

1. `RecordAiDraft`: `draftEntryId`, `sourceEntryId` not null/blank;
   `DraftFingerprint.IsValid(fingerprint)`. Messages (param name in
   parentheses):
   - `AI draft: DraftEntryId is empty.` (`draftEntryId`)
   - `AI draft: SourceEntryId is empty.` (`sourceEntryId`)
   - `AI draft: the fingerprint must be 64 lower-case hex characters.` (`fingerprint`)
   Times are stored with `ToUnixTimeSeconds()`. No check that
   `checkedUpTo >= created` (callers pass the source's time, which is
   earlier).
2. The other methods: as in their `<exception>` docs; `ArgumentException.ThrowIfNullOrEmpty`
   for ids, `ArgumentOutOfRangeException` (`Enum.IsDefined`) for enums.
3. All stored strings are ids or fixed values; nothing from mail.

### C. `DueRevisits(createdSince, max)` (§23.2, index part)

1. Tracked = `ai_drafts` rows with `state = 'open'` and `created >=
   createdSince`, joined to `emails e ON e.entry_id = d.source_entry_id`
   (exact) with `e.conversation_topic IS NOT NULL`. A draft whose source
   row is missing or has no topic never appears.
2. **Newest per thread:** among tracked rows, per topic (`COLLATE NOCASE`)
   keep only the one with the greatest `created` (tie: greatest
   `draft_entry_id`, ordinal). Older open drafts of the same topic are
   never returned, even when they alone would be due (§23.2 "Only the
   newest `open` draft of a thread is revisited").
3. **Due:** the kept row is returned when at least one `emails` row of
   that topic (`COLLATE NOCASE`) is in Inbox or under it and has
   `event_time > checked`. `UpTo` = the greatest such `event_time`. Any
   sender and any addressing count (incl. the user's own address; M16.5
   decides "user replied").
4. Order: `UpTo DESC`, then `created DESC`, then `draft_entry_id DESC`.
   `LIMIT max`.
5. Inbox filter (one private constant in `EmailIndex.Revisit.cs`, used by
   `DueRevisits` and `ThreadInbox`), mirroring `SentItemsFilter`:
   `(m.folder = 'Inbox' COLLATE NOCASE OR m.folder LIKE 'Inbox\%')`
   (one literal backslash; `LIKE` is ASCII case-insensitive). Stored
   folders are canonical (`Inbox\Sub`), so this equals
   `FolderPaths.IsUnderInbox`. `InboxOld` or `Inboxes` don't match.
6. A sketch (the coder may write it differently; window functions are
   available in the bundled SQLite):
   ```sql
   SELECT * FROM (
     SELECT t.*, (SELECT MAX(m.event_time) FROM emails m
                  WHERE m.conversation_topic = t.topic COLLATE NOCASE AND <inbox filter on m>
                    AND m.event_time > t.checked) AS up_to
     FROM (SELECT d.*, e.conversation_topic AS topic, e.internet_message_id AS imid, e.event_time AS source_time,
                  ROW_NUMBER() OVER (PARTITION BY e.conversation_topic COLLATE NOCASE
                                     ORDER BY d.created DESC, d.draft_entry_id DESC) AS rn
           FROM ai_drafts d JOIN emails e ON e.entry_id = d.source_entry_id
           WHERE d.state = 'open' AND d.created >= @since AND e.conversation_topic IS NOT NULL) t
     WHERE t.rn = 1)
   WHERE up_to IS NOT NULL
   ORDER BY up_to DESC, created DESC, draft_entry_id DESC LIMIT @max
   ```
7. `AiDraftThread.ConversationTopic` is the source row's stored topic
   (already trimmed by `UpsertBatch`).

### D. `ThreadInbox`, `OpenAiDraftForThread`, `SetAiDraftState`, `AddRevisit`

- `ThreadInbox` selects the same columns as `DraftCandidates` and maps
  them to `DraftCandidate` the same way (reuse the existing private
  `CandidateRow`). No join with `ai_decisions`.
- `OpenAiDraftForThread`: `before` compares with the **source** row's
  `event_time` (strictly earlier). `state = 'open'` only.
- `SetAiDraftState` SQL: `UPDATE ai_drafts SET state = @s, attempts = @a,
  updated = @now, checked = CASE WHEN @c IS NULL THEN checked ELSE
  MAX(checked, @c) END WHERE draft_entry_id = @id AND state = 'open'`.
  Setting `Open` on an open row is allowed (keep: new `checked`,
  `attempts = 0`; failed attempt: `attempts + 1`). A row in any final
  state is never changed, so a later call can't "reopen" it.
- `AddRevisit` inserts `(draft_entry_id, decided, outcome, model_calls)`;
  `id` is the SQLite rowid. No check that the draft row exists (the
  draft row may be purged first; the call still counts).
- `GetAiDraft` reads `state` through `AiDraftStates.FromDb`.

### E. Schema 3 and the migration (§9.1, §23.3)

1. `Step3Ddl` (exactly the §23.3 tables, with `IF NOT EXISTS`):
   ```sql
   CREATE TABLE IF NOT EXISTS ai_drafts (
     draft_entry_id TEXT PRIMARY KEY,
     source_entry_id TEXT NOT NULL,
     created INTEGER NOT NULL,
     fingerprint TEXT NOT NULL,
     checked INTEGER NOT NULL,
     state TEXT NOT NULL,
     attempts INTEGER NOT NULL DEFAULT 0,
     updated INTEGER NOT NULL);
   CREATE INDEX IF NOT EXISTS ix_ai_drafts_state ON ai_drafts(state, created);
   CREATE TABLE IF NOT EXISTS ai_revisits (
     id INTEGER PRIMARY KEY,
     draft_entry_id TEXT NOT NULL,
     decided INTEGER NOT NULL,
     outcome TEXT NOT NULL,
     model_calls INTEGER NOT NULL);
   CREATE INDEX IF NOT EXISTS ix_ai_revisits_decided ON ai_revisits(decided);
   ```
2. Step 3 runs inside the existing single migration transaction (a
   version-1 file goes 1 → 2 → 3 in one transaction). The test seam
   `afterMigrationStep(3)` exists automatically.
3. `meta.thread_meta_complete` handling is unchanged (set only for a new
   file, `current == 0`). A 2 → 3 migration doesn't touch `emails`,
   `ai_decisions`, `meta` (other than `schema_version`) or `sync_state`.
4. A version-3 file opened by a version-2 app is refused by the existing
   rule (no code here). This app refuses version 4+ with the existing
   message (`… supports up to 3. …`).
5. `PurgeOlderThan` (which already purges `ai_decisions` with
   `DateTimeOffset.UtcNow - DecisionRetention`) also deletes `ai_drafts`
   with `updated` and `ai_revisits` with `decided` older than the same
   time, in the same transaction; its return value stays the number of
   **emails** removed. (Spec change 3.)

### F. `ModelCallsSince` and `PurgeDecisions`

- `ModelCallsSince(t)`: one query,
  `SELECT (SELECT COALESCE(SUM(model_calls),0) FROM ai_decisions WHERE decided >= @s) + (SELECT COALESCE(SUM(model_calls),0) FROM ai_revisits WHERE decided >= @s)`.
  A revisit call made yesterday doesn't count today (its row's `decided`
  is yesterday). `DraftsCreatedSince` unchanged (revisit replacements
  record a `drafted` `ai_decisions` row in M16.5 and count there).
- `PurgeDecisions(now)`: cutoff `now - DecisionRetention`, strict `<`
  (a row exactly 30 days old stays, as today), three `DELETE`s in one
  transaction, returns their sum.

### G. `ReviseDrafts`

Plain JSON property; `Settings.Clone()`/`CopyFrom` copy it (they are
JSON round-trips). Nothing reads it in M16.2.

## Spec changes

Not applied by this brief (the caller asked for the brief only); to be
recorded in `SPEC.md` by the architect:

1. **§23.3 API** (exact semantics): `DueRevisits` keeps, per topic
   (`COLLATE NOCASE`), only the newest open draft (`created`, tie
   `draft_entry_id`) among drafts with `created >= createdSince`, and
   returns it when an Inbox-or-under row of the topic is newer than its
   `checked`; `UpTo` is the newest such row; order `UpTo DESC`; `max ≤
   100`. `OpenAiDraftForThread(topic, before)` compares `before` with the
   source row's time (strictly earlier), newest `created` wins, no age
   limit. Return types `AiDraftRecord`, `AiDraftThread`, `DueRevisit`;
   enums `AiDraftState`/`AiRevisitOutcome` with `ToDb`/`FromDb` (an
   unknown stored state reads as `left`, final).
2. **§23.3** "States other than `open` are final" is enforced in SQL:
   `SetAiDraftState` changes only `open` rows and returns whether it did;
   `checked` never moves backwards (`MAX`). `RecordAiDraft` overwrites a
   row with the same `draft_entry_id` and validates the fingerprint
   (`DraftFingerprint.IsValid`, messages starting `AI draft: `).
3. **§23.3 purge**: `PurgeDecisions(now)` returns the total rows deleted
   from the three tables; `PurgeOlderThan` (which already purges
   `ai_decisions`) also purges the two new tables with the same 30-day
   cutoff; its return value stays the email count.
4. **§23.4**: `DraftFingerprintInput(Subject, To, Cc, Bcc, HtmlBody,
   Categories, Importance, AttachmentNames)`; `importance` is the
   invariant decimal integer; a null attachment list and an empty one
   hash the same; `DraftFingerprint.IsValid`; test vectors as in this
   brief.
5. **§3 layout**: add `EmailIndex.Revisit.cs` (ai_drafts/ai_revisits API,
