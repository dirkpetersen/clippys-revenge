Base: `dev` at or after `da4ddee` (M19.7 merged: `OutlookMail.ReadAttachmentForAi`,
`AiFiles`/`AiFilePaths`, `OutlookAttachmentSource`, `OneDriveRegistry`,
`Program` wiring; M19.6 `DraftWorkerServices.Attachments`; M19.1

Tests and the live-test script only: **no `src/` change**. Parallel work:
an M20.1 coder (schema 5, `EmailIndex*`, `DraftWorker*`, `EditLearning*`,
`Settings*`, their tests) and an M19.9 docs writer (`manual/`, `README.md`).
This brief touches none of their files. Don't bump `<Version>` (release

## Goal

Prove §26 end to end against the user's real classic Outlook and real
Claude CLI (§26.12 "Live"), and close M19.1's live check (§19.13): a
synthetic email with a PDF and a `.docx` that each hold a unique fact gives
a manual AI draft that quotes both facts, through the production
`OutlookAttachmentSource` → `ReadAttachmentForAi` → `AiFiles` path, and the
private `ai-files` folder is empty afterwards; an unsynced `/:w:/s/`
SharePoint link in the same email gives the yellow
`Couldn't read the shared file … (not synced to this PC).` note; with a
synced business OneDrive, links to two files the test places there
(direct form and `/:x:/r/` form) are read from disk and used; and the
Outlook questions of §26.3/§26.9 are recorded (printed, not asserted):
cloud-attachment `Type`/`PR_ATTACH_METHOD`/`Size`/URL properties,
`OpenSharedItem` on an attached email without UI, the consumer OneDrive
registry layout. One CLI call's `usage` has numeric `input_tokens` and
`output_tokens` and writes an `ai_calls` row. Nothing is sent; only items
and files the test created are deleted.

SPEC refs: §26.12 (Live), §26.1–§26.3 (sources, sender and host rule,
mapping, sync data), §26.6 (block), §26.7 (notes), §26.8 (event suffix,
privacy), §26.9 (COM side, `ai-files`), §26.10, §26.11 (safety),
§19.13 (usage, `ai_calls`), §19.12 (live Claude: Haiku, effort low),
§15 (live tests), CLAUDE.md "Live Outlook tests" and hard rules.

## Hard rules that apply here

- **Never send anything.** No `.Send(`, `.Display(`, `.Activate(`,
  `.Move(`, `SendAndReceive`, `GetInspector` in any new live file (the
  existing `LiveSafetyScanTests` facts scan every `Live/*.cs`). Synthetic
  emails are **unsent, self-addressed drafts** made by `CreateDraftTool`
  (no signature), as in `LiveAiDraftTests`. `WithCleanupAsync` asserts Sent
  Items and Outbox are unchanged.
- **Delete only what the test created.** Outlook items only through
  `scope.Track(...)` + the fixture's token-checked delete (reply drafts are
  tagged with `LiveDrafts.ReadDraft(..., tag: true)` at once). Files: only
  the exact paths the test wrote (see D.3); never a recursive delete in the
  synced folder.
- **Never launch Outlook** (attach-only fixture, unchanged).
- **Synthetic content only.** Addresses `@example.org`; the unsynced link
  uses the documentation tenant `contoso.sharepoint.com` (never fetched:
  Clippy makes no network request for links, §26.3); facts are random per
  run. The user's real files are never opened: the only real-file access
  is `OneDriveRegistry.Read()` (registry + `Directory.Exists` of mounts) and
  the files the test itself writes in one synced folder. The optional real
  cloud-attachment probe (E.2) reads attachment metadata of one email the
  user prepared and named by an env var, and prints no URL, path or name.
- **Opt-in.** Claude tests: `[Trait("live","outlook")]` +
  `[Trait("live","claude")]` + `[Trait("os","windows")]`, gate
  `LiveClaude.RequireEnabled()` (`CLIPPY_LIVE=1` and `CLIPPY_LIVE_CLAUDE=1`),
  model Haiku/effort low via `LiveClaude.Settings`. Outlook-only probes:
  `[Trait("live","outlook")]` + `[Trait("os","windows")]`, gate
  `fx.RequireReadyAsync`. CI's filter `live!=outlook&live!=claude` excludes
  them all.
- **Nothing private in output.** `fx.Result` lines, skip and assertion
  messages hold no mail text, prompt, model output, URL, local path, tenant
  name or file name from the user's machine (synthetic names and the
  `contoso` host are fine). Use `Assert.True(cond, "fixed text")`.
- Never point at the user's real `%LOCALAPPDATA%\ClippysRevenge\ai-files\`
  or the running app: the tests use their own `AiFiles` under
  `fx.TempRoot` (pinned by a scan, F).

## Behavior

### A. Shared wiring

1. **Settings.** `ai = LiveClaude.Settings(model, DateTimeOffset.UtcNow)`;
   `ai.MeetingTimes = false`; `ai.ReadAttachments = true` (explicit);
   `s = fx.Settings.Clone(); s.AiDrafting = ai`. `RecordConsent` already set
   `AttachmentsNoticeShown`, so no notice fires. The fixture's `Settings`
   is never changed.
2. **Attachment pipeline** (all production code):
   ```csharp
   var log = new LiveCapturingLogger();
   var aiFiles = LiveAttachmentContent.NewAiFiles(fx, log);
   var registry = new OneDriveRegistry(log);
   var source = new OutlookAttachmentSource(fx.Worker, fx.Mail, fx.Stores, aiFiles, registry);
   var collect = new DraftAttachments(source, TimeProvider.System, log);
   ```
   A `FileSystemWatcher` on `aiFiles.Folder` (`Created`, no subdirectories)
   records created file names for the run of the step; every recorded name
   must satisfy `AiFilePaths.IsTempFileName` ("A temp file in ai-files
   has an unexpected name."). The count is printed, not asserted (watcher
   events can coalesce).
3. **Model with usage recording:** `cli = LiveClaude.CreateModel(() => s.AiDrafting, Path.Combine(fx.TempRoot, "ai-attach"))`;
   `await LiveClaude.RequireReadyAsync(cli, ct)`;
   `guard = new GuardedModel(cli, model, fx.RunToken, meetingNote: false, extraCheck: …)`;
   `usage = new AiUsage(() => fx.Indexes.For(""), TimeZoneInfo.Local); usage.Load();`
   `recording = new UsageRecordingModel(guard, () => s.AiDrafting, usage, log)`.
   `DraftWorker` gets `recording` as its model (production order:
   recording outside, the guard plays the CLI's role).
4. **Mailbox:** `identity = await new OutlookAiMailbox(fx.Worker, fx.Mail, fx.Stores).GetIdentityAsync(WorkPriority.Interactive, ct)`;
   `filling = new SenderFillingMailbox(new OutlookAiMailbox(fx.Worker, fx.Mail, fx.Stores), src.Id, identity.OwnSmtp)`;
   `aiMailbox = new FixedSelectionMailbox(filling, new SelectedEmail(src.Id, ownStore))`.
   Reason: an unsent draft may have no sender SMTP, and the §26.3 sender
   rule would then (correctly) refuse its links with
   `from outside your organization`. The test simulates "an email from me"
   only for that one item and only when Outlook gave no SMTP; the result
   line records `sender=outlook` or `sender=filled`. Before any Claude call,
   assert `DraftAttachmentPlan.MayOpenShared(<the sender the pipeline will see>, identity, "")`
   ("The synthetic email's sender isn't the own address, so its links would be refused.").
5. **Worker:**
   ```csharp
   using var hub = new ActivityHub();
   using var drafts = new DraftWorker(new DraftWorkerServices(() => s, fx.Indexes, aiMailbox, writer, recording,
       NoStyleGuide.Instance, () => null, hub, new BalloonCenter(),
       () => fx.Worker.State == OutlookConnectionState.Available, () => false, TimeZoneInfo.Local,
       Logger: log, Attachments: collect));
   ```
   `writer` is `RecordingReplyWriter` over `OutlookReplyDraftWriter`
   tracking and tagging the reply exactly as `LiveAiDraftTests` does.
6. **Guard extra check.** `extraCheck` returns a fixed reason (never
   request text) or null. It runs before the CLI, so a broken extraction
   fails the test without spending a call. B and C list their checks.
7. **Outcome handling** (as `LiveAiDraftTests` 4.6): `guard.Tripped` →
   `Assert.Fail("The live guard refused the Claude request (<reason>). Nothing was sent to Claude.")`;
   `RateLimited` → skip `LiveClaude.UsageLimit`; "Claude isn't ready: "
   message → skip `LiveClaude.NotReady(...)`; else
   `Assert.True(result.Drafted, "Manual draft failed: " + result.Message)`.
8. **Baseline** (as `LiveAiDraftTests` 4.2): `LiveDrafts.TryOwnReply` on the
   source before any Claude call; null → result line + skip
   ("Outlook can't reply to an unsent test item on this profile, so the attachment draft test can't run here. Nothing was sent.").

### D. Synced folder rules (`OwnBusinessRoot`, `SyncedTestFolder`)

1. `OwnBusinessRoot`: the first root with `IsFolderScope == false`, a
   `UrlPrefix` host ending in `-my.sharepoint.com` (case-insensitive) and
   a prefix path whose first segment is `personal`. Team sites, shortcuts
   and folder scopes are never written to (others would see the file);
   `d.docs.live.net` (consumer) isn't used either.
2. `SyncedTestFolder` constructor: `Folder = Path.Combine(root.MountPoint, runToken)`;

Not applied by this brief (the caller asked for the brief file only); to

   lack a sender SMTP; the live tests then give the pipeline the

   `IAiMailbox.ReadEmailAsync`) and record `sender=filled`. The sender
   rule itself is unchanged and covered by Core tests.

   fetched).

   root (`-my.sharepoint.com/personal/…`, not a team site, shortcut or
   folder scope) in `<MountPoint>\<RunToken>`, created with
   `FileMode.CreateNew`, and deleted file by file, then the folder
   non-recursively; no business OneDrive → skip with a printed reason.
   They end up in the user's OneDrive recycle bin.
5. **Attached email** is the test's own inner draft attached as
   `olEmbeddeditem` to its own outer draft; "without UI" = the
   `Inspectors` count is unchanged.
