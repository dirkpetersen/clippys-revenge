# M15.4 Tray **Draft invites (n)** submenu: list, Interactive check on menu open, click opens the meeting

Base: `dev` after M15.2 (`docs/briefs/M15.2.md`). This brief is written
against M15.2's API: `DraftInvites.Pending`, `Count`, `Changed`,
`Forget(entryId)`, `CheckAsync(WorkPriority, ct)`, `DraftInviteEntry`,
`PendingDraftInvite`, `DraftInviteDetails`, `ComErrors.IsItemNotFound`,
and the private helpers of `OutlookCalendar.CheckDraftInvites`
(shared-calendar open, Deleted Items test). If M15.2 landed with different
names, adapt the names, not the behavior. M15.5 (badge) runs in parallel
and also edits `TrayApp.cs`, `TrayServices` and `Program.cs`; keep the
M15.4 edits to `TrayApp.cs` to the few lines listed in Behavior §D so the
merge is mechanical (all other tray code goes into a new partial file).

## Goal

The tray menu gets a **Draft invites (n)** submenu listing the meetings
Clippy saved unsent and still tracks. It shows the last known list the
moment the menu opens and starts an `Interactive` check that refreshes it
when done. Lines are sorted by start and read
`<ddd M/d> <HH:mm–HH:mm>  <subject cut to 40 chars>` (plus
` (<mailbox display name>)` for shared calendars). Clicking a line opens
that meeting's window in Outlook (`.Display()`, non-modal, on the COM
worker at `Interactive` priority) so the user can add the Teams/Zoom link
and send it. This is the only `.Display(` in the codebase. A meeting that
is gone is dropped from tracking with the balloon
`That draft invite is no longer in your calendar.` While Outlook isn't
running the lines come from the last check, are disabled, and a last
disabled line reads `Start Outlook to open them`. The item is hidden when
nothing is tracked.

SPEC refs: §22.3 (When: menu-open check; Tray item: all of it), §22.6
(Click bullet), §6.2 (menu layout: `Draft invites (2) ▸` after **AI
drafts**, hidden when none), §6.5 (click feedback is not rate-limited),
§22.7 (safety-scan bullet for `.Display(`), §4 (UI thread never waits for
COM; Start Outlook is the only launch).

## Hard rules that apply here

- **Never send anything.** No `.Send(`. Opening the window is all Clippy
  does; the user sends.
- **Never delete or move; no writes.** `OpenDraftInvite` reads and calls
  `Display(false)` (and `Activate()` on the inspector). No property
  assignment, no `Save`, `Close`, `Move`, `Delete`. `Forget` only edits
  Clippy's own `draft-invites.json`.
- **Never launch Outlook.** `.Display()` runs on `OutlookWorker` against the
  attached instance; the lines are disabled unless the worker state is
  `Available`, and a click that races an Outlook exit fails with
  `OutlookUnavailableException` (nothing is started).
- **The one `.Display(`** lives in `src/ClippysRevenge.App/OutlookCalendar.OpenInvite.cs`,
  exactly once. The AI files still have none.
- Logs carry no subjects, entry ids, store ids or mailbox addresses
  (outcome and exception **type** only). Balloons carry no subject.
- The UI thread never waits for COM.

## Behavior

### §A `DraftInviteMenu.Build(pending, state, shared, timeZone)`

1. Null checks (`ArgumentNullException`). Null elements of `pending` are
   skipped.
2. `Visible = count > 0` where count = number of non-null `pending`
   entries; `Header = Header(count)` (also when 0: `Draft invites (0)`, unused).
3. **Sort** (stable): entries with `Details` by `Details.Start` ascending,
   then by `Details.End`; then entries without `Details` by
   `Entry.CreatedUtc` ascending. Ties keep the input order. (M15.2's
   `Pending` already sorts this way; sorting again keeps the model correct
   on its own.)
4. **Lines**: the first `MaxLines` (15) entries become lines
   `new DraftInviteMenuLine(label, MenuText(label), p.Entry)`. When more
   than 15, one more line `More(count - 15)` with `Entry = null` (always
   disabled in the App). With exactly 15, no "more" line.
5. **Label** (`Label(p, shared, timeZone)`):
   - With `Details`: `InviteTexts.When(d.Start, d.End) + "  " + subject`
     (two spaces, as in §6.2), where `subject = Clean(d.Subject)`;
     empty → `NoSubject`; then `TrayText.Truncate(subject, MaxSubjectLength)`
     (so at most 40 characters, the 40th being `…` when cut).
   - Without `Details` (after a restart, before the first check):
     `"Draft invite saved " + <ddd M/d HH:mm>` of
     `TimeZoneInfo.ConvertTime(p.Entry.CreatedUtc, timeZone)`, invariant
     culture (e.g. `Draft invite saved Sat 11/14 10:00`).
   - Mailbox suffix when `p.Entry.Mailbox` is not blank:
     ` (<name>)`, `name = Clean(FindShared(mailbox)?.DisplayName)`; blank
     → the mailbox SMTP; then `TrayText.Truncate(name, MaxMailboxNameLength)`.
     `FindShared` compares `MailboxIndexes.Normalize(m.Smtp)` with the
     entry's mailbox (`OrdinalIgnoreCase`), skipping null elements.
     Own-calendar entries (`""`) get no suffix.
   - A multi-day meeting still uses `InviteTexts.When` (end time only,
     no end date), as everywhere else in Clippy.
6. **State**:

   | `state` | `LinesEnabled` | `StartOutlookHint` |
   |---|---|---|
   | `Available` | true | false |
   | `Unavailable` | false | true |
   | `NotResponding` | false | false |
   | `Unknown` | false | false |

   (`Unavailable` is exactly when **Start Outlook** is visible, §6.2; while
   not responding the status line already says so and a click would only
   time out.)
7. `Clean`: null → `""`; every `char.IsControl` → space; runs of
   `char.IsWhiteSpace` → one space; trim.
8. `MenuText`: `label.Replace("&", "&&")`. Without it `R&D` shows as `RD`
   with an underlined `D`.

### §B `DraftInviteClick.OpenAsync(window, entry, forget, log, ct)`

| What happens | Return | Side effect | Log (no ids, no subject) |
|---|---|---|---|
| `Opened` | `null` | none | Debug `Draft invite opened.` |
| `Gone` | `GoneText` | `forget(entry.EntryId)` (its return value is ignored; an exception from it is caught, Warning type only) | Information `Draft invite is gone; no longer tracked.` |
| `OutlookNotRespondingException` | `BalloonTexts.OutlookNotResponding` | none | Information `Opening a draft invite failed: Outlook is not available.` |
| other `OutlookUnavailableException` | `BalloonTexts.OutlookUnavailable` | none | same |
| `OperationCanceledException` | `null` | none | none |
| any other exception | `OpenFailedText` | none (stays tracked) | Warning `Opening a draft invite failed ({Type}).` |

Check `OutlookNotRespondingException` before its base class.

### §C `OutlookCalendar.OpenDraftInvite(app, entryId, storeId, mailbox, log)` (App, worker thread)

All COM objects released in `finally` (the `Release(object?)` style with
the `Marshal.IsComObject` guard, as in M15.2).

1. Blank `entryId` → `ArgumentException`.
2. `ns = app.Session`.
3. `mailbox` not blank: `folder = OpenSharedCalendar(ns, mailbox)` (makes
   sure the shared store is open after an Outlook restart, as the check
   does). If `storeId` is blank use `folder.StoreID`. Exceptions
   propagate (a missing delegate right becomes the `OpenFailedText`
   balloon; the entry stays tracked, the next check decides).
4. `obj = ns.GetItemFromID(entryId, storeId.Length > 0 ? storeId : Type.Missing)`.
   `ComErrors.IsItemNotFound(ex)` → return `Gone`. Other exceptions
   propagate.
5. `obj` is not an `Outlook.AppointmentItem` → release, return `Gone`.
6. `IsInDeletedItems(item)` → return `Gone` (same rule as the check:
   deleted → dropped).
7. `item.Display(false);` (non-modal; if the meeting is already open in an
   Inspector, Outlook brings that window forward instead of opening a
   second one). Then bring it to the front:
   `insp = item.GetInspector; insp.Activate();` inside
   `try { … } catch (COMException ex) when (!ComErrors.IsOutlookGone(ex)) { }`;
   release `insp`.
8. Return `Opened`. Debug log `OpenDraftInvite: {Outcome}`.

Nothing is assigned on the item and no other method is called on it
(no `Save`, `Close`, `Send`, `Move`, `Delete`). The item stays open in the
Inspector; M15.2's check skips category removal while it is open there,
which is what we want while the user edits it.

#### §D.2 State (fields in the new partial file)

```csharp
private readonly ToolStripMenuItem _invites = new("Draft invites") { Visible = false };
private int _invitesQueued;      // coalesced Changed → UI post (Interlocked)
private int _invitesChecking;    // one menu-open check in flight (Interlocked)
private readonly HashSet<string> _invitesOpening = new(StringComparer.OrdinalIgnoreCase); // UI thread only
```

#### §D.3 Fill (`FillDraftInvites()`, UI thread)

- `d = _s.DraftInvites`; null → `_invites.Visible = false`, return.
- `model = DraftInviteMenu.Build(d.Invites.Pending, d.State(), _s.GetSettings().SharedMailboxes, d.TimeZone)`.
- `_invites.Visible = model.Visible`; `_invites.Text = DraftInviteMenu.MenuText(model.Header)`.
- `_invites.DropDownItems.Clear()`, then per line:
  `new ToolStripMenuItem(line.Text) { Enabled = line.Entry is not null && model.LinesEnabled && !_invitesOpening.Contains(line.Entry.EntryId) }`;
  meeting lines get `Click += (_, _) => OpenDraftInvite(entry)` with the
  captured `DraftInviteEntry` (never the menu item). When
  `model.StartOutlookHint`: a last line
  `new ToolStripMenuItem(DraftInviteMenu.StartOutlookHintText) { Enabled = false }`.
- Clearing does not dispose the old items; dispose them
  (`foreach … item.Dispose()` on a copied list) after `Clear()` to avoid
  leaking handles over many refreshes.
- Called: from `AttachDraftInvites()` once, from
  `OnMenuOpeningDraftInvites()`, from the coalesced `Changed` post, and
  after a click finishes. Always fill (whether or not the dropdown is
  open): it's cheap, and the menu is right the next time it opens. When
  the list becomes empty while the menu is open, the item hides
  (its dropdown closes with it).

#### §D.4 Menu open (`OnMenuOpeningDraftInvites()`)

1. `FillDraftInvites()` at once from `Pending` (the last known list, also
   while Outlook is down).
2. If `_s.DraftInvites` is not null, `d.State() == Available`, and
   `Interlocked.Exchange(ref _invitesChecking, 1) == 0`:
   `_ = CheckDraftInvitesAsync(d)`.
3. `CheckDraftInvitesAsync`: `using var cts = new CancellationTokenSource(ListTimeout);`
   `await d.Invites.CheckAsync(WorkPriority.Interactive, cts.Token).ConfigureAwait(false);`
   catch everything (`OperationCanceledException` = slow Outlook; others
   can't happen per M15.2 but must not escape); `finally` reset
   `_invitesChecking`. The result is not used directly: when the check
   changed anything, M15.2 raises `Changed`, which refills (§D.5). The
   timeout only stops this wait; M15.2's shared check keeps running.

#### §D.5 `Changed` → UI thread

`AttachDraftInvites()`: `d.Invites.Changed += OnDraftInvitesChanged;` then
`FillDraftInvites()`. `OnDraftInvitesChanged` runs on any thread and does
only: `if (Interlocked.Exchange(ref _invitesQueued, 1) == 0) PostToUi(() => { Interlocked.Exchange(ref _invitesQueued, 0); FillDraftInvites(); });`.
`DetachDraftInvites()`: `d.Invites.Changed -= OnDraftInvitesChanged;`
(`PostToUi` already drops work after `_disposed`).

#### §D.6 Click (`async void OpenDraftInvite(DraftInviteEntry entry)`, UI thread)

1. `d = _s.DraftInvites`; null → return. If
   `!_invitesOpening.Add(entry.EntryId)` → return (a second click on the
   same line while it is opening does nothing; other lines may open at the
   same time, the worker runs them in order).
2. `AllowForeground()`: `AllowSetForegroundWindow(ASFW_ANY)` (user32,
   `[DllImport("user32.dll", ExactSpelling = true)] [DefaultDllImportSearchPaths(DllImportSearchPath.System32)] private static extern bool AllowSetForegroundWindow(int processId);`,
   `ASFW_ANY = -1`, return value ignored). The tray owns the foreground
   right after a menu click; this lets Outlook's `Activate()` bring the
   meeting window to the front instead of only flashing the taskbar.
3. `text = await DraftInviteClick.OpenAsync(d.Window, entry, d.Invites.Forget, log: null, CancellationToken.None);`
   The worker's own Interactive timeout bounds the wait. The UI thread
   continues while it runs (async, no `.Result`). Logging happens in
   `DraftInviteClick` only if a logger is passed; pass the one from
   `DraftInviteTrayServices` if you add it, else null (no new tray
   logger needed).
4. After the await (back on the UI thread, WinForms context):
   `_invitesOpening.Remove(entry.EntryId)`; if `_disposed` return;
   `text` not null → `_s.Balloons.PostUserFeedback(text)`;
   `FillDraftInvites()` (re-enables the line; a `Gone` already raised
   `Changed`).
5. Wrap 3–4 in `try/finally` so the opening set is cleaned up even on an
   unexpected exception; `DraftInviteClick` never throws, but `async void`
   must not crash the tray: catch-all → `PostUserFeedback(DraftInviteMenu.OpenFailedText)`.
