# M16.6 Rescan in Core (`DraftWorker.Rescan.cs`)

Base: `dev` with M16.1–M16.5 merged (all are). Runs **beside M16.8** (live
tests); the two briefs share no file (see "Parallel work"). Everything here
is Core and is tested with fakes only.

## Goal

Add the manual **Rescan emails from the last 24 hours** engine to
`DraftWorker` (§23.8): `PlanRescan()` (index only, the count for the
confirmation dialog), `RescanAsync(ct)` (oldest first over own + AI-enabled
shared Inbox rows of the last 24 hours, ignoring `EnabledAtUtc`, `MaxAgeDays`
and "decided once"; a `drafted` row is skipped; a later message in a thread
with an open tracked AI draft is a §23.6 revisit with `upTo` = that email;
everything else runs the §19.7 candidate steps), the stops (daily limit,
rate limit, not signed in, Outlook gone, 3 failed calls in a row, cancel),
single flight on the drafting gate, `CancelRescan()`, progress, the summary
`Ai` event and the log line. M16.7 builds the tray item and dialogs on top
of this API and shows the balloon from `RescanResult`.

SPEC refs: §23.8 (all bullets), §23.1 (`ReviseDrafts` off = `draft_exists`),
§23.2/§23.6 (revisit reused, `Interactive` inside a rescan), §19.7 (candidate
steps, manual path's gate/yield, hold), §19.11 (logs), §23.11 (Core bullet
"Rescan with fakes"). Texts already exist in `RescanTexts` (M16.3).

## Hard rules that apply here

- **Never send, never delete.** The rescan only reaches Outlook through
  `IAiMailbox` reads, `IReplyDraftWriter` (save-only, marker `ai`,
  `Re:: ` via `ReplySubject.Normalize` in the writer) and
  `MoveObsoleteAiDraftAsync` (inside the reused `RevisitAsync`, new draft
  first). No other Outlook write.
- **AI files** (§19.12): `DraftWorker.Rescan.cs` matches the AI-file scan
  (name starts with `Draft`): no `.Send(`, `.Display(`, `.Move(`,
  `Delete(`, no COM types. (`CancellationTokenSource.Cancel()` is fine.)
- **Model output is untrusted**: only the existing parsers are used.
- **Logs** (§19.11): no subjects, entry ids, addresses, prompts, model
  output or `reason`. Warnings carry the exception type (and HResult) only.
- Only rows of Clippy's own index are written.

## Public API

### `DraftWorker.Rescan.cs` (top-level records, namespace `ClippysRevenge.Core`)

```csharp
/// <summary>SPEC 23.8 plan (index only). CallsLeft = max(0, Cap - ModelCallsToday()).</summary>
public sealed record RescanPlan(int Emails, int Cap, int CallsLeft, bool ReviseDrafts)
{
    public bool LimitReached => CallsLeft <= 0;
    /// <summary>RescanTexts.Confirm(Emails, CallsLeft, Cap, ReviseDrafts).</summary>
    public string ConfirmText => RescanTexts.Confirm(Emails, CallsLeft, Cap, ReviseDrafts);
}

/// <summary>Emails finished so far / emails in the run (for "Cancel rescan (done/total)").</summary>
public sealed record RescanProgress(int Done, int Total);

/// <param name="Started">False when nothing ran: another rescan is running (Message "") or there is no consent
/// (Message = AiDraftingSettings.ConsentRequiredMessage). Then Stop is null, Processed 0, Counts all 0.</param>
/// <param name="Stop">Null when it ran to the end.</param>
/// <param name="Processed">Emails finished (the "after i" of the stopped text).</param>
/// <param name="Message">The summary text (RescanTexts.Summary or .Stopped); the click-feedback balloon text.</param>
public sealed record RescanResult(bool Started, RescanStop? Stop, int Processed, RescanCounts Counts, int ModelCalls,
    TimeSpan Duration, string Message)
{
    /// <summary>Clicking the balloon shows Drafts (SPEC 23.8): Drafted + Updated &gt; 0.</summary>
    public bool ShowDrafts => Counts.Drafted + Counts.Updated > 0;
}
```

## Behavior

### A. The list (`RescanList`, shared by plan and run)

1. `since = now − 24 h`. Mailboxes: `MailboxIndexes.OwnMailbox` first, then
   every shared mailbox in `cur.SharedMailboxes` order with
   `{ Enabled: true, AiDrafts: true }` whose normalized key is in
   `_s.Indexes.Mailboxes` (the same selection as `RunMailboxesAsync`).
   `mailboxSmtp` = `userSmtp` for own, the key for shared.
2. Per mailbox `rows = index.InboxSince(since, EmailIndex.MaxRescanRows)`.
   A mailbox whose index throws (non-cancel) → Warning
   `AI drafts: listing emails to rescan failed ({Type}).` and no rows.
3. A row is **in the list** when its decision (`GetDecision`) is not
   `Drafted`, and either
   - `cur.AiDrafting.ReviseDrafts` and it is **revisit-due**:
     `t = index.OpenAiDraftForThread(row.ConversationTopic, row.EventTime)`
     is not null and `t.Draft.Checked < row.EventTime` (Spec change 1); or
   - the index rules pass: `DraftRules.EvaluateIndex(row, mailboxSmtp, ai, repliedInIndex)`
     returns null, with `repliedInIndex` exactly as `ProcessCandidateAsync`
     step 1 (own index `RepliedTo(imid, topic, eventTime)`, plus the own
     index for a shared mailbox). When `mailboxSmtp` is blank (own mailbox,
     plan only: address unknown) the index rules are not applied and the
     row is in the list (the count is an upper bound; Spec change 9).
4. Merge all mailboxes and sort by `Email.EventTime` ascending with a
   **stable** sort (ties keep mailbox order, then `InboxSince` order).

### B. `PlanRescan()`

```
cur = _s.Settings().Clone(); ai = cur.AiDrafting; now = _time.GetUtcNow()
userSmtp = own index meta "mailbox_smtp" (trimmed; as UserSmtp's fallback, no COM); "" when unknown
n = RescanList(cur, userSmtp, now).Count
return new RescanPlan(n, ai.DailyCap, Math.Max(0, ai.DailyCap - ModelCallsToday()), ai.ReviseDrafts)
```
No `IAiMailbox` call, no model call, no row written. M16.7 shows
`RescanTexts.NothingToRescan` when `Emails == 0`, else
`RescanTexts.LimitUsedUp(Cap)` when `LimitReached`, else the confirmation.

### C. `RescanAsync(ct)` — start

1. `Interlocked.CompareExchange(ref _rescanning, 1, 0) != 0` →
   `RescanResult(false, null, 0, Zero, 0, TimeSpan.Zero, "")` (no COM, no
   call). `Zero = new RescanCounts(0,0,0,0,0,0,0,0,0)`.
2. `start = _time.GetTimestamp()` (the duration runs from here).
3. `cur.AiDrafting.HasConsent` false → `Started = false`,
   `Message = AiDraftingSettings.ConsentRequiredMessage`; release the flag.
   (`Enabled` is **not** required.)
4. `_rescanCts = CreateLinkedTokenSource(ct)` (under `_lock`);
   `_rescanProgress = new(0, 0)`; `cancel = _rescanCts.Token`.
5. Take the gate as the manual path does: `Interlocked.Increment(ref _yield)`,
   `await _gate.WaitAsync(cancel)`, decrement in both outcomes. A running
   pass yields after its current candidate. Cancelled while waiting → stop
   `Cancelled` with `total = 0` (no gate held).
6. With the gate held (all in `try/finally` that releases the gate, disposes
   the scope and the CTS, sets `_rescanProgress = null`, `_rescanning = 0`):
   - `!_s.OutlookAvailable()` → stop `OutlookUnavailable`, `total = 0`.
   - `identity = GetIdentityAsync(WorkPriority.Interactive, ct)`;
     `OutlookUnavailableException` → stop `OutlookUnavailable`; any other
     non-cancel exception → Warning `AI drafts: reading the user's identity failed ({Type}, HResult {HResult}).`
     and stop `OutlookUnavailable`.
   - `userSmtp = UserSmtp(identity)`; blank → Warning
     `AI drafts: the own mailbox address is unknown; rescan skipped.` and
     stop `OutlookUnavailable` (Spec change 4).
   - `items = RescanList(_s.Settings().Clone(), userSmtp, _time.GetUtcNow())`;
     `total = items.Count`.
   - `p = new PassState(start) { Rescan = true, Priority = WorkPriority.Interactive, CallToken = cancel, Scope = _s.Hub.Begin(ActivityState.Drafting, RescanTexts.ProgressLabel) }`;
     `_s.Hub.Report(ActivityState.Drafting, 0, total)`; `_rescanProgress = new(0, total)`.

### D. Per email (in list order)

```
foreach it in items:
    if cancel.IsCancellationRequested → stop Cancelled
    cur = _s.Settings().Clone()
    if !cur.AiDrafting.HasConsent → stop Cancelled                     (Spec change 5)
    tally0 = Drafted+Updated+Moved+Kept+NoReply+LowConfidence+Skipped+Failed of p
    end = await OneAsync(p, it, cur, identity, userSmtp, ct)          (below)
    if end is a stop → stop (map below); the email is not counted in done
    if tally unchanged → p.Skipped++                                  (every finished email counts once)
    done++; Report(Drafting, done, total); _rescanProgress = new(done, total)
    if p.FailedCallsInRow >= 3 → stop Failures
```

`OneAsync`:
1. Shared mailbox no longer `{Enabled, AiDrafts}` in `cur` → return null
   (counts `skipped`).
2. `index = _s.Indexes.For(it.Key)`; `prior = index.GetDecision(id)`;
   `prior?.Outcome == Drafted` → return null (counts `skipped`; never two
   drafts for one email). No row written.
3. When `cur.AiDrafting.ReviseDrafts` and
   `t = index.OpenAiDraftForThread(topic, e.EventTime)` is not null and
   `t.Draft.Checked < e.EventTime`:
   - `calls0 = p.Revisits`;
     `end = await RevisitAsync(p, new RevisitScope(index, it.Key, it.MailboxSmtp, cur, identity, userSmtp, WorkPriority.Interactive), t, e.EventTime, ct)`.
   - `end` not null → return it.
   - A call was made (`p.Revisits > calls0`) → return null (the revisit's
     step 7 wrote this email's `revisited`/`drafted` row).
   - No call and `index.GetAiDraft(t.Draft.DraftEntryId)?.State` is still
     `Open` (draft open in Outlook, read failed, no source row) → return
     null (counts `skipped`, no row).
   - No call and the draft is no longer open (`replied`, `gone`, `edited`)
     → fall through to 4 (Spec change 2).
4. `return await ProcessCandidateAsync(p, index, it.Key, it.MailboxSmtp, e, cur, identity, userSmtp, ct)`
   (rescan mode, Behavior G). Its `Write` overwrites the decision row with
   `model_calls` = prior + 1 for a call.

An exception from `OneAsync` other than cancellation → Warning
`AI drafts: a rescan step failed ({Type}).`, `p.Failed++`, the email
counts as finished. `OperationCanceledException` (either token) → stop
`Cancelled`.

**End mapping** (`DraftPassEnd` → `RescanStop`): `Cancelled` → `Cancelled`;
`DailyLimit` → `DailyLimit`; `RateLimited` → `RateLimited`; `NotSignedIn`
→ `NotSignedIn`; `OutlookUnavailable` → `OutlookUnavailable`. `Failed`,
`Backoff`, `Yielded`, `Disabled`, `Paused`, `NoIdentity`, `Completed` don't
occur in rescan mode; if one does, treat it as "finished, go on" (defensive).

### E. Cancel and the call token

- `CancelRescan()`: under `_lock`, `_rescanCts?.Cancel()`; swallow
  `ObjectDisposedException`. No-op when none runs.
- The **model call** uses `p.CallToken` (linked: app `ct` + cancel); every
  COM step, the writer, the move and the meeting-time step use `ct`, so
  once a call has returned `Ok` the email is finished (draft saved, old one
  moved) before the loop sees the cancel (§23.8).
- A cancel during a call: the model returns `Failed{Cancelled}` (or the
  token is already cancelled before the call) → `Cancelled`, **no row**.

### F. End: summary, event, log

```
elapsed = _time.GetElapsedTime(start)
counts = new RescanCounts(total, p.Drafted, p.Updated, p.Moved, p.Kept, p.NoReply, p.LowConfidence, p.Skipped, p.Failed)
cap    = _s.Settings().AiDrafting.DailyCap
text   = stop is null ? RescanTexts.Summary(counts, elapsed) : RescanTexts.Stopped(stop.Value, cap, done, counts, elapsed)
_s.Hub.Event(ActivityKind.Ai, text, duration: elapsed)
_log?.LogInformation("AI drafts rescan: {End}, {Emails} emails, {Drafted} drafted, {Updated} updated, {Moved} moved, {Kept} kept, {NoReply} no reply, {LowConfidence} low confidence, {Skipped} skipped, {Failed} failed, {Calls} calls in {Ms} ms",
    stop?.ToString() ?? "Completed", total, ..., p.Calls, (long)elapsed.TotalMilliseconds)
return new RescanResult(true, stop, done, counts, p.Calls, elapsed, text)
```
The event and log are written for every started run (also `total = 0` and
early stops). No `BalloonTexts.AiDrafted` balloon (that's the pass's).
Per-draft `Draft` events, low-confidence `Ai` events, revisit events and the
once-a-day `DraftTexts.DailyLimit` event appear as in a pass.

### G. `ProcessCandidateAsync` in rescan mode (`DraftWorker.cs`)

Pass mode (`p.Rescan == false`, `Priority = Background`, `CallToken = null`)
must stay byte-for-byte the same behavior (all existing tests pass
unchanged). Changes:
1. Every `WorkPriority.Background` in the method (`GetFactsAsync` ×2,
   `_meetings.ApplyAsync`, `MakePlan`) → `p.Priority`.
2. Step 2 (COM facts) generic exception: rescan → `p.Failed++`, return null
   (no row; not a call failure); pass → `Failed` as today.
3. Step 4 backoff: `if (!p.Rescan && _retryAt …) return Backoff;` (§23.8:
   the backoff is ignored).
4. Progress: the `p.Scope ??= …`, `p.Total++`/`p.Done++` and both `Report`
   calls only when `!p.Rescan`.
5. Model call: `callCt = p.CallToken ?? ct`; `if (callCt.IsCancellationRequested) return Cancelled;`
   `RunAsync(request, callCt)`; the cancelled case is
   `Failed { Kind: Cancelled } when callCt.IsCancellationRequested`.
6. The three `_consecutiveFailures = 0;` lines → `CallSucceeded(p);`.
7. Step 6 failure: after `Write(... Failed ...)`: `p.FailedCallsInRow++`;
   rescan → return null (no `_consecutiveFailures`, no `_retryAt`, no
   `CallFailed` event); pass → as today.
8. Step 7 generic exception: rescan → return null after the failed row;
   pass → `Failed`.
9. `RateLimited` (sets `_retryAt` + event), `NotSignedIn` (hold), Outlook
   gone, step 8 outcomes: unchanged in both modes.

### H. `RevisitAsync` in rescan mode (`DraftWorker.Revisit.cs`)

Pass behavior unchanged. Changes:
1. Step 4: `if (!p.Rescan && _retryAt …) return Backoff;`.
2. Progress lines only when `!p.Rescan`.
3. Model call with `callCt` exactly as G.5.
4. Step 6 `_consecutiveFailures = 0;` → `CallSucceeded(p);`.
5. `CallFailed`: `NoteFailedAttempt(...)`; `p.FailedCallsInRow++`; rescan →
   `RevisitOutcome("failed")`, return null; pass → as today (backoff, event,
   `Failed`). `ReplaceAsync`'s `return CallFailed(...)` keeps compiling with
   the nullable return.
6. Every COM call already uses `s.Priority` (rescan passes `Interactive`).

### I. `EmailIndex.InboxSince`

```sql
SELECT <the DraftCandidates columns> FROM emails e
WHERE e.folder = 'Inbox' COLLATE NOCASE AND e.event_time >= @since
ORDER BY e.event_time ASC, e.id ASC LIMIT @max
```
Reuse `CandidateRow`. More than 500 rows in a mailbox → the oldest 500
(Spec change 6).

### J. Concurrency summary

- One rescan at a time (`_rescanning`); a second call returns at once.
- The rescan holds `_gate` from C.5 to the end: no pass or manual draft runs
  alongside; a pass that started first yields (via `_yield`), one that
  starts later waits on the gate and runs after.
- The rescan ignores `_yield` (it never yields) and the `NotSignedIn` hold
  (like the manual path); a parsed `Ok` releases the hold (`CallSucceeded`).

## Spec changes

Not applied by this brief (the caller asked for the brief files only); to be
recorded in `SPEC.md` §23.8 by the architect:

1. **Plan and list**: an email is in the rescan when it has no `drafted` row
   and either (with `ReviseDrafts` on) its thread has an `open` tracked draft
   whose source is older and whose `checked` is earlier than the email
   (revisit-due), or the index rules don't skip it. Revisit-due emails are
   counted even when an index rule (e.g. `not_direct`) would skip them,
   because §23.2 lets any newer message trigger a revisit; without this the
   rescan would miss the motivating "reply addressed to someone else" case.
2. **Revisit without a call**: when the revisit ends without a model call
   and the draft is no longer `open` (`replied`, `gone`, `edited`), the email
   runs the §19.7 candidate steps; when the draft is still `open` (open in
   Outlook, read failed, no source row) the email counts as `skipped` and
   gets no row. Every finished email counts once; one with no other outcome
   counts as `skipped`.
3. **Failures in a rescan**: no per-failure `Ai` "call failed" event (its
   text promises a retry), no change to the failure backoff; failures show
   in the summary. "3 failed calls in a row" counts model-call failures
   (failed result or unusable output) and resets on any parsed result; a
   COM read failure before the call counts as `failed` but not toward the 3.
4. **Start**: Outlook unavailable, the identity read failing, or an unknown
   own address stops the rescan at once with reason `Outlook isn't running`.
   A second rescan returns at once (`Started = false`, no message); no
   consent returns the consent message.
5. **Mid-run settings**: consent withdrawn → stop `cancelled`; a shared
   mailbox turned off → its remaining emails count `skipped`.
6. **API**: `PlanRescan()` → `RescanPlan(Emails, Cap, CallsLeft, ReviseDrafts)`
   (`LimitReached`, `ConfirmText`); `RescanAsync(ct)` → `RescanResult`
   (never throws; `ShowDrafts` = drafted + updated > 0); `CancelRescan()`;
   `CurrentRescan` (`RescanProgress(Done, Total)` or null);
   `EmailIndex.InboxSince(since, max ≤ 500)`: per mailbox at most the oldest
   500 rows of the window; mailboxes merged by time (stable: own first, then
   shared in settings order).
7. **Summary**: the duration runs from the `RescanAsync` call; `<i>` is the
   number of finished emails; the log's `<end>` is `Completed` or the
   `RescanStop` name. Core records the `Ai` event; M16.7 shows the
   click-feedback balloon from `RescanResult.Message`.
8. **Hold**: like the manual path, a rescan runs during a `NotSignedIn`
   hold; a parsed result releases it.
9. **Plan without the own address** (index meta empty): the own mailbox's
   rows are counted without the index rules (an upper bound).
10. **§3 layout** already lists `DraftWorker.Rescan.cs`.
