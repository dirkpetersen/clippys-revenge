# M7.3 `Signatures`, `create_draft` (own + shared, attachments checked first)

## Goal

Build the `create_draft` MCP tool (SPEC §11.5) and the default-signature
loader (§8 `Signatures.Default`, §8 "Draft bodies"), for the own mailbox
and for configured shared mailboxes (§8 `CreateDraft`, §11 "`mailbox`
argument", §11 "File paths"). Every input is validated in **Core** before
any COM call: recipients (`Recipients.Parse`, §12), the mailbox, and
**every attachment path through `PathPolicy` (Read mode) and for
existence** (§11.5, §12). Only then is one `Interactive` work item queued
on the `OutlookWorker` (§4), which builds the `MailItem` and calls
**`.Save()` only** (§1 rule 4, CLAUDE.md). Signature lookup (registry name
→ `.htm` file → decoded HTML → body content) is pure logic except the
registry read, so it lives in Core behind a `Func<SignatureKind,string?>`,
the same pattern as `SettingsStore` + `ISecretProtector`. Activity:
`Blocked` for a refused path, `Draft` for a created draft (§6.4).

## Hard rules that apply here

- **No `.Send(`** anywhere in this task's code, not even in comments or XML
  docs (the M10.1 scan matches text). No `.Display(` either. The draft is
  only ever `.Save()`d.
- No new way to get an `Outlook.Application`: COM code only receives the
  instance from `OutlookWorker.RunAsync`. Don't write `new Application(`,
  `Activator.CreateInstance` or `CoCreateInstance`.
- Every attachment path goes through `PathPolicy.Check(..., PathMode.Read, ...)`
  and only the **returned full path** is handed to COM.
- Nothing about attachment *content* is read, logged or indexed. Activity
  events carry the subject and counts only, never bodies or paths.
- No Graph, no token anywhere.

## Behavior

### A. `Signatures.Default(kind)`

1. Undefined `kind` → `ArgumentOutOfRangeException`.
2. `name = nameSource(kind)`. If `nameSource` throws `IOException`,
   `UnauthorizedAccessException` or `System.Security.SecurityException`,
   return null. Other exceptions propagate.
3. Name check (null on failure): trim; non-blank; length ≤ `MaxNameLength`;
   not `.` or `..`; no char `< 0x20` and none of `\ / : * ? " < > |`
   (hard-coded set, the same on every OS, like `FileNames.SafeFileName`).
   The name is used verbatim otherwise (don't sanitize, just refuse).
4. `path = Path.Combine(signaturesDir, name + ".htm")`. Not a file
   (`File.Exists` false, or it's a directory) → null.
5. Length `> MaxFileBytes` → null. Read with `File.ReadAllBytes`;
   `IOException` / `UnauthorizedAccessException` → null.
6. Return `Decode(bytes)`. No caching: each call reads the file, so the
   user's signature edits apply at once (it is one small file per draft).
7. `PathPolicy` does not apply: this path is not from a tool argument and
   is fixed under `%APPDATA%\Microsoft\Signatures`.

### B. `Signatures.Decode(bytes)`

In order:

1. BOM `EF BB BF` → UTF-8 (BOM removed). `FF FE` → UTF-16LE, `FE FF` →
   UTF-16BE (BOM removed).
2. Look at the first 4096 bytes as Latin-1 text for the regex
   `charset\s*=\s*["']?([A-Za-z0-9_.:\-]+)` (ignore case, culture
   invariant). If found, `Encoding.GetEncoding(name)` after
   `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` (do the
   registration once, in a static constructor). An unknown name
   (`ArgumentException`) falls through to step 3. A declared `utf-16`
   without a BOM also falls through.
3. Strict UTF-8 (`new UTF8Encoding(false, throwOnInvalidBytes: true)`);
   on `DecoderFallbackException`, Windows-1252.

Outlook usually writes signatures as Windows-1252 with a
`<meta … charset=windows-1252>` tag, so step 2 is the common path.

### C. `HtmlBody.BodyContent` and `DraftBody`

- `BodyContent`: find the first `BodyTag()` match (the existing regex). No
  match → return `html` unchanged. Otherwise take the text after it; find
  the **last** `</body\s*>` (ignore case) in that remainder; cut there if
  found. Return the slice, untrimmed.
- `SignatureContent(sig)`: null → null; `c = HtmlBody.BodyContent(sig)`;
  `string.IsNullOrWhiteSpace(c)` → null; else `c`.
- `Fragment(body, html, sig)`: `text = html ? body : HtmlBody.FromPlainText(body)`;
  `s = SignatureContent(sig)`; `s is null` → `text`; `text.Length == 0` →
  `s`; else `text + "<br>" + s`.
- Known v1 limitation (documented, not fixed): styles in the signature's
  `<head>` are dropped, and images that the `.htm` references from its
  `<name>_files` folder are not embedded, so they may show as broken in the
  draft.

### D. `CreateDraftTool.Plan(args)`: order and messages

Checks run in this order; the first failure throws. Nothing in `Plan`
touches COM or the writer.

1. **Mailbox.** `key = MailboxIndexes.Normalize(args.Mailbox)`.
   - `key == "all"` → `McpException`:
     `Mailbox "all" only works with search tools. Use your own mailbox (leave mailbox empty) or one shared mailbox address.`
   - `key != ""` and `settings.FindSharedMailbox(key)` is null or has
     `Enabled == false` → `throw MailboxIndexes.Unknown(args.Mailbox, keys)`,
     where `keys` is `""` followed by the normalized `Smtp` of every
     **enabled** `SharedMailboxes` entry, in settings order, de-duplicated.
     (Same text as the index tools: `Mailbox "<input>" is not configured or not enabled. Available mailboxes: "" (your own mailbox), "<a>". To use another shared mailbox, ask the user to enable it in the Clippy tray menu under Shared mailboxes.`)
2. **Recipients.** For `to`, `cc`, `bcc` (in that order): null/whitespace
   → empty list; otherwise `Recipients.Parse`. A `FormatException` →
   `McpException($"\"{field}\": {ex.Message}")` with `field` = `to`, `cc`
   or `bcc`, e.g.
   `"to": Recipient "bob" has no valid email address. Use "Name <email>" or a bare email, and separate recipients with ";".`
   After parsing, `To.Count == 0` → `McpException`:
   `create_draft needs at least one recipient in "to", like "Sample, Bob <bob.sample@example.org>; someone@example.org".`
   (cc/bcc may repeat a `to` address; no cross-list de-dup.)
3. **Subject.** null → `""`. Replace each `\r\n`, `\r`, `\n` with one
   space, then trim.
4. **Attachments** (null → none). For each entry, `i` 1-based, in order:
   - null/whitespace → `McpException($"Attachment {i} is empty. Pass the full path of an existing file in the allowed folders: {folders}.")`,
     `folders` = `string.Join("; ", settings.EffectiveAllowedFolders())`,
     or `(none)` when empty.
   - `full = PathPolicy.Check(entry, settings.EffectiveAllowedFolders(), PathMode.Read, relativeTo)`,
     where `relativeTo = settings.AttachmentDir` when it is fully
     qualified (`Path.IsPathFullyQualified`), else null. Relative
     attachment paths therefore resolve under `AttachmentDir`, like
     `save_dir`.
   - `PathNotAllowedException ex` → first
     `hub.Event(ActivityKind.Blocked, $"create_draft: attachment {i} refused ({PathPolicy.Describe(ex.Reason)})", mailbox: key.Length == 0 ? null : key)`,
     then `throw new McpException(ex.Message + " Nothing was created.")`.
     (The message already names the path and the allowed folders.)
   - `FileNotFoundException ex` →
     `McpException($"Attachment {i}: {ex.Message} Nothing was created.")`.
     No `Blocked` event (§12: only policy refusals).
   - `IOException` / `UnauthorizedAccessException ex` →
     `McpException($"Attachment {i} could not be checked: {ex.Message} Nothing was created.")`.
   - Keep `full` in the plan. Duplicates are kept (Outlook attaches twice).
   - All attachments are checked before step 5 and before the writer runs.
5. **Body.** `body = args.Body ?? ""`.
   `sig = signatures.Default(SignatureKind.New)`;
   `fragment = DraftBody.Fragment(body, args.Html, sig)`;
   `signatureAdded = DraftBody.SignatureContent(sig) is not null`.
   (Shared-mailbox drafts get the user's own default signature, per §18
   open question 2.)
6. Return the `DraftPlan`.

### E. `CreateDraftTool.RunAsync(args, ct)`

1. `plan = Plan(args)` (synchronous throws surface as a faulted task;
   make the method `async`).
2. `created = await writer.CreateAsync(plan, ct).ConfigureAwait(false)`.
   Exceptions propagate unchanged; no `Draft` event then.
3. `hub.Event(ActivityKind.Draft, $"draft created: {Short(created.Subject)}", mailbox: plan.Mailbox.Length == 0 ? null : plan.Mailbox)`.
   `Short`: subject longer than `MaxEventSubjectLength` → first 80 chars +
   `…`; empty → `(no subject)`.
4. Return `new CreateDraftResult(created.EntryId, created.Subject, plan.Mailbox, plan.SignatureAdded)`.
   `mailbox` is `""` for the own mailbox (same key convention as
   `search_emails` results).

### F. COM: `OutlookMail.CreateDraft(app, store, plan)` (App, worker thread)

Track every COM object in locals and release each with
`Marshal.ReleaseComObject` in `finally` blocks (reverse order). Release
per-recipient and per-attachment objects inside the loops.

1. Create the item:
   - own (`store is null`):
     `item = (Outlook.MailItem)app.CreateItem(Outlook.OlItemType.olMailItem)`.
   - shared: `drafts = store.GetDefaultFolder(Outlook.OlDefaultFolders.olFolderDrafts)`,
     `items = drafts.Items`, `item = (Outlook.MailItem)items.Add(Outlook.OlItemType.olMailItem)`,
     then `item.SentOnBehalfOfName = plan.Mailbox`.
2. `item.Subject = plan.Subject`.
3. `recips = item.Recipients`; for each recipient of `To`, `Cc`, `Bcc`:
   `r = recips.Add(rec.Email)`; `r.Type = (int)OlMailRecipientType.olTo /
   olCC / olBCC`; release `r`. Only the address is passed (a display name
   with a comma could be split by Outlook). No `Resolve`/`ResolveAll`: the
   draft may hold unresolved addresses; Outlook resolves them when the
   user opens it.
4. `item.BodyFormat = Outlook.OlBodyFormat.olFormatHTML`;
   `item.HTMLBody = HtmlBody.InsertAtTop(item.HTMLBody ?? "", plan.HtmlFragment)`.
5. `atts = item.Attachments`; for each `plan.AttachmentPaths` path:
   `a = atts.Add(path, Outlook.OlAttachmentType.olByValue)`; release `a`.
6. `item.Save()`. This is the only state-changing call on the item.
7. Return `new CreatedDraft(item.EntryID, item.Subject ?? "")`.
8. Errors **before** `Save()`: try `item?.Close(Outlook.OlInspectorClose.olDiscard)`
   (swallow any exception from it), so nothing is left behind. Then:
   - `ComErrors.IsOutlookGone(ex)` → rethrow unchanged (`throw;`), so the
     worker reports `OutlookUnavailable`.
   - `McpException` → rethrow unchanged.
   - shared mailbox and a `COMException` with HResult `0x80070005`
     (E_ACCESSDENIED / MAPI_E_NO_ACCESS) in step 1 → `McpException($"Could not create a draft in {plan.Mailbox}: Outlook refused access to that mailbox's Drafts folder. The user needs Full Access or Editor rights on it.")`.
   - an attachment `Add` failure → `McpException($"Outlook could not attach \"{Path.GetFileName(path)}\": {ex.Message} Nothing was created.")`.
   - any other `COMException` → `McpException($"Outlook could not create the draft: {ex.Message}")`.
9. After `Save()` succeeds, don't discard on later errors (reading
   `EntryID`); a failure there becomes
   `McpException("The draft was saved in Outlook, but its id could not be read. Look in the Drafts folder.")`
   (unless gone → rethrow).
