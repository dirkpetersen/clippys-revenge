# M4.3 Tray: `TrayApp`, menu, icon states, paperclip icons, balloons

## Goal

Build the system tray shell (SPEC §6.1, §6.2, §6.5, threading from §4
item 1, `ActivityHub` contract from §7, latency target from §17). Most of
the logic goes in **Core**, where it can be tested on Linux:

- `TrayPresenter` turns `ActivityHub` state, progress and sync stats into
  an icon key, a tooltip of at most 127 characters, the two menu status
  lines, Start Outlook visibility, the Pause/Resume label, and the
  Serving "pulse" that lasts at least 1 s.
- `BalloonCenter` enforces the one-per-minute limit, and
  `StateBalloonPolicy` applies the "more than 2 minutes" rules.
- `TrayIconArt` and `IcoEncoder` draw the original paperclip icons and
  encode them as multi-size `.ico` files.

The generated `.ico` files are checked in and embedded in the App. The
**App** side is a thin `TrayApp : ApplicationContext` with a `NotifyIcon`
and the full §6.2 menu. It renders on the UI thread only. The handlers
that later tasks own (M5.1, M6.1, M9.x) are stubs.

## Cross-task dependencies

M4.3 runs after M4.1 and M4.2 (sequential plan order). It assumes only the
interfaces below. If an actual name differs, adapt the wiring in `Program`.
Do not change the sibling's type.

- **M3.2 `ActivityHub`** (merged): `State`, `Progress`, `GetEvents()`,
  `event Action? Changed`. `Changed` can fire on any thread. Do not edit
  `ActivityHub.cs`.
- **M3.1 `TokenHolder`** (merged): `Current`, `Set(string)`.
- **M4.1 `Program`**:
  - Runs a WinForms message loop on the `[STAThread]` main thread.
  - Has `ActivityHub` and `TokenHolder` as DI singletons.
  - Has a place where the named-pipe "open Settings" message is handled.

  M4.3 edits `Program` in three ways:
  1. Register `BalloonCenter` as a singleton.
  2. Construct `TrayApp` on the UI thread and pass it to
     `Application.Run(trayApp)`. This replaces any placeholder
     `ApplicationContext` / form that M4.1 used.
  3. Route the pipe message to `trayApp.ShowSettings()`.

  When `Application.Run` returns, `Program` stops the host, as M4.1
  already does on exit.
- **M4.2 `SettingsStore`**: `TrayApp` needs these capabilities. They are
  passed in as delegates (see `TrayServices`) so `TrayApp` doesn't bind to
  `SettingsStore` member names:
  1. Read the current `Settings` (`Port`, `StartWithWindows`,
     `SharedMailboxes`, `NotifyOnErrors`).
  2. Persist `StartWithWindows` and apply the HKCU Run key.
  3. Regenerate and persist the token, returning the new token string.
  4. Whether this launch was the first run.
  5. The data folder and log folder paths. Use `SettingsStore`'s paths if
     it exposes them. Otherwise use `%LOCALAPPDATA%\ClippysRevenge` and
     `%LOCALAPPDATA%\ClippysRevenge\logs` (SPEC §5.1).

  If M4.2 lacks capability 2 or 3, pass `null`. `TrayApp` then disables
  that menu item. Note this in the commit message.
- **Later tasks** that will plug in:
  - M5.1: Start Outlook; may replace the `ShowStartOutlook` source with
    the worker's own flag.
  - M6.1: Sync now, Pause/Resume, Rebuild, real `TrayStats`.
  - M6/M8: `BalloonCenter.Post` for backfill-finished and invite
    balloons.
  - M9.1: shared mailbox toggling.
  - M9.2: `ShowSettings`.
  - M9.3: `ShowActivity`.

  None of these is implemented here.

## Behavior

### Presenter: icon and tooltip per state (SPEC §6.1)

`P` is `TrayText.Prefix` (`Clippy — `). `L` is `progress.Label`. Numbers
use `N0` with `CultureInfo.InvariantCulture` (`48,210`). Every
tooltip and status line goes through `TrayText.Truncate`.

| `state` | Icon | Tooltip |
|---|---|---|
| `Error` | `Error` | `P + "error: " + L`; `P + "error"` if `L` is empty |
| `AwaitingConfirmation` | `Confirm` | `Clippy — waiting for you to confirm a meeting invite` |
| `OutlookUnavailable` | `Unavailable` | `Clippy — Outlook is not running` |
| `Backfilling` | `Backfill0`, `Animated=true` | see below |
| `Syncing` | `Busy` | `P + "pulling new mail (" + L + ")"`; `P + "pulling new mail"` if `L` is empty |
| `Purging` | `Busy` | `P + "removing mail older than " + L`; `P + "removing old mail"` if `L` is empty |
| `Paused` | `Paused` | `Clippy — indexing paused` |
| `Serving` | `Serving` | `P + L`; `P + "serving"` if `L` is empty |
| `Idle` | `Idle` | `P + "idle"` + (`EmailCount` ? `" · {n:N0} emails"`) + (`LastSync` ? `" · synced " + RelativePast`) |

**Backfilling.** Split `L` at the first `" ("`. The part before it is
`what`. The rest, including `" ("`, is `range`, which may be empty.

- When `Total > 0`, the tooltip is
  `P + "indexing " + what + " " + Done:N0 + " / " + Total:N0 + range`.
  For example, `L = "Inbox (2025-11 → now)"` with progress 1240/8000
  gives `Clippy — indexing Inbox 1,240 / 8,000 (2025-11 → now)`.
- When `Total == 0`, it is `P + "indexing " + L`.
- When `what` is empty, drop the double space. Use
  `string.Join(" ", nonEmptyParts)`.

### Presenter: Serving pulse (§6.1 "green pulse, ≥1 s")

- When `state == Serving`, remember the label `L`. If the previous
  `Update` was not `Serving` and no hold was active, also set
  `servingSince = now`.
- When `state == Idle` and `now - servingSince < ServingMinimum`, return
  the **Serving** view (hold).
  - If `lastTool` is not null, has `Time >= servingSince` and has a
    `Duration`, the hold tooltip is
    `P + L + " (" + round(Duration.TotalMilliseconds, AwayFromZero) + " ms)"`.
  - Otherwise it is `P + L`.
- Any state other than `Idle` and `Serving` ends the hold immediately and
  shows that state.
- Once `now - servingSince >= ServingMinimum`, the hold is cleared.

### Presenter: menu lines and flags (§6.2)

- `StatusLine`:
  - `Idle`: `P + "idle"` + the emails part only, without " · synced …",
    because line 2 shows it. Example: `Clippy — idle · 48,210 emails`.
  - Serving hold: the hold tooltip.
  - Every other state: the same text as the tooltip.
- `SyncLine`: `"Last sync: " + (LastSync ? RelativePast : "never")`,
  followed by:
  - `" · paused"` when `stats.Paused`;
  - otherwise `" · next in " + NextIn(NextSync)` when `NextSync` has a
    value.
  - Example: `Last sync: 2 min ago · next in 3 min`.
- `ShowStartOutlook` is `state == OutlookUnavailable`.
- `PauseMenuText` is `"Resume indexing"` when `stats.Paused`, and
  `"Pause indexing"` otherwise.

### `TrayText`

- `RelativePast`: `d = now - then`.
  - `d < 1 min`, including negative values: `just now`.
  - `< 60 min`: `{floor(minutes)} min ago`.
  - `< 24 h`: `{floor(hours)} h ago`.
  - Otherwise: `{floor(days)} d ago`.
- `NextIn`: `max(1, ceil((next - now).TotalMinutes))` followed by
  `" min"`. A past `next` gives `1 min`.
- `McpAddCommand(8765, "abc")` returns exactly:
  `claude mcp add --scope user --transport http clippy http://127.0.0.1:8765/mcp --header "Authorization: Bearer abc"`

### Balloons (§6.5)

- **`BalloonCenter.Post` rate limit**:
  - Accept when no rate-limited balloon has ever been accepted, or
    `now - lastAccepted >= MinInterval`.
  - When accepted, set `lastAccepted = now` and raise `Shown`.
  - **Dropped balloons are not queued.**
  - The check-and-set is atomic under a lock.
- **Text cleanup**: text is passed through
  `TrayText.Truncate(text, MaxTextLength)`.
- **`Shown` subscribers**: each delegate in the invocation list is called
  separately, and exceptions are swallowed, as in `ActivityHub.Raise`.
- **`PostUserFeedback`**: same text checks, always raises, and leaves
  `lastAccepted` unchanged.
- **`StateBalloonPolicy.Observe`**: tracks two episodes, keyed on
  `state`.
  - **Unavailable episode**: starts when `state == OutlookUnavailable`
    first appears, at `now`, and ends as soon as `state` is anything else.
    The next appearance starts a new episode.
    - When `now - start >= Threshold` and the episode hasn't notified yet,
      return `new Balloon(BalloonTexts.OutlookUnavailable, Warning)` and
      mark the episode notified.
  - **Error episode**: the same rules for `state == Error`. It needs
    `notifyOnErrors == true` at the moment it fires, and returns
    `new Balloon(BalloonTexts.Error(progress.Label), Error)`.
    - While `notifyOnErrors` is false, nothing fires and the episode is
      not marked notified. If the setting is switched on later in the same
      episode, the balloon fires once.
  - All other states return `null`.
  - Precedence masking is accepted: because only `hub.State` is visible,
    an `Error` that masks `OutlookUnavailable` ends the unavailable
    episode.
- **Out of scope here**: the backfill-finished and invite balloons. M6.1
  and M8.4 call `BalloonCenter.Post` with their own texts.

### Icon art (deterministic, so the golden files match on Linux and Windows)

Use only `+ - * /`, `Math.Sqrt`, `Math.Min/Max/Abs` and `Math.Clamp`
on `double`. **No trigonometry**, because results differ across platforms.

- **Coordinates**: a 32×32 unit design space. The pixel `(x, y)` center
  maps to `u = (x + 0.5) * 32 / size` (and the same for `y`). Distances in
  units are converted to pixels with `* size / 32`.
- **Paperclip**: the centerline is one open path, stroked with half-width
  `1.4` units and round caps. Segment distance gives round caps naturally.
  1. Line `(13,10)` → `(13,21)`.
  2. Bottom semicircle, center `(16,21)`, `r = 3` (covers `y >= cy`).
  3. Line `(19,21)` → `(19,7)`.
  4. Top semicircle, center `(13.5,7)`, `r = 5.5` (covers `y <= cy`).
  5. Line `(8,7)` → `(8,22)`.
  6. Bottom semicircle, center `(16,22)`, `r = 8`.
  7. Line `(24,22)` → `(24,10)`.
- **Semicircle distance**: on the semicircle's side of `cy`, the distance
  is `|sqrt(dx²+dy²) - r|`. Otherwise it is the distance to the nearer
  endpoint, `(cx±r, cy)`.
- **Stroke coverage**: `clamp(halfWidthPx + 0.5 - distPx, 0, 1)`, using
  the minimum distance over all parts.
- **Filled circle or capsule coverage**: `clamp(0.5 - (dist - radius)Px, 0, 1)`.
- **Layers**:
  1. The clip in the state color.
  2. For `Unavailable` only, a badge: a filled circle at `(25,25)` with
     `r = 6.5`, in `#FFFFFF`. On top of it, the mark in `#424242`: a
     capsule from `(25,20.5)` to `(25,25.5)` with half-width `1.2`, and a
     dot at `(25,28.3)` with `r = 1.3`.
  3. For `BackfillN` only, a dot with `r = 2.5` in `#64B5F6` at corner
     `N`: 0 `(3.5,3.5)`, 1 `(28.5,3.5)`, 2 `(28.5,28.5)`, 3 `(3.5,28.5)`.
- **Clip colors**:

  | Key | Color |
  |---|---|
  | `Idle` | `#2E7D32` |
  | `Serving` | `#66BB6A` |
  | `Busy` and `Backfill*` | `#1565C0` |
  | `Paused` and `Unavailable` | `#757575` |
  | `Confirm` | `#FFB300` |
  | `Error` | `#C62828` |
- **Compositing**: straight-alpha source-over, starting from transparent:
  - `oa = sa + da*(1-sa)`;
  - `oc = oa == 0 ? 0 : (sc*sa + dc*da*(1-sa)) / oa`;
  - store channels as `(byte)(int)(v*255 + 0.5)` (alpha uses `oa`).
- **Encoding (`IcoEncoder`)**, all little-endian:
  - `ICONDIR`: `0, 1, count` (`u16` each).
  - One 16-byte entry per image:
    - width and height as `u8`, with 256 written as 0;
    - color count 0, reserved 0;
    - planes 1, bit count 32;
    - `bytesInRes`, `imageOffset`.
  - **Images** follow in the same order, back to back, starting at
    `6 + 16*count`.
  - **Each image**:
    - a 40-byte `BITMAPINFOHEADER`: `biSize` 40, width `s`, height `2s`,
      planes 1, bpp 32, compression 0,
      `sizeImage = s*s*4 + maskBytes`, and the remaining fields 0;
    - then the pixel rows **bottom-up** in BGRA order;
    - then the AND mask: bottom-up rows of `((s+31)/32)*4` bytes. A bit is
      1 (MSB first) where alpha is 0.
  - `bytesInRes = 40 + s*s*4 + maskBytes`.
- The art constants may be tuned once if the result looks bad at 16 px.
  If they are, regenerate the files and update this brief's numbers in the
  commit. The golden test keeps the files and the code in sync.

### `TrayApp` (App, UI thread only, SPEC §4 item 1)

- **Startup**: create the `ContextMenuStrip` first, then capture
  `SynchronizationContext.Current` (see the ctor exception). Then:
  - create the `NotifyIcon`, with `Visible = true` and
    `ContextMenuStrip = menu`;
  - wire `DoubleClick` to `ShowActivity()`.
- **Render coalescing**: `Hub.Changed` must never touch UI objects.
  - The handler does
    `if (Interlocked.Exchange(ref _renderQueued, 1) == 0) _ui.Post(_ => Render(), null)`.
  - `Render` resets the flag first.
  - Together with the hub's 100 ms throttle, this meets the §17 250 ms
    target.
- **`Render()`** (UI thread):
  1. Read `hub.State`, `hub.Progress`, `GetStats()`, and the last `Tool`
     event (scan `GetEvents()` from the end).
  2. Call `presenter.Update`.
  3. Set `NotifyIcon.Icon`, only when the key changed, and `Text`.
  4. Set the two status lines, `Start Outlook.Visible` and the
     Pause/Resume text.
  5. Start the animation timer if `view.Animated`, otherwise stop it and
     reset the frame to 0.
  6. Call `policy.Observe(state, progress, GetSettings().NotifyOnErrors)`.
     If it returns a balloon, call `Balloons.Post`.
- **Timers** (`System.Windows.Forms.Timer`):
  - The animation timer runs at 250 ms and cycles `Backfill0..3` only
    while animated.
  - The housekeeping timer runs at 1000 ms, always, and calls `Render()`.
    This drives the Serving hold expiry, the relative times and the
    2-minute balloon rules.
- **Balloons**: on `Balloons.Shown`, post to the UI thread and call
  `ShowBalloonTip(5000, BalloonTexts.Title, text, icon)`, where the icon
  maps `Info`/`Warning`/`Error` to `ToolTipIcon.Info`/`Warning`/`Error`.
- **Menu**: exactly the order of §6.2, with separators where the spec
  shows them.
  - **Status line 1 and status line 2**: `Enabled = false`.
  - **Stub items** (`Start Outlook`, `Sync now`, `Pause indexing`,
    `Rebuild index…`): `Enabled = false` until their owning task. Each
    gets a `// TODO(M5.1)`, `// TODO(M6.1)` or `// TODO(M9.x)` comment.
    Visibility and text still come from the view.
  - **`Shared mailboxes ▸`**: rebuilt on `DropDownOpening` from
    `GetSettings().SharedMailboxes`.
    - One item per entry: `Text = MenuLabel`, `Checked = Enabled`, and
      `Enabled = false` (`// TODO(M9.1)`).
    - Then a separator, but only if there are any entries.
    - Then `Manage in Settings…`, which calls `ShowSettings()`.
  - **`Copy "claude mcp add" command`**:
    `Clipboard.SetText(TrayText.McpAddCommand(GetSettings().Port, Token.Current))`,
    then `Balloons.PostUserFeedback(BalloonTexts.Copied)`.
  - **`Copy auth token`**: `Clipboard.SetText(Token.Current)`, with no
    balloon.
  - **Clipboard errors**: catch `ExternalException` from either Copy item.
    Then call `Balloons.PostUserFeedback("Couldn't reach the clipboard — try again.")`.
    Never put the token in a log, event or balloon.
  - **`Regenerate auth token…`**: disabled if the delegate is null.
    Otherwise it shows a `MessageBox` with
    `MessageBoxButtons.OKCancel`, `MessageBoxIcon.Warning` and
    `MessageBoxDefaultButton.Button2`, captioned `BalloonTexts.Title`.
    The text is:
    `Regenerate the auth token?\n\nThe current token stops working immediately. Claude Code must be set up again with the new "claude mcp add" command.`
    On OK: `var t = RegenerateToken(); Token.Set(t);`
  - **`Activity…`** and **`Settings…`**: call `ShowActivity()` and
    `ShowSettings()`. Those are no-ops for now
    (`// TODO(M9.3)`, `// TODO(M9.2)`). Leave both items enabled.
  - **`Open log folder` and `Open data folder`**: call
    `Directory.CreateDirectory(path)`, then
    `Process.Start(new ProcessStartInfo(path) { UseShellExecute = true })`.
  - **`Start with Windows`**: checkable. `Checked` is refreshed from
    `GetSettings().StartWithWindows` on the menu's `Opening`. A click
    calls `SetStartWithWindows(!current)`. The item is disabled if the
    delegate is null.
  - **`Exit`**: set `NotifyIcon.Visible = false`, then call
    `ExitThread()`.
- **Dispose**:
  - unsubscribe `Hub.Changed` and `Balloons.Shown`;
  - stop and dispose the timers;
  - hide and dispose the `NotifyIcon`;
  - dispose the menu and `TrayIcons`.

  `Changed` callbacks that arrive after dispose are ignored, using a
  `_disposed` flag checked in the posted delegate.
- **Program wiring**:
