# M3.1 `BearerAuth` middleware + tests

## Goal

Add the ASP.NET Core middleware that guards the MCP endpoint (SPEC §1.2,
§3, §13, §15). It reads the expected token from a `TokenHolder` that the
tray updates directly, so a regenerated token takes effect immediately
without a restart (§5.2 "Auth token ... Live (old token rejected
immediately)", §6.2, §6.3). It compares tokens in constant time with
`CryptographicOperations.FixedTimeEquals`. It rejects anything other than a
matching `Authorization: Bearer` header with "a 401 with an empty body", and
any request that carries an `Origin` header also gets a 401. Everything
lives in Core and is tested on Linux without a server: the tests drive
`DefaultHttpContext` directly. Wiring the middleware into Kestrel before
`MapMcp` is M4.1, not this task.

## Public API

Namespace `ClippysRevenge.Core` (file-scoped).

```csharp
using System.Security.Cryptography;
using System.Text;
using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Microsoft.Net.Http.Headers;

/// Holds the expected bearer token. Thread-safe: the UI thread calls Set,
/// request threads read it. Registered as a DI singleton by M4.1.
public sealed class TokenHolder
{
    /// <exception cref="ArgumentException">initialToken is null, empty or whitespace.</exception>
    public TokenHolder(string initialToken);

    /// The current token. Needed by "Copy auth token" / the claude mcp add command.
    public string Current { get; }

    /// Replace the token. Later requests (any that read the holder after Set
    /// returns) must use the new token; the old one fails right away.
    /// <exception cref="ArgumentException">token is null, empty or whitespace.</exception>
    public void Set(string token);

    /// Constant-time check of a presented token against Current.
    /// null or "" → false. Never throws.
    public bool Matches(string? presented);

    /// Must NOT return the token. Returns "TokenHolder" (no secret in logs or
    /// debugger displays).
    public override string ToString();
}

/// Middleware. Put it before MapMcp (M4.1).
public sealed class BearerAuth
{
    public BearerAuth(RequestDelegate next, TokenHolder tokens);   // ArgumentNullException on null
    public Task InvokeAsync(HttpContext context);
}

public static class BearerAuthExtensions
{
    /// app.UseMiddleware<BearerAuth>(); TokenHolder comes from DI.
    public static IApplicationBuilder UseBearerAuth(this IApplicationBuilder app);
}
```

Both `ArgumentException` throws use `ArgumentException.ThrowIfNullOrWhiteSpace(token)`.
The message must not contain the token value.

## Behavior

### `TokenHolder`

- Store an immutable snapshot `(string Token, byte[] Hash)` in one field,
  where `Hash = SHA256.HashData(Encoding.UTF8.GetBytes(Token))`. Read it
  with `Volatile.Read` and replace it with `Volatile.Write` (or mark it
  `volatile`). Both reads in `Matches` must use the same snapshot. Don't
  use a lock.
- `Matches(presented)`: return `false` for null or empty. Otherwise compute
  `SHA256.HashData(Encoding.UTF8.GetBytes(presented))` and return
  `CryptographicOperations.FixedTimeEquals(thatHash, snapshot.Hash)`.
  Hashing first makes the comparison independent of length, because
  `FixedTimeEquals` returns early when the lengths differ. The comparison is
  ordinal and case-sensitive: `ABC` does not match `abc`.
- The holder doesn't check the format of the token (64 hex characters is
  `SettingsStore`'s job, M4.2). It only rejects null and whitespace.
- Never log or print the token, and never put it in an exception message.

### `BearerAuth.InvokeAsync`

Check in this order. The first rule that fails ends the request with a 401:

1. **Origin.** If `context.Request.Headers.ContainsKey(HeaderNames.Origin)`
   is true, return 401. Any value counts, including `""` and `null`. This
   also covers CORS preflights (`OPTIONS` with `Origin`), so there is no
   CORS support.
2. **Exactly one Authorization value.** `context.Request.Headers.Authorization`
   must have `Count == 1`. Zero values or more than one value (two headers,
   or a comma-joined `StringValues` with 2 entries) → 401.
3. **Scheme.** The value must start with `"Bearer "` (the word `Bearer` plus
   one ASCII space), compared with `StringComparison.OrdinalIgnoreCase`,
   because RFC 9110 auth schemes are case-insensitive. So `bearer x` and
   `BEARER x` are accepted. `Basic ...`, `Bearer` without a space, and
   `Bearertoken` → 401.
4. **Token.** The token is everything after the first 7 characters. Don't
   trim it. A leading or trailing space becomes part of the token and fails
   the comparison. Kestrel already strips the header's outer whitespace.
   If `tokens.Matches(token)` is false → 401.
5. Otherwise `await _next(context)`.

The 401 response:
- `context.Response.StatusCode = StatusCodes.Status401Unauthorized;`
- `context.Response.ContentLength = 0;`
- Write no body and set no other headers. In particular, don't send
  `WWW-Authenticate`. MCP clients treat `WWW-Authenticate` on a 401 as a
  cue to start OAuth discovery, and this server has no OAuth (hard rule:
  no OAuth).
- Don't call `_next`. Return `Task.CompletedTask`, so there is no async
  state machine on the reject path.

The middleware treats every path and method the same. M4.1 decides where it
sits in the pipeline. It has no logging (the M4.1 activity filter handles
that). Because of that, the token can't leak through it.

`TokenHolder` is read on every request, never cached in the middleware's
fields or in a local outside `InvokeAsync`. That is what makes the live
swap work.

## Cross-task dependencies

None. M3.1 uses no type from another task. M4.1 (host) will register
`TokenHolder` as a singleton built from the token loaded by `SettingsStore`
(M4.2), and will call `app.UseBearerAuth()` before `app.MapMcp("/mcp")`.
The tray's Regenerate action (M4.3/M9.2) calls `TokenHolder.Set`. None of
that is in this task.

## Spec changes (proposed)

Low-risk clarifications of §13. They tighten the existing rules and relax
nothing. Proposed replacement for the `BearerAuth` bullet list in §13:

```
- `BearerAuth` middleware runs before `MapMcp`:
  - It reads the expected token from a `TokenHolder` that the tray updates
    directly, so a regenerated token takes effect without a restart.
  - The comparison is constant-time: both tokens are hashed with SHA-256
    and compared with `CryptographicOperations.FixedTimeEquals`, so the
    length doesn't leak either.
  - Anything other than exactly one `Authorization: Bearer <token>` header
    with a matching token gets a 401 with an empty body. The scheme is
    case-insensitive; the token is case-sensitive and is not trimmed.
  - Requests that carry an `Origin` header (any value, even empty) also get a
    401, which blocks browser pages from calling the server. CORS preflights
    fail the same way.
  - The 401 carries no `WWW-Authenticate` header, so MCP clients don't start
    OAuth discovery.
```
