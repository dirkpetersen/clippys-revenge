# M1.1 Core helpers: `ReplySubject`, `FileNames`, `Recipients`

## Goal

Add three pure helpers to `ClippysRevenge.Core`, with tests. They are
specified in SPEC §12 and their test cases are listed in §15.
`ReplySubject.Normalize` produces the `Re:: ` subject that reply drafts use
(§1 rule 5, §11.6). This is a hard rule: the double colon is intentional.
`Recipients.Parse` / `Format` handle pasted `Last, First <email>; ...` lists
for `find_free_times`, `send_meeting_invite` and the `recipient` search
filter (§11.1, §11.8, §11.9). `FileNames.SafeFileName` / `UniquePath` name
saved attachments (§8, §11.3, §11.4) and shared mailbox index files (§5.1).
All three are cross-platform. They use no COM, registry or WinForms, and
their tests run on Linux.

## Cross-task dependencies

None. M1.1 owns `Recipient` (the record) and `Recipients`. Later tasks
(M2.2, M7.2, M8.2, M8.4) consume these types. They must not redefine them.

## Spec changes (proposed)

The orchestrator applies these. They make §12 precise and do not change any
hard rule. Replace the `Recipients.Parse`, `Recipients.Format`,
`ReplySubject.Normalize` and `FileNames` bullets in §12 with:

```markdown
- `Recipients.Parse(string raw)` → `IReadOnlyList<Recipient(Name, Email)>`:
  - Split on `;` **only**, never on `,`, because names are written
    `Last, First Middle`.
  - Accept `Name <email>`, a bare `email`, and `"Name" <email>`. `Name` is
    `""` for a bare email or `<email>`.
  - An email is valid when it has exactly one `@`, text on both sides, and
    no whitespace or `< > " , ;`.
  - Trim whitespace, skip empty entries, and de-duplicate case-insensitively
    by email while keeping the original case. The first occurrence wins.
    Empty input returns an empty list.
  - When an entry has no valid email, throw `FormatException` with
    `Recipient "<entry>" has no valid email address. Use "Name <email>" or a bare email, and separate recipients with ";".`
- `Recipients.Format(list)`: the inverse, `Name <email>; ...`. A recipient
  with an empty name is written as the bare email.
```

```markdown
- `ReplySubject.Normalize(string?)`:
  - Trim, then repeatedly strip a leading `re`, `fw`, `fwd`, `aw` or `wg`
    followed directly by one or more colons, in any case, and the
    whitespace after it.
  - Return `"Re:: " + rest` (rest trimmed). An empty subject becomes `"Re::"`.
```

```markdown
- `FileNames.SafeFileName(string?)` replaces `\ / : * ? " < > |` and
  control characters with `_` (the same set on every OS), trims whitespace
  and trailing dots, prefixes `_` when the part before the first `.` is a
  Windows device name (`CON`, `PRN`, `AUX`, `NUL`, `COM0`–`COM9`,
  `LPT0`–`LPT9`), and shortens names longer than 200 characters while
  keeping the extension. It returns `"attachment"` if nothing is left.
  `FileNames.UniquePath(dir, name)` sanitizes `name` the same way and
  returns a path in `dir` that doesn't exist yet, as a file or a directory,
  using `name (n).ext` with n = 2, 3, …
```

## Public API

```csharp
namespace ClippysRevenge.Core;

public static partial class ReplySubject
{
    public const string Prefix = "Re:: ";
    /// Never throws. null/whitespace -> "Re::".
    public static string Normalize(string? subject);
}

/// Name is "" (never null) when the entry had no display name.
public sealed record Recipient(string Name, string Email);

public static partial class Recipients
{
    /// ArgumentNullException if raw is null.
    /// FormatException (message below) on the first entry without a valid email.
    public static IReadOnlyList<Recipient> Parse(string raw);

    /// ArgumentNullException if recipients is null. Empty sequence -> "".
    public static string Format(IEnumerable<Recipient> recipients);
}

public static class FileNames
{
    public const string Fallback = "attachment";
    public const int MaxLength = 200;
    /// Never throws. null -> "attachment".
    public static string SafeFileName(string? name);

    /// ArgumentException if dir is null/empty/whitespace.
    /// IOException if no free name is found up to n = 9999.
    public static string UniquePath(string dir, string name);
}
```

Use `[GeneratedRegex]` (hence `partial`) for any regex, with
`RegexOptions.IgnoreCase | RegexOptions.CultureInvariant` where case matters.
A plain char loop is also fine. Don't use `Regex` static methods with
uncached patterns.

## Behavior

### `ReplySubject.Normalize`

1. `null`, empty or whitespace-only input returns `"Re::"` (no trailing space).
2. `s = subject.Trim()`.
3. Loop: if `s` starts with `(re|fwd|fw|aw|wg):+` (case-insensitive,
   culture-invariant, with the colons **directly** after the token), remove
   that match and `TrimStart()` the remainder. Repeat until nothing matches.
4. `rest = s.Trim()`. If `rest` is empty, return `"Re::"`, else `"Re:: " + rest`.

Notes and edge cases:
- Idempotent: `Normalize(Normalize(x)) == Normalize(x)` for every x.
- The prefix needs at least one colon. `Reply needed` and `Fwding` are not
  prefixes. `RE:Budget` (no space) is stripped.
- `Re :` (space before the colon), `Re[2]:`, `SV:` and `Antw:` are **not**
  stripped. That is what the spec says. Leave them.
- Inner text is unchanged, including inner `Re:` (`Budget Re: Q3` stays).
- Never use `Re: ` with a single colon. Do not "fix" the double colon.

### `Recipients.Parse`

1. `raw` null → `ArgumentNullException(nameof(raw))`.
2. Split `raw` on `';'` only. Trim each entry. Skip empty entries. So a
   trailing `;` or `;;` is fine, and an all-whitespace input → empty list.
3. For each entry:
   - If it matches `^(?<name>.*?)\s*<(?<email>[^<>]*)>$` (with `.` matching
     any character on the single line), then name = `name` group trimmed,
     and email = `email` group trimmed. If the name is at least 2 characters
     long and starts **and** ends with `"`, remove those two quotes and trim
     again. Inner quotes are not unescaped.
   - Otherwise the whole entry is the email, and the name is `""`.
   - The email is valid when it contains exactly one `@`, has at least one
     character before and after it, and contains no whitespace and none of
     `< > " , ;`. Otherwise throw a `FormatException` with exactly this
     message, where `{entry}` is the trimmed entry:
     `Recipient "{entry}" has no valid email address. Use "Name <email>" or a bare email, and separate recipients with ";".`
4. De-duplicate by email with `StringComparer.OrdinalIgnoreCase`. The
   first occurrence wins, keeping its name and its email case. Order follows
   the first appearance.
5. Return a read-only list (`List<T>` via `IReadOnlyList<T>` or an array).

Notes:
- `a@x.org, b@y.org` (comma-separated) is one entry, and it throws because
  of the `,`. This is intended: the message tells the model to use `;`.
- The email is not lower-cased.
- The exception is a plain `FormatException`. The App layer turns it into
  an `McpException` with the same message. Core does not reference MCP.

### `Recipients.Format`

- Each recipient becomes `Name <Email>`, or just `Email` when `Name` is
  null, empty or whitespace. Join with `"; "`. No trailing separator.
- No quoting. Round-trip property: `Parse(Format(Parse(x)))` equals
  `Parse(x)` (sequence equality of records) for any `x` that `Parse` accepts.

### `FileNames.SafeFileName`

Run these steps in order:
1. `null` → `"attachment"`.
2. Replace every `\ / : * ? " < > |` and every char where
   `char.IsControl(c)` is true with `_`. Use this **fixed** set, not
   `Path.GetInvalidFileNameChars()`, which differs on Linux.
3. Trim leading whitespace. Then repeatedly trim trailing `.` and trailing
   whitespace together until the name ends in neither, so `"name. . "`
   becomes `"name"`. Windows silently drops trailing dots and spaces, so
   keeping them would break uniqueness checks.
4. If the result is empty → `"attachment"`.
5. Device names: take the part before the first `.` and `TrimEnd()` it. If
   it equals (case-insensitive) `CON`, `PRN`, `AUX`, `NUL`, `COM0`–`COM9` or
   `LPT0`–`LPT9`, prefix the whole name with `_` (`con.txt` → `_con.txt`).
6. Length: if longer than `MaxLength` (200) chars, let `ext =
   Path.GetExtension(name)`. If `ext.Length` is between 1 and 16, the result
   is `stem[..(200 - ext.Length)] + ext`. Otherwise it is `name[..200]`. If
   the cut leaves a lone high surrogate at the end of the kept part, drop
   that char too. Then repeat step 3's trailing trim. The result can't be
   empty here.
- The function is idempotent: `SafeFileName(SafeFileName(x)) == SafeFileName(x)`.
- Leading dots are kept (`.env` stays `.env`). Path traversal can't happen
  because separators are already replaced (`..\..\x` → `.._.._x`).

### `FileNames.UniquePath`

1. If `dir` is null, empty or whitespace → `ArgumentException("Directory is required.", nameof(dir))`.
2. `safe = SafeFileName(name)`.
3. `candidate = Path.Combine(dir, safe)`. If neither `File.Exists` nor
   `Directory.Exists` is true for it, return it.
4. Split `safe` into stem and ext: `ext = Path.GetExtension(safe)`,
   `stem = Path.GetFileNameWithoutExtension(safe)`. If `stem` is empty (as in
   `.bashrc`), use `stem = safe` and `ext = ""`.
5. For n = 2 … 9999: try `Path.Combine(dir, $"{stem} ({n}){ext}")`, and
   return the first one that doesn't exist as a file or a directory.
6. Otherwise throw `IOException($"No free file name for \"{safe}\" in \"{dir}\".")`.

- It does not create `dir` or the file, and it doesn't check that `dir`
  exists (a missing dir means the first candidate is returned). `dir` is
  used as given. `PathPolicy` has already run on it (§8). Not normalizing it
  is deliberate.
- It isn't atomic. Callers write with `FileMode.CreateNew` (App, M7.2, not here).

### `RecipientsTests`

The seven-recipient list (one string, as pasted):

```
Example, Alice Marie <alice.example@example.edu>; Sample, Bob <bob.sample@example.edu>; Sample, Carol Ann <carol.sample@example.edu>; Garcia-Example, Maria Elena <maria.garcia-example@example.edu>; O'Example, Sean Patrick <sean.oexample@example.edu>; Smith, John <john.smith@example.edu>; Sample, Ji-Woo <jiwoo.sample@example.edu>
```

1. `Parse_SevenRecipientList_SevenRecipientsWithCommasInNames`: count 7, in order. For
   example, [0] = `("Example, Alice Marie", "alice.example@example.edu")`,
   [1] = `("Sample, Bob", "bob.sample@example.edu")`,
   [4] = `("O'Example, Sean Patrick", "sean.oexample@example.edu")`.
2. `Parse_TrailingSemicolon_Ignored`: `"Sample, Bob <bob.sample@example.edu>;"` → 1 item. Also `"a@x.org;; ;b@y.org; "` → `[("", "a@x.org"), ("", "b@y.org")]`.
3. `Parse_BareEmail`: `"bob.sample@example.edu"` → `[("", "bob.sample@example.edu")]`.
4. `Parse_QuotedName`: `"\"Sample, Bob\" <bob.sample@example.edu>"` → `[("Sample, Bob", "bob.sample@example.edu")]`.
5. `Parse_AngleOnly`: `"<bob@x.org>"` → `[("", "bob@x.org")]`.
6. `Parse_WhitespaceAroundParts`: `"  Sample, Bob   <  bob@x.org >  "` → `[("Sample, Bob", "bob@x.org")]`.
7. `Parse_Duplicates_CaseInsensitive_FirstWins`: `"Bob <Bob.Sample@x.org>; B. Sample <bob.sample@X.ORG>; bob.sample@x.org"` → `[("Bob", "Bob.Sample@x.org")]`.
8. `Parse_EmptyOrWhitespace_ReturnsEmpty`: `""`, `"   "`, `";;"` → empty list.
9. `Parse_Null_Throws`: `ArgumentNullException`.
10. `Parse_MissingEmail_ThrowsQuotingEntry` (Theory). Each case throws
    `FormatException`, and its `Message` equals the exact text from Behavior
    with that entry:
    - `"Sample, Bob <bob@x.org>; Example, Alice"` → entry `Example, Alice`
    - `"Bob <bob>"` → entry `Bob <bob>`
    - `"Bob <>"` → entry `Bob <>`
    - `"a@x.org, b@y.org"` → entry `a@x.org, b@y.org`
    - `"a@@x.org"` → entry `a@@x.org`
    - `"@x.org"` → entry `@x.org`
    - `"Bob <bob@x.org> extra"` → entry `Bob <bob@x.org> extra`
11. `Format_Basic`: `[("Sample, Bob","bob@x.org"), ("","a@y.org")]` → `"Sample, Bob <bob@x.org>; a@y.org"`. An empty list → `""`.
12. `Format_Null_Throws`: `ArgumentNullException`.
13. `Format_Parse_RoundTrip`: for the seven-recipient list and for cases 2–7,
    `Parse(Format(Parse(x)))` is sequence-equal to `Parse(x)`.
