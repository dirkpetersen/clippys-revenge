# M15.3 Note in Drafts (`reply_to_id`) + skill meeting section v2

Base: `dev` with **M15.1 merged** (`create_meeting_draft`, `MeetingDraftResult`
with `note_draft_id`/`note_error` omitted while null, `MeetingInvites.CreateDraftAsync`,
`InviteTexts.When`/`Calendar`/`Saved`). Design against `docs/briefs/M15.1.md`.
M15.2 (category, tracking) runs in parallel and also edits `MeetingInvites`;
if it landed first, keep everything it added and apply this brief on top
(see Behavior §C "Order").

## Goal

`create_meeting_draft` gets an optional `reply_to_id`: the index id of the
email that asked for the meeting. It is checked (SPEC §8 GetItem chain)
**before** anything is created; an unknown id fails the call with the
`ItemNotFoundException` message and nothing is created. After the meeting is
saved, Clippy saves a reply draft to that email through the existing reply
path (`ReplyPlan` → `IReplyDraftWriter` → `OutlookMail.CreateReplyDraft`:
reply, not reply-all; the email's own mailbox; `Re:: ` via
`ReplySubject.Normalize`; marker `tool`; reply signature; `.Save()` only;
the existing single `.Move(` into a shared mailbox's Drafts). Its body is one
highlighted paragraph with the fixed note text and an empty paragraph. A note
failure never undoes the meeting: the result gets `note_error`, success gets
`note_draft_id` and a sentence in `message`. Separately, the writing-style
skill's meeting section moves to **v2** (new marker, new last bullet telling
Claude Code to call `create_meeting_draft` with `reply_to_id`); unedited
existing skills pick it up through the existing `RefreshMeetingSection`.

SPEC refs: §22.1 (`reply_to_id`, result `note_draft_id?`/`note_error?`,
message suffix, tool description), §22.4 (all), §22.5 (v2 section),
§21.7 (fixed section, "Existing skills" refresh), §22.7 (Core tests:
`reply_to_id` unknown → nothing created; note planned with the exact text;
note failure → `note_error`, meeting kept; skill v2 text; refresh v1 → v2),
§8 (`GetItem` chain, `CreateReplyDraft`), §11.6 (`reply_draft` path).

## Hard rules that apply here

- **Never send anything.** No `.Send(`. The note is a reply draft that is
  only `.Save()`d by the existing `CreateReplyDraft`.
- **Never delete or move mail.** No new `.Move(`; the note reuses the one
  allowed `reply.Move(drafts` in `OutlookMail.Reply.cs`
  (`OnlyMoveIsNewReplyDraftIntoDrafts` must stay green unchanged).
- **`Re:: `** comes from `ReplySubject.Normalize` inside
  `CreateReplyDraft`; don't set the subject anywhere else.
- **Never launch Outlook.** No new COM entry points; the check runs on the
  existing `OutlookWorker`.
- **No logging of ids, subjects, mailboxes or text**: the Warning on a note
  failure logs the exception type only (the `LogArgumentHits` scan applies).

```csharp
namespace ClippysRevenge.Core;

/// <summary>Checks a reply_to_id before a meeting is created (SPEC §22.4). App: OutlookReplyDraftWriter.</summary>
public interface IReplyTargetCheck
{
    /// <summary>COM, Interactive. Resolves the email by the SPEC §8 GetItem chain and releases it; creates nothing.
    /// Returns the normalized mailbox key the email is in ("" = own).</summary>
    /// <exception cref="ItemNotFoundException">No such email in the own or an enabled shared mailbox.</exception>
    /// <exception cref="OutlookUnavailableException">Outlook is not running / not responding.</exception>
    /// <exception cref="OperationCanceledException">ct fired.</exception>
    Task<string> CheckAsync(string id, CancellationToken ct);
}

/// <summary>The note text (SPEC §22.4). Fixed English. Pure.</summary>
public static class MeetingNoteText
{
    public const int MaxSubjectChars = 80;
    public const int MaxReasonChars = 400;
    public const string SavedSuffix = " A note was saved in Drafts as a reply to the email.";
    public const string UnexpectedError = "an unexpected error";

    /// <summary>The note as plain text, including the [[ and ]] brackets; not HTML-escaped.</summary>
    /// <param name="timeZoneLabel">Already resolved (TimeZoneLabels.Resolve); null/blank = no label.</param>
    /// <param name="calendarMailbox">The meeting's normalized mailbox ("" = own calendar).</param>
    /// <exception cref="ArgumentNullException">subject or calendarMailbox null.</exception>
    public static string Text(DateTime start, DateTime end, string? timeZoneLabel, string subject, string calendarMailbox);

    /// <summary>"&lt;p&gt;" + HighlightOpen + Escape(Text(...)) + HighlightClose + "&lt;/p&gt;&lt;p&gt;&amp;nbsp;&lt;/p&gt;".</summary>
    /// <exception cref="ArgumentNullException">subject or calendarMailbox null.</exception>
    public static string Html(DateTime start, DateTime end, string? timeZoneLabel, string subject, string calendarMailbox);

    /// <summary>"The meeting was saved, but the note in Drafts couldn't be created: &lt;reason&gt;."</summary>
    public static string Error(string? reason);

    /// <summary>McpException (incl. ItemNotFoundException, OutlookUnavailableException) → its Message;
    /// anything else → "an unexpected error (&lt;TypeName&gt;)" (never the message). Null → UnexpectedError.</summary>
    public static string Reason(Exception? ex);
}

/// <summary>DraftId = the note's EntryID on success; Error = the note_error text on failure. Exactly one is non-null.</summary>
public sealed record MeetingNoteOutcome(string? DraftId, string? Error);

/// <summary>Checks the reply target and saves the note reply draft (SPEC §22.4). Never sends.</summary>
public sealed class MeetingNotes
{
    /// <exception cref="ArgumentNullException">targets, writer or replySignatureHtml null.</exception>
    public MeetingNotes(IReplyTargetCheck targets, IReplyDraftWriter writer, Func<string?> replySignatureHtml,
        ILogger? logger = null);

    /// <summary>Delegates to IReplyTargetCheck.CheckAsync(id.Trim(), ct). Exceptions propagate unchanged.</summary>
    /// <exception cref="ArgumentNullException">id null.</exception>
    public Task CheckAsync(string id, CancellationToken ct);

    /// <summary>The plan SaveAsync hands to the writer. Pure apart from calling replySignatureHtml.</summary>
    /// <exception cref="ArgumentNullException">id, request or timeZoneLabel null.</exception>
    public ReplyPlan Plan(string id, MeetingRequest request, string timeZoneLabel);

    /// <summary>Builds the plan and calls IReplyDraftWriter.ReplyAsync. Never throws (except ArgumentNullException
    /// for null arguments): every failure becomes Outcome(null, MeetingNoteText.Error(MeetingNoteText.Reason(ex)))
    /// plus one Warning log with the exception type only.</summary>
    public Task<MeetingNoteOutcome> SaveAsync(string id, MeetingRequest request, string timeZoneLabel, CancellationToken ct);
}
```

## Behavior

### §A The note (`MeetingNoteText`)

Exact text (one line; `<…>` filled in as below):

```
[[Draft invite saved in <cal>: <when> "<subject>". Open it from the Clippy tray (Draft invites) or <cal2>, add the Teams or Zoom link and send it. Delete this note before you send this reply.]]
```

- `<cal>` = `InviteTexts.Calendar(calendarMailbox)`: `your calendar` for
  `""`, else `the calendar of <smtp>`.
- `<cal2>` = `your calendar` for `""`, else `that calendar`.
  For the own calendar the text is exactly SPEC §22.4's.
- `<when>` = `InviteTexts.When(start, end)` (`Tue 11/17 13:00–14:30`,
  invariant culture, U+2013, midnight end `00:00`), then `" " + label.Trim()`
  when `timeZoneLabel` is not null/blank (no trailing space otherwise).
  One space between date and time (SPEC §21.5's two spaces collapse in HTML
  anyway; see Spec changes).
- `<subject>`: every `char.IsControl` character → space, whitespace runs
  collapsed to one space, trimmed; then `TrayText.Truncate(s, 80)` (so at
  most 80 characters, the last being `…` when cut). Cut **before**
  escaping.
- `Html`: `"<p>" + DraftHtml.HighlightOpen + Esc(Text(...)) + DraftHtml.HighlightClose + "</p><p>&nbsp;</p>"`.
  `Esc` replaces `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;` only (in that
  order, `&` first), like `MeetingTimesHtml`/`DraftHtml.Sanitize`: quotes and
  apostrophes stay literal. Private helper in `MeetingNote.cs`.
- The note is never passed through `DraftHtml.Sanitize` (it is Clippy's own
  markup; Sanitize would strip the span).
- `Error(reason)`: `r = (reason ?? "").Trim().TrimEnd('.').TrimEnd()`; empty
  → `UnexpectedError`; `r = TrayText.Truncate(r, 400)`; returns
  `$"The meeting was saved, but the note in Drafts couldn't be created: {r}."`.
  So a reason ending with `.` never gives `..`.
- `Reason(ex)`: `ex is McpException` → `ex.Message`; `null` →
  `UnexpectedError`; else `$"{UnexpectedError} ({ex.GetType().Name})"`.
  Non-MCP exception messages are never returned to the model.

### §B Checking `reply_to_id` (App)

- `OutlookMail.CheckReplyTarget(app, id)`: `var r = Resolve(app, id); try { return r.Mailbox; } finally { Release(r.Item); }`.
  `Resolve` already throws `ItemNotFoundException` for blank ids, ids in no
  index and no mailbox store, ids whose item is gone, and non-`MailItem`
  items. Nothing is created or saved.
- `OutlookReplyDraftWriter.CheckAsync(id, ct)`:
  `ArgumentNullException.ThrowIfNull(id)`;
  `await stores.EnsureResolvedAsync(WorkPriority.Interactive, ct)`;
  `return await worker.RunAsync(app => mail.CheckReplyTarget(app, id), WorkPriority.Interactive, ct)`.
- **Ids from another mailbox** (decision, same as `reply_draft`): the email
  may be in the own mailbox or any **enabled** shared mailbox, regardless of
  the meeting's `mailbox`. An id that is only in a disabled or unconfigured
  mailbox fails the check with the `ItemNotFoundException` message
  (`Email "<id>" was not found in Outlook. It may have been deleted or moved to a folder that isn't indexed. Run search_emails again to get a current id.`)
  and nothing is created. There is no extra parameter to pick the note's
  mailbox.

### §C `MeetingInvites.CreateDraftAsync` (additions to M15.1 §C)

1. Mode check exactly as M15.1 (Disabled refuses first; no `reply_to_id`
   check, nothing created). Read `var s = settings();` once here and use
   `s` for the mode and the label below.
2. `MeetingRequest.Create(...)` as M15.1 (bad arguments fail before any COM).
3. **New.** `var replyTo = string.IsNullOrWhiteSpace(replyToId) ? null : replyToId.Trim();`
   (blank = no note). If `replyTo is not null`:
   - `notes is null` (the index failed to open) →
     `throw new McpException(Optional<MeetingNotes>.IndexUnavailableMessage)`.
   - else `await notes.CheckAsync(replyTo, ct)`. Its exception propagates
     unchanged (the same `ItemNotFoundException` instance).
   Both failures go through M15.1's wrapper: one event
   `meeting draft not created: <message cut to 200>`, rethrow; nothing resolved,
   nothing created.
4. `ResolveAsync`, unresolved → error (M15.1). So the order is: Disabled →
   arguments → `reply_to_id` → recipients → create.
5. `CreateAsync(req, CancellationToken.None)` (M15.1).
6. Saved event (M15.1, unchanged text, exactly one event per call).
7. (M15.2's tracking step, if present, stays here.)
8. **New.** If `replyTo is not null`:
   `var label = TimeZoneLabels.Resolve(s.TimeZoneLabel, timeZone, req.Start);`
   `note = await notes!.SaveAsync(replyTo, req, label, CancellationToken.None);`
   Once the meeting exists, the caller's cancellation no longer stops the
   note (same rule as creation). `SaveAsync` never throws, so nothing after
   step 6 records a second event or fails the call.
9. Result (M15.1 fields unchanged) plus:
   - `Message = InviteTexts.Saved(req.Mailbox) + (note?.DraftId is not null ? MeetingNoteText.SavedSuffix : "")`
   - `NoteDraftId = note?.DraftId`, `NoteError = note?.Error`.
   Without `reply_to_id` both stay null and are omitted from the JSON.

**Note after the meeting was created fails** (decision, SPEC §22.4): the
meeting stays saved (nothing is undone or deleted), `status` stays
`saved_as_draft`, `message` has no note sentence, `note_error` carries the
text from §A, one Warning log; the Activity event is still the normal saved
event. The tool call succeeds.

**No extra Activity event** for the note (one `Invite` event per call, §22.1).

**Order** if M15.2 landed first: its constructor parameters stay where they
are; `notes` is appended last. Its tracking step runs before step 8.

### §C2 `MeetingNotes`

- `CheckAsync(id, ct)`: `ArgumentNullException.ThrowIfNull(id)`; `return targets.CheckAsync(id.Trim(), ct);`
- `Plan(id, request, label)`:
  ```csharp
  var sig = replySignatureHtml();
  var html = MeetingNoteText.Html(request.Start, request.End, label, request.Subject, request.Mailbox);
  return new ReplyPlan(id.Trim(), Mailbox: null, ReplyAll: false,
      DraftBody.Fragment(html, html: true, sig), DraftBody.SignatureContent(sig) is not null,
      DraftMarker.Tool, WorkPriority.Interactive);
  ```
  `Mailbox: null` = the email's own mailbox (shared mailbox email → that
  mailbox's Drafts, `SentOnBehalfOfName`, via the existing `.Move(`).
- `SaveAsync`: argument null checks first (throw). Then inside
  `try { var plan = Plan(...); var made = await writer.ReplyAsync(plan, ct); return new(made.EntryId, null); }`
  `catch (Exception ex) { logger?.LogWarning("Meeting draft: the note in Drafts couldn't be created ({ExceptionType}).", ex.GetType().Name); return new(null, MeetingNoteText.Error(MeetingNoteText.Reason(ex))); }`
  (the signature getter is inside the `try`). Catch everything, including
  `OperationCanceledException`. Exact log template as written (no id,
  subject, mailbox).
- Known edge: `CreateReplyDraft` throws
  `The draft was saved in Outlook, but its id could not be read. Look in the Drafts folder.`
  when the id can't be read after `.Save()`; that becomes `note_error` with
  that text (honest: the model tells the user to look in Drafts). Don't
  special-case it.
- A model-written AI draft for the same email is not touched; the note is a
  second reply draft (SPEC §22.4).
