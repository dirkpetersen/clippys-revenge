# M1.6 `InviteGate` + tests

## Goal

Add `InviteGate` to Core: the single, pure function that turns the
`MeetingInviteMode` setting, the user's choice in the confirmation dialog
and the dialog timeout into the action `send_meeting_invite` takes: `Send`,
`SaveDraft`, `Cancel` or `Refuse(reason)` (SPEC §1.4, §5.2
`MeetingInviteMode`, §6.6, §8 `CreateMeeting`, §11.9, §12 last bullet,
§15 `InviteGate` row). It is the safety gate in front of the one `.Send()`
in the codebase. So the rule is that it returns `Send` for exactly one input
combination, and every other combination is tested. No COM, no UI, no
timers: the dialog (M8.3) and the tool (M8.4) only call it.

## Public API

Namespace `ClippysRevenge.Core`, file-scoped. Use XML doc comments on the
public types.

```csharp
// MeetingInviteMode.cs
public enum MeetingInviteMode { Send, DraftOnly, Disabled }

// InviteGate.cs
/// The button the user clicked in InviteConfirmForm (§6.6).
public enum InviteChoice { Send, SaveDraft, Cancel }

/// What send_meeting_invite must do.
public enum InviteAction { Send, SaveDraft, Cancel, Refuse }

/// Why a meeting is saved unsent.
public enum InviteDraftReason { UserChoice, Timeout, DraftOnlyMode }

public sealed class InviteDecision : IEquatable<InviteDecision>
{
    public InviteAction Action { get; }
    /// Non-null if and only if Action == SaveDraft.
    public InviteDraftReason? DraftReason { get; }
    /// Non-null if and only if Action == Refuse. Text for the McpException.
    public string? RefuseReason { get; }
    /// Wire code for the §11.9 result "reason" field:
    /// UserChoice -> "user_choice", Timeout -> "timeout",
    /// DraftOnlyMode -> "draft_only_mode", otherwise null.
    public string? ReasonCode { get; }

    public static InviteDecision Send { get; }      // singleton
    public static InviteDecision Cancel { get; }    // singleton
    public static InviteDecision SaveDraft(InviteDraftReason reason);
    public static InviteDecision Refuse(string reason); // ArgumentException if null/whitespace

    private InviteDecision(InviteAction action, InviteDraftReason? draftReason, string? refuseReason);
    // Value equality over (Action, DraftReason, RefuseReason); override
    // Equals(object), GetHashCode, and ToString() e.g. "SaveDraft(Timeout)",
    // "Refuse(<reason>)", "Send", "Cancel" (for readable test failures).
}

public static class InviteGate
{
    public const string DisabledMessage =
        "Meeting invites are disabled in Clippy's Revenge. Ask the user to " +
        "enable them in the tray settings (Meeting invite mode: Send or " +
        "Draft only), then try again.";

    /// True only for MeetingInviteMode.Send: the tool must show
    /// InviteConfirmForm and await it before calling Decide.
    /// Throws ArgumentOutOfRangeException for an undefined mode.
    public static bool RequiresConfirmation(MeetingInviteMode mode);

    /// Throws ArgumentOutOfRangeException (param name "mode" / "userChoice")
    /// when mode or a non-null userChoice is not a defined enum value.
    public static InviteDecision Decide(MeetingInviteMode mode, InviteChoice? userChoice, bool timedOut);
}
```

Don't use a `record` for `InviteDecision`: a public `with` / primary
constructor would let callers build a `Send` decision with any other
fields. The private constructor plus factories keeps the invariants
(`DraftReason` only on `SaveDraft`, `RefuseReason` only on `Refuse`).

## Behavior

Principle: **the most restrictive input wins**, and the gate never returns
an action stronger than every input allows. Strength order, weakest first:
`Refuse` / `Cancel` (nothing is created) < `SaveDraft` (created, unsent) <
`Send`.

`Decide` checks, in this order:

1. If `mode` is not a defined `MeetingInviteMode` value
   (`Enum.IsDefined`), throw `ArgumentOutOfRangeException(nameof(mode))`.
   If `userChoice` is non-null and not defined, throw
   `ArgumentOutOfRangeException(nameof(userChoice))`. (A corrupted
   `settings.json` or a bad cast must never fall through to `Send`.)
2. `mode == Disabled` → `Refuse(DisabledMessage)`, whatever `userChoice`
   and `timedOut` are (§11.9 "Disabled").
3. `userChoice == Cancel` → `Cancel` in both `Send` and `DraftOnly` mode,
   timed out or not. An explicit user Cancel always means nothing is
   created (§6.6, §11.9).
4. `mode == DraftOnly` → `SaveDraft(DraftOnlyMode)` for any other
   `userChoice` (including `Send`) and either `timedOut` (§11.9
   "DraftOnly"). No dialog is shown in this mode, so a choice is unexpected;
   it can only lower the action, never raise it.
5. `mode == Send`:
   - `timedOut == true` → `SaveDraft(Timeout)` for `userChoice` null,
     `Send` or `SaveDraft` (§6.6: "When `InviteConfirmTimeoutSeconds` runs
     out, the meeting is **saved as a draft**"). This covers the race where a
     click and the timeout arrive together: timeout beats Send.
   - `userChoice == Send` → `Send`. **This is the only path that returns
     `Send`**: `(Send, Send, false)`.
   - `userChoice == SaveDraft` → `SaveDraft(UserChoice)`.
   - `userChoice == null` (dialog closed without a button and without the
     timeout, e.g. the window was closed or disposed) → `Cancel`.

`RequiresConfirmation(mode)`: validate as in step 1, then return
`mode == MeetingInviteMode.Send`.

Strings to copy exactly:

- `InviteGate.DisabledMessage` as above.
- `ReasonCode`: `"user_choice"`, `"timeout"` (from §11.9) and
  `"draft_only_mode"` (new; see Spec changes).

Other rules:

- Pure and static: no I/O, no clock, no logging, no state. Thread-safe.
- `InviteDecision.Send` and `InviteDecision.Cancel` are cached singletons.
  `SaveDraft(reason)` validates `reason` with `Enum.IsDefined` (throws
  `ArgumentOutOfRangeException`). `Refuse(reason)` throws
  `ArgumentException` for null, empty or whitespace.
- The cancelled-result text ("The user declined this invite. Do not retry
  unless they ask.") and the draft "review it in Outlook" text belong to the
  tool (M8.4), not here.
- Don't add a `.Send(` call or the string `.Send(` anywhere (the §15
  safety scan counts it in `src/`). The enum member `InviteAction.Send` and
  the property `InviteDecision.Send` are fine: neither is followed by `(`.
  Don't write `InviteDecision.Send()` in comments either.

## Tests

`tests/ClippysRevenge.Core.Tests/InviteGateTests.cs`, namespace
`ClippysRevenge.Core.Tests`, class `InviteGateTests`. Everything is
cross-platform: no `os` or `live` traits.

1. `Decide_FullMatrix` — `[Theory]` with `TheoryData` (or `MemberData`)
   covering all 3 modes × 4 choices (null, Send, SaveDraft, Cancel) × 2
   timeouts = **24 rows**. Assert `Assert.Equal(expected, actual)` on the
   `InviteDecision`. Expected:

   | mode | choice | timedOut | expected |
   |---|---|---|---|
   | Send | null | false | Cancel |
   | Send | null | true | SaveDraft(Timeout) |
   | Send | Send | false | **Send** |
   | Send | Send | true | SaveDraft(Timeout) |
   | Send | SaveDraft | false | SaveDraft(UserChoice) |
   | Send | SaveDraft | true | SaveDraft(Timeout) |
   | Send | Cancel | false | Cancel |
   | Send | Cancel | true | Cancel |
   | DraftOnly | null | false | SaveDraft(DraftOnlyMode) |
   | DraftOnly | null | true | SaveDraft(DraftOnlyMode) |
   | DraftOnly | Send | false | SaveDraft(DraftOnlyMode) |
   | DraftOnly | Send | true | SaveDraft(DraftOnlyMode) |
   | DraftOnly | SaveDraft | false | SaveDraft(DraftOnlyMode) |
   | DraftOnly | SaveDraft | true | SaveDraft(DraftOnlyMode) |
   | DraftOnly | Cancel | false | Cancel |
   | DraftOnly | Cancel | true | Cancel |
   | Disabled | each of the 4 choices | false and true (8 rows) | Refuse(DisabledMessage) |

2. `Decide_ReturnsSendOnlyForSendModeSendChoiceNoTimeout` — loop over
   `Enum.GetValues<MeetingInviteMode>()` × (null + `Enum.GetValues<InviteChoice>()`)
   × {false, true}. Assert `Action == InviteAction.Send` exactly when
   `(Send, Send, false)`, and assert the loop visited 24 combinations. This
   guards against new enum members being added without updating the gate.
3. `Decide_Invariants` — over the same 24 combinations: `DraftReason` is
   non-null iff `Action == SaveDraft`; `RefuseReason` is non-null iff
   `Action == Refuse`; `ReasonCode` is non-null iff `Action == SaveDraft`.
4. `ReasonCode_Values` — `SaveDraft(UserChoice).ReasonCode == "user_choice"`,
   `SaveDraft(Timeout).ReasonCode == "timeout"`,
   `SaveDraft(DraftOnlyMode).ReasonCode == "draft_only_mode"`,
   `InviteDecision.Send.ReasonCode` and `InviteDecision.Cancel.ReasonCode`
   are null.
5. `Decide_Disabled_RefuseReasonIsDisabledMessage` —
   `Decide(Disabled, null, false).RefuseReason == InviteGate.DisabledMessage`,
   and the message contains `"tray settings"`.
6. `Decide_UndefinedMode_Throws` — `Decide((MeetingInviteMode)42, InviteChoice.Send, false)`
   throws `ArgumentOutOfRangeException` with `ParamName == "mode"`. Same for
   `(MeetingInviteMode)(-1)`.
7. `Decide_UndefinedChoice_Throws` — `Decide(MeetingInviteMode.Send, (InviteChoice)42, false)`
   throws `ArgumentOutOfRangeException` with `ParamName == "userChoice"`.
8. `RequiresConfirmation` — `[Theory]`: Send → true, DraftOnly → false,
   Disabled → false; `(MeetingInviteMode)42` throws
   `ArgumentOutOfRangeException`.
9. `MeetingInviteMode_DefaultIsSend` — `default(MeetingInviteMode) == MeetingInviteMode.Send`
   (matches the §5.2 default), and `Enum.GetValues<MeetingInviteMode>()` is
   exactly `[Send, DraftOnly, Disabled]`.
10. `InviteDecision_Factories` — `SaveDraft((InviteDraftReason)42)` throws
    `ArgumentOutOfRangeException`; `Refuse(null!)`, `Refuse("")`,
    `Refuse("  ")` throw `ArgumentException`;
    `InviteDecision.Send` is the same instance on two reads;
    `SaveDraft(Timeout).Equals(SaveDraft(Timeout))` is true with equal hash
    codes; `SaveDraft(Timeout).Equals(SaveDraft(UserChoice))` is false;
    `SaveDraft(Timeout).ToString() == "SaveDraft(Timeout)"`.

## Spec changes (proposed)

Low-risk and reversible; they only make conservative choices explicit. They
don't loosen any hard rule. For the orchestrator to apply to SPEC.md:

1. §12, replace the `InviteGate.Decide` bullet with:

   > - `InviteGate.Decide(mode, userChoice?, timedOut)` → `Send`,
   >   `SaveDraft(reason)`, `Cancel` or `Refuse(reason)`. It is the only
   >   place that maps these inputs, so it is fully unit-tested. The most
   >   restrictive input wins:
   >   - `Disabled` → `Refuse` with "Meeting invites are disabled in
   >     Clippy's Revenge. Ask the user to enable them in the tray settings
   >     (Meeting invite mode: Send or Draft only), then try again."
   >   - A user **Cancel** → `Cancel`, in any mode other than `Disabled`,
   >     even if the timeout fired at the same moment.
   >   - `DraftOnly` → `SaveDraft(draft_only_mode)` for any other input.
   >   - `Send` mode: timeout → `SaveDraft(timeout)`, even if a Send click
   >     raced with it; **Send** → `Send`; **Save as draft** →
   >     `SaveDraft(user_choice)`; dialog closed with no choice and no
   >     timeout → `Cancel`.
   >   - `Send` is returned only for (`Send` mode, Send click, no timeout).
   >     Undefined enum values throw instead of falling through.

2. §11.9, `DraftOnly` bullet, append: "Result
   `{status: "saved_as_draft", reason: "draft_only_mode", …}`."
