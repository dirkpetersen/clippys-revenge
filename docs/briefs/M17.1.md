# M17.1 Core link store and helpers

User-approved 2026-11-15 (M17: one-time attachment download links, this
option only: no text extraction, no image content in results). Pure Core
work: no COM, no App, no endpoint. M17.2 (endpoint) and M17.3 (tool,
wiring, ACL) consume the API below.

## Goal

Build the Core pieces of SPEC §24 that M17.2 and M17.3 need: the
in-memory link store `AttachmentLinks` (§24.3: 43-character base64url
tokens, 10-minute lifetime, single use via atomic `TryRemove`, the four
limits with their pinned texts, a 60 s sweep, clear, start-up cleanup,
retry of failed deletes, with injected time and file operations), the
private folder path `LinkPaths` and its temp-file naming (§24.2), the
name helpers `LinkFileName.Safe`/`ForShell` (§24.4, §24.5), the response
headers `FileDownloadHeaders.Build` (§24.4), the tool-result strings
(`url`, `curl`, `note`, `expires_at`; §24.1) and the `/files/` mask in
`LogRedactor` (§24.4, §5.1). Hard rules (CLAUDE.md, §24.6): attachment
content never enters the index (no `EmailIndex`/`MailboxIndexes`
reference here), the bearer token is never logged or put in a string
built here, link tokens/paths/file names are never logged, and every
path Clippy writes goes through `PathPolicy` (§12).

## Hard rules that apply here

- Nothing in these files references `EmailIndex`, `MailboxIndexes`,
  `UpsertBatch` or `SetThreadMeta` (M17.3 adds the scan; write it so it
  passes).
- Logger calls in `AttachmentLinks*.cs` take only literals, counts and
  exception **type names** (`ex.GetType().Name`). Never the token, the
  temp path, the folder, the original file name, or an exception message
  (a message can contain the path).
- No bytes of an attachment are read by Clippy. The store only knows a
  path, a name and a size; deleting is the only file operation on link
  files.
- The bearer token never appears in any string here: `curl` reads it
  from `$CLIPPY_TOKEN` in the user's shell.
- `File.Delete` only on Clippy's own temp files (names matching
  `^[0-9a-f]{32}\.bin$` directly inside the link folder). Never delete
  through a junction/symlink folder.

    /// Throws on any failure. Tests pass d => Directory.CreateDirectory(d).</summary>

/// <summary>In-memory one-time download links (SPEC 24.3). Thread-safe. Memory only: nothing on disk but the temp files.</summary>
public sealed class AttachmentLinks : IDisposable
{
    public const string FilesPath = "/files";                     // M17.2 maps FilesPath + "/{token}"
    public const int TokenLength = 43;
    public const long MaxLinkBytes = 100L * 1024 * 1024;          // per attachment
    public const int MaxOpenLinks = 10;
    public const long MaxOpenBytes = 200L * 1024 * 1024;
    public const int MaxLinksPerWindow = 20;
    public static readonly TimeSpan LinkLifetime = TimeSpan.FromMinutes(10);
    public static readonly TimeSpan RateWindow = TimeSpan.FromMinutes(10);
    public static readonly TimeSpan SweepInterval = TimeSpan.FromSeconds(60);

    /// <exception cref="ArgumentNullException">options, Folder, EnsurePrivateFolder, Files or Time is null.</exception>
    /// <exception cref="ArgumentException">Folder is blank or not fully qualified.</exception>
    public AttachmentLinks(AttachmentLinksOptions options);

    public string Folder { get; }                 // Path.GetFullPath(options.Folder), trailing separators trimmed
    public int OpenCount { get; }                 // unexpired links in the store
    public long OpenBytes { get; }                // sum of their Size

    /// <summary>32 random bytes, base64url without padding: 43 chars of [A-Za-z0-9_-].</summary>
    public static string NewToken();

    /// <summary>^[A-Za-z0-9_-]{43}$ (ordinal). Null/empty = false.</summary>
    public static bool IsWellFormedToken(string? token);

    /// <summary>Pre-check before the COM save: open count, open bytes, rate (in that order).
    /// Throws AttachmentLinkException (TooManyOpen / TooManyBytes / RateLimited); ObjectDisposedException after Dispose.</summary>
    public void CheckCanCreate();

    /// <summary>Ensures the private folder and returns a fresh temp path in it (Folder + LinkPaths.NewFileName()).
    /// Throws AttachmentLinkException(FolderUnusable, LinkTexts.FolderUnusable, inner); ObjectDisposedException.</summary>
    public string PrepareTempPath();

    /// <summary>Registers a saved temp file. Rechecks every limit atomically; on refusal deletes the file, then throws
    /// AttachmentLinkException (TooBig / TooManyOpen / TooManyBytes / RateLimited).
    /// ArgumentException: tempPath isn't a temp-file name directly in Folder. ArgumentNullException: tempPath or fileName null.
    /// ArgumentOutOfRangeException: size &lt; 0. ObjectDisposedException after Dispose.</summary>
    public AttachmentLink Add(string tempPath, string fileName, long size);

    /// <summary>Single use: atomically removes and returns the link, or null when the token is malformed, unknown,
    /// already used or expired (an expired one's file is deleted). Never throws; null after Dispose.</summary>
    public AttachmentLink? TryConsume(string? token);

    /// <summary>After a download ends (completed or aborted): deletes the link's temp file; a failed delete is retried
    /// at the next sweep. Idempotent. Never throws (ArgumentNullException for null aside).</summary>
    public void Complete(AttachmentLink link);

    /// <summary>Deletes a temp file from PrepareTempPath that never became a link (failed save). Same retry rule.
    /// ArgumentException when the path isn't a temp-file name directly in Folder. ArgumentNullException for null.</summary>
    public void Discard(string tempPath);

    /// <summary>Removes expired links, deletes their files, retries failed deletes, prunes the rate history.
    /// Runs on a timer every SweepInterval (created in the constructor). Public for tests. Never throws.</summary>
    public void Sweep();

    /// <summary>Port change, host restart, app exit: removes every link and deletes its file (failures retried).
    /// The rate history is kept. Never throws.</summary>
    public void Clear();

    /// <summary>App start: ensure the folder, then delete every temp-file-named file directly in it.
    /// Skipped (Warning) when EnsurePrivateFolder throws or the folder is a link. Never throws.</summary>
    public void CleanUpAtStart();

    /// <summary>Stops the timer, then Clear(). Idempotent.</summary>
    public void Dispose();
}

## What M17.2 and M17.3 will consume

So their briefs don't reinvent anything:

- **M17.2 (endpoint, `McpHttpHost`)**: `AttachmentLinks.FilesPath`,
  `AttachmentLinks.IsWellFormedToken`, `TryConsume(token)` (after
  `UseBearerAuth`, so a 401 never reaches it), `FileDownloadHeaders.Build(link.FileName, stream.Length)`,
  `Complete(link)` in `finally`. The store instance reaches the host as an
  option or DI singleton (M17.2 decides). `LogRedactor` needs no more
  work there.
- **M17.3 (tool and wiring)**: `LinkPaths.Default(localAppData)`, a
  singleton `new AttachmentLinks(new() { Folder = paths.Folder, EnsurePrivateFolder = PrivateFolder.Ensure, Logger = … })`,
  `CleanUpAtStart()` at start-up, `Clear()` on port change / host restart
  / exit (and `Dispose()` at exit). Tool flow: `CheckCanCreate()` →
  `PrepareTempPath()` → COM save with `AttachmentLinks.MaxLinkBytes` and
  `LinkTexts.TooBig(bytes)` (thrown as
  `AttachmentLinkException(LinkRefusal.TooBig, …)`) → on any failure
  `Discard(path)` → `Add(path, originalName, size)` →
  `AttachmentLinkResult.Create(link, host.Port, TimeZoneInfo.Local)`.

## Behavior

### A. Tokens and temp names

1. `NewToken()` = `Base64Url.EncodeToString(RandomNumberGenerator.GetBytes(32))`.
   That is 43 characters with no padding. Assert the length in debug
   (not needed at runtime).
2. `IsWellFormedToken`: length exactly 43 and every char in
   `A-Z a-z 0-9 - _` (a loop or a `GeneratedRegex` `^[A-Za-z0-9_-]{43}$`;
   don't use `$` without `\z` semantics: a trailing `\n` must fail, so use
   `\z` or a loop).
3. `LinkPaths.NewFileName()` = `Convert.ToHexStringLower(RandomNumberGenerator.GetBytes(16)) + ".bin"`.
   It is never derived from the attachment name.
4. `IsTempFileName`: exactly 36 chars, the first 32 in `0-9a-f`, then
   `.bin`. Upper-case hex is **not** accepted.

### B. Store state and time

- `ConcurrentDictionary<string, AttachmentLink>` keyed by token
  (ordinal). Also a `Lock _gate` that serializes `CheckCanCreate`, `Add`,
  `Sweep`, `Clear` and the retry set. `TryConsume` uses only
  `TryRemove` (atomic, no lock), so it stays single-use under any race.
- `now = Time.GetUtcNow()`. `CreatedAt = now`,
  `ExpiresAt = now + LinkLifetime`. A link is **expired when
  `now >= ExpiresAt`**.
- The rate history is a `Queue<DateTimeOffset>` of the `CreatedAt` of
  every **successful** `Add`. An entry is in the window while
  `entry > now - RateWindow`. Entries are pruned in `CheckCanCreate`,
  `Add` and `Sweep`. `Clear` does **not** reset it (a port change
  shouldn't reopen the rate limit). It lives in memory, so an app
  restart resets it.
- Retry set: `HashSet<string>` (OrdinalIgnoreCase) of temp paths whose
  delete failed.
- The constructor normalizes `Folder` (`Path.GetFullPath`, trailing
  separators trimmed) and creates the sweep timer:
  `Time.CreateTimer(_ => Sweep(), null, SweepInterval, SweepInterval)`.
  It doesn't touch the disk.

### C. Limits (`CheckCanCreate` and `Add`)

Both run under `_gate`, first removing expired links (as in `Sweep`,
files deleted) and pruning the rate history, so expired links never
count. Then they check in this order, and the first failing check
throws:

1. **(Add only)** `size > MaxLinkBytes` →
   `AttachmentLinkException(TooBig, LinkTexts.TooBig(size))`. Exactly
   `MaxLinkBytes` is allowed.
2. `OpenCount >= MaxOpenLinks` → `(TooManyOpen, LinkTexts.TooManyOpen)`.
3. `CheckCanCreate`: `OpenBytes >= MaxOpenBytes`; `Add`:
   `OpenBytes + size > MaxOpenBytes` → `(TooManyBytes, LinkTexts.TooManyBytes)`.
4. Rate history count `>= MaxLinksPerWindow` →
   `(RateLimited, LinkTexts.RateLimited(n))`, with
   `n = max(1, ceil((oldest + RateWindow - now).TotalMinutes))`, where
   `oldest` is the oldest entry in the window.

`Add` additionally:
- validates first (before any check, without deleting anything):
  null → `ArgumentNullException`; `size < 0` →
  `ArgumentOutOfRangeException`; `Path.GetFileName(tempPath)` fails
  `LinkPaths.IsTempFileName`, or
  `Path.GetDirectoryName(Path.GetFullPath(tempPath))` isn't `Folder`
  (OrdinalIgnoreCase) → `ArgumentException("tempPath must be a link temp file in the link folder.")`.
  The message names no path.
- on a limit refusal, deletes `tempPath` (the retry rule applies) and
  then throws, so a refused save leaves nothing behind.
- on success: a new token (`NewToken()`, regenerated if `TryAdd` finds a
  collision), the link added, `CreatedAt` enqueued, the link returned.
  `FileName` is stored exactly as given (the original attachment name;
  sanitizing happens where it is used).

### D. Single use (`TryConsume`, `Complete`)

1. `!IsWellFormedToken(token)` → `null`, with no dictionary access.
2. `TryRemove(token, out link)` fails → `null`.
3. Removed but expired → delete its file (retry rule), return `null`.
4. Otherwise return the link. It no longer counts toward
   `OpenCount`/`OpenBytes`. The endpoint streams it, then calls
   `Complete(link)`, which deletes `link.TempPath` (retry rule).
5. After `Dispose`, `TryConsume` returns `null`.

### E. Deleting files (one private helper used everywhere)

`TryDelete(path)`: `Files.Delete(path)`, then remove `path` from the
retry set. On `IOException` or `UnauthorizedAccessException`, add it to
the retry set and log **Warning**
`Could not delete a download link file ({Type}); retrying at the next sweep.`
with `Type = ex.GetType().Name`. Other exceptions propagate (bugs).
Never log the path.

### F. `Sweep` (timer, every 60 s)

Under `_gate`: remove every link with `now >= ExpiresAt` (using
`TryRemove`, so a concurrent consume of the same token wins cleanly) and
delete its file, retry every path in the retry set once, and prune the
rate history. When at least one link expired, log **Debug**
`Download links: {Expired} expired, {Open} open.` The whole method is
wrapped so it never throws (a timer callback must not crash the
process). An unexpected exception logs Warning
`Download link sweep failed ({Type}).` After `Dispose` it does nothing.

### G. `Clear`

Under `_gate`: remove every link and delete its file, then retry the
retry set. Log **Debug** `Download links cleared ({Count}).` only when
`Count > 0`. Never throws. Links already handed out by `TryConsume` are
not affected (their `Complete` deletes their file).

### H. Folder: `PrepareTempPath` and `CleanUpAtStart`

`PrepareTempPath()`:
1. `options.EnsurePrivateFolder(Folder)`. Any exception except
   `OperationCanceledException` → `AttachmentLinkException(FolderUnusable, LinkTexts.FolderUnusable, ex)`.
2. `Files.IsLink(Folder)` true, or it throws → same refusal. This is
   Core's own check on top of the App hook: `PathPolicy` allows the root
   itself to be a link (§12), so the link test on the root has to be
   here.
3. `PathPolicy.Check(Folder, [Folder], PathMode.Write)`.
   `PathNotAllowedException`, `IOException` or
   `UnauthorizedAccessException` → same refusal.
4. Return `Path.Combine(<the checked folder>, LinkPaths.NewFileName())`.
   The file isn't created here. (See Spec changes: `PathPolicy.Check` in
   `Write` mode creates a *directory*, so it is applied to the folder,
   and the file name is generated and fixed in format.)

`CleanUpAtStart()`:
1. `EnsurePrivateFolder(Folder)`. If it throws, log Warning
   `Download link folder not usable at start-up ({Type}); cleanup skipped.`
   and return.
2. `Files.IsLink(Folder)` true (or it throws) → Warning
   `Download link folder is a junction or symbolic link; cleanup skipped.`
   and return. Nothing is deleted through a link.
3. For each path from `Files.EnumerateFiles(Folder)` whose
   `Path.GetFileName` passes `LinkPaths.IsTempFileName`: `TryDelete`.
   Other files and all subfolders are left alone. An enumeration failure
   logs Warning `Download link cleanup failed ({Type}).`
4. Log **Debug** `Download link folder cleaned ({Count} files).` when
   `Count > 0`. Never throws.

### I. `Dispose`

Disposes the timer, sets the disposed flag, then `Clear()`. Idempotent.
After it: `CheckCanCreate`/`PrepareTempPath`/`Add` throw
`ObjectDisposedException`. `TryConsume` returns null. `Complete`,
`Discard`, `Sweep` and `Clear` still delete files (or do nothing), so a
download in flight at exit still cleans up.

### J. `LinkFileName`

- `Safe(original)` = `FileNames.SafeFileName(original)`. So null, empty
  and whitespace give `attachment`, `..` and `.` give `attachment`
  (trailing dots trimmed), `CON.txt` gives `_CON.txt`, `"` `\` `/` and
  control chars become `_`, and non-ASCII is kept.
- `ForShell(original)`: `s = Safe(original)`, replace every `'` with
  `_`, then if `s[0]` is `-` or `.` replace that one character with `_`.
  Only the first character is changed: `--x` → `_-x`, `...pdf` (Safe
  keeps it) → `_..pdf`.

### K. `FileDownloadHeaders.Build(originalName, length)`

`safe = LinkFileName.Safe(originalName)`. The list, in this order, with
exact names:

1. `Content-Type` = `application/octet-stream`
2. `Content-Disposition` = `attachment; filename="<AsciiName(safe)>"; filename*=UTF-8''<PercentEncode(safe)>`
3. `Content-Length` = `length` (invariant culture)
4. `X-Content-Type-Options` = `nosniff`
5. `Cache-Control` = `no-store`

- `AsciiName(s)`: walk `s` by Unicode scalar
  (`Rune.DecodeFromUtf16`). `"` and `\` are dropped. Each scalar outside
  `0x20..0x7E`, and each invalid UTF-16 unit, becomes one `_`. Everything
  else is kept. (`Safe` already removes `"`, `\` and control chars. The
  rules are applied again so the function is safe on its own.) An empty
  result becomes `attachment`.
- `PercentEncode(s)`: `Encoding.UTF8.GetBytes(s)` (lone surrogates
  become U+FFFD). The bytes `A-Z a-z 0-9 - . _ ~` are kept, and every
  other byte becomes `%XX` with upper-case hex.

### L. `LinkTexts`

- `TooBig(bytes)`: `n = ceil(bytes / 1,048,576)` (integer math:
  `(bytes + 1048575) / 1048576`), invariant culture, then
  `The attachment is <n> MB; attachment_link handles up to 100 MB. Use get_attachment to save it on the Windows side.`
  `bytes < 0` → `ArgumentOutOfRangeException`.
- `RateLimited(m)`: `Too many download links in the last 10 minutes (20). Try again in <m> min.`
- `Url(port, token)`: `http://127.0.0.1:` + port (invariant) + `/files/` + token.
- `Curl(shellName, url)`: `curl -fsS -H "Authorization: Bearer $CLIPPY_TOKEN" -o '` + shellName + `' '` + url + `'`.
  The `$CLIPPY_TOKEN` is literal text. The real token is never passed
  in.
- `FormatExpires(at, tz)`: `TimeZoneInfo.ConvertTime(at, tz).ToString("yyyy-MM-dd'T'HH:mm:sszzz", CultureInfo.InvariantCulture)`
  (same format as `FreeTimeFinder`/`MailQueries`).
- Copy the constant texts byte for byte from SPEC §24.1–§24.3 (note the
  ASCII apostrophes in `can't`/`isn't` and `~/.bashrc`).

### M. `LogRedactor`

Add `FilesLinkRegex` and apply it in `Redact` after the existing
replacements: `/files/` (any case) followed by 20 or more
`[A-Za-z0-9_-]` characters becomes `/files/[redacted]`. The text after
the token (`?x`, ` HTTP/1.1`, `"`) is kept. Existing behavior and tests
are unchanged.

### `AttachmentLinksTests`

Tokens
1. `NewToken()` ×1000: every one has length 43, matches
   `^[A-Za-z0-9_-]{43}\z`, and all are distinct.
2. `IsWellFormedToken`: a `NewToken()` → true. `null`, `""`, 42 chars,

## Spec changes

Proposed by the architect (low-risk, reversible, no hard rule touched).
The caller applies them to SPEC.md. This brief already follows them.

1. **§24.2 PathPolicy check.** The text says the full temp *file* path is
   checked with `PathPolicy.Check(path, [LinkPaths.Folder], Write)`. But
   `Write` mode creates the path as a **directory** (§12), so the
   following `SaveAsFile` would fail. Replace it with: "The link folder is
   checked with `PathPolicy.Check(LinkPaths.Folder, [LinkPaths.Folder], Write)`,
   and Core refuses it when the folder itself is a junction/symlink
   (`PathPolicy` allows a link as the root). The file path is that folder
   plus a generated name matching `^[0-9a-f]{32}\.bin$`
   (`AttachmentLinks.PrepareTempPath`)." The policy is still applied, and
   no tool input reaches the path.
2. **§24.2 start-up cleanup.** Replace "every file in the folder is
   deleted" with "every file directly in the folder whose name matches
   `^[0-9a-f]{32}\.bin$` is deleted. Other files and subfolders are left
   alone. The cleanup is skipped (Warning) when the folder can't be made
   private or is a junction/symlink." This deletes less, and never deletes
   through a link.
3. **§24.3 limits, precise.** Expired links don't count toward the open
   limits. A link is expired when `now >= expires_at`. The order is
   size, count, bytes, rate. The pre-save check refuses when the open
   bytes are already ≥ 200 MiB, and registering a saved file refuses
   when open + size > 200 MiB (the file is deleted). The rolling window
   counts successful creations only, and clearing the store doesn't reset
   it. `<n>` MB = bytes ÷ 1,048,576 rounded **up**. `<n>` min = minutes
   until the oldest counted creation leaves the window, rounded up, at
   least 1.
4. **§24.4 header encoding.** The ASCII `filename` replaces each non-ASCII
   *character* (Unicode scalar) with one `_`. `filename*` percent-encodes
   UTF-8 bytes, keeping only `A-Z a-z 0-9 - . _ ~`.
5. **§24.4 / §5.1 log mask.** `/files/[A-Za-z0-9_-]{20,}` is matched
   case-insensitively (ASP.NET routing is case-insensitive). Add to the
   §5.1 "Redaction is defensive" bullet: "and `/files/<20+ token chars>`
   becomes `/files/[redacted]` (M17)."
6. **§5.1 Storage table.** Add the row: "Download link temp files (§24.2,
   M17) | `%LOCALAPPDATA%\ClippysRevenge\links\` (user-only ACL; each file
   deleted after its one download, on expiry, on clear, and at start-up)".
7. **§3 layout (Core).** Add
   `AttachmentLinks.cs  AttachmentLinks store (tokens, limits, single use, sweep, cleanup), ILinkFileSystem, AttachmentLinkException (§24.3)`
   and
   `AttachmentLinks.Helpers.cs  LinkPaths, LinkFileName, FileDownloadHeaders, LinkTexts, AttachmentLinkResult (§24.1–§24.5)`.
