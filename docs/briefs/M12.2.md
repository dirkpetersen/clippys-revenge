# M12.2 `UpdateClient` and `UpdateService`

Base: `dev` with M12.1 merged. Core only. It runs in parallel with M12.3
and doesn't use M12.3's types. The service installs through a callback
(`RequestInstall`) that M12.4 wires to M12.3's `UpdateInstall.BeginAsync`.

## Goal

Talk to GitHub and run the update schedule (SPEC §20.3–§20.5, §20.8,
§20.10, §6.7). `UpdateClient` looks up the latest full release and
downloads `SHA256SUMS.txt` and `ClippysRevenge.exe` into the staging
folder. It uses only the pinned URLs, follows redirects by hand through
the host allow-list, enforces the size and time limits, and checks the
hash, size and `MZ` header. `UpdateService` is a `BackgroundService`. It
checks at most weekly (installed copies, `Updates` ≠ `Off`), notifies or
downloads per mode, installs during the start-up window when Clippy is
idle, and serves the About window: `Status`, `Changed`,
`CheckNowAsync`, `UpdateNowAsync`.

## Hard rules that apply here

- **Pinned endpoints only.** Every request URL comes from
  `UpdateEndpoints.LatestReleaseApi` or `UpdateEndpoints.AssetUrl(tag, name)`,
  or is a redirect target that passed `UpdateEndpoints.IsAllowedRedirect`.
  Never use `browser_download_url`, `html_url` or any other URL from the
  JSON. No URL or host literal in `UpdateClient.cs` or `UpdateService.cs`
  (M12.4's scan allows them only in `UpdateRelease.cs`).
- **No user data.** Requests carry only the headers listed in §A.1. No
  `Authorization`, no cookies (`UseCookies = false`), no query strings
  added by Clippy.
- **Never weaken verification.** A download is used only after the exact
  size, the SHA-256 from `SHA256SUMS.txt` (and the asset `digest` when
  present), `MZ` and the exe version all match. Any failure deletes the
  file.
- **No process starts, no file swaps here.** Installing means calling
  `RequestInstall`. `.Kill(`, `Process` and `File.Move` on the installed
  exe are M12.3/M12.4.
- `new HttpClient(` only in `UpdateClient.cs` (allowed by the M12.4
  scan, together with `ConnectionTester.cs` and `AnthropicApiModel.cs`).
- Logs carry versions, tags, hosts, sizes, outcomes, durations and
  exception **type names**. No exception messages from the network
  stack (they can be long and noisy); reasons come from `UpdateTexts`.

## Public API

### `UpdateClient.cs`

```csharp
namespace ClippysRevenge.Core;

public enum UpdateCheckOutcome { Ok, NoRelease, Failed }

/// <summary>Ok: Release set, Error null. NoRelease: both null. Failed: Error = an UpdateTexts reason.</summary>
public sealed record UpdateCheckResult(UpdateCheckOutcome Outcome, ReleaseInfo? Release, string? Error);

/// <summary>A verified file in the staging folder (StagedFileName of Version).</summary>
public sealed record StagedDownload(SemVersion Version, string Path, string Sha256, long Size)
{
    public StagedUpdate ToStaged();          // new StagedUpdate(Version.ToString(), Sha256, Size)
}

/// <summary>Message = Reason = an UpdateTexts reason (SPEC 20.10).</summary>
public sealed class UpdateDownloadException : Exception
{
    public UpdateDownloadException(string reason, Exception? inner = null);
    public string Reason { get; }
}

public sealed class UpdateClient : IDisposable
{
    public static readonly TimeSpan ApiTimeout = TimeSpan.FromSeconds(15);
    public static readonly TimeSpan SumsTimeout = TimeSpan.FromSeconds(60);
    public static readonly TimeSpan ExeTimeout = TimeSpan.FromMinutes(10);
    public static readonly TimeSpan StallTimeout = TimeSpan.FromSeconds(60);
    public static readonly TimeSpan ConnectTimeout = TimeSpan.FromSeconds(15);
    public const int MaxRedirects = 5;
    public const int BufferSize = 81_920;

    /// <param name="handler">Tests pass a fake (not disposed by the client). Null → the default handler (§A.1),
    /// owned and disposed by the client.</param>
    /// <exception cref="ArgumentNullException">running is null.</exception>
    public UpdateClient(SemVersion running, HttpMessageHandler? handler = null, TimeProvider? time = null);

    /// <summary>GET releases/latest (SPEC 20.3, 20.4). Never throws except OperationCanceledException when ct is
    /// cancelled.</summary>
    public Task<UpdateCheckResult> GetLatestAsync(CancellationToken ct);

    /// <summary>Downloads SHA256SUMS.txt and returns the expected exe hash (lower-case hex). Checks the asset digest
    /// too, when the release has one.</summary>
    /// <exception cref="UpdateDownloadException">Any failure (reason in Message).</exception>
    /// <exception cref="OperationCanceledException">ct was cancelled.</exception>
    public Task<string> GetExpectedHashAsync(ReleaseInfo release, CancellationToken ct);

    /// <summary>GetExpectedHashAsync, then the exe to &lt;stagingDir&gt;\ClippysRevenge-&lt;v&gt;.exe.partial, verified,
    /// renamed to ClippysRevenge-&lt;v&gt;.exe (overwriting). progress gets 0–100, only when the value grows.</summary>
    /// <exception cref="UpdateDownloadException">Any failure; the partial and final file are deleted first.</exception>
    /// <exception cref="OperationCanceledException">ct was cancelled; the partial file is deleted.</exception>
    public Task<StagedDownload> DownloadAsync(ReleaseInfo release, string stagingDir, IProgress<int>? progress,
        CancellationToken ct);

    public void Dispose();
}
```

## Behavior

### A. `UpdateClient`

**A.1 HTTP setup.**
- Default handler: `new SocketsHttpHandler { AllowAutoRedirect = false, UseCookies = false, AutomaticDecompression = DecompressionMethods.None, ConnectTimeout = ConnectTimeout, PooledConnectionLifetime = TimeSpan.FromMinutes(5) }`.
  `UseProxy` stays at its default (true, system proxy). No
  `ServerCertificateCustomValidationCallback`.
- `HttpClient(handler, disposeHandler: owned) { Timeout = Timeout.InfiniteTimeSpan }`.
  Each operation has its own timeout CTS made with
  `new CancellationTokenSource(timeout, time)` and linked with `ct`. A
  cancellation while `ct` isn't cancelled is a timeout.
- Every request is a new `HttpRequestMessage(HttpMethod.Get, uri)` with
  `Version = HttpVersion.Version11`, `VersionPolicy = RequestVersionOrHigher`,
  `HttpCompletionOption.ResponseHeadersRead`, and only these headers:
  - lookup: `User-Agent: UpdateEndpoints.UserAgent(running)`,
    `Accept: application/vnd.github+json`,
    `X-GitHub-Api-Version: 2022-11-28`;
  - downloads (every hop): `User-Agent` as above,
    `Accept: application/octet-stream`.

  Set `User-Agent` with `request.Headers.TryAddWithoutValidation("User-Agent", …)`
  so the exact string is sent.

**A.2 `GetLatestAsync`.**
- `GET UpdateEndpoints.LatestReleaseApi`, `ApiTimeout` for the whole call
  (headers and body).
- `200`: read the body with `ReadCapped(stream, ReleaseParser.MaxJsonBytes)`
  (read up to cap + 1 bytes; over the cap → `Failed(ReasonBadJson)`),
  decode as UTF-8 (invalid bytes → replacement chars, then the parser
  decides), `ReleaseParser.Parse` → `Ok(release)` or `Failed(error)`.
- `404` → `NoRelease`.
- `403`, `429` → `Failed(ReasonRateLimited)`.
- Any other status (3xx included, since redirects aren't followed here)
  → `Failed(ReasonHttp(code))`.
- Timeout → `Failed(ReasonTimeout)`. `HttpRequestException`,
  `IOException`, `SocketException`, `AuthenticationException` or any
  other exception that isn't `ct` cancellation →
  `Failed(ReasonNetwork(ex.GetType().Name))`.
- Log at Information:
  `"Update lookup: {Outcome} {Tag} in {Ms} ms"` (tag or `-`); failures
  at Warning with the reason.

**A.3 Following redirects (downloads only).** `SendFollowingAsync(Uri first, CancellationToken linked)`:
- `current = first` (`AssetUrl`, a `github.com` URL, which itself passes
  `IsAllowedRedirect`). Up to `MaxRedirects + 1` requests:
  - `301`, `302`, `303`, `307`, `308`: `Location` missing →
    `ReasonHttp(code)`. `target = new Uri(current, location)` (handles
    relative). `!IsAllowedRedirect(target)` →
    `ReasonRedirect(target.IsAbsoluteUri ? target.Host : "(none)")`.
    Dispose the response, `current = target`, and continue.
  - `200` → return the response.
  - `403`, `429` → `ReasonRateLimited`. Other → `ReasonHttp(code)`.
- More than `MaxRedirects` redirects → `ReasonHttp(<last code>)`.
- Log each hop's host at Debug.

**A.4 `GetExpectedHashAsync(release)`.**
- `SumsTimeout` overall. `SendFollowingAsync(AssetUrl(release.Tag, SumsAssetName))`.
  Content-Length present and over `ReleaseParser.MaxSumsBytes` →
  `ReasonNoAssets`. Body via `ReadCapped(…, MaxSumsBytes)`; over →
  `ReasonNoAssets`. UTF-8 decode, then
  `Sha256Sums.Find(text, ExeAssetName)`. Null → `ReasonSumsMissing`.
- `release.ExeDigest` not null and `!UpdateHash.Same(digest, hash)` →
  `ReasonHashMismatch`.
- Timeout → `ReasonDownloadTimeout`. Network exceptions →
  `ReasonNetwork(type)`.

**A.5 `DownloadAsync(release, stagingDir, progress, ct)`.**
1. `expected = await GetExpectedHashAsync(release, ct)`.
2. `Directory.CreateDirectory(stagingDir)`. `partial =
   Path.Combine(stagingDir, UpdatePaths.StagedFileName(v) + UpdatePaths.PartialSuffix)`,
   `final = Path.Combine(stagingDir, UpdatePaths.StagedFileName(v))`.
3. `ExeTimeout` overall CTS, plus a stall CTS made with
   `new CancellationTokenSource(Timeout.InfiniteTimeSpan, time)`, all
   linked. `stall.CancelAfter(StallTimeout)` before the request, and
   again after each successful read.
4. `SendFollowingAsync(AssetUrl(release.Tag, ExeAssetName))`. A
   `Content-Length` that is present and differs from `release.ExeSize`
   → `ReasonSizeMismatch`.
5. `FileStream(partial, FileMode.Create, FileAccess.Write, FileShare.None, BufferSize, useAsync: true)`.
   Loop: read into a `BufferSize` buffer. `IncrementalHash.CreateHash(SHA256)`
   appends each chunk. Keep the first two bytes. Count bytes; a count
   over `release.ExeSize` → `ReasonSizeMismatch` (stop reading). Write
   the chunk; `IOException`/`UnauthorizedAccessException` from the
   **write or the open** → `ReasonSaveFailed(type)`. Report
   `(int)(count * 100 / ExeSize)` when it is larger than the last value
   reported.
6. At the end: `count != ExeSize` → `ReasonSizeMismatch`; first two
   bytes not `0x4D 0x5A` → `ReasonNotExe`; `!Same(hash, expected)` →
   `ReasonHashMismatch`. Flush and close the stream.
7. `File.Move(partial, final, overwrite: true)`. Failure →
   `ReasonSaveFailed(type)`.
8. Return `new StagedDownload(v, final, hash, count)`. Log Information
   `"Update {Version} downloaded: {Bytes} bytes in {Ms} ms"`.
- Overall timeout or stall → `ReasonDownloadTimeout`. Read-side
  `HttpRequestException`/`IOException` → `ReasonNetwork(type)`. On any
  failure or cancellation, delete `partial` and `final` (best effort,
  swallow I/O errors), then throw.

### B. `UpdateService`

**B.1 State.**
- `_state`: an `UpdateState`. Installed: `Store.Load()` at construction,
  and every change goes through `Mutate(change)` = `_state = Store.Update(change)`;
  an `IOException`/`UnauthorizedAccessException` there is logged
  (Warning, type) and the change is applied to the in-memory copy
  instead. Not installed: the store is **never** read or written. The
  state lives only in memory (SPEC §20.6).
- `_op`: a `SemaphoreSlim(1, 1)`. Every check, download or install takes
  it with `Wait(0)`. If it's taken, the call returns at once (no-op).
- `_activity`, `_percent`, `_activityVersion`, `_actionMessage`: under a
  private lock, together with `_state`. Each change raises `Changed`
  (outside the lock). `_percent` changes raise `Changed` only when the
  integer value changes.
- `Status` builds an `UpdateStatus` from these and
  `Settings().Updates`: `LastCheckUtc`, `LastError`, `LatestTag`,
  `LatestPublishedUtc`, `StagedVersion = _state.Staged?.Version`,
  `FailedVersion`.

**B.2 `ExecuteAsync`.**
`await Task.Delay(UpdatePolicy.FirstCheckDelay, time, ct)`, then loop:
`await RunAutomaticAsync(ct)`, then
`await Task.Delay(UpdatePolicy.EvaluateInterval, time, ct)`. Any
exception other than cancellation on stop is logged (Error, type) and
the loop goes on. Returns on stop.

**B.3 `RunAutomaticAsync(ct)`** (SPEC §20.8):
1. `!Installed` → false. `Settings().Updates == Off` → false.
2. `_op.Wait(0)` fails → false. (Release `_op` in a `finally`.)
3. Reload `_state` from the store (it may have been changed by
   `UpdateStartup` in M12.3). `!UpdatePolicy.IsDue(_state, now)` → false.
4. `r = await CheckCoreAsync(ct)` (§B.5). Return true from here on.
5. `r.Outcome != Ok` → done.
6. `latest = r.Release`. `!UpdatePolicy.IsUpdate(latest.Version, running, _state.FailedVersion)`
   → `DropStaged(keep: null)` (§B.7) → done.
7. Re-read the mode:
   - `Off` → done.
   - `Notify` → `NotifyOnce(latest.Version, BalloonTexts.UpdateAvailable(v))` → done.
   - `Install`:
     - `staged = ReusableStaged(latest.Version)` (§B.7), or
       `await DownloadCoreAsync(latest, ct)` (§B.6). Null (failed) → done.
     - If `UpdatePolicy.InStartupWindow(StartedUtc, now)`:
       `if (await InstallWhenIdleAsync(staged, StartupIdleWait, manual: false, ct)) return true;`
       (the app is exiting).
     - `NotifyOnce(latest.Version, BalloonTexts.UpdateReady(v))`.

**B.4 Manual calls.**
- `CheckNowAsync(ct)`: `_op.Wait(0)` else return. `_actionMessage = null`.
  `r = await CheckCoreAsync(ct)`. `Failed` → `_actionMessage = UpdateTexts.CheckFailed(r.Error)`.
  No download and no balloon in any mode. Works when not installed
  (in-memory state).
- `UpdateNowAsync(ct)`: `!Installed` → `_actionMessage = InstallFailed(ReasonNotInstalled)`,
  return. `_op.Wait(0)` else return. `_actionMessage = null`.
  1. `latest = _state.LatestVersion`. If null: `r = await CheckCoreAsync(ct)`.
     `Failed` → `_actionMessage = CheckFailed(r.Error)`, return. `latest`
     is then the new value or null.
  2. `latest == null || !UpdatePolicy.IsNewer(latest, running)` → return
     (the status line says "You have the latest version.").
  3. `staged = ReusableStaged(latest)`, else `DownloadCoreAsync`
     (needs the `ReleaseInfo`: if the last lookup's release object isn't
     cached for this tag, run `CheckCoreAsync` first; keep the last
     `ReleaseInfo` in a field). Failure →
     `_actionMessage = DownloadFailed(reason)`, return.
  4. `await InstallWhenIdleAsync(staged, ManualIdleWait, manual: true, ct)`.
  `FailedVersion` doesn't block **Update now** (`IsNewer`, not
  `IsUpdate`).

**B.5 `CheckCoreAsync(ct)`.** Activity `Checking`. `r = await Client.GetLatestAsync(ct)`.
`now = time.GetUtcNow()`. Then:
- `Ok`: `Mutate(s => { s.LastCheckUtc = now; s.LastAttemptUtc = now; s.LastError = null; s.LatestTag = r.Release.Tag; s.LatestPublishedUtc = r.Release.PublishedUtc; })`.
  Keep `r.Release` in `_lastRelease`. Event (`ActivityKind.Update`):
  `EventAvailable(v)` when `IsNewer(v, running)`, else
  `EventUpToDate(running)`.
- `NoRelease`: as `Ok` but with `LatestTag = null`,
  `LatestPublishedUtc = null`, and the event `EventUpToDate(running)`.
- `Failed`: `Mutate(s => { s.LastAttemptUtc = now; s.LastError = r.Error; })`.
  Event `EventCheckFailed(r.Error)`. Log Warning.
- Activity back to `None` in a `finally`. Return `r`.

**B.6 `DownloadCoreAsync(release, ct)`** → `StagedUpdate?`:
- Activity `Downloading`, `_activityVersion = v`, `_percent = 0`. The
  progress callback is a small private `IProgress<int>` that sets
  `_percent` directly (not `Progress<T>`, which captures a
  `SynchronizationContext`).
- `d = await Client.DownloadAsync(release, Paths.StagingDir, progress, ct)`.
- Activity `Verifying`. `ver = ReadExeVersion(d.Path)`.
  `ver != v.ToString()` (ordinal) → delete `d.Path` (best effort), and
  treat as the failure `ReasonVersionMismatch`.
- Success: `Mutate(s => { s.Staged = d.ToStaged(); s.LastError = null; })`,
  `DropStaged(keep: v)`, event `EventStaged(v)`, log Information, return
  `d.ToStaged()`.
- `UpdateDownloadException ex` (or the version mismatch):
  `Mutate(s => s.LastError = reason)`, event `EventDownloadFailed(reason)`,
  log Warning, return null.
- Activity back to `None` in a `finally` (unless an install follows,
  which sets its own activity).

**B.7 Staging helpers.**
- `ReusableStaged(v)`: `_state.Staged` with `Version == v.ToString()`,
  whose file `Paths.StagedExePath(v)` exists with `Length == Size`.
  Otherwise null. (The SHA-256 is checked again by `RequestInstall` in
  M12.3; don't hash here.)
- `DropStaged(keep)`: if `_state.Staged` isn't `keep`, clear it
  (`Mutate`). Delete every file in `Paths.StagingDir` (if the folder
  exists) whose name parses with `UpdatePaths.TryParseStagedFileName`
  to a version other than `keep`, and every `*.partial`. Swallow and log
  (Debug, type) I/O errors. Never delete anything else, and never
  outside `StagingDir`.

**B.8 `InstallWhenIdleAsync(staged, maxWait, manual, ct)`** → bool:
- If `IsBusy()`: Activity `WaitingForIdle`. Poll every
  `UpdatePolicy.IdlePoll` (`Task.Delay(…, time, ct)`) until `!IsBusy()`
  or `maxWait` has passed. Still busy → Activity `None`; if `manual`,
  `_actionMessage = UpdateTexts.Busy`; return false.
- Activity `Installing`, `_activityVersion = staged.Version`. Event
  `EventInstalling(v)`. Log Information.
  `err = await RequestInstall(staged, ct)`.
- `err == null` → return true. Keep Activity `Installing` (the app is
  exiting).
- Else `Mutate(s => s.LastError = err)`, event `EventInstallFailed(err)`,
  log Warning, Activity `None`, and if `manual`,
  `_actionMessage = InstallFailed(err)`. Return false.
- An exception from `RequestInstall` (it shouldn't throw) is handled
  like `err = ReasonReplaceFailed(type)`.

**B.9 `NotifyOnce(v, text)`.** `_state.NotifiedVersion == v.ToString()`
→ nothing. Else `if (Balloons.Post(text)) Mutate(s => s.NotifiedVersion = v.ToString())`.

**B.10 Events and logs.** Events use `Hub.Event(ActivityKind.Update, text)`
with no mailbox and no duration. Never log full exception messages;
log reasons and type names.

## Tests

`FakeGitHubHandler` maps an absolute URI to a queue of responses:
status, headers (`Location`, `Content-Length`), body bytes (optionally
split into chunks, with an optional `Func<int, CancellationToken, Task>`
before each chunk so a test can stall), or "hang until cancelled". It
records each request's URI and headers. Unmapped URIs fail the test.

Constants used below: `Api = UpdateEndpoints.LatestReleaseApi`,
`ExeUrl = AssetUrl("v0.0.6", "ClippysRevenge.exe")`,
`SumsUrl = AssetUrl("v0.0.6", "SHA256SUMS.txt")`,
`Cdn = https://release-assets.githubusercontent.com/x/y?sig=1`.
The fake exe is `"MZ"` + 1 MiB of seeded random bytes (so it meets
`MinExeBytes`). The release JSON is a builder, so tests can vary
fields.

### T1 `UpdateClientTests`
1. Lookup ok: exactly one request to `Api`, with headers
   `User-Agent: ClippysRevenge/0.0.5`, `Accept: application/vnd.github+json`,
   `X-GitHub-Api-Version: 2022-11-28`, and **no** `Authorization` or
   `Cookie`. Result `Ok`, tag `v0.0.6`.
2. 404 → `NoRelease`. 403 → `Failed(rate limit)`. 429 → the same.
   500 → `Failed("GitHub answered HTTP 500")`. 302 with a `Location` →
   `Failed("GitHub answered HTTP 302")`, and the location isn't
   requested.
3. Body over 1 MiB → `Failed(BadJson)`. Pre-release JSON →
   `Failed(NotFullRelease)`.
4. Hang + `ManualTimeProvider` advanced by 15 s → `Failed(ReasonTimeout)`.
   Caller's `ct` cancelled → `OperationCanceledException`.
5. Handler throws `HttpRequestException` →
   `Failed("network error (HttpRequestException)")`.
6. Download happy path: `SumsUrl` → 302 → `Cdn` (sums text with the
   right hash) and `ExeUrl` → 302 → `Cdn2` (the exe). Result:
   `StagedDownload` with the hash and size, the file
   `ClippysRevenge-0.0.6.exe` exists with the same bytes, no `.partial`
   left. Each hop sends only `User-Agent` and
   `Accept: application/octet-stream`. Progress values strictly
   increase and end at 100.
7. A redirect chain `github.com` → `objects.githubusercontent.com` →
   `release-assets…` works (3 hops). A sixth redirect fails with
   `ReasonHttp(302)`.
8. Redirect to `https://evil.example/x` → `ReasonRedirect("evil.example")`,
   and the evil URL is never requested. Redirect to `http://release-assets.githubusercontent.com/x`
   → `ReasonRedirect(…)`. A relative `Location: /a/b` resolves against
   `github.com` and is followed.
9. Sums without an exe line → `ReasonSumsMissing`. Sums over 64 KiB
   (body or Content-Length) → `ReasonNoAssets`.
10. Release `ExeDigest` differs from the sums hash → `ReasonHashMismatch`
    before any exe request.
11. Exe body one byte short → `ReasonSizeMismatch`. One byte long → the
    same (the read stops). `Content-Length` header ≠ `ExeSize` →
    `ReasonSizeMismatch` before reading. Body not starting with `MZ` →
    `ReasonNotExe`. One flipped byte → `ReasonHashMismatch`. After each
    failure, neither `.partial` nor the final file exists.
12. Stall: a chunk delay that waits for cancellation, and time advanced
    by 60 s → `ReasonDownloadTimeout`; the partial is deleted. The
    10-minute overall limit, with chunks every 59 s → also
    `ReasonDownloadTimeout`.
13. A read-only staging folder (Windows-only: set
    `FileAttributes.ReadOnly` on a pre-created `.partial`, or point the
    staging dir at a file path) → `ReasonSaveFailed(<type>)`.
14. An existing `ClippysRevenge-0.0.6.exe` is overwritten by a
    successful download.

### T2 `UpdateServiceTests`
Harness: temp `UpdatePaths` (via `UpdatePaths.Default(tempRoot)`), a
real `UpdateStateStore`, `ManualTimeProvider` at `2026-11-20T12:00Z`,
`ActivityHub`, `BalloonCenter` (same time provider), a settings object,
`IsBusy` from a mutable flag, `ReadExeVersion` returning a configurable
value (default `"0.0.6"`), and `RequestInstall` recording calls and
returning a configurable result (default null). Running `0.0.5`,
installed, `StartedUtc = now`.

1. Not installed → `RunAutomaticAsync` false, no request, no state file
   created.
2. Mode `Off` → false, no request.
3. Not due (last check 1 day ago) → false, no request.
4. Due, release `v0.0.5` → true. `LastCheckUtc`/`LastAttemptUtc` = now,

   download, no balloon.

    → `LastError` set, event `update failed: …`, Activity `None`,

    `Staged` null, `LastError` = version mismatch, event `update download

    balloon. Latest `v0.0.7` → downloaded.
13. Reuse: `Staged` 0.0.6 with an existing file of the right size → no

14. Latest not an update while `Staged` 0.0.6 exists (e.g. running
