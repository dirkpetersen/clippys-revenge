# M10.2 Live Outlook tests and runner script

Base: branch `chain/X` (HEAD at the time of writing; it holds the M9.4 file log
and the M9.5 watchdog). Read the code there, not on `dev`.

## Goal

Add one opt-in live suite (`[Trait("live","outlook")]`, SPEC §15) that the
user runs once on their own machine with `CLIPPY_LIVE=1`. The suite checks
the real App COM code against the user's real classic Outlook: attach-only
(§4), stores and folders (§8), Table paging and `ReadForIndex` (§8 Details
M5.3), one end-to-end sync into a temporary index (§10), the `get_message`
live fallback (§8 GetItem chain, §11.2), attachment listing and saving
through `PathPolicy` (§11.3, §11.4, §12), `create_draft` and `reply_draft`
(§8, §11.5, §11.6), a meeting in `MeetingInviteMode.DraftOnly` (§6.6, §11.9),
`list_events` (§11.7) and `find_free_times` (§11.8). It must also settle the
open live items listed under "Carry-forward notes" in `docs/PLAN.md`:
calendar DASL dates in local time vs UTC, the store owner SMTP lookup when
offline, and Move-before-Save of reply drafts into a shared Drafts folder.
It also covers §18 open item 1 (whether marking a message read bumps
`LastModificationTime`). The 2026-11-12 smoke test showed that a cached-mode
Outlook with an unreachable server can hang the first COM call. So the suite
runs **sequentially**, sends **every** COM call through the M9.5 watchdog,
**skips with a clear message** when Outlook is offline or not responding
(it never hangs), cleans up everything it creates, and checks that nothing
was sent. A runner script (`scripts/run-live-tests.ps1`) does the
pre-checks, enforces a hard timeout and prints a summary.

## Design decision: how the tests reach App code

The App code is `internal`, lives in a `net10.0-windows` WinExe, and embeds
the Outlook interop types. A `ProjectReference` from the tests to the App
does not work: `OutlookWorker : ComWorker<Outlook.Application>` and
`Func<Outlook.Application, T>` are generic instantiations over an embedded
interop type, so using them across an assembly boundary fails with CS1769.
It would also pull WinForms into the test project.

So on Windows, the test project **compiles the App's Outlook source files
into the test assembly** as linked `<Compile>` items, from an explicit list,
and references the Outlook PIA the same way the App does (embedded,
compile-time only). The tests then exercise the exact production code,
including the M9.5 watchdog, through `OutlookWorker`. Off Windows, nothing
changes: the project stays `net10.0` with Core only, and `Live/` is not
compiled.

```csharp
namespace ClippysRevenge.Core.Tests.Live;

[CollectionDefinition(Name, DisableParallelization = true)]
public sealed class LiveOutlookCollection : ICollectionFixture<LiveOutlook>

/// <summary>One worker, one temp root and one ledger for the whole live run.</summary>
public sealed class LiveOutlook : IAsyncLifetime
{
    public static bool Enabled { get; }              // OperatingSystem.IsWindows() && env CLIPPY_LIVE == "1"
    public string RunToken { get; }                  // "clippy-live-" + yyyyMMddHHmmss (local) + "-" + 4 lowercase hex chars
    public string TempRoot { get; }                  // Path.Combine(Path.GetTempPath(), "clippy-live", RunToken)
    public string AllowedDir { get; }                // TempRoot\allowed  (created)
    public string? SharedMailbox { get; }            // EmailAddress.Normalize(env CLIPPY_LIVE_SHARED), or null when unset/blank
    public string ConnectionMode { get; }            // e.g. "olCachedConnectedFull (700)", "unknown" before preflight
    public string? NotReadyReason { get; }           // null = preflight passed
    public ActivityHub Hub { get; }
    public Settings Settings { get; }                // see Behavior: fixture settings
    public MailboxIndexes Indexes { get; }           // TempRoot\index; own + SharedMailbox when set

    internal OutlookWorker Worker { get; }
    internal OutlookStores Stores { get; }
    internal OutlookMail Mail { get; }

    public ValueTask InitializeAsync();
    public ValueTask DisposeAsync();

    /// <summary>Assert.Skip(NotReadyReason) when set. If the worker is NotResponding/Unavailable,
    /// waits up to 60 s for Available first, then skips with SkipTexts.NotResponding("waiting for Outlook", 60).</summary>
    public Task RequireReadyAsync();

    /// <summary>Worker.RunAsync(work, Interactive, TestContext.Current.CancellationToken, timeout).
    /// OutlookNotRespondingException → Assert.Skip(SkipTexts.NotResponding(step, seconds));
    /// OutlookUnavailableException (not the NotResponding subtype) → Assert.Skip(SkipTexts.NotRunning).</summary>
    internal Task<T> RunAsync<T>(string step, Func<Outlook.Application, T> work, TimeSpan? timeout = null);

    /// <summary>Records an item for cleanup. Call right after the item exists, before any assert.</summary>
    public void Track(TrackedItem item);

    /// <summary>Deletes the item, then deletes any item whose subject contains RunToken from the Deleted Items
    /// of the own store and of the item's store. Removes it from the ledger on success. Never throws: returns false and logs.</summary>
    public Task<bool> DeleteAsync(TrackedItem item);

    /// <summary>Appends "LIVE-RESULT: {key}: {value}" to the results file and the test output.</summary>
    public void Result(string key, string value);

    /// <summary>Runs the end-to-end sync once (lazily, under a SemaphoreSlim) and caches the outcome.</summary>
    public Task<LiveSyncOutcome> EnsureSyncedAsync();

    /// <summary>Sent Items and Outbox item counts of the own store (and of SharedMailbox when given).</summary>
    public Task<SentSnapshot> SnapshotSentAsync(string? mailbox = null);

    /// <summary>Asserts counts equal to the snapshot and that no item in Sent Items or Outbox has RunToken in its subject.</summary>
    public Task AssertNothingSentAsync(SentSnapshot before);
}

public enum TrackedKind { Draft, Meeting }
public sealed record TrackedItem(TrackedKind Kind, string Mailbox, string EntryId, string StoreId, string Subject);
public sealed record SentSnapshot(string Mailbox, int SentItems, int Outbox);
public sealed record LiveSyncOutcome(MailboxSyncResult? Result, bool TimedOut, long IndexedCount,
    DateTimeOffset StartedUtc, DateTimeOffset CutoffUtc);

public static class SkipTexts
{
    public const string NotLive = "Set CLIPPY_LIVE=1 with classic Outlook running (scripts/run-live-tests.ps1 does this).";
    public const string NotRunning = "Outlook is not running. Start classic Outlook and run the live tests again.";
    public static string NotResponding(string step, int seconds) =>
        $"Outlook did not answer within {seconds} s during {step}. It may be offline, busy or showing a dialog (for example a security prompt). Skipped; nothing was sent.";
    public static string NoData(string what) => $"No {what} found in the mailbox; nothing to test.";
    public const string NoShared = "Set CLIPPY_LIVE_SHARED to the SMTP address of a shared mailbox open in Outlook to run this test.";
}

/// <summary>Fails the test if the confirmation dialog is ever requested (DraftOnly must never ask).</summary>

/// <summary>Wraps OutlookMeetingCalendar. CreateAsync throws InvalidOperationException("Live test refused: only SaveDraft is allowed.")
/// BEFORE delegating unless decision.Action == InviteAction.SaveDraft. Records the decision it saw.</summary>
internal sealed class DraftOnlyCalendar(IMeetingCalendar inner) : IMeetingCalendar
{
    public InviteDecision? LastDecision { get; }
}
```

Every live test class looks like this:
`[Collection(LiveOutlookCollection.Name)] [Trait("live","outlook")] [Trait("os","windows")] public sealed class X(LiveOutlook fx, ITestOutputHelper output)`.
Every test is `async Task`, has `[Fact(Timeout = …)]` (see Timeouts), and
starts with `await fx.RequireReadyAsync();`.

## Behavior

### Safety (all of these are mandatory)

- No `.Send(`, `.Display(`, `OutlookLauncher`, `new Outlook.Application`,
  `Activator.CreateInstance` or `CoCreateInstance` in any test source.
  `LiveSafetyScanTests` enforces it. The only path to `.Send()` is the linked
  `OutlookCalendar.CreateMeeting`. The tests reach it only through
  `MeetingInvites` with `Settings.MeetingInviteMode = DraftOnly`,
  `RefusingConfirmer`, and `DraftOnlyCalendar`, which refuses anything but
  `SaveDraft` before COM runs.
- Every test that creates something does this: (1) take `SnapshotSentAsync`
  before, (2) `Track` the item the moment its entry id is known, (3) in
  `finally`, call `DeleteAsync`, then (4) `AssertNothingSentAsync`. Mail
  items also assert `item.Sent == false`, and that the parent folder is the
  store's Drafts folder (compare folder EntryIDs). Meetings assert
  `PidLidFInvited` is false or absent (DASL
  `http://schemas.microsoft.com/mapi/id/{00062002-0000-0000-C000-000000000046}/8229000B`,
  read through `PropertyAccessor`; a missing property counts as false).
- Every subject the tests create starts with `[<RunToken>] `. Recipients
  are only the current user's own address (from
  `OutlookFreeBusySource.GetCurrentUserAsync`). Search by token with
  `@SQL="urn:schemas:httpmail:subject" LIKE '%<RunToken>%'`. The token only
  contains `[a-z0-9-]`, so no escaping is needed.
- The user's real data stays untouched: no `%APPDATA%`/`%LOCALAPPDATA%`
  Clippy files, no `SettingsStore`, no registry writes. The index lives under
  `TempRoot\index`. The fixture asserts that `Indexes` paths start with
  `TempRoot`.
- If the user's tray app is running, that's fine (two COM clients). The
  runner only warns about it.

### Fixture (`LiveOutlook`)

- The constructor does no COM. When `!Enabled`, `InitializeAsync` sets
  `NotReadyReason = SkipTexts.NotLive` and returns; `Worker` etc. may be
  null-forgiving placeholders that are never used. The CI Windows job
  filters `live!=outlook`, so the fixture is never built there anyway.
- Fixture settings: `Settings.CreateDefault(TempRoot\profile)`, then
  `AttachmentDir = TempRoot\attachments`, `AllowedFolders = [AllowedDir]`,
  `MeetingInviteMode = DraftOnly`, `RetentionMonths = 1`,
  `IndexedFolders = ["Inbox"]`, and, when `SharedMailbox` is set,
  `SharedMailboxes = [new SharedMailbox { Smtp = SharedMailbox, Enabled = true, IndexedFolders = ["Inbox"] }]`.
  Create every directory.
- Worker: `new OutlookWorker(Hub, NullLogger.Instance)` with production
  timeouts, then `Start()`. Build `Stores = new OutlookStores(Worker, () => Settings)`
  and `Mail = new OutlookMail(Stores, Indexes, Settings)`.
- Preflight, in `InitializeAsync`: one item through the worker with
  `timeout: 20 s` that reads `app.Name`, `app.Version`,
  `app.Session.ExchangeConnectionMode` and `app.Session.Offline`, releasing
  the session. Map the outcome: `OutlookNotRespondingException` sets
  `NotReadyReason = SkipTexts.NotResponding("the first call to Outlook", 20)`;
  `OutlookUnavailableException` sets `SkipTexts.NotRunning`. On success,
  set `ConnectionMode` to the enum name and number, and write
  `Result("connection-mode", "<mode>, Offline=<bool>, Outlook <version>")`.
- Previous-run leftovers: after a good preflight, search Drafts, Calendar
  and Deleted Items of the own store for subjects containing `[clippy-live-`.
  Write each one as `LIVE-LEFTOVER: previous run|<folder>|<subject>`.
  Report only; never delete them.
- Results file: path from env `CLIPPY_LIVE_RESULTS`, or
  `TempRoot\results.txt` when unset. Append-only with a lock, UTF-8, one
  line per entry.
- `DisposeAsync`: for every item still in the ledger, wait up to 60 s for
  `Worker.State == Available`, then try `DeleteAsync`. Write each item that
  is still left as `LIVE-LEFTOVER: <mailbox or "own">|<folder>|<subject>`.
  Then dispose `Indexes` and `Worker`, and delete `TempRoot` recursively
  (best effort, but keep `results.txt` if it lives under `TempRoot`: write
  it to `%TEMP%\clippy-live\last-results.txt` first when
  `CLIPPY_LIVE_RESULTS` is unset). `DisposeAsync` must never throw.

### Timeouts and ordering

| Layer | Limit |
|---|---|
| Each COM call | Worker defaults (interactive 30 s), `OutlookStores.LookupTimeout` (10 s) for owner lookups, `AttachmentTimeout` (120 s) for saves, 20 s for the preflight |
| Each test | `[Fact(Timeout = 180_000)]`, except the sync test (`600_000`) |
| End-to-end sync | `CancellationTokenSource(TimeSpan.FromMinutes(5))`. A cancel is not a failure: `TimedOut = true` and the tests use what got indexed |
| `RequireReadyAsync` wait for recovery | 60 s |
| Whole run | the runner's `-TimeoutMinutes` (default 20), then the process tree is killed |

The suite runs sequentially: one collection with
`DisableParallelization = true`. Tests must not depend on execution order.
Shared state (the sync) is lazy, through `EnsureSyncedAsync`.

### End-to-end sync (`EnsureSyncedAsync`)

`new SyncEngine(new OutlookMailSource(Worker, Stores, Mail), Hub, logger: null, reconcile: null)`
then `SyncMailboxAsync(new MailboxPlan("", ["Inbox"], 1), Indexes.For(""), cts.Token)`.
Record `StartedUtc` before the call and `CutoffUtc = StartedUtc.AddMonths(-1)`.
On `OperationCanceledException` from the 5-minute token, set `TimedOut`.
Let `OutlookUnavailableException` (including NotResponding) become a skip,
using `SkipTexts.NotResponding("the sync", 60)` or `NotRunning`.
A skip outcome is cached too: later callers skip with the same message,
and the sync is not retried. `IndexedCount = Indexes.For("").Status().TotalEmails`. Write
`Result("sync", "<n> emails in <s> s, backfill complete=<bool>, timed out=<bool>")`.

## Tests

All tests below are live (`[Trait("live","outlook")]`,
`[Trait("os","windows")]`), except §G. "Skip" always means `Assert.Skip`
with a `SkipTexts` message.

### A. `LiveConnectionTests`

1. `Attach_never_launches_outlook`: does **not** call `RequireReadyAsync`
   (it must also run when Outlook is closed; it still skips with `NotLive`
   when `!Enabled`). Take `Process.GetProcessesByName("OUTLOOK")` ids
   before. Call `new OutlookAttacher().TryAttach()` on a fresh STA thread,
   then release. If Outlook was not running: the result is `null`, and after
   5 s there is still no `OUTLOOK` process. If it was running: the result is
   not null, and after 2 s the set of `OUTLOOK` pids is unchanged.
2. `Preflight_reports_connection_mode`: `fx.ConnectionMode` is not
   `"unknown"`, and `Worker.State == Available`.
3. `Stores_list_has_own_mailbox`: `Stores.List(app)` has exactly one
   `IsOwn` entry with a non-empty `StoreId`. A non-empty `Smtp` satisfies
   `MailAddresses.LooksLikeSmtp`. `Stores.Get(app, "")` returns a store
   whose `StoreID` equals it (release it). With `SharedMailbox` set,
   `StoreCatalog.Find(list, SharedMailbox)` is not null, else skip with
   `SkipTexts.NoShared` for that part only (use a separate test
   `Stores_list_has_shared_mailbox`).
4. `Owner_smtp_lookup_is_bounded_offline`: for the own store, call
   `Worker.RunAsync(app => Stores.LookupOwnerSmtp(app, id), Interactive, ct, OutlookStores.LookupTimeout)`
   **directly** (not `fx.RunAsync`: a timeout is an expected outcome here).
   - It returns: a non-null value satisfies `LooksLikeSmtp` and, when the
     Accounts SMTP is known, equals it ignoring case.
   - It throws `OutlookNotRespondingException`: the call must fail within
     `10 s + 5 s`. Then poll `Worker.State` until `Available` (90 s max). If
     it stays down, skip with `NotResponding("recovery after the owner lookup", 90)`.
     After recovery, `Stores.List(app)` succeeds in under 30 s, since it
     makes local calls only.
   Write `owner-smtp-lookup` either way.
5. `Mail_folders_include_inbox_and_sent`: `Stores.ListMailFolders(app, "")`
   contains `"Inbox"` and `"Sent Items"` (canonical) and has at most 2000
   entries. `Mail.ResolveFolder(app, "", "inbox")` has `Path == "Inbox"`
   and `TimeField == Received`; `"sent items"` gives `Sent`.
   `ResolveFolder(app, "", "No Such Folder <RunToken>")` throws
   `MailFolderNotFoundException` with the message
   `Folder "No Such Folder <RunToken>" was not found in your own mailbox. Check the indexed folders in the Clippy tray settings.`

### B. `LiveMailReadTests`

1. `Range_pages_are_disjoint_and_ordered`: use the Inbox `ResolvedFolder`
   and the last 30 days, with `maxRows = 25`. Page with `to = last.EventTime`
   until `!HasMore` or 6 pages. Across pages: no duplicate `EntryId`; each
   page's `EventTime` is non-increasing; every row is in `[from, to)`; and
   a page ends with `HasMore == false` only on the last page. Skip with
   `NoData("Inbox mail in the last 30 days")` when page 1 is empty.
2. `Changed_pages_are_ascending`: `EnumerateChanged(app, inbox, now-30d, now-365d, 25)`
   for up to 4 pages, using `last.LastModified + 1 s`. `LastModified` is
   non-decreasing, there are no duplicates, and no row has
   `LastModified < modifiedFrom`.
3. `Sync_end_to_end_into_temp_index` (600 s): `EnsureSyncedAsync()`. Skip
   with `NoData(...)` when `IndexedCount == 0`, there was no timeout, and
   test B1 found no mail. Assert: the index file is under `TempRoot`; every
   indexed row (`Indexes.Search` with an empty filter, paged, limit 200,
   at most 1000 rows) has `Folder == "Inbox"` and
   `EventTime >= CutoffUtc.AddDays(-1)`. When not `TimedOut`, every
   `EnumerateRange(CutoffUtc.AddDays(1), StartedUtc)` row (all pages) is in
   the index by EntryId. Then run `SyncMailboxAsync` a second time (5 min
   cap): it must not throw, and its total `Upserted` is at most
   `max(25, first run's Upserted / 10)`. Write the numbers as a result.
4. `ReadForIndex_matches_live_item`: for up to 5 indexed rows (newest), call
   `Mail.ReadById(app, entryId)`. `EntryId`, `Subject` and `Unread` equal
   the indexed values. `EventTime` is within 1 s. `SenderEmail` is null or
   satisfies `LooksLikeSmtp` and never starts with `/o=` (case-insensitive).
   Every `To`/`Cc` address part matches `MailAddresses.LooksLikeSmtp` or is
   empty. `Attachments` have distinct positions, and file names are not
   blank.
5. `GetMessage_index_hit`: `MailQueries.GetIndexed(fx.Indexes, TimeZoneInfo.Local, id)`
   is not null for an indexed id, and its subject equals the index row.
6. `GetMessage_live_fallback_when_not_indexed`: build a second empty
   `MailboxIndexes` under `TempRoot\index2` and a second
   `OutlookMail(Stores, index2, Settings)`. `ReadById(app, id)` for an
   indexed id from the main index returns `Mailbox == ""` and the same
   EntryId.
7. `GetMessage_finds_moved_item_by_message_id`: pick an indexed row with
   an `InternetMessageId`, or skip with `NoData("indexed email with an internet message id")`.
   Take the row's `IndexedEmail` (via `Mail.ReadById`) and change
   `EntryId` to the real id with its last 8 hex chars replaced by
   `"00000000"` (a well-formed but non-existent id). Upsert it into
   `index2`. `index2Mail.ReadById(app, fakeId).Email.EntryId` equals the
   **real** id.
8. `GetMessage_unknown_id_throws_not_found`: `index2Mail.ReadById(app, id)`
   with `id = "0000000000000000" + Guid.NewGuid().ToString("N").ToUpperInvariant()`. It throws
   `ItemNotFoundException` with the message
   `Email "<id>" was not found in Outlook. It may have been deleted or moved to a folder that isn't indexed. Run search_emails again to get a current id.`
9. `Read_state_and_LastModificationTime` (§18 open item 1): pick the newest
   indexed row with `Unread == false`, else skip with
   `NoData("read email in the Inbox")`. In one worker item: open it with
   `GetItemFromID`, read `LastModificationTime` (L0), set
   `UnRead = true`, and release **without `Save()`**. In the next item,
   reopen it. If `UnRead` is still false, write
   `read-state-bumps-lmt: inconclusive: UnRead did not persist without Save()`
   and stop. Otherwise read L1, set `UnRead = false`, release, reopen, read
   L2 and `UnRead`. Write `yes` if `L1 > L0` or `L2 > L1`, else `no`.
   `finally`: make sure the item ends up `UnRead == false`. Set it back
   without `Save()`; if that fails, write
   `LIVE-LEFTOVER: own|Inbox|<subject> (left unread)`. Assert the final

## Runner: `scripts/run-live-tests.ps1`

Works on Windows PowerShell 5.1 and pwsh 7. `Set-StrictMode -Version Latest`,
`$ErrorActionPreference = 'Stop'`. Run it from any directory: it resolves
the repo root from `$PSScriptRoot\..`.

Parameters: `[int]$TimeoutMinutes = 20`, `[string]$Shared`,
`[switch]$AllowClosed`, `[switch]$NoBuild`, `[switch]$DryRun`.

Steps:

1. Not on Windows: write `Live tests need Windows with classic Outlook.` and exit 2.
2. `Get-Process OUTLOOK -ErrorAction SilentlyContinue`. If there is none and
   not `-AllowClosed`: `Outlook is not running. Start classic Outlook (not the new Outlook) and try again.`, exit 2.
   With `-AllowClosed`, set the test filter to
   `FullyQualifiedName~Attach_never_launches_outlook` only.
3. Responding check (no COM from the script): up to 3 tries 5 s apart,
   `(Get-Process OUTLOOK).Responding`. If it is still false:
   `Outlook is not responding. Check it for an open dialog, or wait until it finishes starting, then try again.`, exit 3.
4. If `Get-Process ClippysRevenge` finds it: warning
   `Clippy's Revenge is running. That is OK, but pausing sync from the tray makes the run faster.`
5. Write the results file: `$results = Join-Path $env:TEMP "clippy-live\results-<yyyyMMdd-HHmmss>.txt"`.
   Set `$env:CLIPPY_LIVE='1'` and `$env:CLIPPY_LIVE_RESULTS=$results`, and
   `$env:CLIPPY_LIVE_SHARED=$Shared` when given. Restore the previous
   values in `finally`.
6. Unless `-NoBuild`, run `dotnet build -c Release`, and exit 1 if it
   fails.
7. Run `dotnet test tests/ClippysRevenge.Core.Tests -c Release --no-build --filter "live=outlook"` (or the `-AllowClosed` filter)
   with `--logger "trx;LogFileName=live.trx" --logger "console;verbosity=normal" --results-directory <TEMP>\clippy-live\TestResults-<stamp>`
   and `--blame-hang --blame-hang-dump-type none --blame-hang-timeout 11m`.
   Start it with `Start-Process -PassThru -NoNewWindow`. Wait up to
   `$TimeoutMinutes`. On timeout, run `taskkill /T /F /PID <pid>`, print
   `Timed out after <n> minutes; the test run was stopped. Check Outlook, then look in Drafts, Calendar and Deleted Items for "[clippy-live-" items.`,
   and exit 4 after the summary. With `-DryRun`, print the command and the
   environment it would set, then exit 0 without running anything.
8. Summary: parse the `.trx` (XML `ResultSummary/Counters`, `UnitTestResult`).
   Print `Passed: n  Failed: n  Skipped: n`, then each failed test with its
   first message line, then each skipped test with its reason, then every
   `LIVE-RESULT:` line and every `LIVE-LEFTOVER:` line from `$results`. When
   there are leftovers, add
   `Delete the items above in Outlook (they were never sent).`
9. Exit codes: 0 = no failures and no leftovers; 1 = test failures or
   build failure; 2 = preconditions; 3 = Outlook not responding;
   4 = timeout; 5 = only leftovers. Never print environment values except
   `CLIPPY_LIVE*`.
