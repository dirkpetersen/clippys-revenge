# M16.7 Tray and Settings: Rescan emails from the last 24 hours, ReviseDrafts checkbox

Base: `dev` with M16.1–M16.6 merged. **Depends on the M16.6 Core API**
(`docs/briefs/M16.6.md`, "Public API"): `RescanPlan`, `RescanProgress`,
`RescanResult`, `DraftWorker.PlanRescan()`, `RescanAsync(ct)`,
`CancelRescan()`, `CurrentRescan`. Do not start before M16.6 is merged; if
any of those names or shapes differ in the merged code, stop and report.

## Goal

Put the §23.8 rescan in front of the user. A new item
**Rescan emails from the last 24 hours…** in the tray's **AI drafts**
submenu, right after *Draft a reply to the selected email* (§6.2, §19.10),
runs: consent dialog (when there is no consent) → backend check → plan
(`PlanRescan`, off the UI thread) → "nothing to rescan" / "limit used up"
balloon or the confirmation dialog → `RescanAsync`. While the run lasts the
item reads `Cancel rescan (<done>/<total>)` and calls `CancelRescan()`, and
*Draft a reply to the selected email* is disabled. At the end a
click-feedback balloon shows `RescanResult.Message`; clicking it shows Drafts
when anything was drafted or updated. The Settings AI drafts tab gets the
checkbox *Update or remove my AI drafts when a thread moves on*
(`AiDrafting.ReviseDrafts`, §19.2, §19.10). `Program` wires the worker into
the tray and cancels a running rescan on exit. Pure menu/text/balloon logic
lives in Core with tests; WinForms only in App.

SPEC refs: §23.8 (Needs, Plan, Confirmation, One at a time, Progress and
Cancel, Summary), §6.2 (menu layout), §19.10 (tray submenu, Settings tab
checkbox), §19.2 (`ReviseDrafts`), §6.5 (click-feedback balloons are not
rate-limited), §23.1 (`ReviseDrafts` meaning).

## Hard rules that apply here

- **Never send, never delete.** The tray only calls the M16.6 Core API; no
  COM, no Outlook object, no `.Send(`, `.Move(`, `Delete(` in any file of this
  task. The dialog text ends with `Nothing is sent.` (already in
  `RescanTexts.Confirm`).
- **Consent first** (§19.10): no `PlanRescan`/`RescanAsync` call without
  consent; the consent dialog is the existing `AiConsentDialog.Ask(null)`.
- **Never touch Claude credentials**: the backend check is the existing
  `AiStatusChecker.CheckAsync` (sign-in state only via the model's
  `CheckAsync`); no new text mentions a sign-in, login or token (the
  existing `No_text_constant_mentions_a_sign_in` test covers `AiTabTexts`).
- **UI thread never waits on COM, SQLite or the model** (§19.10 "The window
  never runs a model call or a status check on the UI thread"; §4).
  `PlanRescan` runs through `Task.Run`; everything else is awaited.
- Balloons/events never get mail text; the summary text is Core's
  (`RescanResult.Message`: counts, reason, duration only).

## Behavior

### A. `AiDraftsMenu.Build` (Core)

`running = available && rescan is not null`;
`starting = available && rescanStarting && !running`.

| Field | Value |
|---|---|
| `AutoChecked`, `AutoEnabled`, `ShowDraftsVisible`, `ShowDraftsEnabled` | unchanged (a rescan doesn't affect them) |
| `DraftSelectedEnabled` | `available && !outlookUnavailable && !running && !starting` |
| `RescanText` | `running ? RescanTexts.CancelItem(rescan.Done, rescan.Total) : RescanTexts.MenuItem` |
| `RescanEnabled` | `running ? true : available && !outlookUnavailable && !starting` |
| `RescanCancels` | `running` |

- Cancel stays enabled while Outlook is unavailable (the user can always stop
  it).
- `busy` (a tray toggle) affects only `AutoEnabled`, as today.
- With the defaults (`rescan = null`, `rescanStarting = false`) every
  existing call returns the same values as before plus
  `(MenuItem, available && !outlookUnavailable, false)`; the two existing
  `Assert.Equal(new AiDraftsMenuModel(…5 args…), m)` tests stay green.

### B. `RescanFlow` (Core)

- `PlanBalloon`: `plan.Emails == 0` → `RescanTexts.NothingToRescan`
  (`There are no emails from the last 24 hours to rescan.`), even when the
  limit is also reached; else `plan.LimitReached` →
  `RescanTexts.LimitUsedUp(plan.Cap)` (`Today's AI draft limit (<cap>) is used up.`);
  else null.
- `ResultBalloon`: `!result.Started && string.IsNullOrWhiteSpace(result.Message)`
  → null. Otherwise `new Balloon(result.Message, BalloonKind.Info, action)`
  with `action = result.Started && result.ShowDrafts ? BalloonAction.ShowDrafts : BalloonAction.None`.
  (`!Started` with the consent message → a balloon without action.)

### C. Menu wiring (`TrayApp.cs`)

### D. `RescanClicked()` (`TrayApp.Rescan.cs`, UI thread)

```
ai = _s.Ai; if null → return
if ai.CurrentRescan() is not null → ai.CancelRescan(); return          (the item is "Cancel rescan (…)")
if Interlocked.CompareExchange(ref _rescanPhase, 1, 0) != 0 → return    (already preparing/awaiting)
try
    1. Consent: if !_s.GetSettings().AiDrafting.HasConsent:
         if !AiConsentDialog.Ask(null) → return; ai.Toggler.RecordConsent()
       (exactly as DraftSelected; Enabled is NOT turned on)
    2. status = await ai.Checker.CheckAsync(refresh: false, CancellationToken.None)
       !status.Ready → PostUserFeedback(RescanTexts.NotReady(status.Text)); return
    3. plan = await Task.Run(ai.PlanRescan)                              (SQLite off the UI thread)
       text = RescanFlow.PlanBalloon(plan); not null → PostUserFeedback(text); return
    4. if _disposed → return
       if !ConfirmRescan(plan) → return
    5. r = await ai.Rescan(CancellationToken.None)
       b = RescanFlow.ResultBalloon(r); not null → _s.Balloons.PostUserFeedback(b.Text, b.Action)
catch (IOException or UnauthorizedAccessException or InvalidOperationException ex)   (RecordConsent's save)
    PostUserFeedback(RescanTexts.StartFailed(ex.Message))
catch (OperationCanceledException) { }
catch (Exception ex)
    PostUserFeedback(RescanTexts.StartFailed("something went wrong (" + ex.GetType().Name + ")"))   (type only)
finally
    Interlocked.Exchange(ref _rescanPhase, 0)
```

- `PostUserFeedback` = `_s.Balloons.PostUserFeedback(...)` (click feedback,
  not rate-limited, §6.5). The summary `Ai` event is Core's (M16.6 F); the
  tray adds no event and no log line.
- The tray never calls `RescanAsync` a second time while one runs: the
  `_rescanPhase` guard and the Cancel item make that impossible; Core's
  single flight (`Started == false`, `Message == ""`) is the backstop and
  shows nothing (B).
- The item is enabled while a pass or a manual draft runs: `RescanAsync`
  takes the gate (the pass yields; a manual draft finishes first). While it
  waits, `CurrentRescan` is `(0, 0)` and the item reads `Cancel rescan (0/0)`.
- Cancel: the click calls `CancelRescan()` and returns; the item keeps its
  `Cancel rescan (d/t)` text until Core finishes the current email (§23.8:
  an email whose call returned `Ok` is finished first), then the summary
  balloon `Rescan stopped (cancelled) after …` appears.
- The balloon click goes through the existing `BalloonTipClicked` handler
  (`BalloonAction.ShowDrafts` → `ShowDraftsInOutlook()`); no new handler.

## Spec changes

Not applied by this brief (the caller asked for the brief file only); to be
recorded in `SPEC.md` §23.8 / §19.10 by the architect. All low-risk and
reversible; none touches a hard rule.

1. **Dialog**: a task dialog with caption `Clippy's Revenge`, heading
   `Rescan the last 24 hours?` (the "title"), the `RescanTexts.Confirm` text,
   buttons **Rescan** / **Cancel** (default, Esc), like *Rebuild index…*.
2. **Start failure text**: a consent save failure or an unexpected tray
   error shows the click-feedback balloon
   `I couldn't start the rescan: <reason>` (`RescanTexts.StartFailed`;
   unexpected errors give only the exception type).
3. **Backend check** goes through `AiStatusChecker.CheckAsync(refresh: false)`
   (as the *Draft replies automatically* toggle), so the result also updates
   the worker's status.
4. **Menu states**: from the click until `RescanAsync` returns, the item is
   disabled (while preparing) or reads `Cancel rescan (<done>/<total>)`
   (`(0/0)` while it waits for a running pass to yield); *Draft a reply to
   the selected email* is disabled for that whole time. Cancel stays
   enabled while Outlook is unavailable. The text updates while the submenu
   is open.
5. **Plan balloons**: `n = 0` is checked before the daily limit.
6. **Summary balloon** is shown for every started run (also early stops and
   `0 of 0`); its click shows Drafts only when `drafted + updated > 0`. A
   rescan refused by Core's single flight shows nothing.
7. **Exit** cancels a running rescan (`CancelRescan()` right after the
   message loop ends).
8. **Settings**: the *Update or remove my AI drafts when a thread moves on*
   checkbox sits after *Only when I'm in To or CC* and is enabled whether
   or not automatic drafting is on.
